Обзор

Эта статья призвана облегчить миграцию проектов с CRYENGINE 5.3 на CRYENGINE 5.4 и фокусируется на изменениях, внесенных в формат исходного кода CRYENGINE.

Устаревшие функции

Со временем, по мере появления новых функций, мы устареем от старых, и они будут удалены в будущих выпусках Engine.

В версии 5.4.0 устарели следующие функции:

  • Игровые объекты (доступны только для C++)
  • Lua — заменен на C#
  • Система Actor – заменена компонентами сущности.
  • Система игровых правил — заменена сущностными компонентами и сетевыми клиентскими прослушивателями.
  • Стандартные объекты — недавно были представлены в CRYENGINE 5.3.0, но теперь устарели в пользу новых стандартных компонентов.

Кроме того, следующие функции уже устарели и были удалены из исходного кода Engine и, следовательно, больше не будут работать:

  • Облака - заменены объемными облаками
  • Объемные объекты — заменены объемными облаками

Наконец, рендерер OpenGL больше не поддерживается, однако исходный код по-прежнему поставляется вместе с движком — Vulkan теперь считается эффективной заменой.

Настройка нового проекта CMakeLists

Система проекта была переработана для автоматического создания настройки CMake (CMakeLists.txt) всякий раз, когда используется опция «Создать решение».

Это достигается за счет автоматического обнаружения файлов .cpp и .h в каталоге кода и добавления их в решение. Это означает, что любые настройки, внесенные вами в CMakeLists.txt, будут удалены после создания решения, поэтому мы настоятельно рекомендуем создать резервную копию этого файла перед обновлением.

Файл CMakeLists по-прежнему можно настроить с помощью помощников BEGIN-CUSTOM и END-CUSTOM:

#BEGIN-CUSTOM
# Custom changes in here
#END-CUSTOM

Все, что находится между пользовательскими помощниками, будет автоматически перенесено во вновь созданный файл CMakeLists.txt.

Кроме того, также можно использовать чистый рабочий процесс CMake, не используя опцию «Создать решение» после первого поколения, а затем запуская CMake GUI напрямую.

Как перенести проект с CRYENGINE 5.3 на CRYENGINE 5.4

  1. Откройте проект 5.3, щелкните правой кнопкой мыши проект CryEngine (это файл *.cryproject), затем нажмите «Переключить версию движка».
  2. Во всплывающем окне выберите CRYENGINE 5.4 (используя раскрывающееся меню), а затем нажмите кнопку OK.
  3. Во всплывающем окне нажмите OK, чтобы начать процесс переключения.
  4. Если версия проекта изменится, во всплывающем окне вам будет предложено сначала сделать резервную копию проекта.
  5. Если переключение прошло успешно, в другом всплывающем окне будет предложено сгенерировать решение и пересобрать проект.
  6. Теперь щелкните правой кнопкой мыши файл *.cryproject и выберите «Создать решение» в меню.
  7. Если это проект C++, CMake создаст решение в каталоге Solutions/win_x64. Если это проект C#, решение будет создано в папке кода. Решение будет называться Game.sln.
  8. Если при создании решения в CMake возникает ошибка, убедитесь, что Visual Studio установлен с поддержкой проектов C++.
  9. Теперь решение можно открыть. Для проектов C++ решение можно открыть в Visual Studio. Для проектов C# его можно открыть с помощью Xamarin Studio, если в нем установлена ​​надстройка CRYENGINE. Для получения дополнительной информации см. Программирование на С#.
  10. Затем создайте решение, нажав кнопку «Сборка/сборка решения» в Visual Studio или «Сборка/сборка всего» в Xamarin Studio.
  11. API изменился между CRYENGINE 5.3 и 5.4, поэтому в процессе сборки могут возникнуть ошибки — эти ошибки необходимо исправить вручную. Более подробную информацию об изменениях кода можно найти в Важная информация CRYENGINE 5.4. Изменения данных и кода.
  12. Если решение построено успешно, можно запустить редактор GameLauncher и Sandbox. В Visual Studio это можно сделать, установив редактор GameLauncher, GameServer или Sandbox в качестве запускаемого проекта в обозревателе решений. В Xamarin Studio есть раскрывающееся меню (вверху слева), в котором можно выбрать предпочитаемую программу запуска. После того, как программа запуска выбрана, ее можно запустить, нажав F5.

Необходимые изменения кода для сборки с CRYENGINE 5.4

Если вы используете какой-либо из перечисленных ниже макросов, вам придется обновить свой код, чтобы отразить изменения, которые мы внесли в код Engine.

Вам нужно будет заменить все вхождения старых макросов на их новую форму - это также потребует обновления параметров. Старые макросы принимали два 64-битных целых числа unsigned, тогда как новые ожидают CryGUID.
