Обзор

Большая часть визуальных эффектов в CRYENGINE создается шейдерами. Разработка шейдеров — это особая дисциплина программирования, требующая большого количества экспертных знаний, особенно потому, что код шейдера может быть очень критичным к производительности и зависеть от платформы.

Это руководство поможет начать разработку шейдеров в CRYENGINE, однако общее введение в программирование шейдеров выходит за рамки этой статьи.

Написание шейдерного кода

Самый простой способ написать шейдеры — использовать текстовый редактор и Sandbox. Sandbox поддерживает горячую перезагрузку шейдеров, поэтому всякий раз, когда вы изменяете и сохраняете файл шейдера в текстовом редакторе, он автоматически перезагружается, и результаты можно просмотреть непосредственно на тестовом уровне.

Горячая перезагрузка также поддерживается на консолях путем ввода r_reloadshaders 1 во внутриигровой консоли. Перед перезагрузкой шейдеры необходимо скопировать в консоль.

Для X360 их необходимо скопировать непосредственно в Engine/Shaders каталог в наборе для разработки HDD, а для PS3 — локальные файлы в app_home каталог необходимо обновить. Легко написать пакетный файл, который автоматически копирует обновленные шейдеры в необходимые папки.

Чтобы горячая перезагрузка шейдеров работала правильно, в system.cfg необходимо добавить следующие параметры:

sys_PakPriority = 0

r_ShadersEditing = 1

sys_PakPriority 0 гарантирует, что файлы шейдеров загружаются непосредственно из файловой системы, а не только из pak-файлов. r_ShadersEditing 1 гарантирует, что код шейдера может быть перекомпилирован во время выполнения.

Удаленный компилятор шейдеров

Настоятельно рекомендуется использовать локально работающий удаленный компилятор шейдеров, чтобы генерировались символы отладки шейдера. См. Удаленный компилятор шейдеров для получения подробных инструкций.

Использование инструментов отладки и профилирования шейдеров

На Xbox 360 PIX можно использовать для отладки и профилирования кода шейдера. Чтобы это работало правильно Использование PIX для профилирования GPU и CPU необходимы. Для PS3 GPAD предоставляет аналогичную функциональность.

Чтобы использовать его, необходимо отключить автоматическое переключение обратного буфера с частотой 10 Гц и использование памяти RSX в качестве памяти virtual:

sys_flip10Hz = 0

ps3_virt_mem_rsx_size_kb = 0

Базовый формат шейдера

CRYENGINE использует собственный формат эффектов шейдера, очень похожий на HLSL и CgFX. Файл эффекта содержит базовый код аппаратного шейдера. Кроме того, он может определять методы и объявлять сэмплеры и константы.

Чтобы обеспечить повторное использование общего кода, файлы эффектов могут включать в себя другие файлы шейдеров.

Шейдеры, которые можно использовать непосредственно для рендеринга (например, в материале), имеют расширение .cfx в то время как включаемые файлы шейдера имеют расширение .cfi.

Флаги шейдеров

CRYENGINE использует систему убершейдеров с определениями во время компиляции для обработки множества различных Перестановки шейдеров которые необходимы для объединения многочисленных функций шейдера.

Используя ifdefs с флагами шейдера, можно определить несколько ветвей кода, которые компилируются и используются в зависимости от битовой маски флага. Компилятор шейдеров генерирует разные аппаратные программы шейдеров для каждой ветви и сохраняет их в кэше шейдеров. Большое количество флагов может привести к множеству перестановок, поэтому важно, чтобы количество флагов было как можно меньшим. Существует три различных типа флагов:

  • Флаги двигателя - Этот тип флага напрямую выставляется движком. Флаги движка содержат общую информацию, такую ​​как поддерживаемая модель шейдера или платформа, на которой в данный момент работает движок.
  • Флаги материалов — Флаги материалов определяют локальные параметры для одного шейдера. Эти флаги оцениваются во время компиляции, поэтому их нельзя изменить во время выполнения. Флаги материалов используются для параметризации шейдеров и обычно предоставляются дизайнерам через редактор материалов.
  • Флаги времени выполнения — Флаги времени выполнения динамически устанавливаются и снимаются движком во время рендеринга. Они дают возможность отключить специальную функцию, если она не требуется для текущего объекта на текущем этапе конвейера рендеринга.

Флаги материалов определяются в файлах расширения (.ext). Каждый файл эффекта, предоставляющий новые флаги, должен иметь соответствующий файл расширения с тем же именем. Файл ext содержит список Недвижимость блоки, где каждый из этих блоков определяет один флаг. Каждое свойство должно содержать Имя атрибут (который будет использоваться в шейдере для доступа к флагу) и битовую маску. Битовая маска должна быть уникальной внутри файла ext и используется компилятором шейдеров для определения того, какие ветки необходимо перекомпилировать в случае обновления кода шейдера. Имя флага отображается глобально, поэтому необходимо позаботиться о том, чтобы не возникало конфликтов имен.

Все доступные флаги времени выполнения определены в файле расширений. RunTime.ext.

Пример использования флагов времени выполнения в коде шейдера:

#if %_RT_HDR_MODE && %_RT_HDR_FAKE
    OUT.Color1 = sceneColor1;
#else
    OUT.Color1 = sceneColor2;
#endif
