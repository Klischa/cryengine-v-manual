Цель CryLobby

CryLobby — это набор модулей, абстрагирующих службы лобби и подбора игроков, специфичные для конкретной платформы. На данный момент Crytek реализовала поддержку следующих сервисов:

  • Сеть PlayStation
  • Xbox Live
  • LAN

Начиная с CryEngine 5.2, CryLobby отделен от движка в CryExtensions/CryLobby папку и совершенно необязателен для сборки и запуска движка. Вы можете управлять созданием экземпляра CryLobby, используя InitializeEngineModule(...) из игры. Для получения дополнительной информации см. CGame::Init() из примера GameSDK:

if (!gEnv->pSystem->InitializeEngineModule("CryLobby", "EngineModule_CryLobby", false))
{
 CryWarning(VALIDATOR_MODULE_GAME, VALIDATOR_ERROR, "Error creating Lobby System!");
}

Интерфейсы

  • ICryLobby: Центральная точка доступа к услугам лобби, доступная через gEnv->pNetwork->GetLobby().
  • ICryMatchmaking: обрабатывает задачи на основе сеанса, такие как создание, поиск или присоединение к комнатам.
  • ICryVoice: Завершает VOIP; в настоящее время используется в основном для отключения звука групп игроков.
  • ICryStats: обрабатывает постоянную статистику и операции с таблицами лидеров.
  • ICryReward: обрабатывает достижения.
  • ICryTCPService: базовая реализация TCP (используется для телеметрии).
  • ICryFriends: используется для управления списком друзей, например для списка друзей или отправки приглашения в игру.
  • ICryLobbyUI: Доступ к xmb - показывать карты игроков, показывать список друзей, устанавливать богатое присутствие.

CryLobby API

Услуга — eCLS_LAN или eCLS_Online. В настоящее время вы можете иметь только по одному экземпляру каждого из них. LAN предоставляет только ICryMatchMaking интерфейс.

Онлайн предоставляет более полный набор. В общем, все функции лобби ожидают обратного вызова и возвращают идентификатор задачи.

CryLobby Конфигурация

Из-за различий в функциональности сторонних разработчиков дополнительный обратный вызов может быть выполнен в любое время.

CryLobbyConfigurationCallback используется для предоставления подробной информации о вашей игре, которая не отображается через обычный API.

CryLobby Использование

События

Игра может регистрироваться как заинтересованная в событиях. Например, игрок подключился к LIVE, сетевой кабель отключен, приглашение в игру получено.

Обратный звонок

Большинство функций в CryLobby и подсистемах возвращают код ошибки.

  • eCLE_Success = 0
  • eCLE_TooManyTasks
  • eCLE_InvalidSession
  • ...

Эти коды ошибок также возвращаются в функциях обратного вызова. Полный список можно найти в ICryLobby.h.

Отмена задач

Это происходит, например, когда ваш класс слушателя уничтожается.

taskId — это выходной параметр любой функции лобби, которая также принимает обратный вызов.

Рекомендуется избегать, где это возможно, особенно при выполнении определенных задач, таких как SessionCreate, SessionJoin или SessionDelete. Это может не остановить выполнение задачи (может быть слишком поздно прерывать ее), но остановит запуск обратного вызова.

CryMatchMaking

Управляет сессиями

Ограничения:

  • Максимум 4 сеанса (MAX_MATCHMAKING_SESSIONS)
  • До 64 игроков (MAX_LOBBY_CONNECTIONS)

Лимит подключений — это общий лимит, который распределяется между сеансами.

Большинству функций требуется дескриптор сеанса, который возвращается SessionCreate или SessionJoin.

SessionCreate
virtual ECryLobbyError SessionCreate(uint32* users, int numUsers, uint32 flags, SCrySessionData* data, 
CryLobbyTaskID* taskID, CryMatchmakingSessionCreateCallback cb, void* cbArg) = 0;

Пользовательский указатель вместе с параметрами счетчика numUsers передает массив пользовательских индексов и соответствует индексу площадки.

Параметр flags может быть одним из следующих:

  • CRYSESSION_CREATE_FLAG_SEARCHABLE
  • CRYSESSION_CREATE_FLAG_INVITABLE
  • CRYSESSION_CREATE_FLAG_NUB
  • CRYSESSION_CREATE_FLAG_MIGRATABLE
  • CRYSESSION_LOCAL_FLAG_CAN_SEND_SERVER_PING

Аргумент Data представляет объявленные/синхронизированные значения, которые можно изменить с помощью SessionUpdate.

SessionJoin
virtual ECryLobbyError SessionJoin(uint32* users, int numUsers, uint32 flags, CrySessionID id, 
CryLobbyTaskID* taskID, CryMatchmakingSessionJoinCallback cb, void* cbArg) = 0;

Функция аналогична SessionCreate. В качестве аргумента он принимает CrySessionID. Предоставляется обратным вызовом поиска, обратным вызовом приглашения или игровым пакетом в другом сеансе.

SessionDelete
virtual ECryLobbyError SessionDelete(CrySessionHandle h, CryLobbyTaskID* taskID, 
CryMatchmakingCallback cb, void* cbArg) = 0;

CrySessionHandle предоставляется обратным вызовом SessionCreate или SessionJoin.

Пользовательские пакеты

Отправляйте произвольные пакеты. Не использует фиксированный формат.

Вот пример:

CCryLobbyPacket packet;
Uint32 bufferSize = CryLobbyPacketReliableHeaderSize + CryLobbyPacketUINT8Size;
 
if (packet.CreateWriteBuffer(bufferSize))
{
  packet.StartWrite(type, reliable);
  packet.WriteUINT8(3);
}

Также посмотрите SendToClient и SendToServer.

События

Обрабатывается тем же механизмом, что и CryLobbyEvents.

События MatchMaking будут иметь sessionHandle как часть данных обратного вызова. Проверьте это по текущему сеансу, поскольку вы не регистрируетесь на события в конкретном сеансе.
