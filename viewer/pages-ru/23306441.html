Обзор

Анимация может быть очень ресурсоемким ресурсом. Ограниченный бюджет памяти, большое количество анимированных соединений и высокие требования к качеству анимации делают загрузку всех анимаций крайне расточительной для проекта. в памяти все время.

Система анимации CRYENGINE решает эту проблему за счет потоковой передачи ресурсов анимации (уровень детализации файлов), когда они необходимы, и выгрузки их, когда они больше не используются. Потоковая передача файлов ресурсов достигается с помощью Потоковая система. Потоковая передача ресурсов позволяет хранить в памяти только те ресурсы, которые нам нужны, за счет большей сложности, поскольку теперь нам требуется определенное планирование того, как и когда будут использоваться ресурсы анимации.

Данные анимации

Использование данных анимации можно разделить на два основных раздела: Данные заголовка и Данные контроллеров.

заголовок раздел содержит общую информацию об анимации (имя файла, продолжительность, флаги и т. д.).

контроллер раздел содержит кривые анимации. Для каждого задействованного сустава он содержит информацию обо всех значениях положения и ориентации, которые необходимы суставу для воспроизведения этой анимации. Даже в сжатом виде данные контроллера могут легко занять более 95% всей памяти, необходимой для анимации.

Данные заголовка анимации

Данные заголовка для анимации хранятся в файлах CAF и в файлеanimations.img.

Файлы CAF содержат информацию заголовка для одной анимации, а файлanimations.img содержит информацию заголовка для всех анимаций в сборке. Animations.img получается в результате обработки всех анимаций компилятором ресурсов.

Движок обычно загружает заголовки всех файлов анимации из файла анимации.img, а не из отдельных файлов, поскольку чтение информации из отдельных файлов может значительно замедлить время загрузки.

Учитывая огромную разницу в размерах между контроллерами и заголовками, мы осуществляем только потоковую передачу данных контроллера. Данные заголовка для всех анимаций всегда хранятся в памяти, поскольку практично всегда иметь эту информацию под рукой.

В ходе разработки, например при работе с локальными файлами анимации необходимо отключить использование анимации.img и вместо этого загружать информацию заголовка из отдельных файлов CAF. Для этого установите ca_UseIMG_CAF консольная переменная в 0 раньше двигатель запускается.

Данные контроллера анимации

Расположение в файлах

Данные контроллера для анимации хранятся в файлах CAF или DBA файлов.

Файлы CAF содержат информацию о контроллере для одной анимации.

Файлы DBA содержат информацию о контроллере для группы анимаций.

Когда DBA загружен, контроллеры для всех анимаций, содержащихся в этом DBA, будут доступны до тех пор, пока DBA не будет выгружен. По этой причине полезно группировать одинаковые анимации DBA, которые используются вместе (например, в Crysis3 для каждого оружия был файл DBA). Дополнительным преимуществом объединения похожих анимаций в DBA является то, что одинаковые контроллеры сохраняются только один раз. Это потенциально может значительно сократить использование памяти вашей анимацией.

Загрузка данных контроллера

Система анимации может правильно воспроизводить анимацию только тогда, когда ее контроллеры находятся в памяти.

Если нам не повезет и данные контроллера будут недоступны при запросе воспроизведения ресурса, система анимации передаст его с диска. Потоковая передача данных контроллера выполняется асинхронно: система анимации не ждет после запроса воспроизведения ресурса. Это предотвращает нежелательные зависания системы.

Если системы высокого уровня не уведомляют систему анимации о том, что им требуются данные контроллера (см. функции предварительной загрузки ниже), то самое раннее, когда система анимации узнает, что актив требуется, является моментом, когда его запрашивают на воспроизведение. Это опасно близко к тому моменту, когда необходимы данные контроллера. Если данные контроллера недоступны к моменту, когда они необходимы, это обычно приводит к визуальным сбоям. (Эти случаи иногда можно выявить, когда мы наблюдаем сбои, например, только при первом воспроизведении анимации)

Поэтому считается очень удобным передавать данные контроллера в потоковом режиме до того, как будет запрошено воспроизведение анимации: чтобы минимизировать нежелательные сбои из-за ожидания окончания потоковой передачи анимации.

Время, необходимое для завершения потоковой передачи, зависит от многих факторов, таких как текущая загрузка системы, скорость потоковой передачи целевой системы, размер ресурса, который необходимо загрузить, и т. д.

Выгрузка данных контроллера

Система анимации не будет выгружать данные контроллера во время использования.

Можно полностью предотвратить выгрузку данных анимации, установив ca_DisableAnimationUnloading до 1.

Контроллеры в файлах CAF выгружаются после того, как система выясняет, что ими больше никто не пользуется. Чтобы предотвратить выгрузку контроллеров в файлах CAF, установите ca_UnloadAnimationCAF до 0.

Контроллеры в файлах DBA остаются в памяти до тех пор, пока не пройдет определенное время с момента использования анимации в них, если только DBA не заблокирован, и в этом случае он не будет выгружен, пока статус блокировки не будет установлен обратно в 0.

Чтобы настроить время, которое система анимации использует для выгрузки контроллеров в файлах DBA, используйте следующие переменные:

ca_DBAUnloadUnregisterTime: Тайм-аут в секундах перед последним использованием контроллера в DBA и когда все анимации, использующие этот DBA, будут отмечать данные своего контроллера как выгруженные.

ca_DBAUnloadRemoveTime: тайм-аут в секундах с момента последнего использования контроллера в DBA, который должен пройти до того, как DBA действительно будет выгружен из памяти. Должно быть больше или равно ca_DBAUnloadUnregisterTime.

В памяти можно заблокировать отдельные ресурсы, чтобы система не могла их выгружать.

Предварительная загрузка и хранение контроллеров в памяти

Ответственность за вызов функций предварительной загрузки возлагается на системы высокого уровня или пользовательский код (обычно код игры), поскольку именно здесь доступна большая часть информации о том, когда и как осуществляется доступ к ресурсам. Например, trackview просматривает на временной шкале на несколько секунд вперед любую анимацию, которая может появиться, и вызывает функции предварительной загрузки.

Предварительная загрузка контроллеров в файлах DBA

Чтобы предварительно загрузить и запустить потоковую передачу файла DBA:

gEnv->pCharacterManager->DBA_PreLoad(dbaFilename, priority);

Чтобы запустить потоковую передачу файла DBA (и запросить изменение состояния блокировки, которое указывает, следует ли заблокировать его в памяти):

gEnv->pCharacterManager->DBA_LockStatus(dbaFilename, lockStatus, priority);

Выгрузить все данные контроллера в DBA из памяти (данные будут выгружены только в том случае, если ни один из контроллеров в данный момент не используется).

gEnv->pCharacterManager->DBA_Unload(dbaFilename);

Вы можете заставить систему автоматически загружать и блокировать файл DBA во время загрузки персонажа, используя функцию flags="persistent" в файле chrparams. См. Файл базы данных (dba) или CHRPARAMS Файл для более подробной информации.

Предварительная загрузка контроллеров в файлах CAF

Чтобы увеличить количество ссылок файла CAF:

gEnv->pCharacterManager->CAF_AddRef(lowercaseAnimationPathCRC);

Контроллеры файла CAF начнут потоковую передачу, когда его счетчик ссылок изменится с 0 на 1.

Чтобы уменьшить количество ссылок файла CAF:

gEnv->pCharacterManager->CAF_Release(lowercaseAnimationPathCRC);

Контроллеры для файла CAF будут выгружены системой анимации только после того, как счетчик ссылок достигнет 0 (система анимации при воспроизведении файла CAF также увеличивает этот счетчик ссылок, поэтому анимация не будет выгружена во время использования).

Чтобы проверить, загружены ли контроллеры для файла CAF:

gEnv->pCharacterManager->CAF_IsLoaded(lowercaseAnimationPathCRC);

Чтобы синхронно загрузить контроллеры для файла CAF:

gEnv->pCharacterManager->CAF_LoadSynchronously(lowercaseAnimationPathCRC);

Настоятельно не рекомендуется синхронно загружать ресурсы CAF без крайней необходимости, поскольку это, скорее всего, приведет к зависаниям.
