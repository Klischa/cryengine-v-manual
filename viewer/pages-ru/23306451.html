Обзор

Особенности

  • Отделение пользовательского кода сериализации от фактического формата хранения. Это возможность переключаться между форматами XML/JSON/Binary без изменения пользовательского кода.
  • Повторное использование того же кода сериализации для редактирования в PropertyTree. Напишите код сериализации один раз и используйте его, чтобы представить свою структуру в редакторе в виде дерева параметров.
  • Возможность написать сериализацию неинтрузивным способом (как глобальные перегруженные функции) без изменения сериализуемых типов.
  • Легко изменить формат, т. е. добавить/удалить или переименовать поля, сохраняя при этом возможность загружать старые данные.

Урок

Я начну с макета данных, использующего некоторые общие функции: стандартные типы, перечисления, контейнеры.

Обратите внимание, что я добавляю метод Serialize к структурам с некоторой фиксированной сигнатурой.

Определение данных

#include "Serialization/IArchive.h"
#include "Serialization/STL.h"

enum AttachmentType
{
  ATTACHMENT_SKIN,
  ATTACHMENT_BONE
};
struct Attachment
{
  string name;
  AttachmentType type;
  string model;
  void Serialize(Serialization::IArchive& ar)
  {
    ar(name, "name", "Name");
    ar(type, "type", "Type");
    ar(model, "model", "Model");
  }
};
struct Actor
{
  string character;
  float speed;
  bool alive;
  std::vector<Attachment> attachments;
  Actor()
  : speed(1.0f)
  , alive(true)
  {
  }
  void Serialize(Serialization::IArchive& ar)
  {
    ar(character, "character", "Character");
    ar(speed, "speed", "Speed");
    ar(alive, "alive", "Alive");
    ar(attachments, "attachments", "Attachment");
  }
};
 
// Implementation file:
#include "Serialization/Enum.h"

SERIALIZATION_ENUM_BEGIN(AttachmentType, "Attachment Type")
SERIALIZATION_ENUM(ATTACHMENT_BONE, "bone", "Bone")
SERIALIZATION_ENUM(ATTACHMENT_SKIN, "skin", "Skin")
SERIALIZATION_ENUM_END()
Зачем нужны два имени?

Вызов ar() принимает два строковых аргумента: один вызывается имяи второй этикетка. Первый используется для постоянного хранения параметров, например, для JSON и XML. Второй параметр используется для PropertyTree. Почему они разные? Этикетка Параметр часто длиннее, более описателен, содержит пробелы и может быть легко изменен без нарушения совместимости со старыми данными. Имя с другой стороны, это идентификатор стиля C. Также удобно иметь имя соответствие имени переменной, чтобы разработчик мог легко найти переменную, просматривая файл данных.

Пропуск этикетка Параметр (эквивалент передачи nullptr) скроет параметр в PropertyTree, но он по-прежнему будет сериализован и его можно будет скопировать с помощью копирования и вставки вместе со своим родительским элементом.

Обратите внимание, что на данный момент макросы SERIALIZATION_ENUM должны находиться в файле реализации (.cpp), поскольку они содержат определения символов.

Сериализация в/из файла

Теперь ваши данные готовы к сериализации. Например, вы можете использовать Serialization::JSONOArchive:

#include <Serialization/IArchiveHost.h> 

 
Actor actor;
Serialization::SaveJsonFile("filename.json", actor);

Это создаст контент в следующем формате:

{
  "character": "nanosuit.cdf",
  "speed": 2.5,
  "alive": true,
  "attachments": [
    { "name": "attachment 1", "type": "bone", "model": "model1.cgf" },
    { "name": "attachment 2", "type": "skin", "model": "model2.cgf" }
  ]
}

Чтение данных аналогично:

#include <Serialization/IArchiveHost.h>
 
Actor actor;
Serialization::LoadJsonFile(actor, "filename.json");

Упомянутые функции Функции сохранения/загрузки являются обертками интерфейса IArchiveHost, экземпляр которого находится в gEnv->pSystem->GetArchiveHost().
В качестве альтернативы, если у вас есть прямой доступ к коду архивов (если они расположены в одних и тех же модулях, например, в CrySystem или EditorCommon), вы можете напрямую использовать классы архивов:

#include <Serialization/JSONOArchive.h>
#include <Serialization/JSONIArchive.h>

Serialization::JSONOArchive oa;

Actor actor;
oa(actor);
oa.save("filename.json");
 
// to get access to the data without saving:
const char* jsonString = oa.c_str();
 
// and to load
Serialization::JSONIArchive ia;
if (ia.load("filename.json"))
{
  Actor loadedActor;
  ia(loadedActor);
}

Редактирование в PropertyTree

Если у вас есть метод Serialize, реализованный для ваших типов, достаточно предоставить его QPropertyTree.

#include <QPropertyTree/QPropertyTree.h>
 
QPropertyTree* tree = new QPropertyTree(parent);
 
static Actor actor;
tree->attach(Serialization::SStruct(actor));

Обратите внимание, что вы можете выбирать значения перечисления из списка, а также добавлять/удалять векторные элементы с помощью кнопки [ 2 ] или контекстного меню.

В момент подключения будет вызван метод Serialize для извлечения свойств из вашего объекта. Как только пользователь изменяет свойство в UI, вызывается метод Serialize для записи свойств обратно в объект.

Важно помнить, что QPropertyTree содержит ссылку на прикрепленный объект, если его время жизни короче, чем необходимо выполнить явный вызов дерева QPropertyTree::detach().

Варианты использования

Неинтрузивная сериализация

Обычно, когда struct или экземпляр класса передается в архив, вызывается метод Serialize экземпляра. Это поведение можно override изменить, объявив следующую глобальную функцию:

bool Serialize(Serialization::IArchive&, Type& value, const char* name, const char* label);

Возвращаемое значение здесь имеет то же поведение, что и IArchive::operator(). Для входных архивов функция возвращает false, если поле отсутствует и не было прочитано. Для выходных архивов он всегда возвращает true. Обратите внимание, что возвращаемое значение не распространяется вверх. Если одно из вложенных полей отсутствует, блок верхнего уровня все равно вернет true.

Этот подход полезен в нескольких сценариях:

  • Добавьте сериализацию ненавязчивым способом;
  • Преобразование данных во время сериализации;
  • Добавьте поддержку неподдерживаемых типов, например. простые указатели.

Вот пример добавления поддержки типа std::pair<>:

template<class T1, class T2>
struct pair_serializable : std::pair<T1, T2>
{
  void Serialize(Serialization::IArchive& ar)
  {
    ar(first, "first", "First");
    ar(second, "second", "Second");
  }
}

template<class T1, class T2>
bool Serialize(Serialization::IArchive& ar, std::pair<T1, T2>& value, const char* name, const char* label)
{
  return ar(static_cast<pair_serializable<T1, T2>&>(value), name, label);
}

Преимущество использования наследования заключается в том, что вы можете получить доступ к полям protected. В случаях, когда политика доступа не важна и наследование нежелательно, вы можете заменить такой код следующим шаблоном:

template<class T1, class T2>
struct pair_serializable
{
  std::pair<T1, T2>& instance;

  pair_serializable(std::pair<T1, T2>& instance) : instance(instance) {}
  void Serialize(Serialization::IArchive& ar)
  {
    ar(instance.first, "first", "First");
    ar(instance.second, "second", "Second");
  }
}

template<class T1, class T2>
bool Serialize(Serialization::IArchive& ar, std::pair<T1, T2>& value, const char* name, const char* label)
{
  pair_serializable<T1, T2> serializer(value);
  return ar(serializer, name, label);
}

Регистрация Enum внутри класса

SERIALIZATION_ENUM_BEGIN() не будет компилироваться, если вы укажете перечисление, указанное внутри класса (вложенное enum).

В таком случае вы можете использовать SERIALIZATION_ENUM_BEGIN_NESTED:

SERIALIZATION_ENUM_BEGIN_NESTED(Class, Enum, "Label")
SERIALIZATION_ENUM(Class::ENUM_VALUE1, "value1", "Value 1")
SERIALIZATION_ENUM(Class::ENUM_VALUE2, "value2", "Value 2")
SERIALIZATION_ENUM_END()

Полиморфные типы

Библиотека сериализации поддерживает загрузку сохранения полиморфных типов. Это реализуется посредством сериализации интеллектуального указателя на базовый тип.

Например, если у вас есть следующая иерархия:

IBase

  • ImplementationA
  • ImplementationB

Вам нужно будет зарегистрировать производные типы с помощью макроса:

SERIALIZATION_CLASS_NAME(IBase, ImplementationA, "impl_a", "Implementation A");
SERIALIZATION_CLASS_NAME(IBase, ImplementationA, "impl_b", "Implementation B");

Теперь вы можете сериализовать указатель на базовый тип:

#include <Serialization/SmartPtr.h>
 
_smart_ptr<IInterfface> pointer;

ar(pointer, "pointer", "Pointer");

Как обычно, первая строка используется для обозначения типа постоянного хранилища, а вторая строка представляет собой удобочитаемое имя для отображения в PropertyTree.

Настройка презентации в PropertyTree

В PropertyTree можно настроить два аспекта:

  • Расположение полей свойств. Они управляются управляющими последовательностями в метке (третий аргумент IArchive::opearator()).
  • Декораторы. Они определяют способ редактирования или представления определенных свойств.
Управляющие персонажи

Управляющие последовательности ставятся в качестве префикса к метке свойства, т.е. третьего аргумента архива. Несколько управляющих символов можно объединить, чтобы объединить их эффекты. Например: 

ar(name, "name", "^!<Name"); // inline, read-only, expanded value field
Декораторы

Существует два типа декораторов:

  • Обертки, которые принимают исходное значение и реализуют пользовательскую функцию сериализации для выполнения над ним двустороннего преобразования.
    Например, Serialization/Math.h содержит Serialization::RadiansAsDeg(float&), который позволяет хранить и редактировать углы в радианах.
  • Обертки, которые не выполняют преобразований, но их тип используется для выбора реализации пользовательского свойства в PropertyTree.
    Примером такой оболочки могут быть все селекторы ресурсов.
Пример использования
float scalar;
ar(Serialization::Range(scalar), 0.0f, 1.0f); // provides slider-UI
string filename;
ar(Serialization::CharacterPath(filename), "character", "Character"); // provides UI for file selection with character filter

Контекст сериализации

Сигнатура метода Serialize фиксирована, и это может помешать вам передавать дополнительные аргументы во вложенные методы Serialize. Чтобы решить эту проблему, был введен контекст сериализации.

Предоставляя контекст сериализации, вы можете передать указатель определенного типа на вложенные вызовы сериализации. Например:

void Scene::Serialize(Serialization::IArchive& ar)
{
  Serialization::SContext sceneContext(ar, this);
  ar(rootNode, "rootNode")
}
 
void Node::Serialize(Serialization::IArchive& ar)
{
  if (Scene* scene = ar.FindContext<Scene>())
  {
    // use scene
  } 
}

Контексты организованы в связанные списки, узлы хранятся в стеке (в экземпляре SContext).

У вас может быть несколько контекстов. Если вы предоставите несколько экземпляров одного и того же типа, будет получен самый внутренний контекст.

Вы также можете использовать контексты с PropertyTree без изменения существующего кода сериализации. Самый простой способ сделать это — использовать CContextList (QPropertyTree/ContextList.h):

// CContextList m_contextList;
tree = new QPropertyTree();
m_contextList.Update<Scene>(m_scenePointer);
tree->setArchiveContext(m_contextList.Tail());
tree->attach(Serialization::SStruct(node));

Сериализация непрозрачных блоков данных

Блокировку данных в архиве можно трактовать непрозрачным способом. В основном это используется редактором для работы с форматами данных, о которых он не знает полностью.

Такие блоки данных могут храниться в Serialization::SBlackBox. Его можно сериализовать или десериализовать как любое другое значение. SBlackBox, десериализованный из архива, можно сериализовать только с помощью соответствующего архива. Т.е. если вы получили свой SBlackBox из JSONIArchive, его можно сохранить только через JSONOArchive.

Добавление обратных вызовов в PropertyTree

Когда вы меняете одно свойство в дереве свойств, весь прикрепленный объект десериализуется. На первый взгляд это может показаться расточительным: зачем нам обновлять все свойства, если было изменено только одно? Но на практике такой подход имеет ряд преимуществ:

  • Нет необходимости отслеживать время жизни вложенных свойств. Удаляет требование, чтобы на вложенные типы можно было безопасно ссылаться извне.
  • Содержимое дерева свойств не является данными static static, а скорее результатом вызова функции. Это означает, что контент может быть полностью динамичным. Вместе с предыдущим пунктом это позволяет сериализовать/десериализовать переменные, созданные в стеке.
  • Пользователю библиотеки рекомендуется работать с более грубой детализацией данных, что приводит к меньшему объему кода.

Тем не менее, бывают ситуации, когда желательно точно знать, какое именно свойство меняется. Есть два способа заархивировать это:

  • Сравните новое значение с сохраненным предыдущим значением с помощью метода Serialize:

    void Type::Serialize(IArchive& ar)
{
  float oldValue = value;
  ar(value, "value", "Value");
  if (ar.IsInput() && oldValue != value)
  {
  // handle change
  } 
}

  • Используйте сериализацию::Callback.
    Этот декоратор дает вам возможность добавить функцию обратного вызова для каждого свойства. Он работает только с PropertyTree и должен использоваться только в коде редактора:

    #include <Serialization/Callback.h>
using Serialization::Callback; 
 
ar(Callback(value,
            [](float newValue) { /* handle change */ }), 
   "value", "Value");

    Его также можно использовать вместе с другими декораторами, но довольно неуклюже:

    ar(Callback(value,
            [](float newValue) { /* handle change*/ }, 
            [](float& v) { return Range(v, 0.0f, 1.0f); }), 
   "value", "Value");

Второй подход более гибкий, но требует от пользователя тщательного отслеживания времени жизни объектов, которые используются лямбда/функтором обратного вызова.

PropertyTree в окне MFC

Если в вашей кодовой базе все еще используется MFC, но вы хотели бы использовать с ним PropertyTree, существует оболочка, которая делает это возможным. 

#include <IPropertyTree.h> // located in Editor/Include
 
int CMyWindow::OnCreate(LPCREATESTRUCT pCreateStruct)
{
  ...
  CRect clientRect;
  GetClientRect(clientRect);
  IPropertyTree* pPropertyTree = CreatePropertyTree(this, clientRect);
  ...
}

IPropertyTree предоставляет методы QPropertyTree, такие как Attach, Detach и SetExpandLevels.

Документация и валидация

QPropertyTree предоставляет возможность добавлять документацию short в виде всплывающих подсказок и базовой проверки.

Первый метод позволяет добавлять всплывающие подсказки в QPropertyTree:

void IArchive::Doc(const char*)
void SProjectileParameter::Serialize(IArchive& ar)
{
  ar.Doc("Defines projectile physics.");
 
  ar(m_velocity, "velocity", "Velocity");
  ar.Doc("Defines initial velocity of the projectile.");
}

Он добавляет подсказку к последнему сериализованному элементу или ко всему блоку при использовании в начале функции.

Два других вызова позволяют отображать предупреждения и сообщения об ошибках, связанные с определенным свойством в дереве свойств.

template<class T> void IArchive::Warning(T& instance, const char* format, ...)
template<class T> void IArchive::Error(T& instance, const char* format, ...)

Например:

void BlendSpace::Serialize(IArchive& ar)
{ 
  ar(m_dimensions, "dimensions, "Dimensions");
  if (m_dimensions.empty()) 
    ar.Error(m_dimensions, "At least one dimension is required for BlendSpace");
}

Выпадающий список с динамическим списком

Если вы хотите указать значение перечисления, я предлагаю вам использовать макрос регистрации enum из Определение данных раздел.

Есть два способа определить раскрывающийся список. Один из них — преобразовать ваши данные в Serialization::StringListValue. Ниже приведен небольшой пример пользовательской ссылки.

// a little decorator that would annotate string as a our special reference
struct MyReference
{
  string& str;
  MyReference(string& str) : str(str) {}
};

inline bool Serialize(Serialization::IArchive& ar, MyReference& wrapper, const char* name, const char* label)
{
  if (ar.IsEdit())
  {
    Serialization::StringList items;
    items.push_back("");
    items.push_back("Item 1");
    items.push_back("Item 2");
    items.push_back("Item 3");
    Serialization::StringListValue dropDown(items, wrapper.str.c_str());
    if (!ar(dropDown, name, label))
      return false;
    if (ar.IsInput())
      wrapper.str = dropDown.c_str();
    return true;
  }
  else
  {
        // when loading from disk we are interested only in the string
    return ar(wrapper.str, name, label);
  }
}

Теперь вы можете создать MyReference в стеке в методе Serialize для сериализации строки в виде раскрывающегося списка:

struct SType
{ 
  string m_reference;
  void SType::Serialize(Serialization::IArchive& ar)
  { 
  ar(MyReference(m_reference), "reference", "Reference");
  }
};

Другой способ потребует от вас реализации пользовательского PropertyRow в UI. Это требует немного больше усилий, но позволяет полностью переместить код, создающий список возможных элементов, в код редактора.
