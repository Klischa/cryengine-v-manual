Обзор

В этом документе представлена информация о компиляторе ресурсов (часто называемом «RC»). Для большинства пользователей RC — это инструмент, работающий в фоновом режиме.

Однако зачастую важно понимать причины существования RC, а также ту важную роль, которую он играет в разработке игр с помощью CRYENGINE.

В CRYENGINE есть концепция исходных и целевых ресурсов. Исходные ресурсы хранятся в формате без потерь (без сжатия с потерями) и могут иметь метаданные, специфичные для ресурса, например, качество сжатия, которое следует использовать. Эти исходные ресурсы не используются движком напрямую, но должны быть скомпилированы в формат, оптимизированный для платформы. В этом процессе исходные данные предварительно обрабатываются и часто сжимаются, чтобы уменьшить требования к памяти и ускорить процесс загрузки в игре. Целевой формат может отличаться на разных платформах. PC и консоли имеют разный порядок байтов и поддерживают разные схемы сжатия текстур. Преобразование источника в целевой объект (компиляция) выполняется компилятором ресурсов (RC), который вы можете найти в RC подпапку папки «Инструменты».

Одной из основных целей RC является сжатие текстур с помощью ResourceCompilerImage модуль. Все исходные текстуры сохраняются в формате TIF без потерь и конвертируются в формат DDS. Экспорт текстур с помощью CryTIF — Photoshop Страницу можно использовать для экспорта файла TIF из Photoshop и открытия диалогового окна, в котором можно выбрать метаданные, например желаемую схему сжатия.

Компилятор ресурсов вызывается из следующих инструментов:

  • Sandbox при использовании LiveCreate или при загрузке текстур TIF, для которых DDS отсутствует.
  • CryTIFPlugin (плагин Photoshop 6 и выше).
  • Средство рендеринга CryENGINE (консольная переменная r_RC_AutoInvoke имеет значение 0 в полноэкранном режиме).
  • PolybumpPlugin (плагин 3ds Max).
  • CryMaxExporter (плагин 3ds Max).
  • CryMayaExporter (плагин Maya).

Пресеты

Компилятор ресурсов поддерживает различные предустановки, определяющие параметры, которые следует применять при компиляции ресурса изображения. При запуске RC загружаются основные настройки и пресеты из основного файла конфигурации (rc.ini).

Файл настроек для компиляции изображений (от TIF до DDS) выглядит следующим образом:

; diffuse colour textures without alpha channel
[Albedo]
pixelformat=BC1
pixelformat:es3=ETC2
rgbweights=ciexyz
powof2=1
mipmaps=1
colorspace=sRGB,auto
;discardalpha=1
filemasks=*_diff*

; diffuse colour textures with alpha channel for alphablend
[AlbedoWithOpacity]
pixelformat=BC7t
pixelformat:es3=ETC2A
rgbweights=ciexyz
powof2=1
mipmaps=1
colorspace=sRGB,auto
filemasks=*_diff*

Вызов RC из командной строки

Следующие примеры позволяют открыть диалоговое окно пользователя, чтобы пользователь мог изменить параметры, хранящиеся в файле TIF.

Обратите внимание, что при использовании диалогового окна можно создать файл .dds, используя Создать DDS кнопка.

Tools\rc\rc c:\temp\test.tif /userdialog

Несколько каталогов и типов файлов могут обрабатываться рекурсивно с помощью расширения . или *. расширение:

Tools\rc\rc c:\*.tif /refresh

Та же команда, но без компиляции файлов .tif, у которых уже есть файлы .dds:

Tools\rc\rc c:\*.tif

Используйте кавычки для компиляции ресурсов со специальными символами (например, пробелами) в пути:

Tools\rc\rc "c:\data folder\*.tif"

Диалоговое окно компилятора ресурсов

На следующем изображении показан пользовательский интерфейс, который можно вызвать с помощью /пользовательский диалог или с помощью Экспортируйте текстуры с помощью CryTIF — Photoshop для Photoshop. Экспортируйте текстуры с помощью CryTIF — Photoshop в документации содержится дополнительная информация об использовании исходной текстуры (.tif) в CRYENGINE.

Примечание

Диалог RC можно вызвать только при обработке файлов SRF и TIF.

Обработка файла Collada из командной строки

Это необязательно, вы можете использовать его, если хотите использовать Collada в качестве промежуточного формата. В противном случае файлы коллады автоматически конвертируются в процессе экспорта.

Чтобы обработать файл Collada с помощью RC из командной строки, вам необходимо выполнить следующие шаги:

  1. Обработайте файл Collada напрямую с помощью RC из командной строки, чтобы вывести несжатый файл. *.caf файл.
rc.exe "fullpath"\walk.dae

2. Обработайте *.i_caf файл, который вы получили на шаге 1, еще раз с помощью RC в командной строке, указав имя подпапки, содержащей SkeletonList.xml и DBATable.json для вывода сжатого *.caf файл.

Начиная с версии движка 5.6, список скелетов больше не используется, а это означает, что вы можете игнорировать любые ссылки на него на этой странице.

cd SDKFolder
rc.exe path\to\walk.i_caf /animConfigFolder=Animations /sourceroot=GameSDK_Source /targetroot=GameSDK /SkipDBA /refresh

Чтобы double проверить, были ли файлы обновлены, обновите проводник Windows, чтобы увидеть, имеет ли файл другой размер (повторно обработанный), или проверьте отметку времени.

Также обязательно укажите следующие аргументы:

  • /skipdba — пропустить сборку базы данных.
  • /refresh — принудительно перекомпилировать ресурсы с актуальной меткой времени.

Создание журнала дампа из скомпилированных ресурсов

Компилятор ресурсов можно использовать для создания дампа CGF. Синтаксис выполнения этой операции указан ниже:

rc.exe /refresh /debugdump filename.cgf

Это создаст новый текстовый файл с расширением *.dump расширение с информацией о данных, содержащихся в файле CGF.

Поскольку CHR и CGA также используют файловую структуру CGF, можно также сделать дамп этих файлов. Вам просто нужно использовать перезаписать расширение параметр командной строки:

rc.exe /refresh /debugdump /overwriteextension=cgf filename.chr

Аргументы командной строки

Ниже приведены еще несколько примеров того, как можно запустить компилятор ресурсов из командной строки:

rc myassset.tif /userdialog
 
Tools/rc/rc.exe c:\temp\*.tif /refresh /wait

Ниже приведен список полезных аргументов командной строки, заданных в виде пар ключ-значение. Более подробную информацию и полный список ключей можно получить, используя rc.exe с аргументом /help (см. пример файла, RCkeys.txt.log).

  • /рекурсивный = 0/1.
  • /обновить для деактивации инкрементальной компиляции (игнорирует дату файла).
  • /подожди дождаться нажатия клавиши для завершения.
  • /подождать=4 всплывающее окно сообщения и дождитесь нажатия кнопки при запуске и завершении.
  • /статистика = 1 для создания файлов статистики: rc_stats_filedependencies.log, rc_stats_materialdependencies.log, rc_stats_presetusage.log, rc_stats_filesizes_xls.log (в формате, который можно легко прочитать в Excel).
  • /файлы журналов = 1, чтобы запретить создание файла журнала rc_log.log (rc_log_warnings.log и rc_log_errors.log все еще создается).
  • /время журнала = 0 для подавления времени регистрации.
  • /WX рассматривать предупреждения как ошибки.
  • /тихий для подавления всех распечаток.
  • /целевой корень = чтобы определить папку назначения. Примечание: данная папка и ее поддеревья будут исключены из процесса проверки исходных файлов.
  • /перезаписать расширение = расширение. Выберите конвертер, используя указанное расширение.
  • /пользовательский диалог чтобы отобразить диалоговое окно пользователя для ResourceCompilerImage.
  • /cachefolder=путь чтобы позволить RC кэшировать скомпилированные файлы. Это позволяет использовать кэшированные файлы вместо того, чтобы каждый раз перекомпилировать их заново.
  • /forceVCloth: Включает создание чанка VCloth. Он перезаписывает настройку экспорта MAKE_VCLOTH для CGF.
    Это позволяет файлу CGF содержать информацию о предварительной обработке сетки ткани путем сохранения метаданных в файле CGF. И не позволяет системе анимации VCloth предварительно обрабатывать сетку ткани файла SKIN во время выполнения, что позволяет избежать падения производительности при создании группы персонажей, использующих одну и ту же сетку ткани. Дополнительную информацию о системе анимации VCloth см. Урок — Настройка VCloth 2.0.

RC_Options.txt

Если вы ищете более постоянное/часто используемое решение, вы можете создать файл с именем rc_options.txt внутри используемой папки RC. Это можно использовать для применения определенных настроек каждый раз при вызове RC. Ниже приведен пример:

Рис3: Пример файла rc_options.txt.

  • предварительный просмотр=0 отключит предварительный просмотр вывода изображения в диалоговом окне CryTIF. Это позволяет работать с изображениями высокого разрешения намного быстрее, поскольку изображение предварительного просмотра не требует обработки.
  • пользовательскийдиалог = 0 полностью отключит диалоговое окно CryTIF. Это может быть полезно, если вы работаете с определенным набором файлов, которые, как вы знаете, настроены правильно (их пресеты, разрешения и т. д.), и вы хотите часто вносить изменения, не беспокоясь каждый раз о всплывающем диалоговом окне CryTIF.

В этом файле можно использовать любой параметр для автоматизации RC в соответствии с вашими потребностями. Чтобы получить полный список доступных параметров, откройте папку RC в командной строке и введите rc / помощь.

Автоматические настройки

Если есть альфа-канал, выбранный формат пикселей корректируется так, чтобы можно было использовать альфа-канал.

Например, X8R8G8B8 становится A8R8G8B8. Если альфа-канала нет, формат также корректируется. Система пытается быть интеллектуальной, используя текстуры одинакового качества.

Это означает, что вам не нужен новый пресет для поддержки текстур с альфа-каналом. Под правым окном предварительного просмотра вы можете увидеть используемый формат текстуры (CryTIFPlugin).

Вывод в расширенном формате DDS

Формат файла DDS включает дополнительные метаданные (собственный механизм расширения), как указано ниже:

void CImageObjectBase::AppendExtendedData( FILE *out )
{
  uint32 dwStartMagicWord = swizzle32('CExt');                 // Crytek Extended -start
  fwrite(&dwStartMagicWord,4,1,out);

  uint32 dwChunkName = swizzle32('AvgC');                      // Chunk AverageColor
  fwrite(&dwChunkName,4,1,out);
  uint32 dwChunkSize = 4;
  fwrite(&dwChunkSize,4,1,out);
  fwrite(&m_colAverageARGB,4,1,out);

  uint32 dwEndMagicWord = swizzle32('CEnd');                  // Crytek Extended - end
  fwrite(&dwEndMagicWord,4,1,out);
}

Общее использование, связанное с анимацией

Экспортировано *.i_caf файлы содержат анимацию в несжатом формате. Для загрузки в движок их сначала нужно сжать в *.caf файлы. При локальном использовании во время производства это обычно делается автоматическим вызовом RC в Sandbox.

Чтобы выполнить полную сборку на вашем локальном компьютере PC, вы можете использовать следующую командную строку:

cd C:\CryENGINE
Tools\rc\rc.exe *.i_caf /animConfigFolder=Animations /p=PC /sourceroot=GameSDK_Source /targetroot=C:\Build\GameSDK /refresh
  • /animConfigFolder используется для указания местоположения SkeletonList.xml и DbaTable.json внутри /исходный корень.
  • /исходный корень и /targetroot параметры не должны указывать на одно и то же место.
  • /п options указывает целевую платформу. Возможные значения: «PC», «X360» и «PS3». Если не указано, по умолчанию используется «PC».
  • /обновить Параметры используются для того, чтобы гарантировать, что целевые файлы будут перезаписаны, если они существуют и даты изменения соответствуют исходным файлам.
  • Результат журнала вызова можно найти в файлах Tools\rc\rc_log*.log.

Подробности сжатия анимации

Исходный файл анимации обрабатывается RC для вывода сжатого файла CAF, используемого CRYENGINE. Сжатие включает в себя следующие этапы:

Удалить данные в каналах без перемещений (то же самое, что и поза привязки в течение всего времени)

Удалите некоторые ключевые кадры на основе пороговых значений ошибок.

  • Ключевые кадры, которые можно интерполировать с заданным порогом ошибки, удаляются.
  • Каждое соединение может иметь собственный порог ошибки.

Квантовать кватернионы

  • Кватернион обычно состоит из 4 чисел с плавающей запятой (128 бит). Но для нормализованного мы можем сохранить только 3 числа с плавающей запятой (96 бит).
  • Существует три вида схем квантования:
    • 128 бит (без сжатия),
    • 48 бит (15 бит+15 бит+15 бит и остальные биты для индексации пропущенного элемента),
    • 64 бита (20 бит+21 бит+21 бит и остальные биты для индексации пропущенного элемента).
  • По умолчанию в большинстве случаев используется 48-битная схема.
  • RC определяет наиболее эффективную схему при заданном пороге ошибки (тот же, что указан в шаге 2).
    • Фактически, RC применяет удаление и квантование ключевых кадров для всех трех схем в пределах заданного порога ошибки и выбирает ту, которая приводит к наилучшему сжатию (т. е. к минимальному размеру).
  • Более подробную информацию вы можете найти в 'QuatQuantization.h'.

Создайте базы данных анимации (необязательно)

  • При этом несколько файлов CAF объединяются в один файл DBA, все дублирующиеся контроллеры удаляются.
