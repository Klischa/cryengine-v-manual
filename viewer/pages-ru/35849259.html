Обзор

Начиная с 5.3, CMake теперь является системой сборки по умолчанию для CRYENGINE, заменяя WAF. На этой странице будет описана структура скриптов CMake.

Если вы ищете информацию о различиях между CMake и WAF, перейдите на страницу Миграция с WAF на CMake.

Связанные двоичные файлы CMake

При сборке для Windows мы предоставляем предварительно скомпилированные двоичные файлы для CMake. Существует два набора двоичных файлов, используемых для разных платформ. При использовании пакетных файлов, найденных в Tools\CMake, соответствующие двоичные файлы будут использоваться автоматически.

Msvc-android-cmake

Эти двоичные файлы содержат настройки Microsoft для использования поддержки проекта Android в Visual Studio. Они используются только для сборок Android.

Win32

Эти двоичные файлы используются для всех других платформ, которые можно собрать из Windows. Они содержат небольшое количество исправлений ошибок и настроек, обеспечивающих правильную сборку CRYENGINE.

При создании сборок Windows также можно использовать стандартную установку CMake, но для этого может потребоваться более новая версия, чем та, которую мы предоставляем.

Добавление модуля

Стандартных команд CMake достаточно для добавления новых модулей. Однако сценарии CMake предоставляют некоторые дополнительные функции поддержки, реализованные в виде макросов и функций в Tools\CMake\CommonMacros.cmake. Использование этих макросов значительно упростит объем необходимых вам настроек, например. автоматически обрабатывая создание файлов uber.

Это не полный список макросов и функций, содержащихся в этом файле, но он должен охватывать все, что может вам понадобиться для ваших собственных проектов. Дополнительные макросы, используемые внутри скриптов CMake, здесь не документируются.

Если вы переходите с более старой версии CRYENGINE, основанной на WAF, перейдите на страницу Миграция с WAF на CMake для более подробного объяснения того, как чтобы сопоставьте проекты WAF с CMake.

После того как вы создали CMakeLists.txt для модуля просто добавьте его с помощью add_subdirectory в соответствующем Build*.cmake файл в Tools\CMake (например BuildEngine.cmake для модуля двигателя или BuildSandbox.cmake для модуля песочницы).

Указание исходных файлов

Поскольку версия 5.3 поддерживает как WAF, так и CMake в качестве систем сборки, мы создали несколько пользовательских макросов, позволяющих представить одну и ту же файловую структуру. Они используются waf2cmake инструмент, описанный в тот Миграция с WAF на CMake руководство, но также доступны для недавно добавленных модулей CMake.

Типы модулей

Как и в случае с WAF, модули классифицируются в соответствии с их типом, в результате чего автоматически применяются различные настройки компиляции. Большинство этих категорий перенесены прямо из WAF, что упрощает конвертацию.

Общая форма объявлений этих модулей имеет следующий вид (с CryEngineModule это имя, присвоенное категории):

CryEngineModule(module_name [PCH file] [SOLUTION_FOLDER folder] [extra])

Module_name должен быть первым аргументом; дополнительные аргументы могут появляться в любом порядке.
