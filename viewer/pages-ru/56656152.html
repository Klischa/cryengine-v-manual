Обзор

Пример проекта GalaxSys включает в себя несколько ресурсов, которые можно использовать в ваших собственных проектах в CRYENGINE, а также набор дополнительных компонентов, упрощающих разработку игровой логики. Идея состоит в том, что вы можете использовать этот пример проекта в качестве основы для аналогичных игр, используя добавленные компоненты или просто расширяя существующую структуру.

Вы также можете углубиться в код этого проекта, чтобы узнать о различных системах, а также о том, как взаимодействовать и раскрывать различные системы, используемые в CRYENGINE. Целью этого документа является предоставление общего обзора общего дизайна и структуры проекта.

Слои уровня

Первое, что вы можете заметить при открытии уровня, это то, что слои содержат не так много объектов.


Слои уровня

Геймплей

Этот слой используется для хранения объектов, содержащих логику или необходимых для стабильного игрового процесса.

  • PlayerSpawnPoint: эта сущность управляет местоположением и логикой появления игрока.
  • Арена: Объект Arena использует компонент Arena для определения игровой области, а также предоставляет список автоотражения, который может автоматически отскакивать объекты от края внутри границы.
  • Создатель: Создатель управляет логикой появления врагов. Здесь вы можете определить, какие враги могут быть созданы, а внутри самой сущности (через Schematyc) вы контролируете, когда и как появляются враги.
  • Игра: Сущность — это особая сущность, в которой находится общая игровая логика. Он управляет сочетаниями клавиш для запуска игры, показывает UI, отслеживает и обновляет таймер и подсчет очков.
  • StartingCamera: Это камера, используемая в начале игры, до появления игрока и при отображении текста «Нажмите Start или Enter». Камера игрока автоматически переопределяет эту камеру после появления игрока.
  • ParticlePrecache: Объект ParticlePrecache содержит несколько компонентов эффектов частиц, по одному для каждого из эффектов частиц, используемых в игре, которые не присутствуют статически на уровне (например, WaveGrid размещен статически). Эффект каждой частицы «Загрунтован»; это позволяет системе частиц загружать необходимые ресурсы для каждой частицы во время загрузки уровня, а не во время выполнения, что может вызвать скачки производительности.

Аудио

Слой Audio просто содержит музыкальный объект.

  • Музыка: эта сущность просто управляет музыкой при запуске уровня. Конечно, с помощью системы Schematyc можно создать более сложные настройки для разных эффектов в разное время.

Освещение

Этот слой содержит зонд окружающей среды.

  • TS_EnvProbe_Global: Зонд окружающей среды. Это используется для создания кубических карт уровня, которые можно увидеть в отражениях на кожухе кабины корабля игрока.

Арена

Слой Арены содержит все объекты static на уровне, включая эффект частиц волновой сетки.

  • Black_*: эти объекты просто используются для добавления эффекта «Затухания» по краям волновой сетки. Мы также используем черный пол, чтобы звезды скайбокса не мешали эффекту частиц волновой сетки.
  • WaveGrid: Сущность WaveGrid — наиболее заметный эффект сэмпла GalaxSys. Это динамическая сетка частиц, которая может реагировать на физические эффекты, такие как ветер.

Сущности

Большинство сущностей в этом проекте состоят из сущностей визуальных сценариев, которые можно создать с помощью функции визуальных сценариев CRYENGINE.

В CRYENGINE 5.6 эти объекты известны как объекты Schematyc, которые используют экспериментальную версию системы визуальных сценариев. Здесь мы кратко рассмотрим каждую скриптовую сущность, не вдаваясь в подробности. Если вы хотите узнать больше о том, как эти сущности взаимодействуют друг с другом, мы советуем открыть их и поиграть с ними.


Активы предприятия

Враги

  • основной враг: это первый враг, с которым вы столкнетесь при игре в образец проекта.
  • связанный враг: Эта сущность является «половинкой» второго врага, с которым вы столкнулись. Он действует как основная логика второго врага, а также контролирует появление своего партнера.
  • связанный враг: Эта Сущность является второй «половинкой» второго врага. По сути, это просто мишень для связанный враг Entity, чтобы эффект электрических частиц мог казаться «прикрепленным» к каждой части. Для эффекта частиц хост должен иметь ссылку на сущность с именем «target», связанную с целевой сущностью. Это указывает эффекту частиц, где закончиться.
  • создатель: Создающая сущность управляет типами врагов и временем появления.

Физика

  • взрыв: Эта сущность представляет собой набор компонентов, которые могут физически влиять на другие динамические объекты; он также имеет эффект частиц, который активируется сразу после появления.
  • смерть игрока: смерть игрока Сущность по сути такая же, как и Сущность Взрыва. Только на этот раз мы используем его исключительно для события смерти игрока. Это помогает отличить смерть игрока от смерти врага, например, по более сильному эффекту взрыва.

Игрок

  • игрок: Эта Сущность говорит сама за себя. Он состоит из множества компонентов, таких как контроллер игрока, камера и других, необходимых для того, чтобы игрок выглядел и чувствовал себя в игре.

Снаряды

  • снаряд по умолчанию: Это снаряд, который вы видите, когда игрок стреляет. Использование для этого пользовательской сущности позволяет не только переключать типы снарядов, но и контролировать всю логику, лежащую в их основе. Например, можно было бы создавать «самонаводящиеся» снаряды, которые захватывают врагов. В настоящее время в примере проекта мы предоставляем только базовый снаряд по умолчанию.

Оружие

  • базовое оружие: базовое оружие Entity предоставляет возможность переключать различные виды оружия независимо от используемых им снарядов. Это позволяет одному и тому же оружию использовать разные снаряды, например, стрелять более чем одним снарядом одного и того же или разных типов одновременно или с разной скорострельностью. В настоящее время мы предоставляем только базовое оружие в тестовом проекте.

Разное

  • игра: Игровая сущность предназначена для размещения и загрузки вместе с уровнем во время загрузки. Эта сущность управляет UI, запуском и сбросом привязок игры.
  • музыка: Эта сущность просто предоставляет музыку для примера проекта.
  • частицапрекэш: этот объект используется для предварительного кэширования различных эффектов частиц во время выполнения, используемых в образце, таких как эффекты частиц снаряда и взрыва.
  • точка появления: Сущность точки появления контролирует место, в котором появляется игрок. Логику появления игрока можно найти внутри графа.

Компоненты

В пример проекта были добавлены различные компоненты Entity, чтобы обеспечить гораздо большую гибкость при разработке и итерации функций.

Почти все сущности, используемые в примере проекта, используют один или, как правило, несколько компонентов для создания функциональности сущности. Это дает дизайнеру гораздо больше контроля при разработке уровня и игровой механики, не прибегая к программированию.


Добавленные компоненты

CollisionMask

Предоставляет интерфейс для масок физических столкновений для этого объекта. Маски столкновений позволяют указать до 32 типов сущностей, которые могут игнорироваться друг другом. Например, при наличии трех объектов: A, B и C, с установленными типами 1, 2 и 3 соответственно, добавление 2 и 3 в список игнорируемых типов для объекта A приведет к тому, что объект A не будет реагировать на столкновения с объектами B и C.

ControllableTimer

Этот специальный компонент таймера обеспечивает гораздо больший контроль над временем в вашей логике для каждого объекта. С помощью этого таймера вы можете использовать узлы «Стоп» и «Возобновить», чтобы «приостановить» таймер во время выполнения, сбросить его и изменить его интервалы.

Урон

Этот компонент предназначен для использования с компонентами «Здоровье», но его также можно использовать и без него, что по сути делает этот объект неуязвимым.

Компонент «Повреждения» будет автоматически реагировать на столкновения с другими физическими объектами и наносить заданный размер урона другому объекту только в том случае, если у другого объекта есть компонент «Здоровье». Вы также можете использовать узел GiveDamage, чтобы произвольно наносить урон определенным Сущностям в определенных количествах, при условии, конечно, что они также содержат компонент здоровья, который может получить урон.

Враг

Компонент Enemy используется по существу в качестве прокси для предоставления некоторых легкодоступных настроек, которые можно использовать при появлении. Например, настройки начальной скорости и начального направления. Сам компонент не имеет логики в коде.

Исключение появления врагов

Этот компонент предоставляет возможность добавлять зоны отчуждения к компоненту спавнера врагов. По сути, эти зоны являются зонами «без появления», чтобы предотвратить появление врагов в этом месте. Например, игрок использует круглую запретную зону, чтобы враги не появлялись слишком близко, что делает игру слишком сложной.

Создатель врагов

Компонент создания врагов определяет, какие типы врагов и время появления каждого типа. Что касается кода, это поддерживает список зон исключения, добавленный Enemy Spawn Excluders, и устанавливает таймеры для каждого из «Определений врагов», установленных разработчиком.

Ссылки на сущности

Этот компонент предоставляет интерфейс для взаимодействия с Entity Links. Вы можете создавать, переименовывать и удалять связи между этой Сущностью и другими Сущностями. Вы также можете прикрепить объект к другому концу ссылки на объект по имени. Это используется, например, для настройки целевой сущности для связанный враг (2-й враг) в примере проекта.

Взрыв

Этот компонент позволяет дизайнеру добавить к сущности физическую взрывную силу. Компонент может быть автоматически активирован при инициализации (когда создается объект-владелец) или по требованию через узел разнесения.

FlashElement:HUDMAIN

Это динамический компонент.

Это означает, что этот компонент создается динамически на основе доступных в данный момент элементов Flash в вашем проекте. Элемент Flash в данном случае называется HUDMAIN и представляет собой среду UI, которую вы видите в примере проекта, от панели состояния до текста «Нажмите старт». Эти компоненты будут автоматически предоставлять зарегистрированные функции и события, определенные в UI XML, подготовленном разработчиком, во многом аналогично версии Flow Graph.

Один и тот же компонент FlashElement на разных объектах будет управлять одним и тем же элементом (без учета отдельных экземпляров). Например, в примере проекта здоровье игрока изначально настраивается игровой сущностью и обновляется сущностью игрока при получении урона.

Здоровье

Компонент «Здоровье» действительно полезен только в сочетании с компонентом «Урон».

Когда на его работоспособность влияет, например, компонент повреждения, это вызывает сигнал OnDamage для сущности-владельца. Как только свойство Health компонента Health достигнет нуля, он отправит сообщение KillEntity сигнал сущности-владельцу, которая может выбрать, как обрабатывать это событие. Если Entity удаляется со сцены (например, через узелentity:remove), этот компонент отправит широковещательное сообщение. OnEntityKilled событие для всех подписанных объектов и компонентов.

Смещение частиц

Этот компонент повлияет на сетку частиц на уровне. Это эффект, наблюдаемый вокруг игрока и вокруг взрывов, когда отдельные частицы отталкиваются от Сущности.

Играть на Арене

Компонент Play Arena определяет игровые границы игры.

Он также может автоматически отражать физические объекты от внутреннего края границы, при условии, что они являются определенными объектами, такими как снаряд по умолчанию и враги в примере проекта. Арена использует внутренний триггерный компонент области, чтобы сигнализировать сущности, когда она покинула зону. Сущность игрока использует размеры игровой арены на уровне для обработки своей собственной границы, которая немного меньше игровой арены.

Мы делаем это для того, чтобы создаваемые снаряды не появлялись за пределами игровой зоны при выстреле.

Игрок

Компонент Player имеет две основные функции: во-первых, это камера игрока, которая ограничена границей арены. используя размеры арены, а также сохраняя стабильность при перемещении и вращении игрока. Во-вторых, этот компонент предоставляет доступ к системе визуальных сценариев, позволяя другим компонентам и объектам получать информацию о положении игроков во время выполнения.

Контроллер игрока

Компонент Player Controller определяет эффект ввода пользователя (с помощью мыши и клавиатуры, с помощью контроллера или даже комбинации того и другого) на объект-владелец. Он также контролирует видимость компонента курсора в зависимости от последнего использованного устройства для управления кораблем игрока.

Курсор игрока

Этот пользовательский компонент предназначен для использования вместе с контроллером игрока. Он определяет несколько параметров, которые может настроить дизайнер, таких как текстура курсора, чувствительность и смещение оси.

Точка появления игрока

Этот компонент предоставляет игровой узел SpawnPlayer, позволяющий игровой сущности инициировать появление игрока.

Оружие

Компонент «Оружие» — это, по сути, настраиваемый таймер, который может контролировать скорость стрельбы из оружия.

Он предоставляет несколько узлов для включения/отключения и обработки событий срабатывания в визуальном графе. На самом деле компонент не создает никаких снарядов, а отправляет сигнал объекту-владельцу, который затем может быть обработан разработчиком, чтобы точно контролировать, как интерпретировать различные настройки, назначенные оружию.

Крепление для оружия

Компонент «Прикрепление оружия» используется для хранения текущего оружия, используемого сущностью-владельцем. Само оружие создается как дочерний объект и прикрепляется к объекту-владельцу. Это позволяет отключать заранее определенное оружие (объекты) по требованию без добавления и удаления, а также настройки свойств самих компонентов.
