Обзор системы ввода

Основная цель CryInput — предоставить абстракцию получения ввода/статуса от различных устройств ввода, таких как клавиатура, мышь, джойстики, геймпады 360/PS3 и т. д.

Он также поддерживает отправку событий обратной связи обратно на устройства ввода, например, в форме событий принудительной обратной связи.

Общие интерфейсы системы ввода можно найти в IInput.h проекта CryCommon.

IВвод

Основным интерфейсом системы ввода является IInput. Экземпляр, реализующий этот интерфейс, создается автоматически во время инициализации системы в функции InitInput (InitSystem.cpp в CrySystem, см. также CryInput.cpp в CryInput).

Будет создан только один экземпляр этого интерфейса. Обновлением и отключением системы ввода также будет управлять CrySystem.

Этот экземпляр IInput будет храниться в структуре SSystemGlobalEnvironment gEnv, и доступ к нему можно будет получить через gEnv->pInput или, альтернативно, через системный интерфейс с помощью GetISystem()->GetIInput(). Доступ через переменную gEnv — наиболее часто используемый метод.

IInputListener

Одним из наиболее распространенных вариантов использования системы ввода является создание классов прослушивателей в других модулях (например, CryGame) путем наследования от IInputEventListener и регистрации/отмены регистрации класса прослушивателя в системе ввода для получения уведомлений о событиях ввода.

Например, система Action Map System регистрируется в качестве прослушивателя ввода и пересылает игровые события только для ключей, определенных в файлах конфигурации профиля, чтобы дополнительно абстрагировать вводимые игроком данные от устройства->игры.

SInputEvent

Это структура, которая инкапсулирует информацию, созданную любым устройством ввода, и принимается всеми прослушивателями событий ввода.

InputDevice

InputDevices обычно относятся непосредственно к физическим устройствам ввода, таким как джойстики, мышь, клавиатура и т. д. Для создания нового устройства ввода все, что необходимо, — это реализовать все функции в интерфейсе IInputDevice и зарегистрировать его экземпляр в системе ввода с помощью функции AddInputDevice.

Функция Init будет вызываться при регистрации IInputDevice в системе ввода, поэтому нет необходимости вызывать ее вручную при создании устройств ввода.

Функция обновления будет вызываться при каждом обновлении системы ввода, и обычно именно здесь следует проверять/обновлять состояние устройства, а события ввода генерировать и пересылать в InputSystem.

Устройства ввода обычно создают и сохраняют список SInputSymbol для каждого символа, который устройство ввода может сгенерировать в функции Init, а затем в функции обновления ищут символ для кнопки/оси, которые изменились, и используют их (через функцию AssignTo), чтобы заполнить большую часть информации, необходимой для событий, и отправить их в систему ввода.

Пример:

// function from CInputDevice ( accessible only within CryInput )
MapSymbol( ... )
{
     SInputSymbol\* pSymbol = new SInputSymbol( deviceSpecificId, keyId, name, type );
     pSymbol->user = user;
     pSymbol->deviceId = m_deviceId;
     m_idToInfo\[ keyId \] = pSymbol;
     m_devSpecIdToSymbol\[ deviceSpecificId \] = pSymbol;
     m_nameToId\[ name \] = deviceSpecificId;
     m_nameToInfo\[ name \] = pSymbol;

     return pSymbol;
}
bool CMyKeyboardInputDevice::Init()
{
      ...
     //CreateDeviceEtc();
      ...
     m_symbols\[ DIK_1 \] = MapSymbol( DIK_1, eKI_1, "1" );
     m_symbols\[ DIK_2 \] = MapSymbol( DIK_2, eKI_2, "2" );
      ...
}
void CMyKeyboardInputDevice::Update( ... )
{
     // Acquire device if necessary
      ...
     // Will want to check for all keys probably, so the following section might be part of a loop
     SInputSymbol\* pSymbol = m_symbols\[ deviceKeyId \];
      ...
     // check if state changed
      ...
     // This is an example for when pressed, see ChangeEvent function for axis type symbols
     pSymbol->PressEvent( true );
 
     SInputEvent event;
     pSymbol->AssignTo( event, modifiers );
 
     gEnv->pInput->PostInputEvent( event );
}

Чтобы пересылать события в систему ввода, чтобы прослушиватели событий могли их получать, используйте функцию PostInputEvent из IInput.

При добавлении устройства ввода в CryInput может оказаться полезным наследование непосредственно от CInputDevice, поскольку оно уже предоставляет общую реализацию для большинства функций в IInputDevice.
