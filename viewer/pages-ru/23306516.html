Обзор

Система транспортных средств реализована в CryAction (интерфейс между Engine и игрой), Game и Lua.

Скрипты

Следующие файлы Lua хранятся в папке Scripts/Entities/Vehicles каталог.

Каждый класс транспортного средства определяется внутри соответствующего файла XML. Файлы класса транспортного средства XML следует хранить в папке Scripts/Entities/Vehicles/Implementations/Xml каталог.

Автомобильные интерфейсы

Следующие интерфейсы представляют собой основные компоненты кода автомобиля:

  • IVehicleAnimation
  • IVehicleClient
  • IVehicleComponent
  • IVehicleHelper
  • IVehicleSeat

За исключением IVehicleClient, все эти интерфейсы реализованы в CryAction. Интерфейс IVehicleClient реализован в GameDLL, поскольку он определяет специфичные для игры способы управления транспортными средствами игроком на клиенте.

CVehicleSystem

Одноэлементный класс CVehicleSystem хранит регистрации всех доступных объектов транспортных средств, а также всех различных классов транспортных средств.

Фабрики объектов транспортных средств

Следующие фабрики объектов можно использовать для расширения функциональности транспортных средств.

  • IVehicleAction
  • IVehicleDamageBehavior
  • IVehicleMovement
  • IVehiclePart
  • IVehicleSeatAction
  • IVehicleView

За исключением IVehicleMovement, все эти интерфейсы являются производными от IVehicleObject.

Чтобы зарегистрировать новую фабрику объектов транспортных средств, мы можем использовать следующий макрос:

IVehicleSystem* pVehicleSystem = pFramework->GetIVehicleSystem();

#define REGISTER_VEHICLEOBJECT(name, obj) \
REGISTER_FACTORY((IVehicleSystem*)pVehicleSystem, name, obj, false); \
obj::m_objectId = pVehicleSystem->AssignVehicleObjectId();
Классы транспортных средств

Класс транспортного средства определяется в файле XML. Система автомобиля проанализирует все файлы .xml, хранящиеся в этом каталоге. Содержимое файла XML будет указывать, какие объекты транспортных средств потребуются этому классу транспортных средств.

Дополнительная информация доступна о структуре файлов класса транспортного средства XML.

Во время инициализации Game Framework (CryAction) вызывается CVehicleSystem::RegisterVehicles(). Эта функция будет искать все файлы XML по этому пути: Game\Scripts\Entities\Vehicles\Implementations\Xml.

Новый экземпляр CVehicle создается системой транспортных средств каждый раз, когда транспортное средство создается системой Entity.

Автомобильный клиент

Клиент транспортного средства — это одноэлементный класс, производный от интерфейса IVehicleClient и обычно реализуемый внутри GameDLL. Он необходим для обработки специфических для игры функций, таких как сопоставление карт действий с особенностями автомобиля, а также высокоуровневая обработка входа/выхода игроков с мест. Действия геймпада принимаются с помощью функции IVehicleClient::OnAction(). Добавление поддержки новых контроллеров ввода можно выполнить внутри этого класса.

Реализация по умолчанию находится по этому пути: Code\Game\GameDll\VehicleClient.cpp

CИнициализация автомобиля

CVehicle::Init() выполнит следующие задачи:

  1. Инициализирует все компоненты автомобиля.
  2. Инициализирует все части автомобиля.
  3. Инициализирует все помощники транспортного средства.
  4. Инициализируйте все эффекты частиц запроса.
  5. Инициализирует все анимации автомобиля.
  6. Инициализирует движение автомобиля.
  7. Инициализирует все сиденья автомобиля.
  8. Устанавливает краску автомобиля.
  9. Инициализирует все действия автомобиля.
  10. Инициализирует повреждения транспортного средства, включая поведение повреждений.

Сиденье автомобиля

Класс сиденья транспортного средства обрабатывает все взаимодействия с участием актеров, сидящих в транспортном средстве. Каждое место может иметь несколько действий сиденья, которые реализуют различные функции игрового процесса, применимые к актеру, использовавшему это место.

Вход в транспортное средство
  1. Физическому объекту транспортного средства отправляется действие пробуждения с использованием структуры pe_action_awake.
  2. В случае, если в данный момент место занимает мертвый актер, его тело перемещается в ближайшее место на земле.
  3. В случае, если актер уже управляет этим креслом удаленно, этот удаленный пассажир отключается.
  4. Затем актер кладет в кобуру свой текущий предмет (если он в данный момент выбран).
  5. Целевой запрос к начальной точке входящей анимации отправляется объекту AI, чтобы тело актера стояло в точной позиции первого кадра входящей анимации (только для актера AI).
  6. График анимации актера отправляется на ввод названия транспортного средства и номера места.
  7. Сетевое состояние автомобиля устанавливается как наличие сидящих пассажиров.
  8. Слот обновления IVehicle::eVUS_PassengerIn игрового объекта транспортного средства включается.
Действия сиденья

Действия сидений позволяют расширить функциональность сидений. Интерфейс IVehicleSeatAction используется для реализации новых действий с местами.

CryAction предоставляет следующие реализации действий сиденья.

Ущерб пассажирам

Сиденье автомобиля позволяет защитить пассажира от повреждений, предусмотренных правилами игры. Параметр isPassengerShielded можно использовать для отключения любых прямых повреждений, отправляемых пассажиру до момента уничтожения самого транспортного средства. Реализация актера должна вызывать IVehicleSeat::ProcessPassengerDamage() каждый раз при получении удара, чтобы отфильтровать урон в случае, если пассажир защищен щитом.

Повреждения автомобиля

Хиты

Любое попадание, отправленное в транспортное средство, проходит через функцию IVehicle::OnHit(). Прежде чем попадание будет обработано транспортным средством, классы, зарегистрированные в качестве прослушивателя событий с помощью функции IVehicle::RegisterVehicleEventListener(), получат событие типа eVE_Hit.

Положение и радиус попадания будут проверены на соответствие всем границам компонентов транспортного средства. Если этот тест положительный, вызывается функция IVehicleComponent::OnHit(), чтобы применить попадание к компоненту.

Существует консольная переменная v_goliathMode, которую можно использовать в чит-режиме, чтобы отключить эффект любого удара, делая все транспортные средства неуязвимыми. Кроме того, если транспортное средство является водителем игрока, который включил режим Бога, транспортное средство также будет неуязвимо.

Множители урона

Множители урона используются для балансировки различных типов ударов, чтобы по-разному влиять на несколько компонентов машины. Например, можно добавить множитель, чтобы сделать танк неуязвимым для пуль, установив множитель пули равным 0.

Компоненты автомобиля

Каждый компонент транспортного средства несет ответственность за определение того, приведет ли столкновение к какому-либо повреждению транспортного средства. В случае, если соответствующий множитель урона не был определен в компоненте, вместо этого он проверит, наносит ли секция повреждений транспортному средству указанную величину.

Поведение при повреждении

Интерфейс Damage Behavior используется для реализации новых способов реагирования автомобиля на повреждения. Взрывы, спущенные шины или тонущая лодка — все это примеры функций, которые реализуются как поведение при повреждении.

Реализация нового поведения повреждений

реализация на С++

Интерфейсы IVehicleDamageBehavior необходимо использовать для реализации нового поведения повреждений. В качестве примера можно использовать следующий пример кода для определения нового поведения повреждения.

class CVehicleDamageBehavior
: public IVehicleDamageBehavior
{
IMPLEMENT_VEHICLEOBJECT
public:

CVehicleDamageBehavior () {}
virtual ~CVehicleDamageBehavior() {}

virtual bool Init(IVehicle* pVehicle, const SmartScriptTable &table);
virtual void Reset() {}
virtual void Release() { delete this; }
virtual void Serialize(TSerialize ser, unsigned aspects) {}
virtual void Update(const float deltaTime) {}

virtual void OnDamageEvent(EVehicleDamageBehaviorEvent event, const SVehicleDamageBehaviorEventParams& behaviorParams);
virtual void OnVehicleEvent(EVehicleEvent event, const SVehicleEventParams& params){}

virtual void GetMemoryStatistics(ICrySizer * s);
};

Важно добавить следующую строку в файл определения C++:

DEFINE_VEHICLEOBJECT(CVehicleDamageBehavior);

Чтобы новое поведение распознавалось системой автомобиля, рекомендуется использовать макрос REGISTER_VEHICLEOBJECT. Этот макрос определен внутри CryAction/VehicleSystem_FactoryRegistration.cpp а также GameFactory.cpp в GameDLL. Строка имени, переданная в этот макрос, затем будет использоваться для определения поведения при запросе новых экземпляров из системы автомобиля.

Регистрация нового поведения повреждений

Если поведение повреждения необходимо запросить из класса транспортного средства на основе XML, необходимо отредактировать файл определения транспортного средства (Game/Scripts/Entities/def_vehicle.xml). Найдите раздел, аналогичный следующему фрагменту:

<Array name="DamageBehaviors" elementName="DamageBehavior" extendable="1" id="idDamageBehaviors">
<Property name="class" type="string">
<Enum>
<Value>AISignal</Value>
...
</Enum>
</Property>

Необходимо добавить новое значение enum, используя ту же строку имени, которая ранее была передана в REGISTER_VEHICLEOBJECT.

Чтобы иметь возможность передавать свойства из класса транспортных средств XML, необходимо добавить новую таблицу внутри DamageBehaviors определение массива. Важно, чтобы эта таблица была указана как необязательная.
