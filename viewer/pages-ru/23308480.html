Обзор

Процедурный клип (структура времени выполнения) и параметр процедурного клипа (структура данных static) претерпели некоторые структурные изменения, чтобы исправить некоторые из их недостатков.

Параметры процедурного клипа в старом формате состояли из фиксированного количества строк и чисел с плавающей запятой. Благодаря новому формату разработчики процедурных клипов имеют контроль над типами, именами и количеством требуемых параметров, а также над тем, как они представляются пользователю в UI. Это достигается за счет того, что каждый процедурный клип определяет конкретную структуру, необходимую для его параметров.

Проекты, обновляющиеся до этой версии Mannequin, должны обновить свой код и структуры данных. См. Обзор необходимой работы по преобразованию в новую структуру для более подробной информации.

Библиотека сериализации используется для сериализации параметров процедурного клипа как на диск, так и в UI. Чтобы это работало, мы должны написать функцию Serialize для структуры параметров процедурного клипа.

Файл ProcDefs.xml больше не нужен.

Формат xml для файлов ADB изменился. Некоторые замечания:

  • Возможна загрузка старых файлов ADB. Для загрузки файлов ADB, сохраненных в старом формате xml, необходим файл преобразования (см. Пример преобразования данных из старых процедурных клипов в новые процедурные клипы подробнее)
  • Сохранение в старом формате xml ADB больше невозможно.

Процедурные клипы и параметры процедурных клипов не используют CryExtension. Обе структуры создаются через ProceduralClipFactory, доступный через основной MannequinInterface.

Сравнение структуры параметров старого процедурного клипа и новой структуры параметров процедурного клипа

Старая структура параметров процедурного клипа состояла из строки, строки + crc32, crc32 строки и массива из примерно 30 чисел с плавающей запятой.

struct SProceduralEntry
{
  ...  
  SAnimRef animRef;
  SProcDataCRC dataCRC;
  TProcClipString dataString;

  float parameters[MAX_PARAMS];
};

Все процедурные клипы унаследованы от SProceduralParams и определяют используемые ими переменные с плавающей запятой, число которых ограничено количеством плавающих точек, указанным в SProceduralEntry.

struct SProceduralParams
{
  SAnimRef animRef;
  SProcDataCRC dataCRC;
  TProcClipString dataString;
};

Пример:

struct SOldProceduralParamsExample
: public SProceduralParams
{
  // Not using animRef or dataString, but still have them.
  // dataCRC represents an attachmentName.
  float additionalParam;
  float offsetX;
  float offsetY;
  float offsetZ;
  float bSomethingElse; // We need to encode other types (e.g. bool) as floats.
};

Начальные значения членов были определены в ProcDefs.xml, когда мы создавали клип процедуры, в котором использовался этот тип параметра.

В новой версии SProceduralParms больше не существует.

Мы должны наследовать интерфейс IProceduralParams, реализовать функцию Serialize.

Мы инициализируем значения членов в конструкторе.

Файл ProcDefs.xml нам больше не нужен.

Мы не ограничены простым использованием чисел с плавающей запятой или количеством/типами имеющихся у нас строк, и мы можем дать всем членам значимые имена.

struct SNewProceduralParams
: public IProceduralParams
{
  SNewProceduralParams()
  : additionalParam(42.f)
  , offset(ZERO)
  , somethingElse(false)
  {
  }

  virtual void Serialize(Serialization::IArchive& ar)
  {
    ar(attachmentName, "AttachmentName", "Attachment Name");
    ar(additionalParam, "AdditionalParam", "Additional");
    ar(offset, "Offset", "Offset");
    ar(somethingElse, "SomethingElse", "Something Else");
  }

  SProcDataCRC attachmentName;
  float additionalParam;
  Vec3 offset;
  bool somethingElse;
};

  • Это однократная операция, поэтому важно тщательно проверить успешность преобразования данных.

Пример преобразования кода из старых процедурных клипов в новые процедурные клипы

Старый формат

Через ProcDefs.xml

<AimPose anim="1">
  <Params blendTime="1.0" layer="4"/>
</AimPose>

ProceduralClipAimPose.cpp:

#include "ICryMannequin.h"
#include <CryExtension/Impl/ClassWeaver.h>
 
// Procedural Clip Parameters
struct SAimIKParams
: public SProceduralParams
{
  float blendTime;
  float layer;
};
 
 
// Procedural Clip and Registration
class CProceduralClipAimPose
: public TProceduralClip<SAimIKParams>
{
public:
  CRYINTERFACE_BEGIN()
    CRYINTERFACE_ADD(IProceduralClip)
  CRYINTERFACE_END()
 
  CRYGENERATE_CLASS(CProceduralClipAimPose, "AimPose", 0x6B0AF1C0BDA843aa, 0xADDFE222F0547BAE)
 
  ...
};
 
CProceduralClipAimPose::CProceduralClipAimPose()
{
}
 
CProceduralClipAimPose::~CProceduralClipAimPose()
{
}
 
CRYREGISTER_CLASS(CProceduralClipAimPose);

Новый формат

Параметры процедурного клипа

Структура процедурных параметров клипа становится следующей:

#include <ICryMannequin.h>
 
// Procedural Clip Parameters
struct SAimIKParams
: public IProceduralParams
{
  SAimIKParams()
  : blendTime(1.0f)
  , layer(4)
  {
  }
 
  virtual void Serialize(Serialization::IArchive& ar);
 
  SAnimRef animRef;
  float blendTime;
  uint32 layer;
};
Функция сериализации

Чтобы реализовать функцию сериализации, мы должны включить платформу сериализации.

#include <Mannequin/Serialization.h>
 
struct SAimIKParams
: public IProceduralParams
{
  ...
 
  virtual void Serialize(Serialization::IArchive& ar);
  {
    ar(animRef, "Animation", "Animation");
    ar(blendTime, "BlendTime", "Blend Time");
    ar(layer, "AnimationLayer", "Animation Layer");
  }
 
  ...
};

Мы также можем дать некоторые подсказки платформе сериализации о том, как представить наши атрибуты в UI с помощью декораторов.

Ниже показано, как заставить свойство Animation отображать браузер анимации и ограничить AnimationLayer значениями от 0 до 15.

ar(Serialization::Decorators::AnimationName<SAnimRef>(animRef), "Animation", "Animation");
ar(blendTime, "BlendTime", "Blend Time");
ar(Serialization::Decorators::Range<uint32>(layer, 0, 15), "AnimationLayer", "Animation Layer");

Дополнительную информацию о функции сериализации можно найти здесь: Библиотека сериализации.

Процедурный клип и регистрация

Процедурный клип и его регистрация также немного упрощены, поскольку больше не требуется CryExtension GUID.

class CProceduralClipAimPose
: public TProceduralClip<SAimIKParams>
{
  ...
};
REGISTER_PROCEDURAL_CLIP(CProceduralClipAimPose, "AimPose");

Пример преобразования данных из старых процедурных клипов в новые процедурные клипы

Чтобы иметь возможность читать базы данных анимации, созданные при использовании старого формата процедурного клипа, у нас есть вспомогательный класс, который позволит загружать старые процедурные клипы, если мы укажем сопоставление старого формата параметров с новым форматом параметров.

Отображение определено в: Scripts/Mannequin/ProcClipConversion.xml

Этот файл используется при загрузке, когда мы сталкиваемся со старым типом процедурного клипа. Он работает на всех платформах, чтобы сделать переход от старых данных к новым данных максимально плавным до тех пор, пока базы данных анимации не будут обновлены путем их повторного сохранения в редакторе.

Вот как выглядит формат файла ProcClipConversion.xml:

<Conversion>
  ...
  <NameOfProcClip anim="NewNameForThisParameter_Optional" string="NewNameForThisParameter_Optional" crcString="NewNameForThisParameter_Optional">
    <Param value="NewNameForFloatParameter_1" />
    <Param value="NewNameForFloatParameter_2" />
    ...
    <Param value="NewNameForFloatParameter_N" />
  <NameOfProcClip />
  ...
</Conversion>

Значения имен параметров в ProcClipConversion — это сериализованные имена параметров в функции Serialize.

Вот как будет выглядеть автоматическое преобразование старых параметров процедурного клипа AimPose в новый формат.

<AimPose anim="Animation">
  <Param value="BlendTime" />
  <Param value="AnimationLayer" />
</AimPose>

Эту структуру можно легко получить с помощью некоторых незначительных модификаций ProcDefs.xml, заполнив для каждого параметра имена, которые мы их используем.

Для справки, вот как выглядела запись ProcDefs.xml для AimPose:

<AimPose anim="1">
  <Params 
    blendTime="1.0" 
    layer="0"/>
</AimPose>

А еще для справки, вот как выглядит функция Serialize:

ar(animRef, "Animation", "Animation");
ar(blendTime, "BlendTime", "Blend Time");
ar(layer, "AnimationLayer", "Animation Layer");

При преобразовании старых параметров процедурного клипа с помощью этого метода журнал будет заполнен сообщениями, подобными следующим:

Loading subADB animations/mannequin/adb/playerdeathreactions3p.adb
...
Converted old format procedural clip with type name 'AimPose' at line '444'.
Converted old format procedural clip with type name 'AttachEntity' at line '458'.

...

Предупреждения и ошибки будут регистрироваться в случае сбоя преобразования, поэтому важно проверить журнал перед сохранением файлов, поскольку преобразование могло завершиться неудачно. Клипы, которые не удается преобразовать, становятся клипами «Нет».

Можно игнорировать сбой конвертера при обнаружении старого процедурного клипа типа «Нет», поскольку в новом формате он становится клипом «Нет». Сообщение об ошибке будет выглядеть следующим образом:

[Error] CProceduralClipFactory::CreateProceduralClipParams: Failed to create procedural params for type with crc '-542986255'.
[Error] Could not create procedural clip parameters for procedural clip with type name 'None' and crc '-542986255' at line '462'.
