Обзор

Ниже приведены некоторые важные изменения кода и данных, о которых вам следует знать при переходе на версию 3.8.1.

С++11

Компиляция C++11 теперь включена для всех платформ. Связанные важные изменения кода:

  • Использование auto_ptr сейчас устарел. Использование std::unique_ptr вместо этого.
  • Макросы в верхнем регистре VIRTUAL, OVERRIDE, FINAL были удалены. Использование virtual, override, final вместо этого.
  • register Ключевое слово было удалено из кода.

Генераторы случайных чисел

Глобальные (для каждого модуля) генераторы случайных чисел теперь доступны через cry_random_ххх() функции (см. Код\CryEngine\CryCommon\Random.h).

Старые случайные функции, такие как ai_rand(), cry_frand(), rnd(), RandomNum(), frand() и т. д. были удалены. Использование cry_random_xxx() вместо этого.

Класс CLCGRndGen (простой линейный конгруэнтный генератор) был переработан и переименован в CRndGen.

Обратите внимание, что ранжированные функции (cry_random(minValue, maxValue), GetRandom(minValue, maxValue) и т. д.) возвращают случайное значение в пределах инклюзивный диапазон между minValue и maxValue. Подробности смотрите в объявлениях функций.

Макросы девиртуализатора

Следующие макросы, специфичные для девиртуализатора, больше не используются и были удалены: UNIQUE_IFACE, UNIQUE_VIRTUAL_WRAPPER, DEVIRTUALIZE_HEADER_FIX, DEVIRTUALIZATION_VTABLE_FIX, DEVIRTUALIZATION_VTABLE_FIX_IMPL.

Поддержка Unicode/UTF-8

Мы начали перемещать наше строковое представление по умолчанию на UTF-8 (было, ASCII/ANSI).
Это изменение также запрещает использование всех широких строк (UTF-16, UCS-2, UTF-32, UCS-4), за исключением границ API, которые не принимают UTF-8.

Поскольку строки UTF-8 могут храниться в строках, состоящих из байтов, это изменение не влияет на все файлы кода, но влияет на все существующие строки.
Вы можете столкнуться с ошибками компиляции (в неванильном коде) при вызове ранее существовавших API широких строк, и вам придется перейти на UTF-8 в рамках обновления этой версии.

Подробности реализации см. Локализация текста и поддержка Unicode страница.

C строки

В Code/CryCommon/StringUtils.h добавлены функции безопасного копирования/конкатенации строк cry_strcpy(), cry_wstrcpy(), cry_strcat(), cry_wstrcat(). Эти функции рекомендуется использовать вместо strcpy(), strcpy_s() и т. д.

CRC-32

Вычисление CRC-32 теперь обрабатывается классом CCrc32 из Code/CryCommon/CryCrc32.h. См. комментарии в файле CryCrc32.h. Методы «генератора crc32» CrySystem были удалены.

CryExtension

Переименованные функции, конфликтующие с Win32, API определяют:

    • ICryFactory::GetClassName переименован в GetName
    • IEntityClassRegistry::RegisterClass переименован в RegisterEntityClass
    • IEntityClassRegistry::UnregisterClass переименован в UnRegisterEntityClass

Изменения в RC

Изменения синтаксиса в "rc.ini"

Были изменены следующие настройки в файле конфигурации:

цветовое пространство

Опция «srgb» больше не поддерживается, она заменена на «colorspace».

Опция цветового пространства определяет цветовые пространства для входных и выходных изображений.

Формат: colorspace=<вход>,<выход>

  • <input> — один из: линейный, sRGB;
  • <выход> — один из: линейный, sRGB, автоматический.

«авто» автоматически выбирает лучшую кодировку (линейную или sRGB) в зависимости от яркости выходного изображения.

Значение цветового пространства по умолчанию — линейное, линейное.

Используйте таблицу ниже, чтобы заменить srgb цветовым пространством. в вашем файле rc.ini:

  • srgb=0 -> цветовое пространство=линейное,линейное
  • сргб=1 -> colorspace=sRGB,авто
  • сргб=2 -> colorspace=sRGB,sRGB
  • сргб=3 -> цветовое пространство = линейное, sRGB
  • сргб=4 -> colorspace=sRGB,линейный

Псевдонимы

Добавлена поддержка псевдонимов для названий пресетов: проверьте новый раздел [_presetAliases] в Бин64/rc.ini.

Изменения предустановок

Мы очистили пресеты текстур, доступные в CryTIF, и скорректировали названия, чтобы они больше соответствовали нашему физическому рендереру. Для обеспечения обратной совместимости старые имена пресетов автоматически переназначаются на новые пресеты. См. rc.ini файл для точных правил переназначения. Наиболее важные изменения имени:

    • Диффузный называется Альбедо сейчас
    • Зеркальный называется Отражение сейчас
    • Блеск называется Гладкость сейчас

Альтернативное распределение шероховатости

Значения блеска (гладкости) теперь сопоставляются с шероховатостью, используемой нашим BRDF, с использованием квадратной функции. По сравнению с предыдущей функцией, это дает результаты, которые немного более линейны по восприятию. Однако более важным преимуществом является то, что квадратичное распределение стало очень распространенным в отрасли, поэтому переход на него упрощает использование сканированных данных о шероховатости, доступных из различных источников внутри CRYENGINE. Для обратной совместимости карты блеска используют старый набор настроек (NormalsWithGlossInAlpha_highQ) автоматически преобразуются в новый дистрибутив при обработке RC.
