Общая настройка

Когда вы запускаете template в GameLauncher, он сначала загружает карту примера. Это делается путем добавления команды карты в файл проекта game.cryproject, которая может выполнять несколько консольных переменных и консольных команд при запуске. Как только карта загрузится, Игрок Компонент обрабатывает весь ввод пользователя и преобразует его в действия в игре. Игрок класс инициализирует себя в два этапа. Впервые в OnInitialize который вызывается после завершения загрузки карты. Следующая часть инициализации выполняется в OnGameplayStart который вызывается каждый раз, когда Sandbox переходит в режим воспроизведения или, в случае с GameLauncher, все-таки OnInitialize были вызваны методы. Как только игра запустится, движок вызовет OnUpdate каждый кадр, который будет обновлять всю логику игрового процесса.

Карты действий

Вместо использования Ввод класс для получения входных данных от пользователя, этот template использует карты действий. Карты действий упрощают последующее изменение элементов управления без необходимости переписывать код. В C# это достигается с помощью ActionHandler класс. Чтобы использовать ActionHandler, вам необходимо его инициализировать, указав путь к XML-файлу, содержащему карту действий, и имя карты действий, которую необходимо загрузить. Как только ActionHandler инициализируется, вы можете добавить обработчики к конкретным действиям, вызвав AddHandler с именем действия и делегатом, который вызывается при запуске действия.

Более подробную информацию о том, как настроить карту действий, можно найти на странице Страница «Настройка элементов управления и карт действий». 

private void InitializeInput()
{
  var actionHandler = new ActionHandler(InputActionMapUrl, InputActionMapName);
  actionHandler.AddHandler("shoot", OnFireWeaponPressed);
}
 
private void OnFireWeaponPressed(string name, InputState state, float value)
{
  if(state == InputState.Pressed)
  {
    Weapon.Fire();
  }
}

protected override void OnRemove()
{
    _actionHandler?.Dispose();
}

Когда компонент использует ActionHandler, он всегда должен избавиться от него после завершения его использования. Обычно это делается в OnRemove метод, который автоматически вызывается при удалении объекта.

Аниматор персонажей

CharacterAnimator это EntityComponent что упрощает настройку и управление анимированным персонажем из C#. CharacterAnimator автоматически добавляется к сущности игрока в OnInitialize метод Игрок компонент. CharacterAnimator имеет несколько свойств, которые необходимо установить, прежде чем его можно будет использовать. Эти свойства можно установить в инспекторе, выбрав объект игрока. Обязательные свойства:

  • AnimationDatabase: Путь к Файл базы данных анимации (.adb)..
  • ControllerDefinition: Путь к Файл определения контроллера (.xml).
  • MannequinContext: Имя контекст для загрузки из файла определения контроллера.
  • StartFragmentName: Имя фрагмент что CharacterAnimator должно начаться в.

В игровом режиме анимацией можно управлять, устанавливая значения MotionParameterIds и AnimationTags. Стоимость а MotionParameterId можно установить напрямую, вызвав SetMotionParameter с MotionParameterId и необходимое значение. А MotionParameterId описывает основные параметры персонажа, такие как скорость движения и угол поворота. На основе значений параметров будет добавлена правильная анимация. AnimationTags сначала нужно найти позвонив FindTag, с именем тега. Как только тег найден, его можно использовать для вызова SetAnimationTag. Ценность AnimationTag можно установить только true или false. Ан AnimationTag описывает состояние персонажа, например ходьбу, вращение или прицеливание. Более одного AnimationTag можно установить на true сразу.

В template PlayerAnimations класс обрабатывает вызовы CharacterAnimator. Он отслеживает движение и действия игрока и каждый кадр. PlayerAnimations вычисляет значения для обоих MotionParameterIds и AnimationTags, и отправляет их в CharacterAnimator.

Физика персонажей

Вместо того, чтобы физикализировать игрока как жёсткий тип, на этот раз он будет физикализован как живой тип. Живой тип наследует от жесткого типа, но специализируется на ходячих существах. Физическая реализация объекта как живого также позволяет его перемещать, вызывая Переместить на PhysicsObject сущности. Переместить метод дает больший контроль над перемещением объекта, чем Импульс, который лучше подходит для перемещения игрока.

Чтобы физикализировать сущность как живую, сущность физикализуют с помощью LivingPhysicalizeParams как параметры. Этот параметр имеет два важных свойства, которые определяют настройки физики для игрока: PlayerDynamicsParameters и PlayerDimensionsParameters.

  • PlayerDimensions Параметр описывает все, что связано с размером, формой и поворотом коллайдера.
  • PlayerDynamics Параметр описывает, как объект реагирует на физические действия, например, насколько объект имеет контроль в воздухе, а также массу объекта.

Форма коллайдера может быть как капсульной, так и цилиндрической. Для этого template вместо цилиндра используется коллайдер в форме капсулы, поскольку он имеет низкую вероятность застревания и плавно движется по неровной местности.

Сообщения о столкновениях

Всякий раз, когда физический объект сталкивается с другим физическим объектом, на него отправляется сообщение. EntityComponents на сущности. Чтобы получать эти сообщения, OnCollision метод необходимо переопределить. Сообщение будет содержать CollisionEvent который содержит информацию о столкновении, такую как объекты столкновения, участвующие в столкновении, и точка столкновения. OnCollision Сообщение может использоваться для выполнения действий при столкновении. Например, Пуля класс в template переопределяет OnCollision метод уничтожения пули, как только она во что-нибудь попадет. Но вместо уничтожения пули можно изменить ее траекторию, заставить ее отскочить от коллайдера, в который она попала.

Материальные эффекты

Для столкновений пуль в template настроен материальный эффект. Возникновение эффекта указано в MaterialEffects.xml файл. Этот файл находится в папке Активы\Библиотеки\MaterialEffects папка. Чтобы изменить файл, вы можете открыть его с помощью такой программы, как Microsoft Excel или OpenOffice Calc. По умолчанию эффекты материала настроены, как показано в примере ниже. Эта установка вызывает столкновение:bullet_hit эффект, когда пуля сталкивается с другой пулей или конкретным объектом.

Действия, которые относятся к столкновение:bullet_hit определены в файле collision.xml, который находится в папке Assets\Libs\MaterialEffects\FXLibs. Этот файл можно открыть в обычном текстовом редакторе, например Notepad++. Этот файл определяет все зарегистрированные на данный момент эффекты столкновений. По умолчанию определен только один эффект: bullet_hit эффект, указанный в MaterialEffects.xml файл. Как только bullet_hit эффект вызывается, он активирует звуковой триггер с именем bullet_impact который определен в Sandbox. Звуковой триггер можно настроить в Sandbox в Редактор управления звуком, находится в меню «Инструменты».

Более подробную информацию о возможностях Material Effects можно найти в _Audio и физика 5.5.2.
