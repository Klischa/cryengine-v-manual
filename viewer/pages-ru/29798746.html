Отладка на экране

Используйте mn_debug Консольная переменная для включения/отключения информации об отладке на экране для определенного объекта.

Это наиболее полезно в сочетании с покадровой записью.

Использование

mn_debug <EntityName>

  • EntityName: имя объекта для отладки. Здесь вы можете использовать табуляцию. Если сущность не найдена или указано «0», отладка отключается. Совет: имя игрока обычно — «Чувак», и чтобы отобразить имена объектов на экране, вы можете использовать «es_entity 1» (используйте «es_entity 0», чтобы отключить это).

Описание информации на экране

Глобальный TagState

Текущий Глобальный TagState отображается в верхнем левом углу.

Области применения

Все области отображаются в списке слева. Каждая область содержит следующую информацию:

  • Область применения: Имя Область применения.
  • Действие: Имя Действие играю на прицеле.
  • FragmentID(Теги): FragmentID из Фрагмент играю на этом прицеле. теги для этого фрагмента указаны в скобках. Фрагтеги, если таковые имеются, отображаются в квадратных скобках. Если соответствующий фрагмент не найден, отображаются теги, используемые для запроса фрагмента, см. область действия Motion1P на обзорном снимке экрана выше.
  • Приоритет: приоритет действия, выполняемого в области видимости.
  • RefCount: счетчик ссылок действия, выполняемого в области действия.
  • Оставшееся время: (приблизительное) время, оставшееся для этого фрагмента. Может быть 0 для зацикливания фрагментов.
  • Воспроизведение клипов: каждая строка представляет слой внутри этого фрагмента. Первый клип в каждой строке показывает, какой клип воспроизводится в данный момент. В случае последовательности или перехода отображаются несколько клипов, а воспроизводимый в данный момент клип выделяется.

Этот раздел неактивен, если область действия неактивный. Это происходит, если Контекст области действия он использует недействительный Файл базы данных анимации (ADB) присвоен ему или если он недействителен (например, ему присвоен несуществующий объект).

Очередь ожидающих действий

В правом верхнем углу показаны действия, ожидающие выполнения, отсортированные по приоритету (чем выше число, тем выше приоритет). Каждая строка содержит следующую информацию:

  • Действие: Имя Действие это ожидается.
  • FragmentID: FragmentID что это действие запрашивается в данный момент.
  • Приоритет: приоритет действия.
  • Маска принудительного прицела: (после «-», не показано на снимке экрана выше) Маска области, которую действие вынуждено использовать, если таковая имеется. По умолчанию он использует ScopeMask создан в FragmentID Редактор, но код может расширите это с помощью «маски принудительной области».

Сохранение последовательности истории

Во время воспроизведения все последние изменения в состоянии манекена записываются и могут быть сохранены в файл. На данный момент зафиксировано 200 последних изменений. Обратите внимание, что этот код удален в сборках выпуска, но он доступен в сборках отладки и профиля.

Для этого вы используете mn_dump консольная команда.

Использование

mn_dump [EntityName] [продолжительность]

  • EntityName: имя объекта для отладки. Здесь вы можете использовать табуляцию. Имя игрока обычно «Чувак». Если объект не найден, объект, указанный с помощью mn_debug <EntityName>, если таковой имеется, используется вместо него.
  • Продолжительность: необязательный параметр, указывающий, сколько секунд назад вы хотите записать. Если вы не укажете это или укажете отрицательное число, будет сохранен весь буфер рекордера.

Результат

Последовательность сохраняется как Файл последовательности (xml) в папке, указанной в переменной консоли mn_debug_sequence, что по умолчанию это Анимации/Mannequin/FragmentSequences/.

Файлы названы <EntityName>_<Date>_<Time>.xml. Например Dude_17_Apr_2012_15_12_37.xml.

Вы можете загрузить эти последовательности в Mannequin Предварительный просмотр.

Регистрация запросов фрагментов

Вы можете регистрировать все запросы фрагментов, используя mn_debugfragments консольная переменная.

Эта информация отображается в журнале только в том случае, если вы также включите mn_LogToFile!

Использование

mn_debugfragments <тип>

Тип:

  • 0, чтобы отключить отладку
  • 1, чтобы включить отладку всех фрагментов, запущенных в корневой области действия для сущности, указанной с помощью mn_debug
  • 2, чтобы включить отладку всех запущенных фрагментов для сущности, указанной с помощью mn_debug

Результат

Это пример вывода:

[ 46539] Fragment MotionMovement (rifle,) queued on scope FullBody3P for action PlayerMovement
[ 46555] Fragment fire (rifle+rapid+localClient+forceFeedback,) queued on scope WeaponForceFeedback for action ItemAction
[ 46555] Fragment rapid_fire (rifle+shoulder,) queued on scope Torso1P for action RapidFireAction
[ 46556] Fragment MotionIdle (rifle,) queued on scope FullBody3P for action PlayerMovement
[ 46561] Fragment fire (rifle+rapid+localClient+forceFeedback,) queued on scope WeaponForceFeedback for action ItemAction
[ 46562] Fragment spin_down (rifle+FP,) queued on scope OneShotSound for action ItemAction
[ 46562] Fragment idle (rifle,) queued on scope Torso1P for action ItemIdle
[ 46564] Fragment idle (No Match,) queued on scope Torso1P for action ItemIdle

Информация, отображаемая в каждой строке:

[ <индекс кадра> ] Фрагмент <fragmentID имя> ( <теги>,<теги, специфичные для фрагмента> ) поставлен в очередь в области видимости <область> для действий <действие>

Имя фрагмента — «Нет совпадения», если совпадение не найдено.

Покадровая отладка

Использование

g_manualFrameStepFrequency <Частота>

  • Частота: частота кадров, которую мы хотим имитировать при использовании режима ручной покадровой отладки. Установка значения 0 (значение по умолчанию) полностью отключит покадровую отладку вручную.

Описание

В примере проекта GameSDK g_manualFrameStepFrequency CVar позволит вам вручную генерировать кадры по одному. Просто установите CVar на желаемую частоту кадров моделирования (например, 30 или 60 кадров в секунду) и нажмите «Пауза» на клавиатуре. После этого движок полностью зависнет, и новые кадры будут генерироваться только при нажатии клавиши со стрелкой вправо. Обратите внимание, что система ввода по-прежнему работает при использовании ручного покадрового шага. Это означает, что вы можете использовать эту функцию для очень легкого тестирования чрезвычайно специфических последовательностей входных данных. Выйти из режима ручного шага кадров можно повторным нажатием клавиши «Пауза». Если вы нажмете клавишу со стрелкой влево, система откроет программу просмотра изображений по умолчанию и позволит вам просмотреть историю ранее созданных кадров.

Покадровый переход также поддерживается в многопользовательском режиме. Если один игрок перейдет в режим ручного шага кадров, команда будет транслироваться, и все клиенты будут зависать и синхронно генерировать кадры по одному при каждом нажатии клавиши со стрелкой вправо. При запуске нескольких клиентов на одном компьютере каждый клиент будет иметь свою собственную историю, доступ к которой можно получить, нажав клавишу со стрелкой влево.

Покадровый шаг, используемый вместе с mn_debug CVar может быть чрезвычайно полезен при отладке проблем, связанных с анимацией. Его можно использовать для проверки того, как игра работает при очень специфической последовательности ввода (даже на нескольких клиентах в многопользовательской среде), измерения задержки ввода, очень внимательного рассмотрения практически любой темы анимации персонажа, отслеживания процесса выбора фрагмента и перехода и многого другого.
