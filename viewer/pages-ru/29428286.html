Обзор

Ввод в двигатель управляется CryInput, система, которая собирает и абстрагирует входные данные, специфичные для платформы. Хотя можно получить данные, специфичные для устройства, из IВвод интерфейс напрямую, игры обычно используют систему отображения действий, предоставляемую через IActionMapManager.

Целью сопоставления действий является поддержка получения входных данных от нескольких типов устройств вместо того, чтобы разработчику приходилось жестко запрограммировать устройства в игровой логике. Например, действие «прыжок» может быть привязано к клавише «Пробел» на клавиатуре и кнопке «А» на геймпаде — независимо от того, какая из них нажата, действие «прыжок» будет отправлено в код, а это означает, что для работы с другими или новыми устройствами не требуется никакой дополнительной работы.

Обратите внимание, что большая часть обработки ввода и карты действий автоматизируется компонентом ввода в подключаемом модуле компонентов по умолчанию, см. Плачь::DefaultComponents::CInputComponent.

Низкоуровневый ввод

Низкий уровень IВвод интерфейс абстрагирует платформу и логику, специфичную для устройства, для получения входных событий. Это достигается за счет IInputDevice интерфейс, традиционно реализованный в CryInput модуля. Каждое устройство ввода отвечает за связь с устройством API (например, вход DirectX), а затем вызывает IInput::PostInputEvent чтобы сообщить о вводе пользователя.

После публикации события прослушиватели ввода (см. IInputEventListener) уведомляются о необходимости обработки события. Одним из примеров этого является система карт действий: она прослушивает необработанные входные события и перенаправляет их на любые игровые действия, которые должны отреагировать.

Карты действий

В лице IActionMap интерфейс, карта действий представляет собой группу действий (см. IActionMapAction), которые индивидуально запускаются необработанными входными данными. Концепция группировки позволяет нам разделить логику игрового процесса на модульные части, например, переключать состояния «в воздухе» и «на земле», а также разрешать запуск определенных действий только в определенном состоянии игрового процесса.

Код игры может прослушивать события карты действий, реализуя IActionListener интерфейс, получающий обратные вызовы при запуске действий из определенной карты действий, см. пример ниже.

Использование компонента ввода приводит к регистрации собственных карт действий и сбросу диспетчера карт действий; Компонент ввода и диспетчер действий нельзя использовать одновременно.

Итак, вам следует либо:

  1. Используйте один входной компонент для обработки входной логики (для простых входных данных для каждого уровня/объекта).
  2. Используйте диспетчер карт действий вручную в коде и не используйте какие-либо входные компоненты (ни в коде, ни в редакторе Sandbox).

Перепривязка действий

В играх обычно реализуется пользовательский интерфейс для переназначения входных данных в зависимости от их предпочтений. Система карт действий облегчает это, позволяя перепривязывать действия с помощью IActionMap::ReBindActionInput функция.
