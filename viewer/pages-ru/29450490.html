Обзор

Предполагается, что InstantEvaluators выполняет быстрые вычисления, чтобы либо оценить элемент в пределах [0,0 .. 1,0], либо полностью отбросить элемент.

Как только элемент будет отброшен, он будет полностью исключен из дальнейшего рассмотрения другими оценщиками в запросе.

Тестировщик против бомбардира

Внутри мы различаем два способа оценки:

  • Тестеры: предполагается, что они просто проверяют, соответствует ли элемент определенному условию, а если нет, то отбрасывают его.
  • Голы: должны просто давать оценку предмету, а не отбрасывать его.

Эти модальности являются скорее подсказкой для запроса и решения, какой тип InstantEvaluators запускать первым: тестеры запускаются перед оценщиками. Это делается для того, чтобы потенциально уменьшить количество оставшихся элементов как можно раньше, чтобы предотвратить вычисления над элементами, которые в любом случае могут быть отброшены.

Различие между тестировщиком и оценщиком не является жестким правилом: InstantEvaluators может быть и тем и другим, в зависимости от его знаний в конкретной предметной области. Например, InstantEvaluator, который оценивает 3D-точку, может выполнять две цели:

  • Сбросьте точку, если она находится ближе N метров или дальше M метров от игрока.
  • В противном случае начисляйте баллы постепенно от [0 .. 1].

В таком случае модальность оценщика должна быть установлена ​​на модальность тестировщика.

Дешево против дорого

Более высокий уровень оптимизации означает выделение уровня затрат InstantEvaluators. Цель состоит в том, чтобы «угадать», насколько сложны их вычисления. В настоящее время мы разрешаем InstantEvaluators относиться к двум категориям стоимости: дешево и дорогой. Что на самом деле означает каждая категория затрат, — вещь очень субъективная и может варьироваться от одного игрового проекта к другому. Грубое практическое правило (относительно того, что предоставляет UQS StdLib):

  • Дешево = что-то вроде проверки евклидового расстояния.
  • Дорого = проверить, находится ли точка в навигационной сетке (это требует на несколько порядков более сложных вычислений, чем просто жонглирование некоторыми числами).

Разница между дешевым и дорогим InstantEvaluators определяет, когда будет запускаться конкретный InstantEvaluators:

  • Сначала побежит вся партия дешевых, чтобы отфильтровать как можно больше позиций и составить представление о наиболее перспективных.
  • Затем, во время дорогостоящей фазы запроса, вместе с DeferredEvaluators будет выполняться дорогой InstantEvaluators.

Основная идея состоит в том, чтобы дешевый InstantEvaluators выполнял большую часть «легкой» работы и выполнял предварительную сортировку по своим оценкам. Затем, глядя на топ-N самых многообещающих предметов, дорогие InstantEvaluators и DeferredEvaluators выполняют свою последнюю работу - ровно до тех пор, пока мы не наберем достаточно предметов, которые мы сможем четко определить как окончательных «победителей».

Пример InstantEvaluator: ScoreDistance

Показанный ниже InstantEvaluator на самом деле является одним из UQS StdLib.

// - scores the distance between 2 points
// - the higher the distance the better the score
// - a threshold is used as a "reference distance" for increasing the score linearly; larger distances clamp the score to 1.0

class CInstantEvaluator_ScoreDistance : public uqs::client::CInstantEvaluatorBase<
    CInstantEvaluator_ScoreDistance,
    UQS::Client::IInstantEvaluatorFactory::ECostCategory::Cheap,
    UQS::Client::IInstantEvaluatorFactory::EEvaluationModality::Scoring
>
{
public:
    struct SParams
    {
        Vec3   pos1;
        Vec3   pos2;
        float  distanceThreshold;

        UQS_EXPOSE_PARAMS_BEGIN
            UQS_EXPOSE_PARAM("pos1", pos1, "POS1", "First position.");
            UQS_EXPOSE_PARAM("pos2", pos2, "POS2", "Second position.");
            UQS_EXPOSE_PARAM("distanceThreshold", distanceThreshold, "MIND", "Minimally required distance between Pos1 and Pos2. If smaller then the item will get discarded.");
        UQS_EXPOSE_PARAMS_END
    };

    ERunStatus DoRun(const SRunContext& runContext, const SParams& params) const
    {
        // guard against potential div-by-zero and other weird behavior
        IF_UNLIKELY(params.distanceThreshold <= 0.0f)
        {
            runContext.error.Format("param 'distanceThreshold' should be > 0.0 (but is: %f)", params.distanceThreshold);
            return ERunStatus::ExceptionOccurred;
        }

        const float distanceBetweenPoints = (params.pos1 - params.pos2).GetLength();
        runContext.evaluationResult.score = std::min(distanceBetweenPoints, params.distanceThreshold) / params.distanceThreshold;

        return ERunStatus::Finished;
    }
};
СПАрамы

Обратите внимание, что каждый пользовательский класс InstantEvaluator должен прийти с СПАрамы struct. Внутренняя архитектура UQS предполагает именно такой встроенный struct.

DoRun()

Обратите внимание на DoRun() метод, который будет вызываться через метод базового класса путем применения
https://en.wikipedia.org/wiki/Curiously_recurring_template_pattern

Регистрация InstantEvaluators

Чтобы UQS мог создать экземпляр этого нового InstantEvaluator позже во время выполнения, ему нужна фабрика, которая знает об этом конкретном классе и о том, как создать его экземпляр:

UQS::Client::CInstantEvaluatorFactory<CInstantEvaluator_ScoreDistance>::SCtorParams ctorParams;
ctorParams.szName = "my::ScoreDistance";
ctorParams.guid = "33161269-cd59-40ab-ad39-a0f561c28eeb"_uqs_guid;
ctorParams.szDescription = "Scores the distance between 2 points.\nThe higher the distance the better the score.\nA threshold is used as a 'reference distance' for increasing the score linearly; distances larger than that will clamp the score to 1.0.";

// Notice: This instance of CInstantEvaluatorFactory<> must _not_ go out of scope for the lifetime of UQS, 
//         since the UQS core will keep a pointer to this particular factory!
static const UQS::Client::CInstantEvaluatorFactory<CInstantEvaluator_ScoreDistance> instantEvaluatorFactory_ScoreDistance(ctorParams);

Чтобы наконец предоставить доступ к вашей новой фабрике InstantEvaluator ядру UQS, вам просто нужно вызвать этот вспомогательный метод static после получения UQS::Core::EHubEvent::RegisterYourFactoriesNow событие:

UQS::Client::CFactoryRegistrationHelper::RegisterAllFactoryInstancesInHub()

Это тот же процесс, который уже выполняется при предоставлении фабрикам предметов ядра UQS.
