Обзор

В отличие от PC, многие консоли не могут компилировать шейдеры локально. По этой причине CRYENGINE SDK содержит серверное приложение, которое может обрабатывать компиляцию шейдеров, назначая сервер в локальной сети, который может обмениваться данными через TCP. Сервер получает исходный файл шейдера от машины, на которой работает CRYENGINE, компилирует его и отправляет обратно двоичный шейдер, который клиентская машина затем может загрузить и использовать. Это приложение называется Remote Shader Compiler.

Кроме того, удаленный компилятор шейдеров также используется для хранения всех комбинаций шейдеров, которые на данный момент запрошены игрой (для каждой платформы). Эти списки используются во время генерации кэша шейдеров, когда все запрошенные шейдеры упаковываются для использования игрой.

Далее будут объяснены шаги по установке и настройке удаленного компилятора шейдеров.

Запуск удаленного компилятора шейдеров

Удаленный компилятор шейдеров можно найти в папке <Root>\Tools\RemoteShaderCompiler. Исполняемый файл называется CrySCompileServer.exe. Также доступен файл конфигурации, который можно использовать для настройки порта TCP, который будет прослушивать серверное приложение.

Вы можете запустить удаленный компилятор шейдеров, запустив CrySCompileServer.exe вручную. Однако обычно имеет смысл настроить его как службу, чтобы он всегда запускался вместе с операционной системой.

Запросы к шейдерам выполняются параллельно, имеет смысл убедиться в наличии достаточного количества ядер для сервера, если вы заметили значительные задержки в получении шейдеров во время выполнения.

Конфигурация удаленного компилятора шейдеров

В файле config.ini необходимо задать четыре важные переменные:

  • MailError должен быть указан внутренний адрес электронной почты компании, на который будут отправляться уведомления об ошибках компиляции.
  • Каталог кэша (TempDir), в котором хранятся двоичные шейдеры после их компиляции, должен указывать на действительный абсолютный путь (по умолчанию — <WorkingDirectory>\Temp).
  • порт это порт TCP, который должен соответствовать настройке в system.cfg игры.
  • MailServer — почтовый сервер вашей компании.

Полный файл config.ini должен выглядеть так:

MailError = shadererror@your_company.tld
MailInterval = 1
port = 61453
TempDir = C:\SHADER_CACHE
MailServer = put.here.your.mailserver
PrintErrors = 1

Компиляторы шейдеров для конкретной платформы — версии и пути

В корневой папке удаленного компилятора шейдеров каждая поддерживаемая платформа имеет собственную подпапку с дополнительными подпапками для разных номеров версий. Пути жестко закодированы и могут быть настроены в RenderDll\Common\Shaders\ShaderCache.cpp если требуется.

Все пути следуют этому шаблону: <Root>\Tools\RemoteShaderCompiler\Compiler\<platform>\Vxxx.

Всю информацию о пути, используемом удаленным компилятором шейдеров, вы всегда можете найти внутри файла ShaderCache.cpp, функция mfGetShaderCompileFlags.

Как часть распространяемого вам пакета движка, для вашего использования уже включены соответствующие шейдерные компиляторы, соответствующие коду этой версии. Просто скопируйте всю папку RemoteShaderCompiler и запустите предоставленный двоичный файл.

Списки кэша шейдеров

Подпапка кэша удаленного компилятора шейдеров будет содержать различные файлы списка txt всех комбинаций, запрошенных игрой. Файлы списков в корневой папке содержат все глобальные комбинации шейдеров, которые когда-либо запрашивались на определенной платформе на любом уровне.

Игра отправляет запросы удаленному компилятору шейдеров либо во время самого игрового процесса, либо на этапе загрузки, даже если сама удаленная компиляция шейдеров отключена. Это делается для того, чтобы быть уверенным, что собраны все возможные комбинации шейдеров, а кэши шейдеров, генерируемые на этапе генерации кэша шейдеров, являются максимально полными.

Конфигурация игры

Использование удаленного компилятора шейдеров игрой можно настроить с помощью следующей настройки квара, которая обычно помещается в файл system.cfg:

r_ShadersRemoteCompiler=1

Если r_ShadersRemoteCompiler установлено значение 0, удаленная компиляция шейдеров выполняться не будет, а вместо этого движок выполнит локальную компиляцию шейдеров (что не удастся на консолях).

Если этот параметр включен, игра должна знать расположение удаленного компилятора шейдеров. Адрес сервера IP можно настроить с помощью следующей переменной CVar:

r_ShaderCompilerServer=<IPv4_of_PC_running_the_RemoteShaderCompiler>

Можно указать несколько удаленных компиляторов шейдеров, как показано в следующем примере. Адреса IP должны быть разделены точкой с запятой.

r_ShaderCompilerServer=10.0.0.10;10.0.0.11

Обратите внимание, что невозможно использовать сетевое имя сервера вместо адреса IP, поскольку разрешение имени не выполняется.

Если удаленный сервер компиляции шейдеров использует определяемый пользователем номер порта (как указано в config.ini), номер порта можно настроить с помощью следующей переменной CVar.

r_ShaderCompilerPort=<номер порта>

Отправку строк запроса удаленному компилятору шейдеров также можно отключить с помощью следующей переменной, которая может быть полезна при экспериментировании с шейдерами, когда вы не хотите, чтобы эти комбинации добавлялись в глобальный кеш шейдеров:

r_shaderssubmitrequestline=0

И последнее замечание: не обязательно иметь центральный удаленный сервер компиляции шейдеров для всей компании. Также можно настроить удаленный компилятор шейдеров локально на каждом PC, который требует компиляции шейдеров, и это действительно удобно при написании шейдеров.
