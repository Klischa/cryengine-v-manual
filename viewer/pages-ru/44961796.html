Обзор

Многослойные навигационные сетки (MNM) могут содержать несколько слоев NavMeshes, каждый из которых может использоваться агентами AI, имеющими разные свойства.

Части этих NavMeshes могут дополнительно быть отмечены специальными областями, которые либо затрудняют навигацию для агентов AI, либо вообще блокируют их. Свойства навигационных агентов, типы областей и многое другое можно настроить в Скрипты/AI/Navigation.xml файл вашего проекта.

Типичная структура А. Navigation.xml Файл с определенными типами агентов, флагами областей и типами областей выглядит следующим образом:

<Navigation version="6" >  
  <AreaFlags>
    ...
  </AreaFlags>
  
  <AreaTypes>
    ...
  </AreaTypes>
  
  <AgentTypes>
     ...
  </AgentTypes>
</Navigation>

Ниже прикреплен образец Navigation.xml файл, который вы можете загрузить и изменить для своих проектов. Его необходимо поместить в папку вашего проекта. Скрипты/AI/ папка.

Navigation.xml

версия атрибут Навигация тег в первой строке Navigation.xml файл всегда должен обновляться каждый раз, когда файл обновляется. В противном случае существует несоответствие между сохраненным NavMesh и данными конфигурации, присутствующими в файле. Navigation.xml файл может привести к сбою движка.

Каждый раз, когда Navigation.xml файл обновлен, пользователи должны повторно создать NavMeshes в редакторе, используя Игра → AI → Восстановить навигацию → Восстановить все слои в главном меню, чтобы увидеть обновленный NavMeshes.

Типы агентов

С точки зрения навигации символы AI можно представить как цилиндры с разными размерами (радиусами, высотой) и свойствами проходимости.

Имея это в виду, каждому типу символов AI должен быть назначен тип навигационного агента; персонажи могут иметь один и тот же тип навигационного агента и, следовательно, использовать один и тот же NavMesh. Свойства типа навигационного агента настраиваются <AgentType> узел:

<AgentType name="MediumSizedCharacters" voxelSize="0.125, 0.125, 0.125" radius="4" height="16" climbableHeight="3" climbableInclineGradient="1" climbableStepRatio="1" maxWaterDepth="8" />

AgentType Свойства

На сгенерированную Navmesh влияют указанные выше свойства размера и проходимости, а также положение и вращение физических прокси в мире, которые вокселируются в процессе генерации Navmesh. Однако разница в создаваемых углах наклона не превышает +/- 5 градусов.

Пример

<AgentTypes>    
   <AgentType name="MediumSizedCharacters" voxelSize="0.125, 0.125, 0.125" radius="4" height="16" climbableHeight="3" climbableInclineGradient="1" climbableStepRatio="1" maxWaterDepth="8" />
   <AgentType name="LargeSizedCharacters" voxelSize="0.15, 0.15, 0.15" radius="6" height="20" climbableHeight="6" maxWaterDepth="10" />
</AgentTypes>

Треугольные аннотации

Каждый треугольник в NavMesh помечен типом области и флагом области, оба из которых используются в запросах NavMesh, таких как поиск пути, raycasts и других, для фильтрации запрещенных треугольников и расчета затрат на обход. Эти аннотации также можно изменить во время выполнения.

Флаги территорий

Флаги областей можно использовать для проверки доступности треугольников NavMesh, а для каждого треугольника можно установить комбинацию флагов.

Флаги областей определяются <Флаг> узлы, имеющие следующие атрибуты: 

<Flag id="4" name="Forbidden" color="64,0,0,127"/>

Система навигации автоматически создает следующие флаги по умолчанию:

  • «Прогулка» (id = 0) — этот флаг используется типом области по умолчанию. Этот флаг установлен для всех треугольников NavMesh, которые не являются частью какой-либо специально отмеченной области.
  • «Недоступно» (id = 1) — этот флаг устанавливается на всех треугольниках, которые не подключены к исходной точке в области навигации.
Параметры (имя и цвет) флагов по умолчанию можно перезаписать, явно указав их в поле Navigation.xml файл конфигурации.

Типы территорий

Типы областей позволяют отмечать особые области, стоимость прохождения которых может иметь разную стоимость в NavMeshes. Типы областей настраиваются <AreaType> узлов и должен содержать список начальных флагов, которые устанавливаются на треугольниках NavMesh при его создании.

<AreaType> узлы имеют следующие атрибуты:

<AreaType id="2" name="DoorClosed" color="255,128,0,127">
   <Flag>Walkable</Flag>
   <Flag>Door</Flag>
   <Flag>Forbidden</Flag>
</AreaType>

Система навигации автоматически создает тип области по умолчанию (id = 0), который применяется ко всем треугольникам, которые не отмечены специально.

Пример

Ниже приведен пример настройки типов областей и флагов:

<AreaFlags>
   <Flag id="2" name="Fire" color="255,0,0,127"/>
   <Flag id="3" name="Door" color="255,255,0,127"/>
   <Flag id="4" name="Forbidden" color="64,0,0,127"/>
</AreaFlags>
  
<AreaTypes defaultColor="0,127,255,127">
   <AreaType id="1" name="DoorOpened" color="255,255,0,127">
    <Flag>Walkable</Flag>
    <Flag>Door</Flag>
   </AreaType>
   <AreaType id="2" name="DoorClosed" color="255,128,0,127">
      <Flag>Walkable</Flag>
      <Flag>Door</Flag>
      <Flag>Forbidden</Flag>
   </AreaType>
   <AreaType id="3" name="Fire" color="255,0,0,127">
      <Flag>Walkable</Flag>
      <Flag>Fire</Flag>
   </AreaType>
   <AreaType id="4" name="DenseGrass" color="0,255,0,127">
     <Flag>Walkable</Flag>
   </AreaType>
</AreaTypes>

NavMesh отмечен специальными типами территорий

Области более низкой высоты

Обычно NavMesh генерируется только в том случае, если зазор не меньше роста агента AI.

Однако в случаях, когда агент может изменить свою стойку, также желательно создать NavMesh, где агент может ходить в присевшей позиции. Этого можно добиться, добавив в конфигурацию агента область меньшей высоты с помощью <LowerHeightArea> дочерний узел.

NavMeshes с областями меньшей высоты также может использоваться персонажами AI разного роста; эти символы AI могут использовать один и тот же тип агента, отфильтровывая недоступные для них треугольники. Кроме того, для одного типа агента можно указать несколько областей нижней высоты разной высоты.

Атрибуты <LowerHeightArea> узел следующие:

<LowerHeightArea height="8" areaType="Crouch" minAreaSize="200"/>

Пример

Если мы возьмем уровень, показанный на NavMesh отмечен специальными типами территорий изображение выше и заблокируйте нижний вход упавшим деревом, там не будет создано NavMesh, поскольку пространство между местностью и деревом недостаточно велико, чтобы сквозь него мог пройти персонаж AI.


Упавшее дерево

Поскольку для персонажа не должно быть проблемой приседать или лежать под ним, мы можем добавить области меньшей высоты, чтобы генерировать NavMeshes в таких местах. Тот же NavMesh затем может использоваться и меньшими агентами (но того же радиуса). 

<AgentType name="MediumSizedCharacters" voxelSize="0.125, 0.125, 0.125" radius="4" height="16" climbableHeight="3" climbableInclineGradient="1" climbableStepRatio="1" maxWaterDepth="8">
   <LowerHeightArea height="8" areaType="Crouch" minAreaSize="200"/>
   <LowerHeightArea height="4" areaType="Prone" minAreaSize="200"/>
</AgentType>

Вокселы и единицы измерения

При создании NavMesh области навигации разбиваются на более мелкие объемы, называемые плитками.

Эти плитки имеют фиксированный размер 8 м х 8 м х 8 м. Более того, тайлы должны состоять из целого числа вокселей (например, 0,1 м х 0,1 м х 0,1 м — допустимый размер воксела); в противном случае размер воксела будет внутренне скорректирован до ближайшего допустимого значения (например, 0,101 м х 0,101 м х 0,101 м будет скорректирован, чтобы 0,125 м х 0,125 м х 0,125 м).

Чем меньше размер воксела, тем точнее (и дороже) будет сгенерированный NavMesh. Минимальный размер воксела составляет 0,025 м х 0,025 м х 0,025 м (меньший размер приведет к сбою генерации NavMesh).

Назначение типа навигационного агента символу AI

Чтобы настроить тип агента персонажа AI:

  • Добавить AI → AI Навигационный агент Компонент персонажа с помощью Добавить компонент кнопку в инструменте «Свойства».
  • Выберите тип агента персонажа, используя Тип навигационного агента раскрывающийся список.

Тип агента сначала должен быть определен в Navigation.xml config, чтобы он был указан в Тип навигационного агента раскрывающийся список.
