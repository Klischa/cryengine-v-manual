Что такое импортер активов?

Пользователи думают о своих данных с точки зрения активы, такие как сетки, скелеты, анимация и т. д., которые обрабатываются как логическая единица внутри Sandbox. Между ресурсами, видимыми в браузере ресурсов, и криассет файлы на диске. Однако эти файлы не хранят фактические данные, используемые движком, а просто хранят список ссылок на файлы данных. Например, ресурс типа Mesh может ссылаться на файл данных типа cgf, в котором хранится фактическая геометрия. Типы файлов данных относятся к CryENGINE (нажмите здесь для обзора этих типов). Ресурс, созданный с помощью какого-либо инструмента DCC, необходимо преобразовать в один из форматов файлов данных CRYENGINE, прежде чем его можно будет использовать в движке.

Работа импортер активов заключается в том, чтобы взять исходный файл определенного типа и создать актив, который включает в себя создание файла криассета, а также необходимых файлов данных. Импортерам активов Sandbox может звонить в разные места. Одним из них, безусловно, является браузер активов, который позволяет импортировать ресурсы. Может существовать несколько импортеров ресурсов, которые обрабатывают различные комбинации типов исходных файлов и типов ресурсов. Например, есть один импортер активов, который создает все типы активов из файлов FBX. Новые импортеры могут быть реализованы в плагинах.

GetAssetNames передается список запрошенных типов активов и возвращается список имен активов, которые могут быть записаны. Однако он не должен ни изменять существующие ресурсы, ни создавать новые, поскольку перед тем, как прикасаться к файлам на диске, могут потребоваться некоторые дополнительные действия. Например, файлы необходимо извлечь для контроля версий. Затем передается список имен активов или, в более общем смысле, его подмножество. ImportAssets который затем фактически записывает файлы.

Каждому из этих методов передается контекст импорта который содержит данные для процесса импорта одного исходного файла. Например, путь к исходному файлу и путь к выходному каталогу можно запросить из контекста (6).

Подробности реализации импортера FBX

Импортер FBX (класс CAssetImporterFBX) делегирует большую часть работы компилятору ресурсов (RC). RC вызывается как отдельный процесс, который принимает некоторые аргументы и создает несколько выходных файлов. Он записывает файлы данных, а также файлы криассетов. К сожалению, RC — это, по сути, «черный ящик», и вызывающая сторона не может заранее сказать, какие файлы будут записаны и сколько. Это противоречит требованиям интерфейса CAssetImporter, который запрашивает у импортера FBX список потенциально записанных файлов ресурсов для заданной пары исходного файла и типов ресурсов.

Чтобы решить эту проблему, импортер FBX всегда импортирует ресурс во временный каталог, а затем ищет файлы CryAsset.

Детали реализации импортера изображений

Импортер изображений (класс CAssetImporterImage) создает текстуры из таких форматов изображений, как png, jpg или bmp. Сначала он преобразует изображение в TIF, а затем вызывает RC для создания CryTif. После этого CryTif конвертируется в dds, как обычно.

Для преобразования TIF мы используем стороннее приложение под названием ImageMagick (IM), который мы поставляем вместе с движком (Tools/third_party/imagemagick). IM вызывается как отдельный процесс, точно так же, как мы вызываем RC. В состав IM входит множество программистов, поддерживающих множество форматов, но большинство из них делают некоторые предположения относительно среды. Поэтому мы поддерживаем только известный белый список форматов для импорта текстур, который включает наиболее часто используемые форматы обмена изображениями.
