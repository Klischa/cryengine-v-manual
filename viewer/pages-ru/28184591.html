Профилирование

Движок предоставляет несколько инструментов для измерения влияния на производительность:

Производительность графики

Для простого просмотра текущей производительности кадра введите «r_Profiler 1» в консоль, в результате чего появится представление ниже:

Вы можете указать цель FPS (r_profilerTargetFPS 30), чтобы выровнять инструмент для измерения. По умолчанию — 30.

В этом обзоре представлена информация о том, что делают основной поток (CPU), поток рендеринга (CPU) и GPU, что позволяет получить хорошее представление о текущих узких местах вашего проекта.

Кроме того, можно включить «r_Profiler 2», чтобы получить гораздо более подробную информацию, давая информацию о том, что именно вызывает проблемы в вашей сцене:

Более детальное профилирование и отладку графики можно измерить с помощью описанного инструмента Renderdoc. здесь.

Время загрузки

Профилировщик загрузки позволяет профилировать время, необходимое для запуска двигателя, а также время загрузки уровней. Для получения дополнительной информации см. Профилирование времени загрузки.

Использование памяти

Инструмент MemReplay позволяет отслеживать использование памяти в движке, чтобы выявить проблемы с использованием памяти и ее утечки. Для получения дополнительной информации см. Профилирование памяти.

CPU Производительность

CRYENGINE предоставляет несколько помощников, которые отслеживают время выполнения критических функций в движке.

Чтобы просмотреть более подробную статистику профилирования, используйте внешний инструмент профилирования Brofiler, упомянутый в разделе Профилирование производительности.

Рисование помощников по физике

Часто бывает полезно просмотреть визуальное состояние физического мира, чтобы решить проблемы игрового процесса, связанные с физикой. Этого можно добиться с помощью p_draw_helpers Cвар. Это значение может быть установлено равным 1, чтобы отображать наиболее распространенные физические типы:

В противном случае более тонкую настройку можно выполнить, объединив типы физических лиц с типы помощников следующим образом:

p_draw_helpers [Entity Types]_[Helper types]

Например, мы можем использовать:

p_draw_helpers s_g

В результате будет отрисована только геометрия static:

Одновременно можно использовать несколько типов, например:

p_draw_helpers st_gb

Будет рисовать только типы объектов static и ландшафта и отображать их геометрию, а также ограничивающие рамки:

Часто бывает очень полезно увидеть, что происходит внутри выделенного сервера. Этого можно добиться, запустив r_debug_renderer_show_window команду, а затем r_debug_renderer_set_eye_pos <X> <Y> <Z>. Рисование помощников отладки для каждого кадра

Средство визуализации предоставляет IRenderAuxGeom интерфейс для поддержки рисования элементарной геометрии, чаще всего в целях отладки. Рисование с помощью вспомогательного рендерера довольно просто и требует предварительного вызова IRenderAuxGeom::SetRenderFlags чтобы установить состояние рендеринга, а затем вызвать одну или несколько функций IRenderAuxGeom::Draw*, представленных в ссылке на API.

Например:

// Restore to default rendering state
gEnv->pRenderer->GetIRenderAuxGeom()->SetRenderFlags(SAuxGeomRenderFlags());
// Draw a red sphere at the specified position
gEnv->pRenderer->GetIRenderAuxGeom()->DrawSphere(worldPosition, radius, ColorB(255, 0, 0, 255));

Обратите внимание: чтобы вспомогательная геометрия отображалась постоянно, она должна отображаться в каждом кадре. Если вам нужен стиль постоянной отладки «выстрелил и забыл», см. раздел ниже.

Рисование постоянных помощников отладки

IPersistantDebug Интерфейс можно использовать для постоянного отрисовки помощников отладки, указав время ожидания и отрисовывая их до истечения времени таймера.

Прежде чем можно будет выполнить рисование, мы должны вызвать метод IPersistantDebug::Начать функцию, после чего мы можем вызвать любое количество функций IPersistantDebug::Add*. Например, чтобы нарисовать красную сферу в течение 60 секунд:

gEnv->pGameFramework->GetIPersistantDebug()->Begin("myDebug", false);
gEnv->pGameFramework->GetIPersistantDebug()->AddSphere(worldPosition, radius, ColorB(255, 0, 0, 255), 60.f);

Связанные переменные

sys_perfhud

Opens a UI panel that provides easy access to profiling and debugging tools. This is particularly useful for consoles, where the Engine console and key inputs are typically not easily accessible.
Usage: sys_perfhud [0/1/2]
0: Off.
1: In focus (cursor control).
2: Out of focus (no cursor control).

Параметры perf hud UI могут различаться в зависимости от проекта и/или загруженных модулей Engine; например, такие проекты, как GameSDK, могут иметь больше параметров, чем пустой шаблон.
