Обзор

Наш инструмент Schematyc меняет способ создания игровых систем. в CRYENGINE и гives Designers — возможность создавать новые объекты многократного использования из набора строительных блоков, предоставленных программистами. На первый взгляд редактор Schematyc немного похож на Flow Graph, но эти две системы были созданы с совершенно разными целями. В то время как Flow Graph(s) очень хороши для сценариев уровней, Schematyc предназначен для обеспечения ограниченного контроля над объектами внутри этих уровней.

Инструменты визуального написания сценариев позволяют создавать сценарии для собственной логики, а конечные автоматы помогают разбивать и структурировать логику. Детерминизм и уменьшенная задержка позволяют вывести новые игровые системы за пределы стадии прототипирования и без необходимости переписывать их на C++.

Инструмент Schematyc в CRYENGINE состоит из следующих панелей:

  1. Меню
  2. Панель инструментов
  3. Браузер сценариев/Обозреватель ресурсов
  4. Свойства
  5. Представление графика
  6. Предварительный просмотр
  7. Журнал

Для получения дополнительной информации об общих концепциях Schematyc см. Схема.

Обозреватель активов

Панели обозревателя ресурсов для конкретных инструментов позволяют пользователям просматривать и редактировать ресурсы в инструменте, который используется в данный момент. В отличие от автономного инструмента «Обозреватель ресурсов», ресурсы, отображаемые на этой панели, по умолчанию предварительно фильтруются; это означает, что он отображает только те ресурсы, которые относятся к самому инструменту.

Параметры меню и их функциональные возможности как в автономном, так и в специализированном браузере активов одинаковы и могут использоваться для достижения одной и той же цели. Для получения дополнительной информации о параметрах меню браузера ресурсов см. Обозреватель активов страница.

Сигнал

Сигналы используются для связи между объектами и их состояниями, поэтому, например, вы можете создать сигнал повреждения, чтобы пересылать повреждения от одного объекта к другому. Сигналы также можно использовать для отправки данных, поэтому в примере с сигналом о повреждении вы можете добавить две переменные; тип повреждения и размер ущерба, чтобы уточнить наносимый ущерб.

  • Входы: определяет, сколько входов имеет сигнал. Каждый ввод может иметь строковый идентификатор и тип.
  • Типы: определяет тип данных входного сигнала.
    • Стандартный: представляет все типы по умолчанию, определенные самим Schematyc. Все определяемые пользователем типы будут показаны под стандартными типами.
    • Ресурс: все поддерживаемые типы ресурсов в Schematyc.
    • Математика: Все типы, связанные с математикой, определенные Schematyc.
    • Бул: Может быть либо истинным, либо ложным.
    • Строка: Массив символов.
    • Int32: Сохраняет целое число signed и unsigned.
    • UInt32: сохраняет только целое число unsigned.
    • ObjectID: Уникальный внутренний идентификатор объекта Schematyc.
    • EntityID: Уникальный идентификатор объекта.

Если другая сущность получает этот сигнал, она знает, какой тип ущерба, какой размер, и может отреагировать на эту информацию.

Функция

Функции в Schematyc аналогичны функциям в любом другом языке программирования. Они передают входные данные, функция выполняет некоторую логику, а затем возвращает выходные данные.

Вход(ы): Требуемые входные данные для функции. Эти типы данных затем можно использовать внутри функции.

Выход(ы): типы данных, которые функция возвращает после ее вызова.

Ниже вы можете увидеть простой пример определения функции. Эта функция не делает ничего, кроме добавления целого числа и возврата результата. Как видите, функция принимает два входных параметра, оба из которых являются целочисленными значениями, и также возвращает результат в виде целого числа.

Узел Begin определяет начало вашей функции. Этот узел содержит все ранее определенные вами типы входных данных, однако данные этих типов данных будут установлены вызывающей стороной вашей функции. После того, как вы выполнили свою логику в функции, вы можете вернуться/завершить свою функцию. Теперь вы можете вернуть результат своей функции или ничего не возвращать и просто завершить функцию.

Государственная машина

Машина состояний, как следует из названия, представляет собой конструкцию для управления состояниями и их передачи. Конечный автомат может использоваться для обработки сложных порядков логики, например, в конечном автомате может быть достигнуто поведение неигрового персонажа (NPC). Таким образом, конечный автомат содержит различные состояния, которые можно добавить, щелкнув правой кнопкой мыши конечный автомат.

Каждое состояние имеет свой собственный график сигналов и получает один и тот же сигнал по умолчанию (начало, обновление, конец). Когда это состояние срабатывает, будет отправлен сигнал запуска, и как long, поскольку это состояние активно, сигнал обновления будет вызываться в каждом кадре. Конечно, когда состояние закончится, будет отправлен сигнал End.

Чтобы настроить общий порядок или поведение состояний, вы можете щелкнуть непосредственно по конечному автомату. На этом графике вы можете добавлять свои состояния и логику для запуска различных состояний. В примере, показанном ниже, вы можете увидеть, как может выглядеть простой конечный автомат. Узел Begin вызывает состояние ожидания при запуске игры. Если сущность получит сигнал «Входит», она перейдет в следующее состояние «Сожжение», а если/как только «BurnTimer» закончится, она перейдет в состояние «Сломан» и останется там до конца игры.

Переменная

Переменные — это способ хранения определенной информации. Переменная состоит из трех параметров, которые вы можете выбрать после добавления ее в свою сущность.

Теперь переменную можно использовать в графике сигналов для описания определенного атрибута вашей сущности. Например, у вас может быть переменная под названием «Урон», которая будет содержать информацию о том, какой ущерб наносит этот объект.

Если опция public активна, вы можете редактировать переменные в свойстве «Переменные схемы».

Таймер

Таймер имеет ограниченное количество единиц и будет отсчитывать эти единицы. Как только «количество единиц» пройдет, это вызовет сигнал.

Приемник сигнала

Приемник сигналов — это просто новый график сигналов, и этот график может делать то же самое, что и график сигналов по умолчанию вашего объекта. Это можно использовать для организации и структурирования вашей логики, например, если у вас довольно сложная логика (после срабатывания определенного сигнала), и вы не хотите помещать все в график сигналов по умолчанию. Поэтому, чтобы сохранить чистоту и структурированность настройки, вы можете создать новый приемник сигналов только для этой конкретной логики.

Компонент

Компоненты — это контейнеры для определенной логики или функциональности. Компоненты, которые вы можете добавить сюда, такие же, как и в редакторе Sandbox с помощью кнопки «Добавить компонент». По умолчанию уже есть некоторые предопределенные компоненты из CryEngine, например, вы можете найти компоненты для ввода, освещения, физики, геометрии и многого другого. Вы также можете выполнить поиск компонента в строке поиска. Если вы создали свои собственные компоненты на C# или C++, они должны быть в списке, и вы можете добавить их в свою сущность Schematyc и использовать логику, которую вы предоставили Schematyc. Дополнительную информацию о компонентах и их возможностях см. Компоненты сущности.

После добавления компонента вы сможете увидеть его в списке компонентов вашего объекта. Все компоненты сущности будут в этом списке, и их можно будет удалить или переименовать здесь. Многие из этих компонентов имеют свои собственные свойства, которые можно редактировать на панели свойств после нажатия на них.

После добавления компонентов вы также сможете использовать предоставляемые ими функции. Эти функции должны быть в вашем списке функций и могут использоваться в графике сигнала. Компонент также может предоставлять сигналы и другие функции Schematyc.


Представление графика

Показывает графическое представление объектов и позволяет добавлять узлы в функцию. СChematyc вводит понятие графа переходов. Здесь мы контролируем, как и когда вы переключаетесь из одного состояния в другое. Примечание. Невозможно инициировать переходы откуда-либо еще, и хотя это может показаться не таким удобным, как просто возможность связать узел «переключения состояния», это значительно облегчает просмотр общей картины и отслеживание проблем, когда проекты становятся более сложными.
