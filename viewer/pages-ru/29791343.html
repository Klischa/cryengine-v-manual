Общая настройка

В Пустой template, большая часть работы выполняется внутри Game класс, который является отправной точкой для приложения. Однако в Rolling Ball template мы использовали другой подход для создания поведения.

Game класс теперь используется только для регистрации при нажатии клавиши ESC (чтобы приложение можно было закрыть). Большая часть логики перенесена в ресурсы C#, к которым можно получить доступ из Обозреватель активов в Sandbox, причем большая часть тяжелой работы происходит в Игрок класс, который представляет собой EntityComponent. Поскольку Игрок это EntityComponent, его можно добавить к сущности в Sandbox. Это достигается нажатием Компоненты в Создать объект окно, а затем перетащив Игрок (новые компоненты по умолчанию будут в категории «Общие») в вашу сцену. Если у вас уже есть сущность, готовая для игрока, вы также можете выбрать сущность и использовать Добавить компонент кнопку в окне свойств, чтобы добавить Игрок-компонент сущности.

Игрок

Игрок Класс отвечает за обработку визуальных эффектов, физики и ввода игрока (в данном случае мяча, который может кататься). Поскольку Игрок это EntityComponent, его можно добавить к сущности на уровне Sandbox из Добавить компонент меню. Игрок теперь будет сохраняться автоматически при каждом сохранении уровня, и если игра будет запущена, она будет автоматически установлена для сущности со всеми ее свойствами, установленными на правильное значение. Свойства Игрок подвергаются воздействию EntityPropertyAttribute которые более подробно описаны в EntityProperties глава.

Однажды созданный, тот Игрок класс настроит свои визуальные эффекты и физизирует себя. За визуальные эффекты отвечает SetPlayerModel метод, который вызывает LoadGeometry и LoadMaterial со значениями, установленными в соответствии с PlayerGeometryUrl и PlayerMaterialUrl. Как только визуальные эффекты будут отрисованы, они будут Физически себя, позвонив PrepareRigidbody метод, в котором он установит Масса организации и установить тип физикализации чтобы Жесткий. Жесткий означает, что объект твердый и может перемещаться. Установив его в жесткое Игрок способен передвигаться и сталкиваться с другими физическими объектами. Если Масса изменено в Sandbox или во время выполнения оно будет запущено PrepareRigidbody еще раз, чтобы обновить Масса из PhysicsEntity. Для объектов, которые не должны перемещаться, тип физикализации должен быть установлен на Статический.

Игрок получает вызовы обновления в OnUpdate, который называется каждым кадром. EntityComponent имеет несколько методов virtual, которые можно переопределить, например OnCollision, OnEditorGameModeChange и OnTransformChanged.

В каждом кадре движение игрока обрабатывается UpdateMovement метод. Во-первых, пользовательский ввод собирается через Ввод класс. Затем извлекается и преобразуется направление камеры вперед (так что она не будет направлена ​​вверх или вниз). После расчета направления вперед правильное направление камеры можно рассчитать с помощью Вектор3.Кросс в сочетании с направлением мира вверх. После расчета прямого и правильного направления камеры их можно использовать для добавления или вычитания направления импульса (в зависимости от входных данных, которые были получены ранее). Наконец, направление импульса умножается на FrameTime чтобы сделать его независимым от частоты кадров и установить импульс на PhysicalEntity's Импульс собственность.

После обновления положения Игрок он также обновит положение камеры. Этим занимается PlayerView класс, который более подробно описан в PlayerView глава.

PlayerView

PlayerView Класс отвечает за перемещение камеры в правильное положение. Однако, поскольку PlayerView не является EntityComponent ему необходимо получать вызовы обновления от Игрок вручную. Кроме того, PlayerView также использует Камера класс для расчета и изменения положения камеры в сцене. Все начинается с получения значений вращения камеры по рысканью, тангажу и крену (оси x, y и z). Вращение по рысканию и тангажу изменяется в зависимости от движения мыши, а вращение по крену полностью удалено. Затем углы возвращаются к вращению Камера. Наконец, направление вперед Кватернион умножается на ViewDistance и вычитается из позиции игрока, чтобы установить камеру в правильное положение.

Несколько интересных вещей, которые следует отметить относительно PlayerView класс;

  1. Поскольку это не EntityComponent он не может использовать EntityPropertyAttribute.
  2. В результате 1. было принято решение сохранить различные свойства, которые PlayerView использует в Игрок вместо этого. Таким образом, настройки по-прежнему можно точно настроить в Sandbox.

EntityProperties

Игрок Класс имеет несколько свойств, которые можно настроить в файле Sandbox. Это делается путем добавления EntityPropertyAttribute к свойствам.

[EntityProperty(0, "Strength of the per-frame impulse when holding inputs")]
public float MoveImpulseStrength{ get; set; } = 800.0f;

В template уже доступны следующие свойства.

  • Mass - Масса объекта Игрок в кг.
  • MoveImpulseStrength - Сила покадрового импульса при удержании входов.
  • RotationSpeedYaw - Скорость, с которой игрок вращает камеру по рысканию.
  • RotationSpeedPitch - Скорость, с которой игрок вращает камеру.
  • RotationLimitsMinPitch - Минимальный предел шага камеры.
  • RotationLimitsMaxPitch - Максимальный предел шага камеры.
  • ViewDistance - Определяет расстояние между игроком и камерой.

Все эти свойства являются свойствами float, но EntityPropertyAttribute можно использовать для демонстрации самых разных типов. По умолчанию предполагается, что тип свойства является примитивным типом (int, float, string, bool). Изменив первый параметр в EntityProperty вы можете настроить представление значения в Sandbox. Например, если вы хотите также раскрыть PlayerGeometryUrl вы можете сделать это, используя значение по умолчанию EntityPropertyType.Примитивный, но вы также можете изменить его на EntityPropertyType.Геометрия. Это по-прежнему создаст текстовое поле, но также даст вам возможность открыть файловый браузер и выбрать файл, на который должно ссылаться свойство. Для PlayerGeometryUrl это будет выглядеть как следующий код.

private string _playerGeometryUrl = "Objects/Default/primitive_sphere.cgf";
 
[EntityProperty(EntityPropertyType.Geometry, "Path where the player's geometry-file is located.")]
public string PlayerGeometryUrl
{ 
  get
  { 
    return _playerGeometryUrl;
  }
  set
  {
    _playerGeometryUrl = value;
    //Initialize again so the geometry is reloaded.
    Initialize();
  }
}
