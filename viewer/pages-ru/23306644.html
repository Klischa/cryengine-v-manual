Использование удаленного компилятора шейдеров

Удаленный компилятор шейдеров — идеальный инструмент для создания списка комбинаций шейдеров для игры, поскольку он регистрирует каждый запрос, сделанный из экземпляров запущенной игры.

Во-первых, убедитесь, что Удаленный компилятор шейдеров настроен успешно. Удаленный компилятор шейдеров должен быть доступен всем, кто играет в игру, особенно QA, чтобы все необходимые запросы шейдеров запускались и регистрировались на сервере. Постарайтесь, чтобы все, кто работает над определенным игровым проектом, использовали один и тот же удаленный компилятор шейдеров.

Как движок загружает шейдеры

Обычные сборки игры должны содержать файлы pak шейдерного кэша, созданные на этапе генерации шейдерного кэша, называемые глобальным шейдерным кешем. В начале проекта это может либо полностью отсутствовать (поскольку запросы на шейдеры еще не были отправлены), либо в файлах pak все еще может отсутствовать много шейдеров.

Когда движок пытается визуализировать объект, он проверяет, доступен ли скомпилированный шейдер. Когда шейдер недоступен, он попытается загрузить его из глобального кэша. Его можно загрузить напрямую или через механизм потоковой передачи. Прямая загрузка приведет к прямому доступу к диску из потока рендеринга, что может привести к серьезным зависаниям из-за того, что поток потоковой передачи пытается одновременно получить доступ к диску.

По умолчанию, когда компиляция шейдеров отключена, движок будет передавать шейдеры из глобального кэша. Объект не будет отображаться при потоковой передаче данных шейдера. Это поведение по умолчанию можно изменить с помощью следующей CVar (обратите внимание, что потоковая передача шейдеров не разрешена, когда включена компиляция шейдеров, и тогда движок автоматически отключит эту CVar):

r_shadersAsyncActivation = 0

Когда шейдер отсутствует в глобальном кэше, «строка запроса» для сохранения этого отсутствующего шейдера напрямую отправляется удаленному компилятору шейдеров, чтобы убедиться, что этот шейдер будет доступен при следующем генерации шейдерного кэша. Это происходит даже тогда, когда компиляция шейдеров отключена, но удаленный компилятор шейдеров должен быть активен.


Если компилятор шейдеров не определен или отключен, строка запроса будет игнорироваться. Настоятельно рекомендуется как можно больше поиграть с удаленным компилятором шейдеров, чтобы собрать как можно больше комбинаций шейдеров. Удаленную компиляцию шейдеров можно отключить с помощью следующей переменной CVar (отключена по умолчанию в релизных сборках, в противном случае всегда включена):

r_shadersRemoteCompiler = 0

Отправку строк запроса шейдера также можно отключить:

r_shadersSubmitRequestLine = 0

Если компиляция шейдера отключена и шейдер отсутствует в глобальном кэше, объект вообще не будет отображаться. Если компиляция шейдеров включена и удаленный компилятор шейдеров активен, к удаленному компилятору шейдеров будет отправлен асинхронный запрос на компиляцию шейдеров. Если удаленный компилятор шейдеров отключен, то шейдер будет скомпилирован локально на PC. Другие платформы не поддерживают локальную компиляцию.

Сбор запросов к глобальному кешу шейдеров

Как объяснялось выше, каждый раз, когда шейдер отсутствует в глобальном кэше, удаленному компилятору шейдеров будет отправлен запрос на сохранение информации об отсутствующем шейдере.

Как отслеживать текущее состояние кеша шейдеров в игре

Дополнительную информацию об отладке можно включить с помощью следующего CVar:

r_displayinfo = 2

Строка с информацией о кэше шейдеров находится в правом верхнем углу экрана и сообщает о количестве обнаруженных на данный момент промахов глобального кэша (GCM). Он также сообщает, включена ли в данный момент компиляция шейдеров или нет.

Все промахи в кэше шейдеров также сохраняются в текстовый файл по следующему адресу: <user>\Shaders\ShaderCacheMisses.txt. Эта информация используется только для отладки текущего состояния кэша шейдеров и в идеале должна быть пустой.
