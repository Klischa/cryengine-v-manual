Обзор

Эта статья призвана облегчить миграцию проектов с CRYENGINE 5.3 на CRYENGINE 5.4 и фокусируется на изменениях, внесенных в формат исходного кода CRYENGINE.

Устаревшие функции

Со временем и по мере появления новых функций мы будем объявлять устаревшими старые и планируем удалить их в будущих выпусках Engine.

В версии 5.4.0 устарели следующие функции:

  • Игровые объекты (доступны только для C++)
  • Lua — заменен на C#
  • Система Actor – заменена компонентами сущности.
  • Система игровых правил — заменена сущностными компонентами и сетевыми клиентскими прослушивателями.
  • Стандартные объекты — недавно были представлены в CRYENGINE 5.3.0, но теперь устарели в пользу новых стандартных компонентов.

Кроме того, следующие функции уже устарели и были удалены из исходного кода Engine и, следовательно, больше не будут работать:

  • Облака - заменены объемными облаками
  • Объемные объекты — заменены объемными облаками

Наконец, рендерер OpenGL больше не поддерживается. Исходный код по-прежнему поставляется вместе с движком, однако Vulkan считается эффективной заменой.

Настройка нового проекта CMakeLists

Система проекта была переработана для автоматического создания настройки CMake (CMakeLists.txt) всякий раз, когда используется опция «Создать решение».

Это делается путем автоматического обнаружения .cpp и .ч файлы в каталоге Code и добавляя их в решение. Это означает, что любые настройки, внесенные вами в CMakeLists.txt, будут удалены после создания решения, поэтому мы настоятельно рекомендую резервное копирование этого файла перед обновлением.

Файл CMakeLists по-прежнему можно настроить с помощью помощников BEGIN-CUSTOM и END-CUSTOM:

#BEGIN-CUSTOM
# Custom changes in here
#END-CUSTOM

Все, что находится между пользовательскими помощниками, будет автоматически перенесено во вновь созданный файл CMakeLists.txt.

Кроме того, также можно использовать чистый рабочий процесс CMake, не используя опцию «Создать решение» после первого поколения, а затем запуская CMake GUI напрямую.

Не рекомендуется переносить существующие проекты в предварительную сборку, поскольку это не полноценная сборка и многие ее аспекты все еще содержат (иногда серьезные) ошибки.

Как перенести проект с CRYENGINE 5.3 на CRYENGINE 5.4 (предварительная версия)

  1. Откройте каталог установки CRYENGINE 5.4 и перейдите в Инструменты/CryVersionSelector.
  2. Пресса Сподъем и Щелкните правой кнопкой мыши в папке установки выбрать Откройте окно PowerShell здесь или Откройте окно командной строки здесь.
  3. Введите команду "cryselect.exe установить" в окне командной строки или ".\cryselect.exe установить" в PowerShell, а затем нажмите Войти.
  4. Теперь откройте каталог проекта 5.3 и щелкните правой кнопкой мыши *.cryproject файл для выбора Переключить версию двигателя из меню.
  5. Во всплывающем окне нажмите кнопку «Обзор» (…), перейдите в каталог установки CRYENGINE 5.4, а затем нажмите OK (Если движок уже зарегистрирован, его можно выбрать из раскрывающегося меню и пропустить этот шаг).
  6. Во всплывающем окне нажмите OK чтобы начать процесс переключения.
  7. Если версия проекта изменится, всплывающее окно уведомит пользователя о необходимости сначала сделать резервную копию проекта.
  8. Если переключение прошло успешно, пользователь будет уведомлен о необходимости создания решения и перестройки проекта.
  9. Теперь щелкните правой кнопкой мыши по *.cryproject файл и нажмите Создать решение из меню.
  10. Если это С++ проект, CMake создаст решение в Решения/Игра.win_x64 каталог. Если это С# проект, решение будет создано в папке кода. Решение будет называться Game.sln.
  11. Если при создании решения в CMake возникает ошибка, убедитесь, что установлен Visual Studio с поддержкой проектов C++.
  12. Теперь пользователь может открыть решение. Для проектов C++ решение можно открыть в Visual Studio. Для проектов C# его можно открыть с помощью Xamarin Studio, если в нем установлена ​​надстройка CRYENGINE.
    Для получения дополнительной информации см. http://docs.cryengine.com/display/CEPROG/C%23+Programming.
  13. Теперь создайте решение, нажав Сборка/сборка решения в Visual Studio или Построить/Построить все в студии Xamarin.
  14. Если в процессе сборки возникают какие-либо ошибки, пользователю необходимо исправить их вручную.
  15. Если решение создано успешно, пользователь теперь может запустить CRYENGINE и средство запуска игры.

Необходимые изменения кода для сборки с CRYENGINE 5.4.

Если вы используете какой-либо из перечисленных ниже макросов, вам придется обновить свой код, чтобы отразить изменения, которые мы внесли в код Engine.

Вам нужно будет заменить все вхождения старых макросов на их новую форму - это также потребует обновления параметров. Старые макросы принимали два 64-битных целых числа unsigned, тогда как новые ожидают CryGUID.
