Обзор

Консоль — это система пользовательского интерфейса, которая обрабатывает консольные команды и переменные консоли. Он также используется для вывода сообщений журнала и хранения истории ввода и вывода.

Цветовое кодирование

Игровая консоль поддерживает цветовое кодирование с использованием индексов цвета. 0..9 с ведущим $ персонаж. Код скрыт в тексте, выводимом на консоль. Простые сообщения журнала через ILog интерфейс можно использовать для отправки текста на консоль.

This is normal $1one$2two$3three and so on

Это нормально одиндватри и так далее.

Дамп всех консольных команд и переменных

Использование команды DumpCommandsVars, все консольные команды и переменные консоли можно записать в файл (по умолчанию consolecommandsandvars.txt).

Можно передать параметр, чтобы ограничить переменные, которые должны быть выгружены. Например, команда:

DumpCommandsVars i_

... будет регистрировать все команды и переменные, которые начинаются, если подстрока i_ нравится i_giveallitems и i_debug_projectiles .

Консольные переменные

Переменные консоли предоставляют удобный способ предоставления переменных, которые пользователь может легко изменить, либо введя их в консоль во время выполнения, либо передав их в качестве аргумента командной строки перед запуском приложения.

Более подробную информацию о том, как использовать аргументы командной строки, можно найти в Аргументы командной строки статья.

Консольные переменные обычно называются CVar в базе кода.

Регистрация новых переменных консоли

Для целочисленной консольной переменной или float рекомендуется использовать IConsole::Регистрация() функция для представления переменной C++ как переменной консоли.

Чтобы объявить новую строковую переменную консоли, IConsole::RegisterString() функцию можно использовать.

Доступ к консольным переменным из C++

Консольные переменные предоставляются с помощью ICVar интерфейс. Чтобы получить этот интерфейс, IConsole::GetCVar() следует использовать функцию.

Самый эффективный способ прочитать значение переменной консоли — это получить прямой доступ к переменной C++, привязанной к прокси-серверу переменной консоли.

Добавление новых консольных команд

Консоль можно легко расширить новыми консольными командами. Новую консольную команду можно реализовать на C++ как функцию static, следующую за типом ConsoleCommandFunc. Аргументы этой консольной команды передаются с помощью IConsoleCmdArgs интерфейс.

Следующий код показывает скелет реализации консольной команды:

static void RequestLoadMod(IConsoleCmdArgs* pCmdArgs);

void RequestLoadMod(IConsoleCmdArgs* pCmdArgs)
{
  if (pCmdArgs->GetArgCount() == 2)
  {
   const char* pName = pCmdArgs->GetArg(1);
   // ...
  }
  else
  {
   CryLog("Error, correct syntax is: g_loadMod modname");
  }
}

Следующий код зарегистрирует команду в консольной системе:

IConsole* pConsole = gEnv->pSystem->GetIConsole();
pConsole->AddCommand("g_loadMod", RequestLoadMod);

Дополнительную информацию можно найти о функции IConsole::AddCommand().

Группы переменных консоли

Группы переменных консоли предоставляют удобный способ одновременного применения предопределенных настроек к нескольким переменным консоли.

Консольные переменные обычно называются CVarGroup в базе кода. Группы переменных консоли могут изменять другие переменные консоли, чтобы их можно было использовать для построения более крупных иерархий.

Предупреждение

Циклы в заданиях не обнаруживаются и могут привести к сбоям.

Регистрация новой группы переменных

Чтобы зарегистрировать новую группу переменных, добавьте новый текстовый файл .cfg в GameSDK\config\CVarGroups каталог.

[default]
; default of this CVarGroup
= 4
e_particles_lod=1
e_particles_max_emitter_draw_screen=64

[1]
e_particles_lod=0.75
e_particles_max_emitter_draw_screen=1

[2]
e_particles_max_emitter_draw_screen=4

[3]
e_particles_max_emitter_draw_screen=16

При этом создается новая группа консольных переменных с именем «sys_spec_Particles», которая ведет себя как целочисленная консольная переменная. По умолчанию эта переменная имеет состояние 4 (устанавливается в строке, следующей за комментарием).

При изменении переменной применяется новое состояние. Переменные консоли, не указанные в файле .cfg, не устанавливаются. Все желаемые переменные консоли должны быть частью раздела по умолчанию. В случае нарушения этого правила выводится сообщение об ошибке.

Если переменная консоли не указана в настраиваемом разделе, применяется значение, указанное в разделе по умолчанию.

Документация по группе переменных консоли

Документация по группе переменных консоли генерируется автоматически.

Console variable group to apply settings to multiple variables

sys_spec_Particles [1/2/3/4/x]:
 ... e_particles_lod = 0.75/1/1/1/1
 ... e_particles_max_screen_fill = 16/32/64/128/128
 ... e_particles_object_collisions = 0/1/1/1/1
 ... e_particles_quality = 1/2/3/4/4
 ... e_water_ocean_soft_particles = 0/1/1/1/1
 ... r_UseSoftParticles = 0/1/1/1/1

Проверка того, представляет ли значение группы переменных консоли состояние переменных, которыми оно управляет.

Из консоли

В консоли вы можете ввести имя группы переменных консоли и нажать Tab. Если значение переменной не является репрезентативным, помимо обычной информации будет напечатано реальное состояние или пользовательское состояние.

sys_spec_Particles=2 [REQUIRE_NET_SYNC] RealState=3
sys_spec_Sound=1 [REQUIRE_NET_SYNC] RealState=CUSTOM
sys_spec_Texture=1 [REQUIRE_NET_SYNC]

Вызвав консольную команду sys_RestoreSpec вы можете проверить, почему sys_spec_ переменные не представляют правильные состояния.

Из кода C++

Из кода вы можете использовать функцию-член GetRealIVal() и сравнить его возвращаемое значение с результатом GetIVal() в ICVar .

Отложенное выполнение консольных команд командной строки

Команды, передаваемые через командную строку с использованием префикса + (например. crysis.exe +карта острова) хранятся в отдельном списке, в отличие от остальных консольных команд.

Этот список позволяет приложению распределять выполнение этих команд по нескольким кадрам, а не выполнять все сразу.

Пример

В качестве примера рассмотрим эту командную строку:

--- autotest.cfg --
hud_startPaused = "0"
wait_frames 100
screenshot autotestFrames
wait_seconds 5.0
screenshot autotestTime

-- console --
crysis.exe -devmode +map island +exec autotest +quit

Были выполнены следующие операции:

  • Загрузите карту острова.
  • Подождите 100 кадров.
  • Сделайте снимок экрана под названием autotestFrames.
  • Подождите 5 секунд.
  • Сделайте снимок экрана под названием autotestTime.
  • Закройте приложение.

Подробности

Определены две категории команд: блокатор и нормальный.

Каждый кадр список отложенных команд обрабатывается как FIFO. Элементы этого списка используются как long как нормальный встречаются команды.

Когда блокатор потребляется из списка и выполняется, процесс задерживается до следующего кадра. Например, такие команды, как карта и скриншот являются блокаторами.

Консольную команду (команду или переменную) можно пометить как блокирующую во время ее объявления с помощью VF_BLOCKFRAME флаг.

Отключение консоли в релизных сборках

Консоль можно отключить в релизных сборках. Для этого откройте ProjectDefines.h (находится в Code\CryEngine\CryCommon\CryCore\Project) и закомментируйте или удалите строку, содержащую #define ENABLE_DEVELOPER_CONSOLE_IN_RELEASE и перекомпилируйте движок.
