Форматирование кода

Средство форматирования кода

Совместимая с C# конфигурация Uncrustify изучается, однако на данный момент такая поддержка недоступна.

Общие правила

Фигурные скобки

Фигурные скобки всегда должны находиться на новой строке.

// good!
public MyGoodBar()
{
}
 
// bad
public MyGoodBar {
}
 
// Bad
public MyGoodBar {}

если утверждения

Фигурные скобки необходимы всегда, даже для операторов с одним выражением.

// Good
if(a < b)
{
    DoMainThing();
}
else if(a == b)
{
    DoSomething();
}
else
{
    DoOtherStuff();
}
 
// Bad
if (a < b)
    DoMainThing();
else if (a == b)
    DoSomething();
else
    DoOtherStuff();

Соглашения об именах

Общие правила именования

  • Используйте осмысленные имена переменных и типов, никогда не используйте неподходящий язык, например дерьмо, дерьмо
  • Все имена и комментарии должны быть на американском английском.
  • Избегайте нестандартных сокращений.
  • Не пишите «2» и «4» вместо «to» и «for».

Пространства имен

Имя namespace должно быть в PascalCase.

Всегда используйте пространства имен для обозначения более крупной подсистемы движка, чтобы не загромождать корень CryEngine namespace.

Примеры
  • CryEngine.EntitySystem
  • CryEngine.FlowSystem
  • CryEngine.Сериализация

Имя класса

Имя класса должно быть в PascalCase, без любые префиксы.

// Good
class MyClass
{
} 
 
// Bad
class CMyClass
{
}

Имя интерфейса

Имя интерфейса должно быть в формате PascalCase с префиксом «I».

// Good
public interface IUpdateReceiver
{
} 
 
// Bad
public interface UpdateReceiver
{
}

Имена перечислений

Имя enum должно быть описательным и написано на PascalCase. Перечисления и их значения должны нет использовать префиксы.

// Good
enum SerializedObjectType
{
    Null,
    Primitive
}
 
// Bad
enum ESerializedObjectType
{
    Null,
    Primitive
}
 
// Bad
enum SerializedObjectType
{
    eNull,
    ePrimitive
}

Имя функции

Имя функции должно быть в формате PascalCase.

Всегда используйте Свойства для простых функций получения/установки.

Имя поля

Имя поля всегда должно начинаться с префикса _ и имя camelCase. Везде, где требуются поля public, используйте Свойства с автоматически создаваемыми полями поддержки.

// Good
class Test
{
  int _someValue;
  bool _active;
} 
 
// Better
class Test
{
  int SomeValue { get; set; }
  bool Active { get; set; }
}
 
// Bad
class Test
{
  public int someValue;
  public int active;
}

Имя свойства

В названии свойства всегда должно использоваться PascalCase. без префикс.

Если для свойства требуются поля, по возможности выбирайте резервные поля.

// Good
class Test
{
  int SomeValue { get; set; }
  bool Active { get; set; }
}
 
// Bad
class Test
{
  int someValue { get; set; }
  bool active { get; set; }
}
 
// Bad
class Test
{
  int someValue;
  bool active;
 
  bool GetSomeValue() { return someValue; }
  bool IsActive() { return active; }
}

Статические члены класса

Используйте члены класса вместо отдельных менеджеров для поиска экземпляров и управления ими.

// Good (usage: var myEntity = Entity.Spawn<MyEntity>();
public partial class Entity
{
  public static T Spawn<T>() where T : Entity, new()
  {
    // return ...
  }
}
 
// Bad
public class EntityFramework
{
  public static T Spawn<T>() where T : Entity
  {
    // return ...
  }
}

Комментарии

Каждый метод и свойство public или protected должны иметь сводку. Сводки оформляются в стиле XML и всегда располагаются на строке перед описываемым объектом.

// Good
/// <summary>
/// Clamps the specified value between 0 and 1.
/// </summary>
/// <returns>The value clamped between 0 and 1.</returns>
/// <param name="value">Value that needs to be clamped.</param>
public static float Clamp01(float value)
{
  // return ...
}
 
// Bad
public CheckBoxCtrl Ctrl; ///< The UIComponent controlling this element.

Файлы

Именование файлов

Исходный файл всегда должен иметь то же имя, что и основной тип, находящийся внутри него. Разделите отдельные классы на несколько файлов.

Макет класса

  • Определите члены в следующем порядке:
    1. Поля
    2. Свойства
    3. Методы
    4. Статические методы

Качество кода

Небезопасно

Наши библиотеки никогда не могут содержать небезопасный код.

Петли

Используйте правильный цикл для соответствующего контекста, например, просто итерируя данные в контейнере, всегда используйте foreach.
