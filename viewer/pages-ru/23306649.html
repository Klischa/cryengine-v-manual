Обзор

Эта статья расскажет вам, какие шаги необходимо предпринять для регистрации данных в Statscope.

Включение групп данных делает влияние на производительность, особенно если вы включаете все сразу.

Выбирайте только те группы данных, которые вы хотите отобразить. Это снижает влияние регистрации данных в Statscope.

Чтобы включить ведение журнала, необходимо установить два CVar в панели запуска или редакторе: e_StatoscopeLogDestination и e_StatoscopeDataGroups

e_StatoscopeLogDestination

Это контролирует, где войти в систему:

0 - Файл - сохраняет журнал в корень/статоскоп папка. В 360 это будет в вашем dev/testkit.
1 - Розетка - инструмент подключается напрямую к игре.

e_StatoscopeDataGroups

Это определяет, какие данные регистрировать. Это битовое поле CVar в верхнем и нижнем регистре, поэтому вы можете выполнять такие действия, как e_StatoscopeDataGroups fg, e_StatoscopeDataGroups A+, e_StatoscopeDataGroups g-, чтобы получить эквивалент e_StatoscopeDataGroups fA.

Очевидно, что добавление и удаление подобных групп наиболее полезно во время выполнения в консоли.

Чтобы добавить группы данных во время выполнения, используйте знак +:

  • e_StatoscopeDataGroups +

Чтобы удалить группы данных во время выполнения, используйте знак –:

  • e_StatoscopeDataGroups А-

Список доступных групп данных см. Статоскоп — Группы данных или выполните поиск в Visual Studio по запросу 'public IStatoscopeDataGroup' вы сможете найти их все.

Использование

По умолчанию настроена загрузка некоторых основных данных, которые будут полезны для прохождения QA и сетевых тестов.

Если вы просто хотите записать некоторые данные, чтобы увидеть, как работает ваша игра, то лучшей настройкой обычно является ведение журнала сокетов, поскольку это дает вам постоянное обновление в инструменте и позволяет избежать хлопот с управлением файлами журналов.

Если вы хотите регистрировать сеансы QA или сравнивать время запуска демонстрационных программ, предпочтительнее вести журнал файлов.

Группы данных

Это сборники статистики. Так, например, группа данных потокового аудио («a») записывает как фактическую, так и запрошенную полосу пропускания звука. Разделить группы данных невозможно – в этом случае вы получите либо обе статистики, либо ни одну.

Какие группы данных вы включите, конечно, будет зависеть от того, какие данные вас интересуют. Многие из них говорят сами за себя, но, возможно, стоит посмотреть на реализацию соответствующих групп данных. IStatoscopeDataGroup класс.

См. Создание новых групп данных для получения более подробной информации о том, как группы данных работают в коде.

Профилирование функций

Группа данных «r» записывает данные функции профилировщика — ту же статистику, которую отображает «профиль 1» (изначально это было реализовано для обнаружения больших всплесков отдельных кадров). Чтобы уменьшить размер журнала, были добавлены некоторые переменные CVar, которые контролируют, какие функции записываются:

  • e_StatoscopeMaxNumFuncsPerFrame - Определяет количество функций, которые необходимо включить в список измерений профиля. В выходных данных сохраняются функции с наибольшим собственным временем, т. е. общим временем выполнения за вычетом времени, затраченного на вызов других функций. (по умолчанию: 150 функций)
  • e_StatoscopeMinFuncLengthMs - Игнорирует функции ниже этого порога - удаляет небольшие случайные функции, особенно те, которые заняли 0 мс (по умолчанию: 0,01 мс).
  • e_StatoscopeDumpAll - Если установлено значение 1, e_StatoscopeMaxNumFuncsPerFrame игнорируется, все функции, которые не соответствуют порогу e_StatoscopeMinFuncLengthMs, добавляются вместе в один показатель "SmallFunctions/SmallFunctions/" (по умолчанию: 0). Поскольку CRYENGINE реализует потоковое двоичное ведение журналов, эту опцию можно всегда включать безопасно.

Если вы ищете данные за пределами основного потока, установите profile_allthreads 1. Статоскоп поддерживает фильтрацию по потокам и модулям, как в интерфейсе, после захвата журнала, так и во время журналирования. Чтобы фильтровать во время регистрации, используйте profile_filter и profile_filter_thread
