Обзор

После введения понятия А. UI Элемент в CRYENGINE следующим шагом будет рассмотрение того, что мы на самом деле можем сделать с этими элементами. Давайте теперь познакомим вас с концепцией действия UI.

UI Действия

Действие UI — это тип блок-графа, основная цель которого — инкапсулировать UI логика, чтобы ее было легко отлаживать и поддерживать.

Чтобы создать новое действие UI внутри инструмента блок-графика перейдите в раскрывающийся список вверху и выберите «Файл->Новое действие UI...".

Важно
  • Все действия UI xml-файлы необходимо сохранить в Game/Libs/UI/UIActions.
  • Все действия UI сохранены. отдельный с уровня. Их необходимо сохранить через Файл->Сохранить в меню блок-схемы. Обязательно сохраняйте каждый раз, когда вносите какие-либо изменения!

Действия UI имеют некоторые особые свойства:

  • Они всегда загружены в память и по умолчанию они активный (если вы их не отключите).
  • Для управления действием UI используйте UI:Действие:Начало, UI:Действие:Конец и UI:Действие:Управление.

UI:Действие:Начать

Это точка входа для каждого действия UI.

  • Если DisableAction порт установлен на FALSE, действие не отключено (оно активно при создании). Это поведение по умолчанию. Это означает, что все узлы/события, содержащиеся в графе UI, будут активны и будут запускать порты без какой-либо дополнительной работы.
  • Если DisableAction порт установлен на TRUE, действие отключено (не активно при создании). Это означает, что все узлы/события в графе UI не будут активны и не будут запускать какие-либо порты. Чтобы запустить график, пользователю необходимо использовать команду UI:Действие:Управление узел, чтобы запустить действие или вызвать его из кода C++.
  • Если действие UI было запущено, StartAction выходной порт активирован, а порт Args содержит стартовые параметры.

Одно действие UI может содержать несколько узлов UI:Action:Start.

UI:Действие:Конец

Это точка выхода действия UI.

  • При выходе пользователь может отключить все действие (это сэкономит вычислительную мощность). Для этого просто установите DisableAction портировать в TRUE.
  • При выходе пользователь может передать возвращаемые аргументы вызывающей стороне или код C++, если мы прослушиваем определенное действие UI.

Одно действие UI может содержать несколько узлов UI:Action:End.

UI:Действие:Управление

Этот узел запускает уже созданное действие UI.

  • Входные порты:
    • UIAction порт — это действие UI, которое будет запущено. Вы можете выбрать действие из списка, автоматически заполняемого движком. Имя графика при его создании определяет имя действия.
    • Строгий используется, если вы хотите зарегистрировать ошибку, если выбранное действие не существует.
    • Старт порт запускает действие.
    • аргументы используются для передачи аргументов действию.

  • Выходные порты:
    • OnStart порт сработает, если указанное действие UI было успешно запущено этим узлом.
    • OnEnd порт сработает, как только действие UI, запущенное этим узлом, достигнет UI:Действие:Конец узел.
    • OnStartAll и OnEndAll порты сработают, если действие UI с указанным имя начался или завершился независимо от того, был ли он запущен этим узлом или нет.
    • аргументы вы можете отправить параметры из запущенного действия UI обратно вызывающему объекту (в данном случае наш узел UI:Action:Control). Это аргументы, установленные в UI:Действие:Конец аргументы порт.

Прототипирование UI в Flowgraph

Один из способов использовать функциональность элементов UI — напрямую использовать доступные функции/события на вашем уровне. Flowgraph (MANUAL). Это не оптимальный подход для разработки. Возможно, это хорошо для прототипирования и быстрого тестирования функций, но у него есть некоторые недостатки:

  • Это вынуждает вас экспортировать свой уровень, даже если вы внесли лишь незначительные изменения в UI.
  • Если вы решите переименовать/удалить что-то из элемента UI, который используется в потоковом графе на основе уровней, эта логика потокового графа сломается и не будет выполняться.
  • Использование узлов UI непосредственно в блок-графике уровня приводит к ухудшению удобства обслуживания. Вы больше не можете легко менять местами логически сгруппированные узлы UI. Вам нужно пойти и изменить это во всех местах, где вы копируете и вставляете узлы.

Чтобы решить вышеуказанные проблемы и сделать разработку UI простой в обслуживании и отладке, CRYENGINE предлагает вам использовать UI Действия.
