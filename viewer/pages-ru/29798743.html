Обзор

Разделы

Файл базы данных анимации — это файл XML, который содержит набор Фрагменты и Mannequin Переходы. Вы можете иметь в игре столько файлов ADB, сколько захотите, чтобы разделить свою коллекцию фрагментов на управляемые наборы.

Файлы ADB должны ссылаться на Файл определения тега (xxxTags.xml) и Файл определения FragmentID (xxxActions.xml) используется этим ADB. Чтобы просмотреть обзорное изображение, показывающее, как файлы манекенов соотносятся друг с другом, см. Mannequin Файлы. Файлы ADB могут включать в себя другие файлы ADB, и тогда они называются суб-ADBс. Суб-ADB можно использовать для организации коллекций фрагментов в разные файлы, которые используются разными пользователями.

Создание файлов ADB

Вы можете создать новый файл ADB вручную в папке Animations/Mannequin/ (см. FileFormat).

Вы также можете автоматически создавать новые файлы ADB, нажимая кнопку «+» при редактировании контекстных данных в Mannequin Редактор контекста. Редактор также предложит вам автоматически создать файл ADB, когда вы ссылаетесь на несуществующий файл в Предварительный просмотр файла настройки (xxxPreview.xml).

Чтобы создать новые суб-ADB или изменить правила, которые следует использовать для перемещения фрагментов в суб-ADB, вы используете команду Mannequin Редактор анимации DB.

Внутри система использует индексы для обозначения тегов и FragmentIDs. Эти индексы являются локальными для каждого тега или файла определения FragmentID. Поэтому для клиентского кода небезопасно предполагать, что один и тот же FragmentID, используемый в разных контекстах, будет везде иметь одно и то же значение. Например, если два разных ADB косвенно ссылаются на один и тот же файл определения FragmentID (через Импорт элемент), FragmentIDs, определенные в этом общем файле, скорее всего, будут иметь разные значения в каждом контексте.

Кроме того, важно, чтобы все файлы ADB, используемые определением контроллера, ссылались на то же самое FragmentID и файлы определения тегов. Это также означает, что если вы повторно используете ADB с двумя разными определениями контроллера, вам необходимо использовать одни и те же файлы FragmentID и определения тега для обоих.

Редактирование файлов ADB

Вы редактируете фрагменты в файлах ADB, добавляя/удаляя Фрагменты в Mannequin Браузер фрагментов. В каком файле ADB находится редактируемый вами фрагмент, показано в верхней части браузера фрагментов. Это определяется тем, какой ADB связан с контекстом, который вы в данный момент редактируете (раскрывающийся список в верхней части браузера фрагментов), а также правилами под-ADB, которые вы установили в Mannequin Редактор анимации DB для этого ADB.

Формат файла

Вот простой пример файла ADB:

<AnimDB FragDef="Animations/Mannequin/ADB/PlayerActions.xml" TagDef="Animations/Mannequin/ADB/PlayerTags.xml">
 <SubADBs>
  <SubADB Tags="rifle" File="Animations/Mannequin/ADB/rifleAnims1P.adb"/>
  <SubADB Tags="pistol" File="Animations/Mannequin/ADB/pistolAnims1P.adb"/>
  <SubADB File="Animations/Mannequin/ADB/Scripting/Level1/database.adb">
   <FragmentID Name="script_level1"/>
  </SubADB>
  <SubADB File="Animations/Mannequin/ADB/Scripting/Level2/database.adb">
   <FragmentID Name="script_level2"/>
  </SubADB> </SubADBs>
 <FragmentList>
  <idlePose>
   <Fragment Tags="nw">
    <AnimLayer>
     <Blend ExitTime="0" StartTime="0" Duration="0"/>
     <Animation name="stand_tac_idlePose_rifle_3p_01" flags="Loop"/>
    </AnimLayer>
    <ProcLayer>
     <Blend ExitTime="0" StartTime="0" Duration="0.41000003"/>
     <Procedural type="PositionAdjust">
      <ProceduralParams />
     </Procedural>
    </ProcLayer>
   </Fragment>
  </idlePose>
 </FragmentList>
 <FragmentBlendList>
  <Blend from="" to="idlePose">
   <Variant from="" to="">
    <Fragment selectTime="0" enterTime="0">
     <AnimLayer>
      <Blend ExitTime="0" StartTime="0" Duration="0"/>
     </AnimLayer>
    </Fragment>
   </Variant>
  </Blend>
 </FragmentBlendList>
</AnimDB>

Корневой элемент AnimDB должен обратиться к Файл определения FragmentID (xxxActions.xml) и Файл определения тега (xxxTags.xml) используется в этом файле ADB.

SubADBs Раздел определяет правила, используемые для сортировки фрагментов по суб-ADB. В примере показано, как фрагменты с тегами «винтовка» или «пистолет» хранятся в отдельных суб-ADB. Также показано, как фрагменты с fragmentIDs, "script_level1" и "script_level2" помещаются в отдельные суб-ADB.

FragmentList содержит фрагменты. Отдельные фрагменты Фрагмент элементы внутри элемента с именем FragmentID. В примере показан только один фрагмент для «idlepose» FragmentID. Внутри элемента Fragment находится список AnimLayer и ProcLayer элементы, содержащие анимационные и процедурные клипы соответственно. Фрагменты сортируются по приоритетам их тегов при сохранении файлов ADB через редактор.

FragmentBlendList содержит переходы. Каждый Фрагмент элемент представляет собой один переход в редакторе. Каждый Вариант элемент сопоставляется с папками в редакторе, которые группируют похожие переходы с разным временем выбора. Каждый Смесь элемент представляет группу переходов между двумя FragmentIDs (или резервным элементом <Any>).
