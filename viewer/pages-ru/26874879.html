Обзор

CRYENGINE оборачивает уровень C 'открыть', 'бояться' и т. д... функционирует через ICryPak интерфейс. Это позволяет поддерживать несколько платформ, а также реализацию пользовательского архива .pak, не усложняя доступ к файлам.

Рабочий каталог

По умолчанию рабочим каталогом движка будет корень проекта, то есть каталог, содержащий ваш файл .cryproject. Однако вызовы «fopen» и т. д. сначала будут искать Активы каталог, а затем вернитесь к проверке каталога проекта.

Псевдонимы

Пути, указанные для ICryPak может содержать псевдонимы, заключенные в знаки процента (%), для доступа к предопределенному местоположению. Обычно это используется для доступа к корневому каталогу Engine или пользовательской папке. Псевдонимы по умолчанию.

PAK Архивы

Очень важный аспект ICryPak заключается в поддержке хранения игрового контента в сжатых или несжатых архивах. Это позволяет осуществлять как синхронную (остановку до загрузки данных), так и асинхронную (потоковую) загрузку архивных данных.

Порядок загрузки файлов

Порядок, в котором CryPak пытается найти файл, зависит от того, готовим ли мы выпуск.

Во время разработки (сборки профиля и отладки)

  1. Необработанная структура каталогов запрашивается с использованием собственной файловой системы платформы API.
  2. Если файл не найден ищем по паку архивам (если есть)

В релизных сборках

В релизных сборках прямой доступ к файловой системе по умолчанию отключен — это означает, что поиск файлов будет запрашивать только загруженные .pak-архивы и полностью игнорировать любые файлы в файловой системе.

Порядок поиска в архиве

Если для операции открытия запрашивается файл, система CryPak просматривает все зарегистрированные файлы .pak, чтобы найти файл. Pak-файлы ищутся в порядке создания. Таким образом, предпочтительными являются файлы patch pak, которые были добавлены в сборку позднее.

Юникод и обработка абсолютного пути

Внутри весь код обработки пути ASCII-на основе, поэтому есть нет Юникод (16-битные символы для разных языков), которые можно использовать. Это для экономии памяти и для простоты. На самом деле, в Unicode нет особой необходимости, поскольку игру можно и нужно разрабатывать с именами путей ASCII. Примечание: Производство без этого требования будет иметь проблемы с интеграцией представителей других национальностей.

Поскольку пользователь может устанавливать игры в папку с символами Юникода, абсолютные пути явно избегаются во всем движке. Системы Internal Engine автоматически преобразуют пути в Unicode при доступе к необработанным API-интерфейсам Windows. Это гарантирует, что специальные символы могут присутствовать в путях установки Engine/проекта.
