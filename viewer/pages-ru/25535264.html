Обзор

Консоль CRYENGINE — это внутриигровой пользовательский интерфейс, обеспечивающий прямую связь с движком. Он обрабатывает ввод в виде консольных команд и переменных и отображает сообщения журнала, сохраняя при этом историю ввода пользователя и вывода механизма.

Консольные переменные и команды

Многие аспекты движка и кода игры можно настроить с помощью переменных консоли. Консольная переменная имеет имя и значение, которые обычно можно изменить. Многие значения можно изменить во время выполнения с помощью консоли, что делает настройку движка или поведения игры более удобной для дизайнеров и программистов, чем изменение файлов конфигурации или даже исходного кода.

Консольная переменная, которая используется довольно часто: r_DisplayInfo, которым могут быть присвоены различные целые числа. Например, значение «1» означает, что некоторая основная информация о профилировании, такая как текущее количество кадров в секунду, отображается в правом верхнем углу экрана. Значение «0» отключает отображение этой информации, а значение «2» будет использовать другой режим отображения с немного другой информацией.

Помимо консольных переменных, которым всегда присвоено значение, существуют консольные команды, которые при вызове выполняют определенные функции.

Базовое использование консоли

Из панели запуска игры или из игрового режима в Sandbox консоль можно открыть с помощью тильды. ~ (каретка ^ на немецкой клавиатуре). В Sandbox, когда пользователь не находится в игровом режиме, доступно отдельное окно консоли, обычно расположенное внизу экрана.


Внутриигровая консоль

Вывод сообщения

Консоль показывает историю сообщений журнала, включая предупреждения и ошибки. Список можно прокручивать с помощью Страница вверх и Страница вниз ключи. Количество сообщений, выводимых на консоль, можно контролировать с помощью детализации журнала, которую можно настроить с помощью CVar: log_verbosity.

log_Verbosity
DUMPTODISK

defines the verbosity level for log messages written to console
-1=suppress all logs (including eAlways)
0=suppress all logs(except eAlways)
1=additional errors
2=additional warnings
3=additional messages
4=additional comments

Весь вывод консоли также направляется в файл журнала, который Редактор.лог при запуске Sandbox или Game.log при использовании лаунчера игры. Оба этих файла хранятся в корневой папке SDK.

Ввод команды

Помимо отображения сообщений, консоль можно использовать для ввода команд и установки значений консольных переменных. Для выполнения команды просто введите имя команды и нажмите Enter. Некоторые команды могут иметь дополнительные параметры, разделенные пробелами.

screenshot myScreenshot

Для установка консольной переменной для определенного значения введите имя переменной, затем пробел и значение, которое вы хотите присвоить.

r_DisplayInfo 1

Консольные переменные и команды не чувствительны к регистру, поэтому не имеет значения, используете ли вы заглавные буквы или нет.

Чтобы запросить значение консольной переменной, просто введите имя переменной и нажмите Tab или Enter. Значение будет выведено на консоль.

r_DisplayInfo

Переменные консоли могут иметь разные значения, причем каждое значение обычно имеет разное значение. Большинство консольных переменных имеют связанный текст справки в котором перечислены доступные значения с небольшим описанием. Вы можете просмотреть текст справки, введя имя переменной и поставив перед ним вопросительный знак.

r_DisplayInfo ?

Вы также можете выполнить поиск по ключевым словам, поставив знак ? перед ключевым словом. Например, поиск ?лаза предоставит результаты для любых CVar, в которых есть «lase»:

?лаза
hud_Crosshair_laser_fadeInTime=1 [ ]
hud_Crosshair_laser_fadeOutTime=1 [ ]
i_laser_hitPosOffset=0,1 [ ]
r_TexPreallocateAtlases=0 [ ]

Автозаполнение и история ввода

Консоль поддерживает автодополнение имен переменных и команд. Введите начало имени переменной или команды и нажмите кнопку вкладка ключ. Консоль отобразит список соответствующих команд и автоматически дополнит имя. Вы можете нажать клавишу Tab несколько раз, чтобы переключаться между всеми доступными командами, соответствующими введенной вами строке.

Если вам нужно быстро опробовать множество значений переменной одно за другим, вы можете избежать повторного ввода переменной, перемещаясь по истории ввода с помощью Вверх и Вниз ключи.

Доступные переменные консоли

CRYENGINE имеет огромный список консольных переменных. Большинство из них организованы по модулям и имеют соответствующий префикс. Префикс r_ в r_Например, DisplayInfo указывает, что переменная связана с рмодуль завершения. Чтобы облегчить отслеживание доступных переменных и команд, существует несколько способов составить их список.

Команда DumpCommandsVars может использоваться для создания списка всех зарегистрированных переменных и команд. По умолчанию список сохраняется в текстовом файле с именем consolecommandsandvars.txt, расположенный в корневой папке SDK. Версия HTML доступна в подпапке ConsoleHTMLHelp, и ее лучше всего открывать с помощью index.html. Если вы ищете конкретную переменную консоли, точное имя которой вам не известно, может быть полезно выполнить поиск в тексте или файле HTML с помощью текстового редактора или браузера.

Окно консоли в Sandbox имеет поле ввода, куда можно вводить команды. Двойной щелчок по нему откроет диалоговое окно со списком всех зарегистрированных переменных консоли. Там даже можно напрямую изменить значения.

Наконец, для удобства заранее сгенерированный список консольных переменных и команд доступен в документации.

Файлы конфигурации

Файл конфигурации (.cfg) может задавать список переменных консоли и может быть выполнен либо вручную через консоль с помощью "exec имя_конфигурации" или автоматически движком, в зависимости от имени и местоположения файла (поясняется ниже).

Каждая строка файла конфигурации содержит имя CVar, за которым следует желаемое значение (необязательное значение). = может использоваться между именем и значением). Однострочные комментарии можно добавлять с помощью -- последовательность символов.

sys_game_folder = Game
-- Disable fullscreen mode
r_Fullscreen = 0

Существует несколько файлов конфигурации, которые выполняются автоматически в следующем порядке (если файл cfg выполняется позже, он может override предыдущие настройки):

  • %USER%/game.cfg
  • корень/system.cfg
  • корень/user.cfg

Наиболее часто используемой/модифицированной конфигурацией является system.cfg, которая загружается как в редакторе, так и в панели запуска. Если вы хотите, чтобы он устанавливался только в редакторе, вы можете установить его в editor.cfg, который загружается после system.cfg и до user.cfg.

Если вы хотите каждый раз использовать определенные настройки для своей игры, например r_displayinfo 0, вы можете установить его внутри system.cfg, и это будет автоматически применять CVar каждый раз, когда вы загружаете движок.

Группы переменных консоли

Группы переменных консоли предоставляют удобный способ одновременного применения предопределенных настроек к нескольким переменным консоли. Группа CVar может изменять другие переменные и группы консоли, поэтому ее можно использовать для построения более крупных иерархий.

Обратите внимание, что циклы в задании не обнаруживаются и могут привести к сбоям. Группы CVar особенно полезны для определения различных профилей качества («системных спецификаций»).

Регистрация новой группы

Каждая группа переменных консоли хранится как отдельная .cfg файл, где имя файла определяет имя группы. По соглашению группы переменных консоли хранятся в папке GameSDK\Config\CVarGroups папка (где Game это имя каталога игры).

Чтобы создать новую группу переменных консоли, добавьте новую .cfg текстовый файл в эту папку.

Пример файла sys_spec_Particles.cfg:

[default]
; default of this CVarGroup
= 4
e_particles_lod=1
e_particles_max_emitter_draw_screen=64

[1]
e_particles_lod=0.75
e_particles_max_emitter_draw_screen=1

[2]
e_particles_max_emitter_draw_screen=4

[3]
e_particles_max_emitter_draw_screen=16

В примере файла создается новая группа переменных консоли с именем sys_spec_Particles это ведет себя как целочисленная консольная переменная. По умолчанию эта переменная имеет состояние 4 (из-за третьей строки). При изменении значения переменной новое состояние применяется к указанным CVar.

Переменные консоли, не указанные в файле cfg, не устанавливаются. Все нужные переменные консоли должны быть частью раздела [default], иначе выводится сообщение об ошибке. Если переменная консоли не указана в пользовательском разделе ([1],[2] и т. д.), применяется значение, указанное в разделе [default].

Документация по группе переменных консоли

Некоторый простой текст документации, который дает информацию о различных состояниях CVar в группе, доступен автоматически. Используйте оператор вопросительного знака, как обычно, для вывода текста документации.

Пример (sys_spec_Particles):

Console variable group to apply settings to multiple variables

sys_spec_Particles [1/2/3/4/x]:
... e_ParticlesLod = 0.75/1/1/1/1
... e_ParticlesMaxScreenFill = 16/32/64/128/128
... e_ParticlesObjectCollisions = 0/1/1/1/1
... e_ParticlesQuality = 1/2/3/4/4
... e_WaterOceanSoftParticles = 0/1/1/1/1
... r_UseSoftParticles = 0/1/1/1/1

Проверка состояния группы переменных

Если CVar организованы в группу CVar и изменяются индивидуально, группа CVar может больше не представлять назначенное ей значение.

Чтобы узнать это через консоль, введите в консоли имя группы CVar. Если значение групповой переменной не является репрезентативным, помимо обычной информации печатается реальное состояние.

Пример:

sys_spec_Particles=2 [REQUIRE_NET_SYNC] RealState=3
sys_spec_Sound=1 [REQUIRE_NET_SYNC] RealState=CUSTOM
sys_spec_Texture=1 [REQUIRE_NET_SYNC]

С помощью консольной команды sys_RestoreSpec, можно проверить, почему переменные спецификации системы не представляют ожидаемые состояния.

sys_RestoreSpec

Restore or test the cvar settings of game specific spec settings,
'test*' and 'info' log to the log file only
Usage: sys_RestoreSpec [test|test*|apply|info]

Консоль фильтра и/или журналирование файлов

Есть два CVar, которые можно использовать для фильтрации консольных сообщений:

log_UseFilter=0,1,2,3
log_Filter="string"

Чтобы включить фильтр консоли, вам необходимо установить log_UseFilter до 1/2/3:

0 - filter is disabled
1 - filter only ingame console
2 - filter only the log file
3 - filter both

Фактический фильтр можно установить через log_Filter. Это строка, которая используется для фильтрации сообщений журнала:

log_Filter  = foo //will only display messages that have the string "foo" somewhere.
log_Filter  = -bar //will remove all loggings that have "bar" somewhere.
log_Filter  = foo|bar|dude //you can combine different filters - this will only display loggings with "foo", "bar" or "dude" in it.
log_Filter  = -foo|-bar|-dude //this will remove all loggings with "foo", "bar" or "dude" in it.
log_Filter  = foo|-bar //this will display only loggings with "foo" but no "bar" in it.
Все фильтры нечувствительны к регистру.

Как отключить окно сообщения «Слишком много приложений»?

Это больше не действует для CRYENGINE 3.5 и более поздних версий.

Если вы откроете более одного экземпляра пусковая установка вы заметите окно сообщения, информирующее вас о том, что экземпляр пусковая установка уже открыт:

Однако в некоторых ситуациях, например при многопользовательской отладке, может потребоваться открыть более одного экземпляра файла. пусковая установка на одной машине. Чтобы отключить окно сообщений, вы можете добавить следующую строку в свой корень/system.cfg файл конфигурации:

ignoreTooManyAppsMessage=1
