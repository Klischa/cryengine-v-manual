Обзор

Функции в основном служат трем целям:

  • Они предоставляют доступ к глобальным входным параметрам.
  • Они предоставляют доступ к текущему оцениваемому элементу.
  • Их можно использовать как «преобразователи» между функциями.

Иерархии функций

Поскольку функция может вызывать другую функцию, в конечном итоге мы получим целую иерархию функций, которая, по сути, представляет собой дерево. Таким образом, нам необходимо различать листовые и нелистовые функции.

Листовые функции — это те, которые не имеют параметров. Неконечные функции имеют один или несколько параметров, и каждый параметр, в свою очередь, рассматривается как дополнительный (вложенный) вызов функции.

Примеры конечных функций:

  • Глобальный входной параметр.
  • Текущий элемент, над которым выполняется запрос.
  • Буквальное значение.

Примеры нелистовых функций:

  • Пользовательская функция, которая складывает 2 вектора и возвращает их сумму.
  • Пользовательская функция, которая возвращает позицию данного объекта.

Встроенные функции

Для удобства универсальная система запросов (UQS) автоматически регистрирует конечные функции для каждого зарегистрированного типа элемента. Таким образом, каждый новый тип элемента автоматически добавляет поддержку глобального входного параметра именно этого типа. То же самое можно сказать и о функциях, которые возвращают литерал и предоставляют доступ к текущему элементу запроса.

Пример функции: Vec3Add()

Пользовательские функции всегда должны быть неконечными функциями (т. е. функциями, которые принимают хотя бы один параметр). В настоящее время не существует варианта использования, который потребовал бы, чтобы он был другим. Вот пример StdLib из UQS для пользовательской функции, которая принимает 2 параметра:

class CFunction_Vec3Add : public UQS::Client::CFunctionBase<
    CFunction_Vec3Add,
    Vec3,
    UQS::Client::IFunctionFactory::ELeafFunctionKind::None>
{
public:

    struct SParams
    {
        Vec3 v1;
        Vec3 v2;

        UQS_EXPOSE_PARAMS_BEGIN
            UQS_EXPOSE_PARAM("v1", v1, "VECA", "First vector to add.");
            UQS_EXPOSE_PARAM("v2", v2, "VECB", "Second vector to add.");
        UQS_EXPOSE_PARAMS_END
    };

public:

    explicit CFunction_Vec3Add(const SCtorContext& ctorContext)
        : CFunctionBase(ctorContext)
    {}

    Vec3 DoExecute(const SExecuteContext& executeContext, const SParams& params) const
    {
        return params.v1 + params.v2;
    }
};
СПАрамы

Обратите внимание, что каждый класс пользовательских функций должен иметь СПАрамы struct встроен. Внутренняя архитектура UQS предполагает это наличие.

DoExecute()

Обратите внимание на DoExecute() метод, который будет вызываться через метод базового класса путем применения

Регистрация пользовательских функций

Чтобы UQS мог создать экземпляр этой новой функции позже во время выполнения, ему нужна фабрика, которая знает об этой конкретной функции и о том, как создать ее экземпляр:

UQS::Client::CFunctionFactory<CFunction_Vec3Add>::SCtorParams ctorParams;
ctorParams.szName = "std::Vec3Add";
ctorParams.guid = "5f4dd307-e32a-450c-a002-3c0e1cad490c"_uqs_guid;
ctorParams.szDescription = "Adds two Vec3s and returns the result.";

// Notice: This instance of CFunctionFactory<> must _not_ go out ouf scope for the lifetime of UQS, 
//         since the UQS core will keep a pointer to this particular factory!
static const UQS::Client::CFunctionFactory<CFunction_Vec3Add> functionFactory_Vec3Add(ctorParams);

Чтобы наконец предоставить новую фабрику функций ядру UQS, вам просто нужно вызвать этот вспомогательный метод static после получения UQS::Core::EHubEvent::RegisterYourFactoriesNow событие:

UQS::Client::CFactoryRegistrationHelper::RegisterAllFactoryInstancesInHub();

Это тот же процесс, который уже выполняется при предоставлении фабрикам предметов ядра UQS.
