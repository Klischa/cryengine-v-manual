Обзор

CryEngine предлагает несколько методов анализа производительности заданий во время выполнения, а также в автономном режиме.

  • Для быстрого просмотра текущей рабочей нагрузки используйте консольную команду Профиль 1.
  • Для более подробного обзора используйте Статоскоп инструмент, который можно найти в game_branch/Инструменты папка.

Профиль 1

Консольная команда Профиль1 отображает информацию об отдельных заданиях и времени их выполнения.

Эту функцию следует использовать для получения приблизительного обзора. Для более подробного анализа данных по каждому кадру см. раздел Статоскоп инструмент.


(Примечание: не беспокойтесь о синхронизации кадров на этом изображении. Скриншот был сделан в оконном режиме + не в фокусе на PC)

Как использовать:
  • Команда внутриигровой консоли: Профиль 1
Особенности:

Типы работ:

  • Нет блокировки
  • Блокировка
  • SPU (только для PS3)

Строка заголовка вакансии:

  • Граф: Количество казней в выборке
  • Time_:_ Время выполнения задания в выборке
  • Function_: Работа name_
Примечание. Время выполнения задания добавляется к кадру, в котором оно было выполнено. Задание, выполняющееся более чем в трех кадрах, может привести к неверным результатам.

Статоскоп

Статоскоп предлагает анализ данных в реальном времени, а также в автономном режиме для каждого кадра.

Ссылка на где можно найти дополнительную информацию об инструменте.

Как использовать:

Шаг 1:

  • В игровой консоли введите: e_StatoscopeLogDestination 1

Шаг 2:

  • В консоли введите: e_StatoscopeDataGroups YZ
  • DataGroup Да = Работа Информация Индивидуальная
  • DataGroup З = Работа Сводная информация
  • (Обратите внимание на заглавные буквы)

Шаг 3:

  • Старт Статоскоп

Шаг 4:

  • Нажмите Файл->Подключиться.

Шаг 5:

  • Подключитесь к платформе, на которой запущена игра.
Особенности:

Информация о вакансии индивидуально:

DataGroup: Да

Индивидуальная статистика заданий для различных типов серверной части для данного кадра.

Типы бэкэнда:

  • Нет блокировки.
  • Блокировка.
  • SPU.

По каждой работе:

  • ExecutionTimeInMs: Общее время, затраченное на выполнение задания в рамках.
  • NumOfExecutions: Общее количество раз, когда это задание выполнялось для одного или нескольких рабочих процессов в кадре.

Сводная информация о вакансии:

DataGroup: З

Сводная информация обо всей активности заданий для различных типов серверной части для данного кадра.

Типы бэкэнда:

  • Нет блокировки
  • Блокировка
  • SPU

Для каждого бэкэнда:

  • TotalExecutionTimeInMs: Общее время, потраченное на выполнение заданий
  • TotalNumberOfJobsExecuted: Общее количество выполненных работ
  • TotalNumberOfIndividualJobsExecuted: Общее количество выполненных отдельных заданий

sys_job_system_profiler

Этот инструмент визуализирует работу, распределенную по различным потокам.

sys_job_system_profiler 1

Он разбит на 3 основных раздела:

  • Основной график выполнения вверху, на котором разными цветами отображаются активные в данный момент задания и в каком потоке: Render/Main/Worker 0-7.
  • Обновление основной темы в левом нижнем углу
  • Обзор нижней части посередине заданий с подробным описанием количества выполнений заданий, а также затраченного времени, ожидания и среднего времени в мс.

Как вы заметите, задания выполняются очень быстро, поэтому вы можете приостановить отображение в любой момент (во время игры) с помощью кнопки Клавиша блокировки прокрутки.

sys_job_system_profiler 2 это просто граф выполнения сам по себе.

sys_job_system_filter

Вы можете отфильтровать отображение определенных систем, чтобы очистить дисплей и облегчить его чтение.

Например: Итак, если бы вы напечатали... sys_job_system_filter CBrushRender, WaterUpdate

Вы удалите их из поля зрения. Чтобы добавить их обратно, просто удалите их из строки выше.

Можно отфильтровать более одного задания, используя запятую, как в примере выше.

Примечание. Регистр чувствителен!

sys_job_system_max_worker
Это устанавливает количество потоков, используемых для системы заданий.

  • По умолчанию 4 на консолях.
  • По умолчанию 8 темы PC.
  • Установить на 0 создать столько потоков, сколько доступно ядер.
