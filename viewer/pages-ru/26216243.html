Обзор

Шейдеры позволяют математически рассчитывать цвет отображаемых пикселей на основе данных, отправленных движком, таких как освещение и текстуры материалов. Это означает, что полный поток из объект для шейдера становится:

  • Геометрия (.cgf, .cdf, .chr, .skin, .cga)
    • Материал (.mtl)
      • Элемент шейдера

Имейте в виду, что любой материал может иметь несколько подматериалов — это означает, что несколько шейдеров нужно рисовать отдельно с помощью уникальных принимать звонки. Это основная причина сокращения количества материалов, поскольку каждый дополнительный подматериал требует отдельного запроса к GPU.

Каталог шейдеров

Шейдеры содержатся внутри Шейдеры/ каталог и может быть загружен из любого Движок/Шейдеры/ для шейдеров движка по умолчанию или <папка ресурсов>/Shaders/. Шейдер определяется .cfx расширение и содержатся внутри Шейдеры/HWScripts/CryFX/. При запуске двигателя поиск .cfx файлы будут выполнены, в результате чего все исходные файлы шейдеров будут проанализированы и добавлены во внутренний реестр шейдеров.

Формат шейдера (.cfx)

Шейдеры CRYENGINE написаны в специальном формате шейдеров, очень похожем на HLSL.

Чаще всего материалы в движке используют шейдер Illum, поскольку он уже настроен для прохождения через общие пути шейдера. Это определено в Движок/Шейдеры/HWScripts/CryFX/Illum.cfx. Более простой пример см. в шейдере ReferenceImage в Движок/Шейдеры/CryFX/ReferenceImage.cfx. Этот шейдер гораздо более легкий и предназначен для рисования диффузной текстуры без внутреннего освещения, влияющего или искажающего изображение.

После обнаружения файла .cfx он анализируется для обнаружения информации о сценарии, обозначаемой именем переменной. «Сценарий», обычно указывается в верхней части исходного файла шейдера следующим образом:

// Shader global descriptions
float Script : STANDARDSGLOBAL
<
  string Script = 
    // Determines if the shader will be made visible to UI elements
    // For example, if set the shader will be available in the Material Editor
    "Public;"
    // If set when SupportsFullDeferredShading is not set, we go through the tiled forward pass
    // In the tiled forward case, we will execute the pass defined in this file - and not Common*Pass
    "SupportsDeferredShading;"
    // Determines that the shader supports fully deferred shading, so will not go through the forward pass
    "SupportsFullDeferredShading;"
>;

После объявления основного скрипта мы обычно включаем общие заголовки, которые будем использовать с помощью '#include' макрос, как в C++. Включения в шейдерную систему движка обозначаются значком .cfi расширение. Например:

#include "ShadeLib.cfi"

... автоматически найдет и включит файл ShadeLib.cfi в Шейдеры/HWScripts/CryFX/ каталог. За общими заголовками следуют определения методов и шейдеров, которые мы будем использовать. Например:

vert2FragGeneral MyVertexShader(app2vertGeneral IN)
{
  vert2FragGeneral OUT = (vert2FragGeneral)0; 
  streamPos vertPassPos = (streamPos)0;
  vs_shared_output(IN, OUT, vertPassPos, true);
  
  return OUT;
}
 
pixout MyPixelShader(vert2FragGeneral IN)
{
  pixout OUT = (pixout)0;
  OUT.Color.rgb = GetDiffuseTex(diffuseTex, IN.baseTC);
  OUT.Color.a = 1;
  return OUT;
}

Однако эти шейдеры не будут выполняться немедленно — нам нужно определить общую технику, определяющую поведение наших шейдеров. Обычно это делается в самом низу файла:

technique General
<
  string Script =
        "TechniqueZ=ZPass;"
    "TechniqueZPrepass=ZPrepass;"
        "TechniqueMotionBlur=MotionBlurPass;"
        "TechniqueCustomRender=CustomRenderPass;"
        "TechniqueShadowGen=ShadowGen;"
        "TechniqueDebug=DebugPass;"
>
{
  pass p0
  {    
    VertexShader = MyVertexShader() GeneralVS;
    PixelShader = MyPixelShader() GeneralPS;
    ZEnable = true;    
    ZWriteEnable = true;    
    CullMode = Back;
  }
}

В приведенном выше примере основной метод шейдера настроен на использование подметодов, импортированных в движок. Это гарантирует, что мы пройдем общий путь отложенного движка вместо того, чтобы каждый раз переписывать все аспекты каждого шейдера. Наиболее важным аспектом для нас здесь является определение использования метода общего буфера глубины, определенного в Движок/Шейдеры/HWScripts/CryFX/CommonZPass.cfi. Для получения дополнительной информации см. раздел «Общие методы» ниже.

После определения подметодов мы определили основной проход нашего шейдера, который будет использоваться в случае прямого рендеринга. В нашем примере это означает настройку вершинных и пиксельных шейдеров, которые мы определили выше, для вызова. Если вы хотите всегда идти по прямому пути, удалите «SupportsDeferredShading;» и "SupportsFullDeferredShading;" строки из объявления скрипта в верхней части файла.

Файлы расширений

После завершения анализа шейдера движок ищет .ext файл с тем же именем, что и наш шейдер (.cfx) внутри Шейдеры/ каталог. Этот файл является необязательным и позволяет отображать свойства, которые пользователь может применить к каждому материалу. Например, Движок/Шейдеры/HWScripts/CryFX/Illum.cfx файл имеет эквивалентное расширение файла, называемое Движок/Шейдеры/Illum.ext.

Например, мы могли бы добавить такое свойство:

Property
{
  Name = %MY_PROPERTY
  Mask = 0x100
  Property    (My Property Name)
  Description (Creates a shader permutation that does fancy stuff!)
}

После создания в редакторе материалов появляется флажок, когда выбран материал с вашим шейдером. Это позволяет отметить наше свойство, применить маску к флагам генерации шейдера материала и позволить нам отслеживать использование свойства внутри одной из наших функций шейдера:

#if %MY_PROPERTY
  // Custom property logic here
#endif

Это фактически создает вариант нашего шейдера, в котором включается или выключается ряд опций, обычно называемых перестановка шейдера. Свойства хранятся как флаги, поэтому нам нужна маска для определения бита, который определяет, установлено ли наше свойство.

Общие методы

Пример, который мы использовали выше, ссылается на распространенные методы, такие как ZPass и ZPrePass. Эти методы определяют общую основу между шейдерами движка, гарантируя, что мы повторно используем функциональность и идем одинаковыми путями вместо противоречивого конвейера.

В этой статье не будут подробно описаны все методы, а вместо этого основное внимание будет уделено двум наиболее важным — проходу глубины, называемому в движке проходом Z.

Для начала мы откроемся Движок/Шейдеры/HWScripts/CryFX/CommonZPass.cfi. В самом низу находится определение метода «ZPass», на который мы ссылались выше. Это определяет, какие шейдеры использовать, в нашем случае мы сосредоточимся на:

VertexShader = Common_ZPassVS() ZVS;
PixelShader = Common_ZPassPS() ZPS;

Это устанавливает две функции, которые будут использоваться для вершинных и пиксельных шейдеров, причем фактические функции определяются далее в файле. Эти знания можно использовать для вставки общих эффектов, например, для изменения выходного цвета нашего материала. Обратите внимание: поскольку проход глубины включен в наш исходный файл, мы всегда можем ссылаться на наши флаги материала для поддержки пользовательских эффектов, которые активируются только для нашего материала, вместо того, чтобы влиять на все шейдеры, проходящие через обычный конвейер.

Редактирование шейдеров

Во время разработки движок автоматически компилирует перестановки шейдеров по мере их использования. Однако перезагрузка во время выполнения также реализована, и ее можно включить, установив параметр r_ShadersEditing CVar присвойте значению 1. Это гарантирует, что при обнаружении изменения в файле .cfx шейдер будет автоматически перекомпилирован.

Дополнительно мы можем установить r_ReloadShaders=1 вручную принудительно перезагрузить все шейдеры в сцене.
