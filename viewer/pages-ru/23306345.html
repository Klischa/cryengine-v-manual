RC Вакансии

"RC Работа" — это набор операций, которые RC должен выполнить для выполнения некоторых задач (в нашем конкретном случае это описывает процесс компиляции ресурсов).

Каждый "RC Работа" определяется как XML-файл.

RC Файл задания — основная структура

К этой странице прикреплен пример файла задания («rcjob_all.xml»), которого обычно достаточно, чтобы начать создавать свои ресурсы. Описание вакансий необходимо включить между основным тегом:

<RCJobs>

[...]

</RCJobs>

Внутри RCJobs вы сначала можете указать некоторые свойства по умолчанию (ни одно из свойств не является обязательным, они просто упрощают обслуживание файла RC-задания):

  <DefaultProperties
    game="Game"
    engine="Engine"
  languages="Localization"
    src="https://www.cryengine.com/docs/static/engines/cryengine-5/categories/23756816/pages/"
    trg="TempRC\${p}"
    pak_root="OutRC\${p}"
    enable_cuda="true"
  />

Вы также можете определить некоторые свойства:

  <Properties
    xml_types="*.animevents;*.cdf;*.chrparams;*.dlg;*.ent;*.fsq;*.fxl;*.ik;*.lmg;*.mtl;*.setup;*.xml;*.node;*.veg"
    non_xml_types="*.ag;*.gfx;*.png;*.usm;*.fev;*.fsb;*.fdp;*.sfk;*.ogg;*.txt;*.anm;*.cal;*.grd;*.grp;*.cfg;*.csv;*.lua;*.dat;*.ini;*.xls;*.as;*.lut;*.mp2;*.mp3;*.xma"

    src_game="${src}\${game}"
    src_engine="${src}\${engine}"
  src_languages="${src}\${languages}"
    trg_game="${trg}\${game}"
    trg_engine="${trg}\${engine}"
  trg_languages="${trg}\${languages}"
    pak_game="${pak_root}\${game}"
    pak_engine="${pak_root}\${engine}"
  />

Например, они описывают, какие типы файлов являются или не являются XML-файлами. Обратите внимание, что вы можете установить новые свойства или override свойства по умолчанию из командной строки с помощью команды myVarName=myValue синтаксис.

С этого момента вы можете определять свои собственные задачи, которые будет выполнять rc. В нашем случае мы используем 4 задания:

1. Задание преобразования, определенное между тегом <ConvertJob> [...] </ConvertJob>
2. Задание по выполнению некоторых дополнительных операций копирования, определенных между тегом. <CopyJob> [...] </CopyJob>
3. Задание по упаковке, определенное между тегом. <PakJob> [...] </PakJob>
4. Задание очистки, которое очищает целевую папку, определенную между тегом. <CleanJob> [...] </CleanJob>

Имя задания не фиксировано, поэтому вы можете использовать любое имя тега, которое предпочитаете. Вы также можете определить больше заданий, чем то, что вы фактически используете (например, для целей тестирования). Чтобы определить, какое задание должен выполнить RC, вам необходимо использовать тег <Run> в конце файла следующим образом:

  <Run Job="ConvertJob"/>
  <Run Job="CopyJob"/>
  <Run Job="PakJob"/>
  <Run Job="CleanJob"/>

Вы также можете, например, создать задание, которое фактически запускает другое задание, следующим образом:

  <CompileAssetsJob>
    <Run Job="ConvertJob"/>
    <Run Job="CopyJob"/>
    <Run Job="CleanJob"/>
  </CompileAssetsJob>

Как определить конкретную операцию в одном задании

Внутри каждого задания (ConvertJob, CopyJob, ...) нужно описать, какие операции необходимо выполнить. Для достижения этой цели вы можете использовать тег <Вакансия>. Этот тег имеет разные параметры, которые дают RC точную информацию о задаче, которую ему необходимо выполнить. Вы можете прочитать некоторые примеры в следующих параграфах, но полный список возможных операций содержится в RCJob, прикрепленном к этой странице.

Преобразование tif-файла
<if p="PC">
    <Job sourceroot="${src_game}"    targetroot="${trg_game}"   input="*.tif" imagecompressor="${imagecompressor}" />
</if>
<ifnot p="PC">
    <Job sourceroot="${src_game}"    targetroot="${trg_game}"   input="*.tif" imagecompressor="${imagecompressor}" streaming="1" />
</ifnot>

Первая команда используется для компиляции файлов .tif для платформы PC, а вторая — для всех остальных платформ.

Sourceroot — это папка с исходными файлами, targetroot — это папка, в которую rc должен выводить результаты, input — это тип файла, который необходимо обработать, imagecompressor сообщает rc, что для операции требуется конкретный компрессор изображений, определенный в переменной ${imagecompressor}, а потоковая передача определяет, нужно ли выводить выходные файлы в папку потоковой передачи. Как видно из этого примера, для выбора конкретной операции для конкретной платформы можно использовать тег <if> или <ifnot>. Переменная p содержит строку, определяющую платформу, на которой работает rc.exe.

Копирование определенного файла из одной папки в другую
<Job sourceroot="${src_game}"   targetroot="${trg_game}"   input="*.chr" copyonly="1"/>

Предыдущая команда копирует из исходного корня в целевой корень все файлы chr.

Упаковка Scripts.pak
<Job sourceroot="${trg_game}" input="Scripts\*.*"     zip="${pak_game}\Scripts.pak" />

Предыдущая команда упаковывает все файлы, содержащиеся в папке *{sourceroot}\Scripts*, в Scripts.pak. Файлы pak выводятся в папку ${pak_game}.

Очистка определенной папки
 <Job input="" targetroot="${trg}" clean_targetroot="1" />

Предыдущая команда очистила указанный целевой корень.

Описание шагов, необходимых для компиляции ресурсов для конкретной целевой консоли.

Процесс компиляции для конкретной целевой консоли может состоять из разных этапов. Вот поток, к которому мы предлагаем подойти:

  1. Скопируйте все ресурсы, необходимые для вашей игры, в целевую папку <workPath>\<gameDir>\ .
  2. Выполните задание RC, которое вы создали для своего проекта для конкретной платформы.
