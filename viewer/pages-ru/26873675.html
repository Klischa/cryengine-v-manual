Обзор

CRYENGINE умеет локализовать текст и звук для разных языков. Все необходимые данные локализации хранятся в pak-файлах, хранящихся в папке <root>/Localization папка (пример: CRYENGINE_3.5/Localization/English_XML.pak).

Внутри pak-файлов все файлы, содержащиеся в папке «Языки», могут быть переведены напрямую, за исключением dialog_recording_list.xml и ai_dialog_recording_list.xml. Эти два файла используются диалоговой системой и требуют дальнейшего пояснения.

g_language Переменную консоли можно использовать для загрузки определенного языка, адрес которого указан в имени файла языкового пакета (пример: g_language = немецкий для German.pak).

Списки записей диалогов, а также переведенный текст загружаются и обрабатываются классом LocalizationManager. Убедитесь, что новые файлы правильно загружены в CSystem::OpenLanguagePak() функция.

Обратная совместимость

Из CRYENGINE 3.4.3 и далее файлы локализации перенесены из <root>/Game/Localized чтобы <root>/Localization. Также обратите внимание, что макет PAK изменился. Папка диалога с аудиофайлами находится в файле English.pak, а файлы шрифтов XML и gfx — в English_xml.pak.

Вы можете установить sys_localization_folder CVar в «Языки», чтобы использовать старую систему. В версии 3.4.3 и более поздних версиях по умолчанию установлено значение «Локализация», что позволит использовать новую структуру.

Использование

Внутри некоторых скриптов, поставляемых с SDK, вы найдете ссылки на строки локализации. Один из примеров можно найти в объекте InteractiveEntity: GameSDK/Scripts/Entities/Others/InteractiveEntity.lua

UseMessage = "@use_object",

Строка локализации для этой ссылки находится внутри: <sdk_root>\Localization\English_XML.pak\text_ui_ingame.xml

Эта таблица используется для определения строк текста, которые затем отображаются в игре. Когда игрок подходит к сущности InteractiveEntity, на экране отображается надпись «Использовать объект».

Если строка определена на альтернативных языках и игрок использует альтернативный язык, она будет отображаться как таковая.

PAK/Структура папок

Использование файлов локализации внутри файлов pak позволяет создавать несколько языковых пакетов. Например, CRYENGINE SDK поставляется с тремя языковыми пакетами: английским (по умолчанию), немецким и корейским. Структура этих пак-файлов одинакова для каждого языка.

Однако в целях тестирования вам не обязательно использовать файлы .pak. Вы можете поместить файлы .xml, например, в основную папку локализации, и движок будет читать их по умолчанию (аналогично извлечению объектов из pak-файлов, движок будет отдавать приоритет внешнему контенту).

Если вы используете не pak-файлы, а XML-файлы в структуре папок, вам необходимо скопировать файлы выбранного языка в корневую папку (не Localization/<language>), пример: <root>/Localization/text_ui_warnings.xml

Перевод разговорного текста

Поскольку упомянутые выше файлы XML содержат весь текст, произнесенный в игре, они могут быть очень большими, и их лучше всего просматривать в программном обеспечении для работы с электронными таблицами, например Excel. Внутри файлов каждая строка представляет предложения, произнесенные персонажем. Предложения, произнесенные разными персонажами, можно составить в диалог с помощью Редактор диалогов* в качестве дополнительного шага для дальнейшего использования в сценах Track View или блок-графах.

AUDIO_FILENAME ряд, который еще называют звуковая клавиша, — уникальный идентификатор произнесенных предложений. Он напрямую ссылается на аудиофайл в папке диалога, при этом папка «Языки» и расширение файла пропускаются. Эту звуковую клавишу можно скопировать в редактор диалогов или любое звуковое поле диалога, поскольку это допустимое имя звука. Для каждой строки, указанной в таблице XML, необходимы два разных файла, которые автоматически загружаются движком; один необязательный и один обязательный.

  • .FSQ — Этот файл содержит данные лицевой анимации, примененные к говорящему персонажу. Его необходимо создать в редакторе лиц, в зависимости от источника звука. Для ускорения процесса перевода эти файлы можно взять за основу для синхронизации губ и перенести без каких-либо изменений. Строки диалога, произносимые за кадром, не нуждаются в файле FSQ.
  • .WAV, .MP2, или .MP3 - Этот файл содержит источник звука. Его расширение должно быть последовательно только одного формата, поскольку движок позволяет настраивать механизм декодирования глобально (с помощью s_Compression консольная переменная). Например, даже если для звука используется внутреннее расширение WAV, файл MP2 будет загружен, если s_Compression установлено значение 2. В идеале все ссылки в диалогах должны указывать на файлы WAV. В этом случае можно выбрать и легко изменить выбранное сжатие.

В простейшем случае перевод аудиоданных — это всего лишь перевод аудиофайлов, содержащихся в описанной выше структуре.

Локализация текстур

CryENGINE выполняет локализацию, используя отдельные папки для каждого языка, каждая из которых имеет одинаковую структуру. Игра автоматически выбирает папку и текстуры в зависимости от настроек языка в конфигурации.

Общая настройка

  • Определите текстуры, которые необходимо перевести и локализовать.
  • Скопируйте все текстуры, которые необходимо локализовать, в соответствующую файловую структуру внутри папки. <root>\Localization папка. то есть; <root>\Localization\Textures или, если вам нужно локализовать много текстур, имитируйте ту же структуру, в которой они были раньше. то есть; <root>\Localization\Objects\Library\Props\sign. Эта папка используется для языка по умолчанию.
  • Скопируйте эту структуру папок со всеми включенными текстурами в папки других языков, которые поддерживает ваша игра. Они должны находиться за пределами обычной папки игры и включаться только во время процедуры сборки с помощью сценария сборки.
  • Обновите файлы материалов объектов, использующих локализованные текстуры, изменив путь к текстуре на местоположение в <root>\Localization папка.
  • Удалите оригинальные файлы из \Game подпапки (нужны только в том случае, если вы решите локализовать текстуры после создания ресурса).
  • Создайте файлы .psd с отдельными слоями, содержащими текст в локализованных версиях, и соответствующим образом обновите файлы .tif в отдельных папках.
  • Проверьте локализацию прямо в игре.

Тестовые настройки локализации

Чтобы протестировать локализованные версии игры, вам необходимо обновить system.cfg в корневой папке вашей сборки. Вам также необходимо скопировать локализованный .pak в подходящее место.

  • Скопируйте дополнительные языковые файлы .paks из вашей специальной папки PAK (расположение зависит от процесса сборки) в локальный <root>\Localization папка. По умолчанию уже должен быть English.pak.
  • добавить g_language="английский" на system.cfg — замените «English» на имя локализованного .pak-файла, т.е. «Турецкий» для использования файла turkish.pak.
