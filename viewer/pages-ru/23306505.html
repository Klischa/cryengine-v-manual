    Сторонние зависимости SDK

    В этом разделе перечислены все SDK, не включенные в пакет кода, с некоторыми комментариями.

    На основе этого вы можете создать список SDK, необходимых для проекта, учитывая, для каких частей вы хотите использовать предварительно скомпилированные двоичные файлы и какие части вы хотите пересобрать.

    Код, поставляемый в пакетах CRYENGINE, содержит определенные предположения о расположении сторонних SDK относительно папки кода.

    Проще всего разместить необходимые SDK в одном месте, поэтому вам не придется перенастраивать пути включения проекта и библиотеки.

    Sandbox

    Sandbox потребляет SDK из Code\SDKs папка. До версии 3.8.0 Code\Sandbox\SDKs папка также используется.

    Пересборка Sandbox не требуется как long, поскольку интерфейсы, объявленные в CryCommon, не изменяются. В этом случае вы можете использовать готовые двоичные файлы из пакета CRYENGINE SDK.
    Если этого не произойдет во время разработки, вам не потребуется пересобирать Sandbox и не нужно будет получать перечисленные здесь SDK.

    Sandbox Плагины

    Плагины Sandbox используют SDK из Code\SDKs папка. До версии 3.8.0 Code\Sandbox\SDKs папка также используется.

    Пересборка плагинов Sandbox не требуется, если вы не хотите их настроить. Вместо этого вы можете использовать готовые двоичные файлы из пакета CRYENGINE SDK.
    Если нет необходимости в настройке, вам не потребуется пересобирать плагины Sandbox и не нужно получать перечисленные здесь SDK.

    Компилятор ресурсов

    Компилятор ресурсов использует SDK из Code\SDKs папка. До версии 3.7.1 Code\Tools\SDKs папка также используется.

    Компилятор ресурсов построен на основе Code\Solutions\Pipeline.sln файл решения

    Пересборка компилятора ресурсов не требуется, если вы не хотите его настроить. Вместо этого вы можете использовать готовые двоичные файлы из пакета CRYENGINE SDK.
    Если нет необходимости в настройке, вам не потребуется пересобирать компилятор ресурсов и не нужно получать перечисленные здесь SDK.

    Плагины экспортера активов

    Плагины экспорта ресурсов используются для экспорта ресурсов для CRYENGINE из сторонних приложений, таких как Autodesk 3ds Max, Autodesk Maya, Autodesk MotionBuilder и Adobe Photoshop.

    Пересборка сторонних плагинов не требуется, если вы не хотите их настроить. Вместо этого вы можете использовать готовые двоичные файлы из пакета CRYENGINE SDK.
    Если нет необходимости в настройке, вам не придется пересобирать сторонние плагины и не нужно получать перечисленные здесь SDK.

    Использование STLport

    STLport — это реализация стандартной библиотеки шаблонов с открытым исходным кодом (STL), отличающаяся от реализации по умолчанию, поставляемой с Visual Studio.

    Использование STLport больше не рекомендуется, поскольку в Visual Studio добавлены улучшения в STL.

    Исходный код STLport включен в состав CRYENGINE SDK. Однако Visual Studio необходимо настроить для использования STLport вместо реализации STL по умолчанию, выполнив следующие действия:

    • Перейти к Инструменты/Опции в главном меню и выберите VC++ Каталоги под Проекты и решения.
    • Выбрать Платформа Win32 и добавьте путь <CRY_SDK_ROOT>\Code\SDKs\STLPORT\stlport вверху файла. Включить файлы и Файлы библиотеки список. Очень важно, чтобы путь STLport находился над путями включения и библиотеки по умолчанию Visual Studio в списке.
    • При необходимости повторите предыдущий шаг для x64 и других платформ.

    Autodesk Чешуйчатая форма

    Заголовочные файлы и библиотеки static расположены по адресу:

    • Code\SDKs\Scaleform\Include
    • Code\SDKs\Scaleform\Lib

    Каждый каталог Lib содержит библиотеки static для конфигураций выпуска, профиля и отладки.

    Для некоторых пакетов лицензирования CRYENGINE, включающих Scaleform, Crytek может напрямую предоставлять заголовки и файлы библиотеки.

    Библиотеки видео Scaleform необходимо получить непосредственно на сайте Autodesk.

    Включить/выключить Scaleform Video можно, изменив следующий оператор определения внутри файла:
    Code\CryEngine\CrySystem\Scaleform\ConfigScaleform.h:

    #define ENABLE_GFX_VIDEO

    Файлы решений

    В следующей таблице описаны различные файлы решений, поставляемые с CRYENGINE SDK.

    Начиная с версии 3.7.0 для генерации решений используется система сборки WAF.
    Проекты и решения больше не поставляются, теперь вы можете восстановить соответствующие файлы проекта с помощью WAF.
    Некоторые автономные инструменты по-прежнему используют файлы решений и проектов. В этом случае соответствующие файлы проекта и/или решения будут находиться в папке кода инструмента.

    В настоящее время невозможно создать CRYENGINE с корневым путем, содержащим пробел (например, C:\).Программные файлы\CryENGINE не сработает).

    Конфигурации компиляции

    При компиляции движка из Visual Studio вы можете выбирать между несколькими конфигурациями.

    Каждый из них по-разному влияет на производительность во время компиляции и выполнения.

    Для PS3 и PS4 во всех конфигурациях будет использоваться связь static, независимо от настроек конфигурации.

    Иногда, будучи программистом, вы работаете над определенным разделом кода движка. В этом случае вы можете совместить настройки отладки и профиля, используя конфигурацию решения.

    Используйте конфигурацию «Профиль» для проектов, над которыми вы не работаете, и конфигурацию «Отладка» для того, над которым вы работаете. Таким образом, вы получите приемлемую производительность во время выполнения, а также хорошие возможности отладки.

    Выделенный сервер

    Версии с 3.7.0 по 3.8.1: WAF не предназначен для выделенных папок, и этот раздел не применим к этим сборкам.
    Для этих версий этот раздел относится только к сборкам на основе MSBuild.

    Бинарные файлы выделенного сервера хранятся в папке bin/XX_dedicated (до версии 3.8.4: BinXX_Dedicated), где XX — платформа, на которой размещен сервер.

    Клиенты могут подключаться к серверу, размещенному на платформе, отличной от той, на которой работает клиент.

    Несмотря на то, что некоторые двоичные файлы выделенного сервера имеют то же имя, что и двоичные файлы клиента (например, CrySystem.dll), они не являются взаимозаменяемыми. Совместное использование выделенных и неспециализированных двоичных файлов поддерживается NOT.
