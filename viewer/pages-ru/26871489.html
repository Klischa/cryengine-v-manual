Тип и экземпляр GUID

Как видно в минимальная реализация компонента сущности, для каждого типа компонента должен быть указан GUID, используемый для уникальной идентификации реализации этого компонента в движке. Это сохраняется как CryGUID. Тип каждого компонента GUID определяется в его функции ReflectType, для справки см. пример минимального компонента.

В дополнение к типу GUID каждому экземпляру компонента назначается GUID. В основном это используется для внутренних целей, но также может использоваться для запроса компонентов с помощью IEntity::GetComponentByGUID. Экземпляр GUID компонента можно получить, вызвав IEntityComponent::GetGUID.

Генерация GUID

GUID можно сгенерировать из Visual Studio, перейдя в Инструменты -> Создать GUID, вызывая диалоговое окно ниже:

После открытия выберите 4. Формат реестра и нажмите Копировать. При этом сгенерированный GUID будет помещен в буфер обмена и готов к использованию в кодовой базе CRYENGINE.

События

Сущности регулярно отправляют события типа EEntityEvent, например ENTITY_EVENT_UPDATE - отправлял каждый кадр, чтобы дать компонентам возможность выполнять покадровую логику.

Компоненты могут обрабатывать события, переопределяя IEntityComponent::ProcessEvent функцию и предоставление битовой маски желаемого события в IEntityComponent::GetEventMask.

Трансформировать

Каждый компонент может содержать преобразование, поддерживающее относительное смещение содержащегося рендеринга или физической геометрии от родительского объекта. Создание и запрос компонентов

Компоненты можно создавать и запрашивать с помощью двух типов функций; помощники шаблонов и функции низкого уровня. Помощники template существуют для упрощения запросов к типу компонента, известному во время компиляции, а функции низкого уровня могут использоваться для работы с компонентами, неизвестными во время написания кода.

Мы также можем получить компоненты из типа интерфейса, предполагая, что интерфейс реализует ReflectType и добавляется в реализацию через Схема::CTypeDesc<T>::AddBase функция.

Помощники функций шаблона

Помощники template принимают один параметр template. Т предполагается, что оно получено из IEntityComponent. Это позволяет легко запрашивать и создавать компоненты интерфейса известного типа.

Функции низкого уровня

Функции низкого уровня работают с уникальными типами компонентов и GUID экземпляров и всегда возвращают IEntityComponent* который затем можно статически привести к запрошенному типу.

Свойства редактора

Часто бывает полезно также открыть свойства компонента в редакторе, чтобы упростить рабочий процесс дизайнера. Это можно сделать, отразив члены в реализации компонента. ReflectType реализации, в результате чего свойства отображаются в Свойства окно, когда выбрана сущность с компонентом:

См. пример ниже:

static void ReflectType(Schematyc::CTypeDesc<CMyComponent>& desc)
{
    /* ...Reflect GUID, set category etc... */
    // Use of multi-character literal to create a unique identifier for this member, in the scope of the component
    const uint32 id = 'floa';
    // Internal name of the property, will be visible in XML files
    const char* szInternalName = "MyParameter";
    // Human readable name, shown in the user interface
    const char* szDisplayName = "My Parameter";
    // Help text / description shown to users when they hover over the property in Editor
    const char* szDescription = "My Parameter Description";
    // Default value of the property
    const float defaultValue = 0.25f;
    desc.AddMember(&CMyComponent::m_floatValue, id, szInternalName, szDisplayName, szDescription, defaultValue);
}

Также возможно создавать группы, это достигается путем создания struct с ReflectType функцию и добавление ее экземпляра в качестве члена в компонент ReflectType функция.

Добавление компонентов к объектам

Существует три метода добавления компонента в сущность:

  1. Через Sandbox Свойства панель (см. ниже)
  2. Путем создания новой сущности Schematyc и добавления компонента (любые экземпляры этой сущности на сцене будут автоматически создавать экземпляры предопределенных компонентов)
  3. Программно с помощью IEntity интерфейс (см. ниже).

Регистрация реализации компонента

Для того, чтобы IEntity::CreateComponent<T> и IEntity::GetOrCreateComponent<T> для работы реализации компонентов должны быть зарегистрированы в реестре компонентов сущности. Кроме того, это открывает доступ к вашему компоненту пользовательскому интерфейсу Sandbox, что позволяет дизайнерам напрямую использовать ваш компонент без необходимости изменения кода.

Это достигается путем создания пакета Schematyc и регистрации в нем ваших компонентов:

static void RegisterComponents(Schematyc::IEnvRegistrar& registrar)
{
  Schematyc::CEnvRegistrationScope scope = registrar.Scope(IEntity::GetEntityScopeGUID());
  {
    Schematyc::CEnvRegistrationScope componentScope = scope.Register(SCHEMATYC_MAKE_ENV_COMPONENT(CMyComponent));
  }
}
 
gEnv->pSchematyc->GetEnvRegistry().RegisterPackage(
  stl::make_unique<Schematyc::CEnvPackage>(
    "{E44AA983-48EF-4567-A545-324AC547A354}"_cry_guid,
    "My Entity Components Package",
    "My Company Name",
    "My Description",
    [this](Schematyc::IEnvRegistrar& registrar){ RegisterComponents(registrar); });

После этого ваш компонент появится в диалоговом окне «Добавить компонент» как для выбранных объектов, так и для редактора схем.
