Оглавление

О образце

Этот пример представляет собой минимальную реализацию игры DLL, предназначенную для демонстрации того, как игровой проект может быть создан с использованием только кода C++, а не комбинации C++ с C# и/или Lua.

В образце реализовано следующее:

  • Анимированный объект — базовый объект, который с помощью свойств редактора может воспроизводить необработанную анимацию (не использует Mannequin!)
  • Environment Probe — встроенная реализация зонда среды, обычно загружаемая через Lua в проектах GameSDK и GameZero.
  • Физический объект — собственная реализация объекта, которая позволяет физизировать указанную модель как жесткий объект или объект static.

Образец делает нет реализуйте игрок, используя интерфейс IActorSystem, вместо этого для простоты примера выберите фиктивный объект игрока.

Разбивка кода

Стартап

Имейте в виду, что раздел запуска охватывает только функции запуска, редактор работает иначе через IEditorGame интерфейс.

  1. Приложение Лаунчер (см. <корень движка>/Код/Launcher/WindowsLauncher/ для примера) загружает образец игры DLL и вызывает внешний 'CreateGameStartup' функция.
  2. Пример функции CreateGameStartup в <корневой пример>/Code/Game/GameDll/Main.cpp вызывается и вызывает CGameStartup::Создать, в результате CGameStartup экземпляр создается.
  3. Приложение Launcher вызывает IGameStartup::Init, который, в свою очередь, инициализирует движок и его модули.
    • Эта функция отвечает за инициализацию Game Framework (содержится в CryAction.dll), который, в свою очередь, инициализирует движок через модуль CrySystem.
  4. Затем программа запуска вызывает IGameStartup::Беги, вызывая основной игровой цикл, который выполняется до тех пор, пока движок не выключится.
    • Эта функция в значительной степени делегирует фактический процесс обновления Интернет-игра реализация внутри игрового модуля, который, в свою очередь, вызывает IGameFramework::PreUpdate и IGameFramework::PostUpdate чтобы начать обновление движка и поток рендеринга.

Сущности

Все объекты в выборке реализуют CNativeEntityBase helper, класс, который, в свою очередь, реализует ISimpleExtension и IGameObjectExtension чтобы предоставить несколько вспомогательных методов для установки и получения свойств сущности, которыми можно манипулировать через панель свойств редактора Sandbox. В образце также реализован пользовательский IEntityPropertyHandler реализация (создается один раз для каждого класса сущностей) для обеспечения поддержки сущностей чистого C++. Без этого объектам понадобится сценарий Lua, чтобы предоставить дизайнерам свойства.

Каждое юридическое лицо зарегистрировано в <корневой пример>/Code/Game/GameDll/Game/GameFactory.cpp, внутри CGameFactory::Init функция. Регистрируемый объект может указать любое количество свойств объекта, а затем зарегистрироваться, используя CGameFactory::RegisterNativeEntity чтобы движок распознавал объект и предоставлял его разработчикам.

Пустынный игрок

«Игрок» в этом примере — это просто фиктивный объект, автоматически появляющийся в центре карты. CGameRules::OnClientConnect (вызывается вскоре после загрузки уровня). Объект не несет ответственности, за исключением ручного обновления положения камеры обзора в каждом кадре, чтобы оно соответствовало положению объекта.
