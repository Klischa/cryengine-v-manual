Обзор

За прошедшие годы CryENGINE превратился в сложное программное обеспечение, которое представляет собой сложную задачу как для новичков, так и для опытных пользователей, пытающихся понять, настроить, запустить и, возможно, расширить его. С постоянно растущим числом разработчиков и лицензиатов, разрабатывающих и использующих движок, становится необходимым реорганизовать его в расширения. Это должно позволить упростить настройку. Существующие функции могут быть отключены (по крайней мере, в некоторой степени), заменены, настроены, а также добавлены новые функции. Более того, это может предотвратить разброс кода одной функции по базовым модулям движка, чтобы реализовать все необходимые аспекты. При правильном выполнении такой рефакторинг облегчает программисту понимание системы.

Платформа расширений CryENGINE во многом основана на некоторых фундаментальных концепциях объектной модели компонентов Microsoft (COM). Платформа определяет два базовых интерфейса, которые должно реализовать каждое расширение, а именно ICryUnknown и ICryFactory. Они похожи на COM. IНеизвестно и IClassFactory. Интерфейсы служат основой для создания экземпляров расширений, позволяют приводить типы интерфейсов, а также выполнять запросы и предоставлять функциональные возможности.

Платформа использует концепцию общих указателей и реализована таким образом, чтобы обеспечить их последовательное использование, что должно помочь снизить вероятность утечек ресурсов. Кроме того, для удобства и для стимулирования рефакторинга движка в расширения предоставляется набор шаблонов C++, завернутых в несколько макросов. Это код клея эффективно реализует все базовые сервисы и регистрирует расширения в движке. Кроме того, несколько вспомогательных функций реализуют безопасное приведение типов интерфейсных указателей, запрос идентификаторов интерфейсов расширения и удобное создание экземпляров классов расширения. Следовательно, нет необходимости снова и снова писать утомительный шаблонный код, и вероятность появления ошибок значительно снижается. Пример приведен здесь. Если предоставленный связующий код неприменим, необходимо обновить интерфейсы и базовые службы. реализовано вручную.

Клиенты получают доступ к расширениям через общесистемный заводской реестр. Он позволяет искать определенные классы расширений по имени или ID и перебирать расширения, используя заданный интерфейс ID в качестве ключа.

Недавно структура была расширена, чтобы позволить расширениям предоставлять определенные внутренние объекты, которые они объединяют или состоят из них. Те, так называемые композиты сами являются расширениями; то есть они наследуют от ICryUnknown. Это позволяет повторно использовать нужные свойства, такие как информация о типе, во время выполнения для безопасного приведения и слабой связи.

GUID

Для уникальной идентификации расширений и их интерфейсов используются глобальные уникальные идентификаторы (GUID). По сути, это 128-битные числа, генерируемые каким-то алгоритмом, чтобы гарантировать, что они существуют только один раз в данной системе, например CryEngine. Без базовой языковой поддержки такая гарантия является ключом к реализации безопасного приведения типов интерфейсов расширения. Меньшие числа, такие как 32-битные целые числа, намеренно не выбирались. Очень высока вероятность того, что некоторые идентификаторы в конечном итоге будут конфликтовать из-за действительно неприятных ошибок, которые трудно отладить. Кроме того, используя GUID, мы не налагаем строгую политику создания ID. Люди могут просто использовать такие инструменты, как «Создать GUID» в Visual Studio IDE или макрос ниже, и быть уверенными, что этот ID еще не занят или не может быть (повторно) востребован в будущем. Это действительно важно для крупномасштабной разработки и лицензиатов, желающих расширить движок самостоятельно.

GUID определяются следующим образом...

struct CryGUID
{
  uint64 hipart;
  uint64 lopart;

  ...
};

typedef CryGUID CryInterfaceID;
typedef CryGUID CryClassID;

ICryUnknown

ICryUnknown предоставляет базовый интерфейс для всех расширений. В случаях, когда сделать его вершиной иерархии классов либо невозможно, либо желательно (например, сторонний код), можно применить дополнительный уровень косвенности, чтобы иметь возможность предоставлять такой код через структуру расширения. Пример того, как это сделать, можно найти здесь.

ICryUnknown объявляется следующим образом...

struct ICryUnknown
{
  CRYINTERFACE_DECLARE(ICryUnknown, 0x1000000010001000, 0x1000100000000000)

  virtual ICryFactory* GetFactory() const = 0;

protected:
  virtual void* QueryInterface(const CryInterfaceID& iid) const = 0;
  virtual void* QueryComposite(const char* name) const = 0;
};

typedef boost::shared_ptr<ICryUnknown> ICryUnknownPtr;
  • GetFactory() возвращает фабрику, с помощью которой был создан экземпляр данного объекта расширения. Используя предоставленный связующий код, эта функция имеет постоянное время выполнения.
  • QueryInterface() возвращает указатель void на запрошенный интерфейс, если расширение реализует его, или NULL в противном случае. Эта функция была намеренно объявлена как protected, чтобы обеспечить использование безопасного по типам интерфейса. семантика приведения типов. Используя предоставленный связующий код, время выполнения этой функции (в худшем случае) линейно зависит от количества поддерживаемых интерфейсов. Однако из-за деталей реализации связующего кода дополнительные внутренние вызовы функций не требуются. Генератор общего кода создает серию инструкций, сравнивающих идентификаторы интерфейсов и возвращающих правильный указатель.
  • QueryComposite() возвращает указатель void на запрошенный составной элемент, если расширение предоставляет его, или NULL в противном случае. Как и в случае с QueryInterface(), эта функция была намеренно объявлена как protected, чтобы обеспечить соблюдение типа. запрос. Время выполнения функции (в худшем случае) линейно зависит от количества открытых композитов.
  • В отличие от COM, ICryUnknown пропускает AddRef() и Release(). Подсчет ссылок реализуется неинтрузивным способом за счет использования общих указателей, возвращаемых платформой при создании экземпляров классов расширения.

Объявлено в следующем заголовочном файле платформы:

  • CryCommon/CryExtension/ICryUnknown.h

ICryFactory

ICryFactory предоставляет базовый интерфейс для создания экземпляров расширений. Объявлено следующее...

struct ICryFactory
{
  virtual const char* GetClassName() const = 0;
  virtual const CryClassID& GetClassID() const = 0;
  virtual bool ClassSupports(const CryInterfaceID& iid) const = 0;
  virtual void ClassSupports(const CryInterfaceID*& pIIDs, size_t& numIIDs) const = 0;
  virtual ICryUnknownPtr CreateClassInstance() const = 0;

protected:
  virtual ~ICryFactory() {}
};
  • GetClassName() возвращает имя класса расширения. Используя предоставленный связующий код, эта функция имеет постоянное время выполнения.
  • GetClassID() возвращает ID класса расширения. Используя предоставленный связующий код, эта функция имеет постоянное время выполнения.
  • ClassSupports(iid) возвращает true, если интерфейс с данным ID поддерживается этим классом расширения. В противном случае возвращается ложь. Используя предоставленный связующий код, время выполнения этой функции (в худшем случае) линейно зависит от количества поддерживаемых интерфейсов.
  • ClassSupports(pIIDs, numIIDs) возвращает указатель на внутренний массив идентификаторов, перечисляющий все интерфейсы, которые поддерживает этот класс расширения, а также длину указанного массива. Используя предоставленный связующий код, эта функция имеет постоянное время выполнения.
  • CreateClassInstance() динамически создает экземпляр класса расширения и возвращает на него общий указатель. Если класс расширения реализован как одноэлементный, он вернет общий указатель (static), обертывающий единственный экземпляр этого класса расширения. Используя предоставленный связующий код, эта функция имеет постоянное время выполнения, за исключением стоимости вызова конструктора для неодноэлементных расширений.
  • Деструктор был объявлен protected, чтобы предотвратить явное уничтожение со стороны клиента посредством удаления, повышения::shared_ptr<T> и т. д. Экземпляры ICryFactory существуют (как одиночные элементы) на протяжении всего времени существования любого процесса CryENGINE и не должен быть уничтожено.

Объявлено в следующем заголовочном файле платформы:

  • CryCommon/CryExtension/ICryFactory.h
ICryFactoryRegistry

ICryFactoryRegistry — это реализованный в системе интерфейс, предоставляющий клиентам возможность запрашивать расширения. Объявлено следующее...

struct ICryFactoryRegistry
{
  virtual ICryFactory* GetFactory(const char* cname) const = 0;
  virtual ICryFactory* GetFactory(const CryClassID& cid) const = 0;
  virtual void IterateFactories(const CryInterfaceID& iid, ICryFactory** pFactories, size_t& numFactories) const = 0;

protected:
  virtual ~ICryFactoryRegistry() {}
};
  • GetFactory(cname) возвращает фабрику класса расширения с заданным именем. В противном случае возвращается NULL.
  • GetFactory(cid) возвращает фабрику класса расширения с заданным ID. В противном случае возвращается NULL.
  • IterateFactory(), если pFactories != NULL, он копирует до numFactories записей указателей на фабрики расширений, поддерживающие iid. numFactories возвращает количество скопированных указателей. Если pFactories == NULL numFactories возвращает общее количество фабрик расширений, поддерживающих iid.
  • Деструктор был объявлен protected, чтобы предотвратить явное уничтожение со стороны клиента посредством удаления, повышения::shared_ptr<T> и т. д. ICryFactoryRegistry — это системный интерфейс, который существует на протяжении всего времени существования любого процесса CryEngine и не должен быть уничтожено.

Объявлено в следующем заголовочном файле платформы:

Семантика приведения интерфейса

Семантика приведения интерфейсов была реализована для обеспечения синтаксически удобного и типовобезопасного приведения интерфейсов. Синтаксис был разработан в соответствии с традиционными приведениями типов C++ и правилами const.

ICryFactory* pFactory = ...;

if (pMyExtension)
{
  // it's safe to work with pMyExtension
}

Запрос композитов

Расширения можно запросить для составных элементов следующим образом:

IMyExtensionPtr pMyExtension = ...;

ICryUnknownPtr pCompUnk = crycomposite_query(pMyExtension, "foo");

IFooPtr pComposite = cryinterface_cast<IFoo>(pCompUnk);
if (pComposite)
{
  // it's safe to work with pComposite, a composite of pMyExtention exposed as "foo" implementing IFoo
}

Обратите внимание: хотя результатом crycomposite_query() может быть NULL, это не означает, что расширение не предоставляет определенный составной элемент. Возможно, он еще не создан. Для сбора дополнительной информации запрос можно переписать следующим образом:

IMyExtensionPtr pMyExtension = ...;

bool exposed = false;
ICryUnknownPtr pCompUnk = crycomposite_query(pMyExtension, "foo", &exposed);

if (exposed)
{
  if (pCompUnk)
  {
    // "foo" exposed and created

    IFooPtr pComposite = cryinterface_cast<IFoo>(pCompUnk);
    if (pComposite)
    {
      // it's safe to work with pComposite, a composite of pMyExtention exposed as "foo" implementing IFoo
    }
  }
  else
  {
    // "foo" exposed but not yet created
  }
}
else
{
  // "foo" not exposed by pMyExtension
}

Как и в случае с составным преобразованием интерфейса, запросы также работают с необработанными указателями интерфейса. Пожалуйста, рассмотрите руководящие принципы относительно необработанных указателей интерфейса.

Указатели общего и необработанного интерфейса

Платформа была разработана и реализована для использования общих указателей и обеспечения их использования, чтобы уменьшить вероятность утечек ресурсов. Однако необработанные указатели интерфейса все еще можно получить. По этой причине необходимо соблюдать осторожность, чтобы предотвратить повторную переноску их в объекты общего указателя. Это нарушит согласованность подсчета ссылок и в конечном итоге приведет к сбоям, если исходный объект общего указателя не будет передан во время построения, чтобы можно было ссылаться на его внутренний счетчик ссылок. Лучшей практикой является использование необработанных указателей интерфейса только для временной работы с интерфейсами, а затем просто забыть о них, т. е. не сохранять их для дальнейшего использования.

Использование расширений

Работа с определенным классом расширения

Чтобы работать с определенным классом расширения, клиентам необходимо знать его имя или идентификатор класса, а также поддерживаемые интерфейсы. С помощью этой информации его фабрику можно запросить из реестра, создать экземпляр и работать с ним, как показано в следующем примере...

// IMyExtension.h
#include <CryExtension/ICryUnknown.h>

struct IMyExtension : public ICryUnknown
{
  ...
};

typedef boost::shared_ptr<IMyExtension> IMyExtensionPtr;


// in client code
#include <IMyExtension.h>
#include <CryExtension/CryCreateClassInstance.h>

IMyExtensionPtr pMyExtension;

#if 0
// create extension by class name
if (CryCreateClassInstance("MyExtension", pMyExtension))
#else
// create extension by class id, guaranteed to create instance of same kind
if (CryCreateClassInstance(MAKE_CRYGUID(0x68c7f0e0c36446fe, 0x82a3bc01b54dc7bf), pMyExtension))
#endif
{
  // it's safe to work with pMyExtension
}

// verbose version of client code above
#include <IMyExtension.h>
#include <CryExtension/ICryFactory.h>
#include <CryExtension/ICryFactoryRegistry.h>

ICryFactoryRegistry* pReg = ...;

#if 0
// search extension by class name
ICryFactory* pFactory = pReg->GetFactory("MyExtension");
#else
// search extension by class id, guaranteed to yield same factory as in search by class name
ICryFactory* pFactory = pReg->GetFactory(MAKE_CRYGUID(0x68c7f0e0c36446fe, 0x82a3bc01b54dc7bf));
#endif

if (pFactory) // see comment below <1>
{
  ICryUnknownPtr pUnk = pFactory->CreateClassInstance();
  IMyExtensionPtr pMyExtension = cryinterface_cast<IMyExtension>(pUnk);
  if (pMyExtension)
  {
    // it's safe to work with pMyExtension
  }
}

В качестве оптимизации вы можете улучшить проверку if <1> следующим образом...

if (pFactory && pFactory->ClassSupports(cryiidof<IMyExtension>()))
{
  ...

Изменение оператора if, как показано, проверит поддержку интерфейса перед созданием экземпляра класса расширения, предотвращая потенциально дорогостоящее создание и уничтожение расширений, несовместимых с данным интерфейсом.

Без использования клеевого кода

Если по какой-либо причине использование связующего кода нежелательно и неприменимо, расширения можно реализовать следующим образом. Рекомендуется реализовать ICryUnknown и ICryFactory так, чтобы их стоимость времени выполнения была равна стоимости, предоставляемой связующим кодом (как описано в документации). здесь и здесь).

///////////////////////////////////////////
// public section

// INoMacros.h
#include <CryExtension/ICryUnknown.h>

struct INoMacros : public ICryUnknown
{
  // befriend cryiidof and boost::checked_delete
  template <class T> friend const CryInterfaceID& InterfaceCastSemantics::cryiidof();
  template <class T> friend void boost::checked_delete(T* x);
protected:
  virtual ~INoMacros() {}

private:
  // It's very important that this static function is implemented for each interface!
  // Otherwise the consistency of cryinterface_cast<T>() is compromised because
  // cryiidof<T>() = cryiidof<baseof<T>>() {baseof<T> = ICryUnknown in most cases}
  static const CryInterfaceID& IID()
  {
    static const CryInterfaceID iid = {0xd0fda1427dee4cceull, 0x88ff91b6b7be2a1full};
    return iid;
  }

public:
  virtual void TellMeWhyIDontLikeMacros() = 0;
};

typedef boost::shared_ptr<INoMacros> INoMacrosPtr;

///////////////////////////////////////////
// private section not visible to client

// NoMacros.cpp
//
// This is just an exemplary implementation!
// For brevity the whole implementation is packed into this cpp file.

#include <INoMacros.h>
#include <CryExtension/ICryFactory.h>
#include <CryExtension/Impl/RegFactoryNode.h>

// implement factory first
class CNoMacrosFactory : public ICryFactory
{
  // ICryFactory
public:
  virtual const char* GetClassName() const
  {
    return "NoMacros";
  }
  virtual const CryClassID& GetClassID() const
  {
    static const CryClassID cid = {0xa4550317690145c1ull, 0xa7eb5d85403dfad4ull};
    return cid;
  }
  virtual bool ClassSupports(const CryInterfaceID& iid) const
  {
    return iid == cryiidof<ICryUnknown>() || iid == cryiidof<INoMacros>();
  }
  virtual void ClassSupports(const CryInterfaceID*& pIIDs, size_t& numIIDs) const
  {
    static const CryInterfaceID iids[2] = {cryiidof<ICryUnknown>(), cryiidof<INoMacros>()};
    pIIDs = iids;
    numIIDs = 2;
  }
  virtual ICryUnknownPtr CreateClassInstance() const;

public:
  static CNoMacrosFactory& Access()
  {
    return s_factory;
  }

private:
  CNoMacrosFactory() {}
  ~CNoMacrosFactory() {}

private:
  static CNoMacrosFactory s_factory;
};

CNoMacrosFactory CNoMacrosFactory::s_factory;

// implement extension class
class CNoMacros : public INoMacros
{
  // ICryUnknown
public:
  virtual ICryFactory* GetFactory() const
  {
    return &CNoMacrosFactory::Access();
  };

  // befriend boost::checked_delete
  // only needed to be able to create initial shared_ptr<CNoMacros>
  // so we don't lose type info for debugging (i.e. inspecting shared_ptr)
  template <class T> friend void boost::checked_delete(T* x);

protected:
  virtual void* QueryInterface(const CryInterfaceID& iid) const
  {
    if (iid == cryiidof<ICryUnknown>())
      return (void*) (ICryUnknown*) this;
    else if (iid == cryiidof<INoMacros>())
      return (void*) (INoMacros*) this;
    else
      return 0;
  }

  virtual void* QueryComposite(const char* name) const
  {
    return 0;
  }

  // INoMacros
public:
  virtual void TellMeWhyIDontLikeMacros()
  {
    printf("Woohoo, no macros...\n");
  }

  CNoMacros() {}

protected:
  virtual ~CNoMacros() {}
};

// implement factory's CreateClassInstance method now that extension class is fully visible to compiler
ICryUnknownPtr CNoMacrosFactory::CreateClassInstance() const
{
  boost::shared_ptr<CNoMacros> p(new CDontLikeMacros);
  return ICryUnknownPtr(*static_cast<boost::shared_ptr<ICryUnknown>*>(static_cast<void*>(&p)));
}

// register extension
static SRegFactoryNode g_noMacrosFactory(&CNoMacrosFactory::Access());

Если ICryUnknown не может быть базой класса расширения

Бывают случаи, когда сделать ICryUnknown базой вашего класса расширения невозможно. Примерами являются устаревшие базы кода, которые не следует трогать, а также сторонний код, к которому у вас может не быть полного доступа к исходному коду или его изменение практически невозможно. Тем не менее, эти базы кода, безусловно, предоставляют множество функций, которые очень хорошо подходят для расширения движка (например, воспроизведение видео, воспроизведение флэш-памяти и т. д.). Чтобы стимулировать рефакторинг в таких случаях, следующий пример демонстрирует, как дополнительный уровень косвенности может помочь заставить его работать.

///////////////////////////////////////////

Пользовательское включение и исключение расширений

Чтобы упростить настройку, CryEngine предоставляет глобальный заголовок «определения расширения», очень похожий на CryCommon/ProjectDefines.h, который автоматически включается во все модули через platform.h. В нем разработчики расширений указывают #define, в который они оборачивают свой код реализации расширения. Таким образом, пользователи могут легко комментировать расширения, которые им не интересны, тем самым исключая неиспользуемый код расширения из своей сборки. Заголовки интерфейса не должны подвергаться воздействию #ifdef, чтобы клиентский код компилировался в любом случае.

///////////////////////////////////////////
// public section

// IMyExtension.h
#include <CryExtension/ICryUnknown.h>

struct IMyExtension : public ICryUnknown
{
  ...
};

typedef boost::shared_ptr<IMyExtension> IMyExtensionPtr;

// ExtensionDefines.h
...
#define INCLUDE_MYEXTENSION
...

///////////////////////////////////////////
// private section not visible to client

// MyExtension.h
#if defined(INCLUDE_MYEXTENSION)

#include <IMyExtension.h>
#include <CryExtension/Impl/ClassWeaver.h>

class CMyExtension : public IMyExtension
{
  ...
};

#endif // #if defined(INCLUDE_MYEXTENSION)

// MyExtension.cpp
#if defined(INCLUDE_MYEXTENSION)

#include "MyExtension.h"

CRYREGISTER_CLASS(CMyExtension)

...

#endif // #if defined(INCLUDE_MYEXTENSION)
