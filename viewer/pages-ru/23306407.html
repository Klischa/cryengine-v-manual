Обзор

В этом уроке вы узнаете, как происходит чтение и запись файлов с помощью CryPak.

После завершения этого руководства вы сможете добавлять новые файлы в свой проект, читать файлы из файловой системы и архивов pak, а также записывать файлы в файловую систему.

Подготовка

Прежде чем вы сможете начать, вам понадобится файл, который будет добавлен в pak-архив. Для простоты создайте текстовый файл с именем ExampleText.txt и напишите в него следующий текст:

Образец был прочитан из архива pak.

На следующем шаге создайте новую подпапку с именем Примеры внутри GameSDK и добавьте в него файл: <root>\GameSDK\Examples\ExampleText.txt

Теперь используйте 7za.exe, который находится в <root>\Tools чтобы создать новый архив под названием «Examples.pak» внутри GameSDK. Этот архив будет содержать Examples\ExampleText.txt только. Альтернативно, вы также можете использовать Устаревший менеджер PAK.

..\Tools\7za.exe a -tzip -r -mx0 Examples.pak Examples

В этом туториале демонстрируются два разных метода загрузки файлов — либо из pak-архива, либо напрямую из файловой системы.

Чтобы проверить, какой файл загружен, в примере используется содержимое текстового файла. Следовательно, измените текущий текст внутри <root>\GameSDK\Examples\ExampleText.txt к чему-то другому, чем раньше:

Образец был прочитан из файловой системы

Теперь есть два разных текстовых файла с одинаковым путем назначения: один хранится непосредственно в файловой системе, другой вложен в архив.

CryPak способен найти оба экземпляра в зависимости от pakPriority.

Значение по умолчанию pakPriority зависит от настроек конфигурации вашей сборки, но его также можно изменить вручную, назначив 0, 1, 2 или 3 в квар sys_PakPriority.

enum EPakPriority
{
    ePakPriorityFileFirst = 0,
    ePakPriorityPakFirst  = 1,
    ePakPriorityPakOnly   = 2,
    ePakPriorityFileFirstModsOnly = 3,
};
О приоритетах папок

Основная причина добавления нового pak-файла в GameSDK в этом примере потому, что здесь гарантированно загружаются все файлы pak.

Порядок загрузки пака:

  1. GameSDK: корень\GameSDK\*.pak
  2. Двигатель: корень\Двигатель\
    1. Engine.pak
    2. ShaderCache.pak
    3. ShaderCacheStartup.pak
    4. Шейдеры.пак
    5. ShadersBin.pak
  3. Моды: корень\Моды\MyMod\GameSDK\*.pak (если вы запускаете игру с аргументом команды -мод "MyMod")

Порядок поиска пака:

  1. Моды (в случае, если добавлено более одной папки мода, они будут проверены в обратном порядке по мере добавления)
  2. Двигатель
  3. GameSDK

Чтение файлов с помощью CryPak

Модуль CrySystem инициализирует CryPak и обеспечивает доступ к файлам pak.

Полная исходная информация

Если быть точным, то это происходит в CSystem::Init когда вызываются следующие функции:

  • InitFileSystem(startupParams.pGameStartup);
  • InitFileSystem_LoadEngineFolders();

Это хорошо, поскольку гарантирует, что файлы pak будут доступны из кода игры в любое время. Хорошее место, чтобы продемонстрировать это, находится в начале CGame::Init внутри Game.cpp.

Давайте напишем несколько строк кода для чтения информации ExampleText.txt, который был создан выше.

    char* fileContent = NULL;
    if (!ReadFromExampleFile(&fileContent))
    {
        CryWarning(VALIDATOR_MODULE_SYSTEM, VALIDATOR_WARNING, "ReadFromExampleFile() failed");
    }
    else
    {
        CryLogAlways("ExampleText contains %s", fileContent);
        [...] // this line will be added later on
    }
  • fileContent это пространство в памяти, содержащее сообщение, прочитанное изнутри ExampleText.txt если ReadFromExampleFile() прошел успешно.
  • ReadFromExampleFile() еще не реализован, но будет обрабатывать чтение файла и его содержимого. Возврат правда в случае успеха, в противном случае ложный.
bool ReadFromExampleFile(char** fileContent)
{
    CCryFile file;
    size_t fileSize = 0;
    const char* filename = "examples/exampletext.txt";

    [...]
}
  • файл типа CCryFile можно использовать CryPak для доступа к файлам непосредственно из файловой системы или из pak-архива.
  • fileSize будет использоваться для определения конца сообщения, поскольку чтение не заканчивается нулевым символом '\0'.
  • имя файла - без учета регистра - указывает путь к загружаемому файлу.
    char str[1024];
    if (!file.Open(filename, "r"))
    {
        sprintf(str, "Can't open file, (%s)", filename);
        CryWarning(VALIDATOR_MODULE_SYSTEM, VALIDATOR_WARNING, "%s", str);
        return false;
    }
  • Открыть() вызовет это CryPak ищет файл, указанный имя файла.
  • Режим доступа к файлам "r" указывает, что будет прочитан простой текстовый файл. В случае чтения двоичного файла используйте "рб".
    fileSize = file.GetLength();
    if (fileSize <= 0)
    {
        sprintf(str, "File is empty, (%s)", filename);
        CryWarning(VALIDATOR_MODULE_SYSTEM, VALIDATOR_WARNING, "%s", str);
        return false;
    }

    char* content = new char[fileSize + 1];
    content[fileSize] = '\0';

    if (file.ReadRaw(content, fileSize) != fileSize)
    {
        delete[] content;
        sprintf(str, "Can't read file, (%s)", filename);
        CryWarning(VALIDATOR_MODULE_SYSTEM, VALIDATOR_WARNING, "%s", str);
        return false;
    }
  • содержание — это локальный указатель на массив char в памяти, который инициализируется длиной, возвращаемой функцией GetLength() и дополнительный нулевой символ.
  • ReadRaw наполняет содержание с информацией, считанной из текстового файла. В случае сбоя выделенная память содержание освобожден.
    file.Close();    

    *fileContent = content;
    return true;

Наконец, мы закрываем дескриптор файла и убеждаемся, что локально созданные данные можно использовать вне функции, установив параметр fileContent указатель и вернуть истину так как чтение прошло успешно.

В нашем примере вызывающий абонент ReadFromExampleFile() отвечает за освобождение кучи памяти, выделенной для хранения данных из текстового файла. Добавлять удалить [] fileContent; после того, как информация была использована.

Если вы запустите игру сейчас, вы можете проверить, сработало ли чтение, проверив Game.log.

Полный код (чтение файла)

    char* fileContent = NULL;
    if (!ReadFromExampleFile(&fileContent))
    {
        CryWarning(VALIDATOR_MODULE_SYSTEM, VALIDATOR_WARNING, "ReadFromExampleFile() failed");
    }
    else
    {
        CryLogAlways("ExampleText contains %s", fileContent);
        delete[] fileContent;
    }
bool ReadFromExampleFile(char** fileContent)
{
    CCryFile file;
    size_t fileSize = 0;
    const char* filename = "examples/exampletext.txt";

    char str[1024];
    if (!file.Open(filename, "r"))
    {
        sprintf(str, "Can't open file, (%s)", filename);
        CryWarning(VALIDATOR_MODULE_SYSTEM, VALIDATOR_WARNING, "%s", str);
        return false;
    }

    fileSize = file.GetLength();
    if (fileSize <= 0)
    {
        sprintf(str, "File is empty, (%s)", filename);
        CryWarning(VALIDATOR_MODULE_SYSTEM, VALIDATOR_WARNING, "%s", str);
        return false;
    }

    char* content = new char[fileSize + 1];
    content[fileSize] = '\0';

    if (file.ReadRaw(content, fileSize) != fileSize)
    {
        delete[] content;
        sprintf(str, "Can't read file, (%s)", filename);
        CryWarning(VALIDATOR_MODULE_SYSTEM, VALIDATOR_WARNING, "%s", str);
        return false;
    }

    file.Close();

    *fileContent = content;
    return true;
 }

Запись файлов с помощью CryPak

CCryFile::Записать всегда пишет в файловую систему и никогда в архивы. Если вы хотите записывать файлы в сжатые или несжатые архивы, пропустите эту главу.

Запись файла аналогична чтению. Сначала давайте вызовем функцию, которая будет реализована на следующем шаге.

    char* newContent = "File has been modified";
    bool appendToFile = false;
    if (!WriteToExampleFile(newContent, strlen(newContent), appendToFile))
    {
        CryWarning(VALIDATOR_MODULE_SYSTEM, VALIDATOR_WARNING, "WriteToExampleFile() failed");
    }
    else
    {
        CryLogAlways("Text has been written to file, %s", newContent);
    }
  • WriteToExampleFile() собирается выполнить логику записи и принимает следующие три параметра
    • newContent содержит текст, который будет записан в ExampleText.txt в файловой системе.
    • стрлен(newContent) возвращает размер newContent. Собственно количество байт, которое надо записать.
    • appendToFile указывает, если newContent добавлю(правда) на уже существующий или если файл должен быть сначала удален (ложный).

Что касается чтения файлов, структура WriteToExampleFile() выглядит следующим образом:

bool WriteToExampleFile(char* text, int bytes, bool appendToFile)
{
    CCryFile file;
    const char* filename = "examples/exampletext.txt";

    assert(bytes > 0);
    char* mode = NULL;
    if (appendToFile)
        mode = "a";
    else
        mode = "w";

    char str[1024];
    if (!file.Open(filename, mode))
    {
        sprintf(str, "Can't open file, (%s)", filename);
        CryWarning(VALIDATOR_MODULE_SYSTEM, VALIDATOR_WARNING, "%s", str);
        return false;
    }

  [...]

    file.Close();
    return true;
}
  • режим указывает, должен ли текст быть добавлен к существующему файлу или сначала он должен быть удален. "ш" = запись в чистый файл, "а" = добавить к существующему файлу.
    int bytesWritten = file.Write(text, bytes);
    assert(bytesWritten == bytes);

    if (bytesWritten == 0)
    {
        sprintf(str, "Can't write to file, (%s)", filename);
        CryWarning(VALIDATOR_MODULE_SYSTEM, VALIDATOR_WARNING, "%s", str);
        return false;
    }
  • bytesWritten сообщает, сколько байт на самом деле было записано, вызывая Запись() функция.

Изменение пакетов с помощью CryArchive

В следующем руководстве объясняется, как создаются новые файлы pak во время выполнения. Кроме того, в примере показано, как файлы добавляются, обновляются и удаляются из архива.

В примере кода мы намеренно используем USER папка вместо GameSDK. Pak-файлы внутри папки USER не загружаются по умолчанию при запуске, тогда как все файлы *.pak внутри GameSDK будут загружены и, таким образом, помечены как Только чтение.

    string pakFilename = PathUtil::AddSlash("%USER%") + "Examples.pak";
    const char* filename = "Examples/ExampleText.txt";
    char* text = "File has been modified by CryArchive";
    unsigned length = strlen(text);
    
    _smart_ptr<ICryArchive> pCryArchive = gEnv->pCryPak->OpenArchive(pakFilename.c_str(), ICryArchive::FLAGS_RELATIVE_PATHS_ONLY | ICryArchive::FLAGS_CREATE_NEW);
    if (pCryArchive)
    {
        pCryArchive->UpdateFile(filename, text, length, ICryArchive::METHOD_STORE, 0);
    }
  • UpdateFile() изменяет существующий файл внутри pak-архива или создает новый, если он не существует.
  • ICryArchive::FLAGS_CREATE_NEW будет следить за тем, чтобы pak-файл создавался с нуля при каждом запуске. Если вы хотите добавить файлы позже, вам придется удалить этот флаг.
  • Удаление файлов и папок из архива осуществляется с помощью одной из команд. RemoveFile(), RemoveDir() или RemoveAll() вместо UpdateFile().
