Обзор

CRYENGINE имеет собственный строковый класс с подсчетом ссылок. CryString (заявлено в CryString.h), который является заменой STL std::string. Ему всегда следует отдавать предпочтение перед std::string. Для удобства, строка используется как typedef для CryString.

Как использовать строки в качестве ключевых значений для контейнеров STL

Следующий код показывает хорошее (эффективное) и плохое использование:

const char *szKey= "Test";

map< string, int >::const_iterator iter = m_values.find( CONST_TEMP_STRING( szKey ) );   // Good way

map< string, int >::const_iterator iter = m_values.find( szKey );  // Bad way, don't do it like this!

Используя предложенный метод, вы избегаете выделения/освобождения и копирования временного строкового объекта. Это общая проблема для большинства строковых классов. Просто используя макрос CONST_TEMP_STRING, мы обманываем класс строк, чтобы он использовал указатель напрямую, не освобождая данные после этого.

Дополнительные советы по использованию

  • Не используйте станд::строка или станд::wstring, просто строка и строка и никогда не включайте стандартный заголовок строки <string>.
  • Используйте c_str() метод для доступа к содержимому строки.
  • Никогда не изменяйте память, возвращаемую c_str() метод, поскольку строки подсчитываются по ссылкам и это может повлиять на неправильный экземпляр строки.
  • Не передавайте строки через абстрактные интерфейсы; все интерфейсы должны использовать const char* в методах интерфейса.
  • CryString имеет комбинированный интерфейс std::string и MFC CString, поэтому оба типа интерфейса можно использовать для операций со строками.
  • Избегайте выполнения большого количества строковых операций во время выполнения, поскольку они часто вызывают перераспределение памяти.
  • Для строк фиксированного размера (например, 256 символов) используйте CryFixedStringT (должен быть предпочтительнее массивов static char).
