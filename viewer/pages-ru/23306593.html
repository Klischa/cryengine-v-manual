Обзор

Script Entity может сериализовать значение в сети. Этот подход реализуется путем установки значений на сервере и их автоматической синхронизации на всех клиентах. Также возможно вызывать функции клиент/сервер RMI.

Имейте в виду следующие ограничения:

  • Нет уведомления об изменении сериализованного значения.
  • Управляется только сервером, нет возможности установить значения для клиента.

Предоставление объекта сценария CryNetwork

Функция ScriptBind Сеть.Expose() требуется вызвать для определения сетевых функций объекта.

Следующий код демонстрирует, как вызвать Сеть.Expose() функция. Его следует писать внутри сценария .lua в глобальном пространстве, а не в функции.

Net.Expose {
  Class = DeathMatch,
  ClientMethods = {
    ClVictory              = { RELIABLE_ORDERED, POST_ATTACH, ENTITYID, },
    ClNoWinner             = { RELIABLE_ORDERED, POST_ATTACH, },

    ClClientConnect        = { RELIABLE_UNORDERED, POST_ATTACH, STRING, BOOL },
    ClClientDisconnect     = { RELIABLE_UNORDERED, POST_ATTACH, STRING, },
    ClClientEnteredGame    = { RELIABLE_UNORDERED, POST_ATTACH, STRING, },
  },
  ServerMethods = {
    RequestRevive          = { RELIABLE_UNORDERED, POST_ATTACH, ENTITYID, },
    RequestSpectatorTarget = { RELIABLE_UNORDERED, POST_ATTACH, ENTITYID, INT8 },
  },
  ServerProperties = {
    busy   = BOOL,
  },
};
RMI функции

Функция RMI должна быть определена в таблицах ClientMethods и ServerMethods, передаваемых в Сеть.Expose() функция.

Эти дескрипторы управляют тем, как RMI планируется в данных сериализации.

Функции можно объявить следующим образом:

function DeathMatch.Client:ClClientConnect(name, reconnect)

Затем его можно вызвать как один из трех следующих примеров:

self.allClients:ClVictory( winningPlayerId );

self.otherClients:ClClientConnect( channelId, player:GetName(), reconnect );

self.onClient:ClClientConnect( channelId, player:GetName(), reconnect );

Более подробную информацию о функциях RMI можно найти в технической документации. RMI Функции.

Примечание. Сеть сценариев не имеет эквивалента RMI зависимых объектов.

ServerProperties

Внутри таблицы сущностей должна быть таблица ServerProperties, в которой указано, какое свойство необходимо синхронизировать. Здесь также можно определить тип переменной значения.

Предоставление объекта сценария CryAction с помощью GameObject

Также необходимо создать GameObject в CryAction и привязать этот новый GameObject к сеансу сетевой игры. В идеале следующий код должен быть помещен в файл OnSpawn() функция.

CryAction.CreateGameObjectForEntity(self.id);
CryAction.BindGameObjectToNetwork(self.id);

Также можно указать GameObject получать обратный вызов обновления для каждого кадра.

Следующий вызов функции CryAction активирует обратный вызов обновления:

CryAction.ForceGameObjectUpdate(self.id, true);

Объект сценария получит OnUpdate обратный вызов функции своей таблицы Server.

function Door.Server:OnUpdate(frameTime)
-- some code
end

Будьте очень осторожны при добавлении кода обратного вызова обновления в объект сценария, поскольку он может легко снизить производительность игры.
