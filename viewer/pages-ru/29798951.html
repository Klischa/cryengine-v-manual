Обзор

Универсальная система запросов (UQS) — это система для выполнения пространственных запросов в трехмерном мире.

Короче говоря, UQS позволяет запрашивать элементы, ранжировать и фильтровать их, а затем возвращать N лучших результатов.

Предполагается, что со временем UQS заменит систему тактических очков (TPS) CryAISystem.

Особенности

В TPS запросы ориентированы на так называемые «тактические точки», которые, по сути, представляют собой позиции в мире, специфичные для объектной модели CryAISystem.

UQS продолжает поддерживать эту концепцию, но в то же время расширяет идею «тактических точек» и их контекста, освобождаясь от некоторых их ограничений, а также предоставляя новые функции. В конечном счете, UQS стремится стать универсальной системой, которая хорошо подходит для любого нового игрового проекта с очень специфическими требованиями к пространственному мышлению.

Некоторые из основных функций, для которых UQS был специально разработан:

  • Поддержка не только 3D-точек, например:
    • Сферы: найдите место для приземления, где достаточно места.
    • Сущности: выберите, какого игрока атаковать.
    • Боевые слоты: боевой менеджер выбирает слот вокруг игрока, откуда он будет атаковать.
    • Треугольники NavMesh: область для исследования.
    • Области: AI Режиссер выбирает, какую область заселить следующей.
  • Поддержка списка N кандидатов с лучшими результатами, например:
    • Полезно для заклинателей, которые могут поразить несколько целей одновременно.
    • Создайте «тепловую карту» с наиболее опасными местами, которые может увидеть AI. Затем их можно передать в систему поиска пути в качестве «подсказок», например, чтобы найти наиболее безопасный путь через территорию.
    • Запрос UQS также можно использовать в качестве предварительного «фильтра», а затем передавать результаты в некоторую узкоспециализированную систему, которая делает с ним что-то «индивидуальное».
  • Поддержка ввода значений параметров в запросы во время выполнения., а не ограничиваться жестко закодированными значениями только во время разработки.

  • Позволяет использовать собственные имена для параметров запроса. чтобы вы могли лучше описать контекст, который должен разрешить запрос, например:
    • В настоящее время слово «марионетка» жестко закодировано и означает «то, что запросило запрос».
    • Лучшими/более наводящими на размышления именами могли бы быть: «запрашивающий», «нападающий», «враждебные лица», «наблюдатели» и т. д.

  • Улучшенная отладка (и журналирование), например:
    • Какие условия были истинными/неверными.
    • Как были построены общие значения баллов.
    • Какие правила сортировки были применены.

  • Визуальная история запросов:
    • Элементы можно визуализировать с помощью встроенных средств отладки.
    • Отдельные элементы можно проверить, чтобы лучше понять, как была построена их оценка.
    • Всю историю можно сохранить и восстановить для просмотра вне запущенной игры.

  • Пользовательская «пост-проверка» для завершения запроса, например:
    • NavMesh мог измениться, пока выполнение запроса заняло пару кадров, поэтому теперь вы хотите убедиться, что результат запроса по-прежнему «действителен».

  • Резервные запросы:
    • Позволяет создавать альтернативные запросы с, возможно, меньшими ограничениями, если «основной» запрос не находит никаких элементов.

  • Цепочка запросов:
    • Используйте результат одного запроса в качестве параметров для другого запроса.

  • Полностью расширяемый на стороне игры:
    • Пользовательские типы элементов
    • Пользовательские генераторы
    • Пользовательские функции
    • Пользовательские оценщики

Основные части запроса

Запрос состоит из 4 основных частей:

  • Предметы
  • Функции
  • Генераторы
  • оценщики

Предметы: Используются для представления пространства рассуждений, над которым работает запрос. Проще говоря, запрос будет оценивать набор элементов, чтобы определить пригодность каждого элемента. Кроме того, они используются в качестве входных параметров и возвращаемых значений в функциях.

Функции: При вызове действуют как входные параметры для генераторов, вычислителей и самих функций. Кроме того, функции можно использовать для преобразования между типами элементов или для смешивания некоторой пользовательской логики перед передачей возвращаемого значения вызывающему объекту.

Генераторы: Несут ответственность за создание предметов. Их цель — создать пространство рассуждений с помощью набора элементов, которые будут оцениваться запросом. Например, генератор может создать набор точек в виде сетки.

оценщики: В наличии 2 вкуса: InstantEvaluators и DeferredEvaluators. Оба типа отвечают за «оценку» переданного им элемента. Точнее, их цель — либо присвоить предмету оценку от 0 до 1 (чтобы выразить пригодность этого предмета), либо просто отказаться от предмета, если он не соответствует определенному условию.

Разница между обоими типами оценщиков заключается в следующем:

InstantEvaluators должны немедленно вернуть результаты оценки. Они хорошо подходят для проведения быстрых вычислений. Типичным вариантом использования будет определение расстояния между двумя точками по заданному опорному расстоянию.

DeferredEvaluators могут работать с течением времени и возвращать результат после завершения обработки элемента. От них зависит, будут ли они выполнять работу с разделением по времени или переносить фактическую работу на другую систему. С точки зрения запроса важно лишь то, чтобы они периодически обновлялись, пока не дадут результат. Типичным вариантом использования будет запуск асинхронной физической рассылки между двумя точками и ожидание выполнения запроса на рассылку.

Оценка предметов

Как упоминалось выше, оценщики несут ответственность за выставление оценок по каждому пункту. Вообще говоря, каждому оценщику в запросе будет предложено оценить каждый сгенерированный элемент. Затем их баллы будут суммироваться, чтобы сформировать общий балл по этому предмету. Чтобы обеспечить немного больший контроль над индивидуальной оценкой со стороны одного оценщика, каждому оценщику присвоен вес, на который будет умножаться оценка, прежде чем она будет добавлена ​​к общему баллу.

Общая оценка элемента будет использоваться для определения того, какие элементы «N» лучше всего будут возвращены в окончательный набор результатов запроса.

    Новые возможности в CRYENGINE 5.4

    • Добавлена концепция GUID для всех элементов UQS, чтобы не полагаться на их имена.
    • Добавлена ​​концепция идентификаторов параметров в параметры генератора, функции и оценщики, чтобы больше не полагаться на их имена.
    • Добавлена ​​поддержка описания всех элементов UQS из кода для отражения в UI.
    • Добавлены вспомогательные классы, которые упрощают выполнение запроса из кода: UQS::Client::CQueryHost, UQS::Client::CQueryHostT<>.
    • Добавлена концепция преобразования результата оценки для управления результатом отдельного элемента. Этого можно достичь с помощью функции оценки и отрицания отбрасывания.
    • Добавлен вспомогательный класс для упрощения настройки UQS при использовании источника данных XML: UQS::DataSource_XML::CXMLDataSource.
    • Добавлена предварительная поддержка Schematyc, позволяющая выполнять запросы изнутри Schematyc.
    • Редактор запросов: добавлены подсказки для большинства элементов, основанные на описаниях, предоставленных программистом.
    • Инспектор истории запросов: нажатие double на исторический запрос теперь «телепортирует» камеру редактора в ближайшее положение.

    Критические изменения в версии 5.4

    Пространства имен и имена переменных в коде C++ были скорректированы для лучшего соответствия соглашениям о кодировании.

    Старые пространства имен:

    • UQS
      • клиент
        • внутренний
      • ядро
      • источник данных
      • datasource_xml
      • редактор
      • общий
      • стандартная библиотека
      • uqseditor

    Новые пространства имен:

    • UQS
      • Клиент
        • Внутренний
      • Ядро
      • DataSource
      • DataSource_XML
      • Редактор
      • Общий
      • StdLib
      • Редактор UQSE
    GUID и комментарии, определенные программистом

    Из-за введения идентификаторов GUID и комментариев, определяемых программистом, во всех элементах UQS изменился способ регистрации фабрик генераторов, функций, вычислителей и т. д. Раньше речь шла в основном о создании глобального экземпляра этой фабрики со списком параметров в качестве аргументов конструктора. Теперь все параметры объединены в struct.

    Старый способ (он больше не будет компилироваться):

    static const UQS::Client::CGeneratorFactory<CGenerator_PointsOnPureGrid> generatorFactory_PointsOnPureGrid("std::PointsOnPureGrid");

    Новый способ:

    UQS::Client::CGeneratorFactory<CGenerator_PointsOnPureGrid>::SCtorParams ctorParams;

ctorParams.szName = "std::PointsOnPureGrid";
ctorParams.guid = "498bce51-a2b9-4e77-b0f9-e127e8a5cc72"_uqs_guid;
ctorParams.szDescription =
    "Generates points on a grid.\n"
    "The grid is specified by a center, size (of one edge) and a spacing between the points.\n"
    "Notice: this generator is very limited and doesn't work well if you intend to use it for things like uneven terrain.";

static const UQS::Client::CGeneratorFactory<CGenerator_PointsOnPureGrid> generatorFactory_PointsOnPureGrid(ctorParams);

    Также возможно использовать лямбда-выражения C++11:

    static const UQS::Client::CGeneratorFactory<CGenerator_PointsOnPureGrid> generatorFactory_PointsOnPureGrid(
    []()
    {
        UQS::Client::CGeneratorFactory<CGenerator_PointsOnPureGrid>::SCtorParams ctorParams;

        ctorParams.szName = "std::PointsOnPureGrid";
        ctorParams.guid = "498bce51-a2b9-4e77-b0f9-e127e8a5cc72"_uqs_guid;
        ctorParams.szDescription =
            "Generates points on a grid.\n"
            "The grid is specified by a center, size (of one edge) and a spacing between the points.\n"
            "Notice: this generator is very limited and doesn't work well if you intend to use it for things like uneven terrain.";

        return ctorParams;
    }()
);
    UQS Стандартная библиотека
    • Тип данных Vec3 был заменен на Pos3, Ofs3 и Dir3. Функции, генераторы и оценки, использующие старый тип данных, были соответствующим образом скорректированы.
