Обзор

После загрузки геометрии в Слот, мы можем создать физический объект (представленный IPhysicalEntity интерфейс) и добавьте физическую геометрию из слотов. В результате получается физическое представление сущности, которая может взаимодействовать с миром.

Чтобы физикализовать сущность, мы можем вызвать IEntity::Физикализовать (пример содержится внутри). Это создаст физический объект для объекта указанного типа и, при необходимости, создаст физические части для отдельных или всех слотов объекта. Обратите внимание, что физикализация слотов предполагает существование физический прокси, настроенный автором в инструменте DCC.

Чтобы запросить физический объект объекта, используйте IEntity::GetPhysicalEntity.

После того, как объект физизирован, мы можем дополнительно добавить физические части для отдельных слотов объекта, вызвав IEntity::PhysicalizeSlot.

Функциональность IPhysicalEntity

После того, как сущность была физикализована, мы можем использовать IPhysicalEntity интерфейс напрямую для управления его физическим поведением. Интерфейс предоставляет, среди прочего, четыре функции, которые имеют решающее значение для взаимодействия с физикой во время выполнения:

IPhysicalEntity::SetParams

Используется для установки параметров, реализующих pe_params структура, будет поставлен в очередь и выполнен на следующем шаге, если не будет выполнен в физическом потоке с bThreadSafe установите значение true.

IPhysicalEntity::GetParams

Используется для получения параметров, реализующих pe_params структура. Это всегда будет выполняться немедленно с использованием блокировок, потенциально прерывая основной и физический потоки, пока не будет выполнено.

IPhysicalEntity::GetStatus

Используется для получения статуса объекта, реализующего структуру pe_status. Как и в случае с IPhysicalEntity::GetParams, это всегда будет выполняться немедленно с использованием блокировок.

IPhysicalEntity::Действие

Выполняет действие, реализующее pe_action структура. Как и в случае с IPhysicalEntity::SetParams это поставлено в очередь по умолчанию.

Физическое моделирование выполняется в другом потоке. Это означает, что любая попытка установки данных будет отложена до следующей синхронизации потока, если для параметра «bThreadSafe» не установлено значение true. Это можно использовать при обработке немедленных событий (таких как ENTITY_EVENT_COLLISION_IMMEDIATE), которые поступают непосредственно из физического потока, чтобы избежать постановки запроса в очередь.

Функциональность Get всегда выполняется немедленно, без очереди.

Прослушивание событий столкновения

Компоненты могут прослушивать события столкновений, регистрируемые физикой, путем обработки Cry::Entity::EEvent::PhysicsCollision (ENTITY_EVENT_COLLISION). Это событие вызывается в следующем кадре после обработки столкновения в физическом потоке и предоставляет данные через структуру EventPhysCollision с подробным описанием произошедшего столкновения.

Рейкасты

Часто бывает полезно проследить луч через физический мир, например, чтобы позволить пользователю навести указатель мыши или щелкнуть объекты в мире. Это возможно через IPhysicalWorld::RayWorldIntersection функция.

Импульсы

Импульсы могут быть вызваны на отдельных физических объектах с помощью pe_action_impulse структура.

Ходячие персонажи

Как упоминалось на родительской странице, PE_LIVING Тип физического объекта предназначен для актеров шагающего типа и специально разработан для таких игр, как Far Cry и Crysis. Физическая реализация живого существа более сложна, чем static и жестких объектов, поскольку требует настройки с помощью pe_player_dimensions и pe_player_dynamics структуры.

После этого сущность будет физикализована и начнет излучать луч на каждом шагу, чтобы проверить, находится ли игрок на земле или нет.

Отправка запросов на перемещение

Живое существо будет двигаться только тогда, когда ему будет отправлен запрос на перемещение через pe_action_move структура. Например, чтобы заставить игрока двигаться вперед:

pe_action_move moveAction;
// Apply movement request directly to velocity
moveAction.iJump = 2;
moveAction.dir = Vec3(0, 1, 0);
physicalEntity.Action(&moveAction);

После этого игрок будет двигаться вперед – как если бы скорость по прямой оси всегда была 1 м/с. Например, это можно использовать, чтобы заставить игрока прыгать и двигаться в сторону.

Получение статуса сущности

Мы можем запросить статус живого существа, используя структуру pe_status_living, в дополнение к pe_status_dynamics. Например:

pe_status_living livingStatus;
if (pPhysicalEntity->GetStatus(&livingStatus) != 0)
{
  const bool isOnGround = !livingStatus.bFlying;
  // Store the ground normal in case it is needed
  // Note that users have to check if we're on ground before using, is considered invalid in air.
  const Vec3& groundNormal = livingStatus.groundSlope;
}

// Get the player's velocity from physics
pe_status_dynamics playerDynamics;
if (pPhysicalEntity->GetStatus(&playerDynamics) != 0)
{
  const Vec3& velocity = playerDynamics.v;
}

Обратите внимание, что обработка ходячих персонажей автоматизируется компонентом «Контроллер символов» в подключаемом модуле компонентов по умолчанию, см. Плачь::DefaultComponents::CCharacterControllerComponent.
