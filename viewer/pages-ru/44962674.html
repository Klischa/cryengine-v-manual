Формат уровня изменен

Формат экспортируемых уровней изменился: пользователям придется повторно экспортировать уровни, содержащие дороги, чтобы загрузить их с помощью программы запуска на базе версии 5.3.0.

Прекращение поддержки игры DLL

Дополнительные игровые библиотеки:

С 5.3.0. мы представляем дополнительные двоичные файлы игрового кода. Это первый шаг к четкому разделению движка и игрового кода. Идея состоит в том, чтобы удалить ненужный код из базы кода и убедиться, что вашему проекту нужно поддерживать только тот код, который фактически им используется.

Устаревшие двоичные файлы игрового кода (например, GameSDK или GameZero) по-прежнему поддерживаются, но в какой-то момент они могут исчезнуть.

Плагины вместо одной игровой dll:

Код, пригодный для повторного использования, но связанный с игрой, будет перенесен в плагины (со временем). Затем ваш проект определяет, какие плагины включить. В качестве временного решения существует файлryplugin.csv, который определяет включенные в данный момент плагины. В конечном итоге это произойдет в виде зависимостей в вашем основном файле *.cryproject.

Новый порядок инициализации:

Чтобы сделать игровые библиотеки DLL необязательными, нам пришлось переместить основной игровой цикл из кода игры в CryAction. Таким образом, CryAction теперь отвечает за запуск двигателя, а также за его правильное выключение.

Это создало новые проблемы с зависимостями, которые нам пришлось решать. Имейте в виду, что какой бы модуль ни регистрировал что-либо в движке (например, прослушиватели, CVar), ему также необходимо правильно отменить регистрацию при завершении работы, чтобы предотвратить утечки и сбои. Мы считаем, что, хотя на данный момент это выглядит более хрупким, это приведет к более стабильному опыту развития в целом.

Что случилось с CEditorGame?

Это использовалось в старых двоичных файлах игр для реализации пользовательского поведения игрового кода для Sandbox. Мы перенесли все важные вещи, которые там были, на сторону движка (ничто не мешает вам повторно реализовать это в коде игры, но имейте в виду, что мы не будем поддерживать этот интерфейс в течение длительного времени).

Доступ к устаревшему коду игры изнутри движка:

Чтобы очистить интерфейсы и сделать движок менее зависимым от устаревшего игрового кода, мы удалили указатель gEnv->pGame. Как правило, доступ к IGame должен быть доступен (если вообще возможен) только внутри CryAction (GetIGame()).

Имейте в виду, что в случае отсутствия устаревшей игровой библиотеки dll с этого момента будет возвращаться nullptr. Мы переместим соответствующие интерфейсы, как только это станет возможным (чтобы еще больше ограничить доступ).

Плагин сущностей по умолчанию

Для дальнейшего отказа от сущностей на основе Lua мы теперь предоставляем модуль CryDefaultEntities. Он содержит несколько написанных на C++ сущностей, использующих новую систему компонентов сущностей, предназначенную для замены некоторых конкретных реализаций GameSDK, ранее реализованных в Lua.

Важно знать о новых сущностях, поскольку они нет обратная совместимость на более старых уровнях используются сущности Lua. Если вам все еще нужна сущность на основе Lua, просто используйте существующий скрипт Lua, и он override получит более новую версию.

Система компонентов сущности

Новая система компонентов сущностей задумана как будущая замена системы игровых объектов. Это означает, что любые новые расширения сущностей будут записаны как компоненты, которые затем можно будет присоединить к любой сущности.

Хотя в будущем система компонентов сущностей полностью заменит игровые объекты, игровые объекты еще не удалены из соображений совместимости с устаревшими версиями.

Переработка свойств сущности

С новой системой компонентов сущностей происходит переработка способа хранения свойств сущностей. Предыдущие реализации IEntityAttribute и IEntityPropertyHandler были удалены, поэтому их больше нельзя использовать с движком.

Чтобы перенести свойства, реализуйте интерфейс IEntityPropertyGroup и верните указатель на экземпляр в функции IEntityComponent::GetPropertyGroup вашего компонента сущности или расширения игрового объекта.

В качестве примера:

class CExampleComponent : public IEntityComponent, public IEntityPropertyGroup
{
    CRY_ENTITY_COMPONENT_INTERFACE_AND_CLASS(CExampleComponent, "ExampleComponent", 0x26AA3CDD57584144, 0xA46E31FE08554C36);
public:
    // IEntityComponent
    virtual struct IEntityPropertyGroup* GetPropertyGroup() override { return this; }
    // ~IEntityComponent
 
    // IEntityPropertyGroup
    virtual const char* GetLabel() const override { return "Example Component Properties"; }
 
    virtual void Serialize(Serialization::IArchive& archive) override
    {
        archive(m_myBoolean, "myBoolean", "MyBoolean");
        archive(m_myInteger, "myInteger", "MyInteger");
 
        if (archive.isInput())
        {
            CryLogAlways("Properties changed, bool is %s, int %i", m_myBoolean ? "true" : "false", m_myInteger);
        }
    }
    // ~IEntityPropertyGroup
 
protected:
    bool m_myBoolean;
    int m_myInteger;
};
 
CRYREGISTER_CLASS(CExampleComponent);

CryAction

  • Инициализация представления ранее выполнялась при загрузке уровня — теперь автоматизирована в IGameObject::CaptureView — никаких изменений кода не требуется.
  • Инициализация карты действий по умолчанию была перенесена с уровня загрузки CryAction на GameSDK — проекты, основанные на GameSDK, должны будут реплицировать это в CGame::LoadActionmaps.

С#

  • Требование иметь отдельную игровую библиотеку C++ было удалено — плагины C# теперь могут работать независимо.
  • Проекты GameMono и MonoLauncher удалены, так как они больше не нужны.
  • Компоненты сущностей теперь должны реализовывать интерфейс EntityComponent.
  • Для регистрации объектам необходимо реализовать EntityComponent и использовать атрибут EntityClass.
  • Интерфейс ICryPlugin изменился
  • Для повышения производительности были введены новые математические классы — старые версии по-прежнему будут работать, но для каждой отдельной математической операции потребуется вызов virtual C++.
