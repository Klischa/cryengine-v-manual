Обзор

Ниже приведены некоторые важные изменения кода и данных, о которых вам следует знать при переходе на версию 3.8.4.

Эмиссионные материалы

В рамках нашего продолжающегося перехода к физическим источникам света излучающие материалы получили некоторые обновления, чтобы упростить их настройку и улучшить согласованность с освещением сцены:

  • Эмиссионное освещение теперь всегда является аддитивным и добавляется поверх рассеянного и зеркального освещения поверхности.
  • Интенсивность излучения теперь указывается в килонитах (ккд/м2).
  • Цвет излучения действует как множитель для карты излучения и не оказывает никакого эффекта, если интенсивность излучения равна 0.
  • Новый отдельный слот текстуры для карты эмиттанса; слот для диффузии и декали больше не используется для измерения излучательной способности
  • Новый гамма-контроль для карты эмиттанса, позволяющий расширять диапазон значений.
  • Преобразование времени загрузки для базовой обратной совместимости:
    • Если свечение было включено, карта диффузии копируется в слот эмиттанса во время загрузки.
    • Существующая интенсивность свечения преобразуется в новые физические единицы.

Настраиваемые папки двоичного вывода

Начиная с версии 3.8.4, расположение папки двоичных выходных данных проекта можно изменить. До версии 3.8.4 местоположение было фиксированным, например. чтобы <корень>/Bin64 для Windows х64 строит.

Кроме того, при компиляции кода движка с использованием WAF все необходимые сторонние библиотеки будут скопированы в папку двоичных выходных данных как часть этапа сборки.

Окончательное расположение двоичного вывода можно изменить с помощью cry_waf.exe -> Параметры WAF -> Выходная папка например out_folder_win64 -> корзина/win_x64

Была добавлена новая переменная параметров «output_extension_<configuration>», позволяющая пользователям выбирать разные выходные папки для разных конфигураций, например. выиграть x64 | выпуск -> bin/win_x64_release

К конечному назначению выходной папки применяются следующие правила:

  1. Путь двоичного вывода указан относительно корневого пути CryEngine. Путь может быть самим корневым путем.
  2. Корневой путь определяется наличием папки с названием «Engine» или «engine».

Экспериментальная поддержка компиляторов Visual Studio 2013 и 2015 гг.

Многие из наших клиентов просили улучшить поддержку других наборов инструментов компилятора Windows, а не только Visual Studio 2012.
Раньше можно было заставить WAF использовать эти цепочки инструментов, но для того, чтобы это заработало, требовались изменения в скриптах WAF.

В версии 3.8.4 мы улучшили поддержку компиляторов Visual Studio 2013 и 2015. Основной поддерживаемой цепочкой инструментов компилятора для Windows (для 3.8.4) остается компилятор Visual Studio 2012, но мы включили экспериментальную поддержку для других цепочек инструментов. Возможно, вам придется изменить некоторые параметры WAF, чтобы указать, какую цепочку инструментов вы хотите использовать. Пожалуйста, прочитайте "Visual Studio поддерживаемые версии» для получения информации о том, как настроить эту функцию.

Для CRYENGINE 3.8.4 - при использовании компилятора Visual Studio 2015 следующие функции не будут работать:

  • PerforcePlugin для SandBox, библиотека 3rdParty, от которой он зависит, не поддерживает Visual Studio 2015.
    Этот проект необходимо удалить из файла спецификации WAF при использовании Visual Studio 2015.
    Для этого отредактируйте <root>\_WAF_\specs\gamesdk_and_tools.json и удалите строку с упоминанием PerforcePlugin.

Эти ограничения не применяются при компиляции с помощью Visual Studio 2012.
Эти ограничения не применяются к версиям EaaS CRYENGINE, поскольку эти инструменты не нужно компилировать в этой версии.

Изменения для утверждения и помощники CRY_ASSERT

В версии 3.8.4 мы внесли некоторые изменения в assert и CRY_ASSERT файлы для подготовки к предоставлению большего контроля над поведением утверждений. Однако в рамках этой работы (недокументированное) FORCE_ASSERTS_IN_PROFILE определение больше недоступно. Аналогичного поведения можно добиться, настроив CryCommon/CryAssert.h в соответствии с вашими целями (убедитесь, что USE_CRY_ASSERT определен до строки 26).

Для CRYENGINE 3.8.4 мы не рекомендуем включать утверждения в профиле.
