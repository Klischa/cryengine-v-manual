Кэши геометрии в CRYENGINE позволяют хранить и воспроизводить произвольную анимированную геометрию (похожую на видео).

Некоторые варианты использования: сложные анимации разрушения, сложное движение ткани или специальные эффекты, которых невозможно достичь с помощью системы частиц CRYENGINE.

Особенности и ограничения

Особенности

  • Импортирует стандартные файлы Alembic:
    • Анимированные иерархии преобразований (т. е. фрагментация объектов).
    • Деформация сеток с постоянной топологией (т.е. ткань, персонажи).
  • Анимированная видимость.
  • Анимированные цвета вершин.
  • Автоматическое обнаружение экземпляров геометрии.
  • Физические прокси.

Ограничения

  • Поддерживаются не все функции Alembic:
    • Никаких сеток с изменяющейся топологией (т. е. текучих кешей, DMM):
      • Деформирующие сетки можно хорошо сжимать, поскольку их вершины просто перемещаются.
        Сети с изменяющейся топологией потребуют хранения всей сетки на кадр, это будет слишком много данных для потоковой передачи в реальном времени.
        Кроме того, к каждому кадру необходимо будет добавлять данные о скорости, с чем многие конвейеры Alembic справляются плохо.
    • Никаких кривых.
    • Никаких поверхностей разделения.
    • Нет камеры, света и т.
  • Нет обратного воспроизведения или быстрой перемотки вперед:
    • Анимация транслируется (аналогично видео на Youtube), поэтому скачки во времени приведут к задержке анимации.

Типы файлов

  • *.abc - Это собственный формат Alembic, который вы можете экспортировать из различных инструментов DCC.
  • *.cbc - Это файл настроек, в котором хранятся параметры, которые использовались для преобразования файла Alembic.
  • *.cax - Этот файл представляет собой обработанный файл Alembic, который RC сжимает в формат, удобный для Engine.
Файл *.cax для GeomCaches аналогичен файлу *.dds для текстур. Он генерируется на основе вашей версии движка из ваших *.abc и *.cbc.
Формат может быть изменен в будущих обновлениях движка и не имеет обратной совместимости!
Сохраняйте файлы *.abc и *.cbc так же, как и файлы *.tif.
См. раздел «Пакетное преобразование» для получения информации о том, как одновременно обновить все файлы *.cax.

Создание ресурсов GeomCache

Общий

Alembic — очень гибкий формат, который можно расширять практически для любого мыслимого пользовательского конвейера.

Таким образом, многие 3D-приложения экспортируют Alembic немного по-разному, что затрудняет импорт кэшей из разных источников.

По этой причине при создании кэшей Alembic для GeomCaches необходимо соблюдать некоторые рекомендации:

  • Поликаунт - как правило, не должен превышать разумного уровня для обычных активов. В каждом узле может быть не более 65,536 вершин/треугольников.
  • Скорость передачи данных - не должна превышать 10 MB/с для всех GeomCaches, работающих одновременно. Дополнительную информацию см. в разделе "Оптимизация" ниже.
  • UV Координаты — Импортер GeomCache загружает только первый канал UV — все остальные каналы будут игнорироваться.
  • Цвета вершин — Импортер GeomCache загружает только первый цветовой канал Vertex — все остальные каналы будут игнорироваться.

Идентификаторы материалов

CRYENGINE требует назначение материала для каждой грани, чтобы можно было установить подматериалы в соответствии с геометрией.

Alembic может экспортировать эту информацию в виде наборов граней (также известных как ShadingEngines или ShadingGroups в Maya).

Импортер будет искать первое целое число в таком имени набора граней и использовать его в качестве материала ID.

Итак, обычно рекомендуется называть ваши материалы следующим образом:

  • mat01_wall
  • mat02_door
  • mat03_etc.

Рекомендуется избегать использования Ламберт1!

Физические прокси

Вы можете создавать анимированные или пассивные физические прокси, включив одну из строк в имя сетки... см. следующий список. Тип поверхности определяется на основе назначенного материала. Примечание. Прокси физики не будут отображаться.

  • CryPhys_box - коробочный прокси. Поддерживает неравномерный масштаб.
  • CryPhys_sphere - сферный прокси. Поддерживает единый масштаб.
  • CryPhys_capsule - капсульный прокси. Поддерживает единый масштаб.
  • CryPhys_cylinder - цилиндр-прокси. Поддерживает единый масштаб.
  • CryPhys_mesh - произвольная сетка. Поддерживает неравномерный масштаб.

Пожалуйста, обратитесь к страницам руководства по настройке любого Пользовательские свойства (UDP) для физических прокси CRYENGINE в Maya или 3ds Max

Экспорт перегонного куба из Maya

Мы используем встроенный Maya 2016 Alembic Exporter и "CryAbc" скрипт с полки Crytek.

Убедитесь, что вы установили плагин экспорта Maya Alembic: в главном меню Maya -> Windows -> Настройки/Настройки -> Диспетчер подключаемых модулей установите флажки «Загружено» и «Автозагрузка» для «AbcExport.mll».

1. Запустите AbcMat скрипт (внутри Crytek Shelf), чтобы подготовить сцену к экспорту. Этот скрипт слегка изменяет вашу сцену, чтобы обойти некоторые ограничения в экспортере Alembic от Maya.

2. Теперь вызовите Maya Экспортер перегонных кубов GUI.

3. В разделе «Дополнительные параметры» (прокрутите вниз) убедитесь, что основные флаги включены — как показано на рисунке ниже.

После того, как вы установили параметры на шаге 3. Не используйте тот Окно параметров «Экспорт Alembic» -> «Экспортный выбор» (или «Экспортировать все») внизу! В противном случае вы потеряете установленные вами идентификаторы материалов и в конечном итоге для вашего актива Alembic останется только материал ONE ID.

После установки этих флагов нажмите кнопку закрытия и перейдите в Crytek Exporter!

4. Просто выберите узлы сетки, которые вы хотите экспортировать, и нажмите кнопку «CryAbc"Кнопка полки. Появится диалоговое окно файла, в котором вас попросят указать местоположение и имя файла Alembic.

Экспорт перегонного куба из 3ds Max

Начиная с версии 2016 года, 3ds Max официально включает экспортер Alembic. Однако он не будет экспортировать деформирующие сетки, читабельные для CRYENGINE, а будет экспортировать только «твердые тела» с анимированными трансформациями. Поэтому, если вы хотите деформировать сетки, например. объекты одежды, анимацию blendshape и т. д., то вам необходимо экспортировать в файл Alembic из 3ds Max 2016. Для этого повторно импортируйте файл *.abc в Maya. Затем установите материалы в соответствии с Maya Alembic (в соответствии с рабочим процессом CRYENGINE) и экспортируйте сцену с помощью CryAbc с помощью экспортера Alembic, который доступен на полке Crytek. (Следуйте разделу руководства выше)

Пакетное преобразование

Запуск компилятора ресурсов из командной строки позволяет выполнить пакетное преобразование нескольких файлов *.abc подряд.

Это может быть полезно для автоматической сборки ресурсов или ручного обновления всех файлов *.cax после установки новой версии Engine.

Вот пример использования компилятора ресурсов через командную строку для преобразования всех файлов *.abc в SDK:

rc.exe /refresh /threads *.abc

Настройка объекта

Можно использовать саму сущность, аналогично AnimObject в Trackview и Flow Graph.

Подробно о свойствах:

  • Файл - Файл GeomCache для этого объекта. Загрузите *.abc для перекомпиляции.
  • FirstFrameStandIn — CGF будет отображаться до запуска анимации кэша. Оставьте пустым, чтобы всегда отображать кэш.
  • FirstFrameStandInMaterial - материал для первого кадра CGF.
  • LastFrameStandIn - CGF будет отображаться после завершения анимации кэша. Оставьте пустым, чтобы всегда отображать кэш.
  • LastFrameStandInMaterial - материал для последнего кадра CGF.
  • Зацикливание - если включено, анимация будет зацикливаться.
  • Играя - если включено, будет воспроизводиться анимация.
  • StandIn — CGF будет отображаться во время воспроизведения анимации кэша. Оставьте пустым, чтобы всегда отображать кэш.
  • StandInDistance - когда камера находится дальше этого расстояния, будут отображаться дублирующие CGF.
  • StandInMaterial - материал для дублера CGF.
  • StartTime - время начала воспроизведения анимации кэша.
  • StreamInDistance - когда камера окажется в этом диапазоне, начнется предварительное кэширование. Выход из диапазона приведет к удалению данных кэша. Должно быть значительно больше, чем StandInDistance.

Оптимизация

Потоковое вещание

Поскольку сложные GeomCaches слишком велики для полной предварительной загрузки, их анимационные данные передаются в потоковом режиме за несколько секунд до воспроизведения.

Меньший размер GeomCaches можно полностью загрузить в память, включив при импорте флаг «воспроизведение из памяти».

По этой причине важно следить за скоростью передачи данных отдельных кэшей и общим объемом данных GeomCache, находящихся в настоящее время в памяти.

Эти значения использовались для Ryse на XboxOne:

  • Макс. комбинированная скорость передачи данных: 10 MB/с
  • Размер буфера GeomCache: 128 MB
  • Макс. воспроизведение из памяти: 16 MB

Для предварительно записанных трейлеров со множеством сложных GeomCaches может потребоваться увеличить "e_GeomCacheBufferSize" и "e_GeomCacheMaxPlaybackFromMemorySize".
Обратите внимание, что это также отрицательно повлияет на время загрузки.

Рендеринг

Большую часть времени работа с GeomCaches сводится к компромиссу между вызовами отрисовки и скоростью передачи данных.

Использование множества недеформирующихся сеток с анимированными преобразованиями приводит к низкой скорости передачи данных, но большому количеству вызовов отрисовки и наоборот.

Вот некоторые методы, которые помогут GeomCaches работать хорошо:

  • Экземпляры - при использовании множества одинаковых, недеформируемых объектов убедитесь, что они созданы в вашем инструменте DCC, это поможет сэкономить вызовы отрисовки.
  • Видимость - когда объект выходит из поля зрения игрока (например, под землей), отключите его видимость. Это предотвратит его рендеринг, а также удалит ненужные данные анимации.
  • Слияние - при работе со многими низкополигональными недеформируемыми объектами объединение их в одну деформирующую сетку может помочь значительно сократить количество вызовов отрисовки (хотя и за счет некоторой скорости передачи данных). Эта техника использовалась для осадной башни в Райсе.
  • уровни детализации - Запасные CGF могут иметь LOD, как и любой обычный CGF. Таким образом, количество полигонов на расстоянии может быть очень низким, а полный GeomCache отображается только тогда, когда камера находится достаточно близко.

Эта последовательность иллюстрирует, как различные методы влияют на вызовы отрисовки и скорость передачи данных, используя "e_GeomCacheDebugDrawMode 3" для раскрашивания экземпляров:

Профилирование

Общее потребление памяти и производительность потоковой передачи всех активных GeomCaches можно профилировать с помощью "e_GeomCacheDebug 1".

Отдельные GeomCaches можно профилировать с помощью наложения статистики сетки.

Вот как отдельные значения влияют на производительность:

  • Воспроизведение с диска/памяти - транслируется ли этот GeomCache или полностью загружен в память.
  • Средняя скорость передачи данных анимации - высокие значения могут привести к зависаниям анимации.
  • Анимированные/статичные трис/верты - как и в случае с обычной геометрией, больше треугольников/вершин = медленнее рендеринг.
  • Анимированные/статичные сетки - количество отдельных сеток (если они не созданы экземплярами) напрямую преобразуется в вызовы отрисовки. Сетки с несколькими подматериалами требуют нескольких вызовов отрисовки.

Отладка и устранение неполадок

Распространенные проблемы и решения

Консольные команды

e_GeomCacheDebug - отображает информацию об отладке потоковой передачи GeomCache. Избегайте полного буфера потоковой передачи, поскольку это приведет к зависанию анимации:

e_GeomCacheDebugFilter - показывать отладочную информацию только в кэшах с этой строкой в ​​имени.

e_GeomCacheDebugDrawMode - отладочная отрисовка для идентификации геометрии static, деформирующей геометрии и экземпляров:

  • 1 - рисовать только деформирующие сетки.
  • 2 - рисовать только сетки static.
  • 3 - сетки одного цвета отображаются как экземпляры.
