Обзор

Элемент UI представляет и определяет ресурс Flash (файл .swf), который может использоваться движком. Все элементы UI определяются как файл сценария XML, расположенный в GameSDK/Libs/UI/UIElements. Файл XML содержит всю информацию, необходимую движку для использования Flash-ресурса в игре.

Определение элемента UI

Итак, представьте, что у нас есть Flash-ресурс HudElements, и мы хотим использовать его в движке. Вам нужно создать HudElements.xml файл и сохраните его в GameSDK/Libs/UI/UIElements как упоминалось ранее.

<UIElements name="HudElements"> <!-- Group name for this elements -->

  <!-- definition of an UI element named "HUD". This name in combination with instance id is used to identify a UI element at runtime. -->
  <UIElement name="HUD">

    <!-- gfx/swf file for this UI element. This is the path to the actual flash asset.
     in this example the HUD element is using "Game/Libs/UI/HUD.gfx" file. This can potentially be
     a more complicated path e.g. in cases when you have a lot of UI elements and you want to have
     better structure, so that everything is easy to find (split UI elements in Menu and HUD elements)
   -->
    <GFx file="HUD.gfx" layer="1">
      <!-- the align mode of this element. These values will be discussed in a special section later on. -->
      <Constraints>
        <Align mode="dynamic" halign="center" valign="center" scale="1" max="1" />
      </Constraints>
    </GFx>

    <!-- available functions -->
    <functions>
    </functions>

    <!-- available events that are raised by the Flash asset -->
    <events>
    </events>

    <!-- available variables -->
    <variables>
    </variables>

    <!-- available arrays -->
    <arrays>
    </arrays>

    <!-- available movieclips -->
    <movieclips>
    </movieclips>

  </UIElement>

  <!-- definition of another UI element named "LoadingScreen" -->
  <UIElement name="LoadingScreen">
      ...
  </UIElement>

</UIElements>

Пример также показывает, что мы можем определить несколько элементов UI в одном файле XML, но рекомендуется избегать этого и создавать отдельный файл XML для каждого элемента UI, чтобы упростить поиск и упростить управление сложностью. Как это организовать, решает разработчик.

Скрипт XML содержит блоки для функций, событий, переменных, массивов и фрагментов роликов. Эти блоки используются движком для создания узлов Flowgraph. автоматически. Узлы можно использовать в действиях UI или Flowgraph для написания логики UI.

Функции

Функции, которые должны вызываться извне (UI Actions/Flowgraph), должны быть определены в файле <функции> блок элемента.

например функция ActionScript для установки шкалы здоровья:

function setHealth(iHealth:Number): void
{
  // set a health bar
}

Это можно определить в XML как:

<function name="SetHealth" funcname="setHealth">
  <param name="Health" desc="Players current health" type="int"/>
</function>
  • <функция> блок объявляет функцию.
    • имя="..." — это имя функции, которая отображается в Flowgraph и имя_функции="..." — настоящее имя функции в ActionScript.
  • <параметр> блок объявляет, какие параметры должна получить функция.
    • имя="..." — это имя параметра, отображаемое в узле Flowgraph. (функция может содержать несколько параметров)
    • по убыванию="..." — это текст, который появится, если пользователь наведет курсор на параметр в Flowgraph. Это используется, чтобы помочь другим пользователям, когда они используют ваши узлы Flowgraph. Если они не знают, для чего нужен параметр, они могут просмотреть удобное описание, предоставленное разработчиком.
    • тип="..." — это тип переменной. Это может быть одно из следующих: int / bool / строка / float . Если вы ничего не укажете, параметр будет типа "любой" и узел попытается преобразовать входящее значение и передать его во Flash. Рекомендуется указывать тип параметра, чтобы избежать потенциальных проблем.

Система автоматически создаст узел для Flowgraph, с помощью которого мы сможем вызвать эту функцию.

Также возможно определить функции, которых нет в корневое пространство Flash-файла, например.

<function name="SetHealth" funcname="myHealthMovieClip.mySubMovieClip.setHealth">
  <param name="Health" desc="Players current health"/>
</function>

События

Чтобы получить уведомление о некотором взаимодействии с пользователем, например. если кнопка была нажата, события можно определить в <события> блок. Чтобы вызвать событие в вашем коде ActionScript, вам нужно вызвать fscommand("commandString"). Эти фскоманды обрабатываются двигателем.

например в функции onPress кнопки, которую вы можете вызвать fscommand со строкой «onMyButtonPressed» и некоторыми аргументами.

myButton.onPress = function()
{
  var args:Array = new Array();
  args.push(argument1);
  args.push(argument2);
  fscommand("onMyButtonPressed", args);
}

Чтобы обработать это событие, добавьте <событие> тег в список <events>:

<event name="OnButton1" fscommand="onMyButtonPressed">
  <param name="Arg1" desc="Some argument"/>
  <param name="Arg2" desc="Another argument"/>
</event>

Переменные, массивы и MovieClips

Доступ к массиву или переменной также можно определить в файле xml.

Просто добавьте <переменная> пометить в <переменные> блок, ан <массив> тег к <массивы> блок, или <фильм> пометить в <видеоклипы> блок.

<variables>
  <variable name="SomeVariable" varname="someVariable"/>
  <variable name="TextField" varname="_root.myTextfield.text"/>
</variables>

<arrays>
  <array name="SomeArray" varname="_root.mc2.someArray"/>
</arrays>

<movieclips>
  <movieclip name="MovieClip1" instancename="_root.Mc1"/>
  <movieclip name="MovieClip2" instancename="_root.Mc1.subMc"/>
</movieclips>

Чтобы получить или установить переменную, выберите переменную в раскрывающемся списке UI:Переменная:Var или UI:Переменная:Массив проточный узел.

Массивы представляют собой строки, разделенные запятыми.

Вы также можете получить доступ к определенному MovieClips через FlowNodes.

Отображение элемента UI

Чтобы показать или скрыть элемент UI, используйте команду UI:Дисплей:Дисплей узел. Вы можете выбрать элемент в раскрывающемся списке. Если элемента нет в списке, это означает, что что-то не так с файлом сценария XML, определяющим Flash-ресурс.

Чтобы настроить поведение и ограничения, используйте UI:Display:Config и UI:Display:Constraints узлы.

Также возможно инициализировать все эти настройки в файле XML. Имейте в виду, что при этом все ваши элементы UI этого типа будут иметь одну и ту же конфигурацию/ограничения (все еще можно настроить их для каждого экземпляра).

<UIElement name="HUD" mouseevents="1" keyevents="1" cursor="1" console_mouse="1" console_cursor="1">
  <GFx file="HUD.gfx" layer="1" alpha="0.5">
    <!-- the align mode of this element -->
    <Constraints>
      <Align mode="fullscreen" />

      <!-- <Align mode="dynamic" halign="center" valign="center" scale="1" max="1" /> -->

      <!-- <Align mode="fixed" /> -->
      <!-- <Position top="20" left="20" width="200" height="200" /> -->

    </Constraints>
  </GFx>
  ...
</UIElement>

Создание экземпляров

Какова цель "InstanceID"порт во всех узлах UI? С помощью этого экземпляра ID вы можете иметь более одного экземпляра Flash-ресурса определенного типа и отправлять команды только на этот узел. "InstanceID" порт любого узла UI определяет, какой экземпляр должен быть затронут этим узлом. Если вы используете узел с новым экземпляром ID, он автоматически создаст новый экземпляр этого Flash-ресурса.

Если вы используете «-1» в качестве экземпляра ID, узел повлияет на все экземпляры этого элемента UI, которые доступны в данный момент (если их нет, он создаст один).

Если вы используете «-2» в качестве экземпляра ID, это активирует функциональность узла на все инициализировано экземпляры этого элемента UI.

Функции, зарезервированные и используемые движком

Есть некоторые особенные ActionScript функции, которые автоматически вызываются системой UI при выполнении определенных условий.

Эти функции должно быть определены в корневое пространство вашего ActionScript и их не нужно указывать в файле элемента UI XML.

// _platformID can be
//     FLASH_PLATFORM_PC       0
//     FLASH_PLATFORM_DURANGO  1
//     FLASH_PLATFORM_ORBIS    2
function cry_onSetup(_platformID)
function cry_onShow()
function cry_onHide()
function cry_onResize(_intWidth, _intHeight)
function cry_requestHide()
