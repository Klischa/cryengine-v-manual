Обзор

Этот документ расскажет вам о самостоятельном создании и изменении карт действий для настройки и адаптации элементов управления к потребностям вашей игры.

Обзор элементов управления пакета SDK можно найти здесь: Сопоставление контроллера.

Вот обзор стандартной настройки, которую вы можете найти в своем профиле:

В этом файле вы можете найти профили Action Maps XML для всех поддерживаемых платформ: Game\Libs\Config\Profile\DefaultProfile.xml

Файл профиля карт действий в играх, выпущенных Crytek, разбит на различные разделы, чтобы сгруппировать определенные элементы управления для облегчения чтения и настройки:

  • мультиплеер
  • одиночная игра
  • отладка
  • флайкам
  • по умолчанию
  • игрок
  • транспортное средство
  • наземное транспортное средство
  • морской транспорт
  • вертолет

Различные разделы можно включать и отключать во время выполнения с помощью Flow Graph, сценариев Lua и кода C++.

Карты действий

Элементы управления организованы в разделы, называемые «Карты действий», и каждый из них представляет собой набор сопоставлений клавиш/кнопок для определенного игрового режима. Например, для элементов управления вертолетом есть раздел карты действий под названием «Вертолет», что означает, что все, что находится ниже этого раздела, вплоть до следующего определения карты действий, состоит из привязок клавиш и кнопок, которые применяются только при управлении вертолетом. Чтобы изменить общие привязки в игре, перейдите в раздел, начинающийся с actionmap name="default". Также есть разделы для привязок, специфичных для многопользовательской игры, и, конечно же, любых других транспортных средств или режимов, которые вам нужны.

Вот обзор стандартной карты действий, в данном случае стандартной карты отладки.

<actionmap name="debug" version="22">
  <!-- debug keys - move to debug when we can switch devmode-->
    <action name="flymode" onPress="1" noModifiers="1" keyboard="f3" />
    <action name="godmode" onPress="1" noModifiers="1" keyboard="f4" />
    <action name="toggleaidebugdraw" onPress="1" noModifiers="1" keyboard="f11" />
    <action name="togglepdrawhelpers" onPress="1" noModifiers="1" keyboard="f10" />
    <action name="ulammo" onPress="1" noModifiers="1" keyboard="np_2" />
    <action name="debug" onPress="1" keyboard="7" />
    <action name="thirdperson" onPress="1" noModifiers="1" keyboard="f1" xboxpad="xi_dpad_up" ps3pad="pad_up"/>
   <!-- debug keys - end -->
  </actionmap>

Версия

<actionmap name="debug" version="22">

Всякий раз, когда значение версии увеличивается, CryENGINE гарантирует, что профиль пользователя получит недавно обновленную карту действий. Это весьма полезно при внедрении новых действий в патч уже выпущенной игры. Если версия остается прежней, изменения или дополнения к картам действий не будут распространяться на профиль пользователя.

Режимы активации

Доступны следующие режимы активации:

  • onPress — нажата клавиша действия.
  • onRelease — клавиша действия отпущена.
  • onHold — клавиша действия удерживается.
  • всегда - постоянно.

Режим активации передается прослушивателям действий и идентифицируется соответствующей константой Lua:

  • eAAM_OnPress
  • eAAM_OnRelease
  • eAAM_OnHold
  • eAAM_Always

Доступные модификаторы:

  • перезапускаемый -
  • holdTriggerDelay -
  • holdRepeatDelay -
  • noModifiers — действие происходит только в том случае, если не нажаты клавиши Control,Shift,Alt или Win.
  • consoleCmd — действие соответствует консольной команде
  • pressDelayPriority -
  • pressTriggerDelay -
  • pressTriggerDelayRepeatOverride -
  • inputsToBlock – укажите здесь действия ввода, которые нужно заблокировать.
  • inputBlockTime — время блокировки указанного действия ввода

Фильтры действий

Теперь вы также можете определить фильтры действий непосредственно в вашем defaultProfile.xml:

<actionfilter name="no_move" type="actionFail">
  <!-- actions that should be filtered -->
    <action name="crouch"/>
    <action name="jump"/>
    <action name="moveleft"/>
    <action name="moveright"/>
    <action name="moveforward"/>
    <action name="moveback"/>
    <action name="sprint"/>
    <action name="xi_movey"/>
    <action name="xi_movex"/>
  <!-- actions end -->
</actionfilter>

Атрибуты

Доступны следующие атрибуты:

  • имя - так будет идентифицироваться фильтр
  • тип (actionFail, actionPass) — указывает, позволит ли фильтр выполнить действие или выполнить его неудачно.

Компоновки контроллеров

В этом файле также можно хранить ссылки на различные макеты контроллера:

<controllerlayouts>
  <layout name="Layout 1" file="buttonlayout_alt.xml"/>
  <layout name="Layout 2" file="buttonlayout_alt2.xml"/>
  <layout name="Layout 3" file="buttonlayout_lefty.xml"/>
  <layout name="Layout 4" file="buttonlayout_lefty2.xml"/>    
</controllerlayouts>


Примечание. Атрибут «file» по умолчанию ссылается на файл, хранящийся в «libs/config/controller/».

Перезагрузка карт действий, фильтров и макетов контроллеров во время работы редактора

В Sandbox вы можете использовать консольную команду «i_reloadActionMaps» для повторной инициализации определенных значений. ActionMapManager отправит событие всем своим слушателям для синхронизации значений во всем движке. Если вы используете отдельный файл GameActions, например GameSDK, убедитесь, что этот класс получит обновление для повторной инициализации действий/фильтров на месте. Имейте в виду, что невозможно дважды определить карты действий, фильтры или макеты контроллеров с одним и тем же именем (например, фильтр действий «no_move», определенный в defaultProfile.xml AND файле GameActions).


Обработка действий во время выполнения

Flowgraph

Входные узлы может использоваться для обработки действий. С Flow Graph можно обрабатывать только цифровые входы.

Lua-скрипт

Хотя действия обычно не предназначены для непосредственного получения сценариями, с диспетчером карт действий можно взаимодействовать из Lua. Более подробную информацию можно найти в ScriptBind_ActionMapManager справочный документ.
