Сторонняя установка

Поддерживается Visual Studio версий

Для версий CRYENGINE до 3.6.2 поддерживается только Visual Studio 2010 Professional (поддержка версии Express только в FreeSDK)
Для версий CRYENGINE до 3.8.4 поддерживается только Visual Studio 2012 Professional (поддержка версии Express только в EaaS)
Для версий CRYENGINE от 3.8.4 до CRYENGINE V (5.1.X) проверьте поддержку в следующей таблице.
Для версий CRYENGINE, начиная с 5.2.0, поддерживается только Visual Studio 2015. Более новые версии могут не работать «из коробки».

Подобно тому, как Sandbox работает только в 64-битной Windows, мы поддерживаем разработку только в 64-битной Windows OS.
Это означает, что мы ожидаем использовать 64-битные размещенные цепочки инструментов для Visual C++.
Для пояснения: 32-битная Windows поддерживается в качестве целевой системы запуска (и для запуска игр CRYENGINE), но не в качестве хоста для компиляции.

Обратите внимание, что для Visual Studio устройства SKU типа Ultimate и/или Enterprise в этой таблице считаются профессиональными.

Если не указано иное, мы используем официальную производственную версию обновления (не бета-версию/RC), выпущенную Microsoft.
Использование RC, бета-версии, CTP или другой экспериментальной версии компилятора может вызвать проблемы, которые не встречаются в процессе разработки Crytek.
При возникновении проблем мы рекомендуем вместо этого попробовать текущую или предыдущую производственную версию (относительно даты выпуска этой версии CE).

Предметы, отмеченные значком поддерживаются частично, некоторые плагины или функции могут быть недоступны при использовании этой версии Visual Studio, поскольку зависимости 3rdParty могут не предоставлять библиотеки, совместимые с этой версией Visual Studio.
Подробную информацию об ограничениях для конкретных версий Visual Studio см. в примечаниях к выпуску конкретной версии CRYENGINE.
Для 3.8.4:

Начиная с Visual Studio 2015, Visual C++ больше не устанавливается вместе с Visual Studio по умолчанию.
Visual C++ и Windows SDK являются обязательными компонентами для всех вариантов компиляции CRYENGINE, поэтому обязательно выбирайте эти функции при установке Visual Studio 2015.

Поддерживаемые версии Windows SDK

Следующие версии Windows SDK поддерживаются каждым поддерживаемым компилятором. Настоятельно рекомендуется использовать эти комбинации, поскольку они официально поддерживаются Microsoft, и их различное смешивание может привести к проблемам.

Примечание для экспресс-версий Visual Studio

Обратите внимание, что при использовании экспресс-версий Visual Studio для компиляции кода CRYENGINE вам необходимо установить Windows SDK.
Это означает, что при загрузке Visual Studio вам следует выбирать варианты «для рабочего стола».

Примечание для версий сообщества Visual Studio

Обратите внимание: при использовании редакций сообщества Visual Studio для компиляции кода CRYENGINE у вас должна быть установлена Windows SDK.
Обычно его можно установить или добавить позже при настройке дополнительных пакетов в установщике Visual Studio.

Начиная с версии CRYENGINE 5.4, для компиляции потребуется обновление сообщества Visual Studio 2015 3.

Примечание относительно распространяемых библиотек.

Этот пункт применим только к WAF, начиная с CRYENGINE 3.8.4.
Для предыдущих версий вам может потребоваться скопировать зависимости вручную.

Когда WAF собирает определенные проекты, он пытается скопировать распространяемые библиотеки DLL либо из Windows SDK, либо из установочных папок Visual Studio. Эти шаги не являются обязательными (сборка не завершится неудачно, если файлы отсутствуют), но настоятельно рекомендуется включать их при каждом тестировании и автоматическом выборе зависимостей.

Обратитесь к следующей таблице, чтобы узнать, где WAF попытается найти распространяемые файлы.
Обычно, если файл отсутствует, будет выдано предупреждение. В этом случае рассмотрите возможность изменения/обновления установки Visual Studio или Windows SDK.

WAF Конфигурация

Оставшаяся часть этой главы относится к CRYENGINE версии 3.8.4 и новее.

Система сборки, распространяемая вместе с CRYENGINE, называется WAF и поддерживает указанные выше конфигурации. Существуют параметры конфигурации, позволяющие контролировать, какая версия компилятора Visual C++ и/или Windows SDK используется для компиляции, если значения по умолчанию не подходят для вашего проекта. Обратите внимание, что в оставшейся части этой главы мы будем использовать «MSVC» для обозначения установки компилятора Visual C++, идентифицируемой по номеру версии, как показано в таблице выше в столбце «Версия Visual C++» (в частности, мы не ссылаемся на номер версии Visual Studio, например 2012 или 2015).

Варианты конфигурации

Параметры, управляющие выбором компилятора WAF, хранятся в файле _WAF_/user_settings.json и могут быть установлены с помощью диалогового окна параметров WAF.
Все эти параметры можно найти на вкладке «Обнаружение компилятора».

Логика выбора по умолчанию для версии MSVC и версии Windows SDK

Теперь мы объясним логику выбора по умолчанию, которая может помочь устранить неполадки в неработоспособной конфигурации WAF.
По умолчанию выбор используемой версии MSVC осуществляется по следующей логике:

  1. Перечислите установленный MSVC на компьютере, сверившись с реестром.
    Это означает, что MSVC необходимо установить с помощью установщика, предоставленного Microsoft.
    Примечание: Обратите внимание, что перечисление может отличаться для x86 и x64, если для текущей целевой архитектуры не найден набор инструментов.
    Компиляторы, размещенные на x64, предпочтительнее компиляторов, размещенных на x86, из-за менее строгого ограничения памяти virtual.
  2. Выберите для компиляции наиболее предпочтительную версию (устанавливается Crytek), указанную в шаге 1.
    Для версии 3.8.4 порядок следующий: 11.0, затем 14.0, затем 12.0, а затем любое другое соответствующее минимальное требование.
  3. Поведение на шаге 2 можно изменить с помощью «minimum_msvc_compiler» (никогда не выбирать более старые версии) или «force_msvc» (выбирать именно эту версию)
    Примечание: Если версия, указанная с помощью «force_msvc», не указана на шаге 1, настройка WAF завершится ошибкой.
  4. Если не было перечислено ни одной версии MSVC, удовлетворяющей шагам 2 и 3, выбирается случайная версия и выдается предупреждение.
    Когда вы получите это предупреждение, установите одну из поддерживаемых версий, как указано выше.

Затем, после выбора MSVC, WAF выберет версию Windows SDK:

  1. Перечислите установленную Windows SDK на компьютере, сверившись с реестром.
    Примечание: Это означает, что SDK необходимо установить с помощью установщика, предоставленного Microsoft.
  2. Выберите Windows SDK, используя версию, поддерживаемую по умолчанию, как указано в таблице выше в разделе «Рекомендуемые Windows SDK».
  3. Поведение на шаге 2 можно изменить через «force_winsdk» (выберите именно эту версию)
    Примечание: для Windows 10 и более поздних версий необходимо указать полный номер версии (т. е. «10.0.10240.0»).

Устранение неполадок: использование --auto-detect-verbose для поиска проблем с выбором WAF

Может быть сложно выяснить, почему WAF не работает должным образом, учитывая конфигурацию хоста с установленными различными версиями MSVC и Windows SDK.
Чтобы упростить поиск причины возникновения проблемы, была добавлена ​​опция, объясняющая логику выбора, используемую WAF.

Чтобы просмотреть расширенный вывод, откройте командную строку, указав в качестве текущего каталога корневую папку CRYENGINE, а затем запустите:
cry_waf.exe configure --auto-detect-verbose True --generate-vs-projects-automatically False
WAF должен предоставить выходные данные с подробным описанием решений, принятых во время настройки MSVC и Windows SDK, как описано выше.

Если проблема остается, откройте заявку в службу поддержки, приложив как минимум выходные данные указанной выше команды и ожидаемое поведение.
Примечание. Только комбинации, перечисленные в таблице выше под заголовком «Поддерживаемые версии Windows SDK», напрямую поддерживаются Crytek.

Устранение неполадок: компиляция завершается с ошибкой WAF после неудачного выбора конфигурации.

После изменения конфигурации MSVC или Windows SDK возможно, что существующие временные файлы вызывают проблемы.
Рассмотрите возможность использования «Чистого решения» от Visual Studio перед первой сборкой после переключения версий MSVC.

Устранение неполадок: WAF выдает предупреждения о невозможности найти определенные файлы.

Поскольку WAF поддерживает различные версии MSVC, зависимости скомпилированных проектов могут различаться в зависимости от того, какая версия MSVC используется во время компиляции. WAF автоматически попытается скопировать соответствующие зависимости (как указано в разделе «Примечание относительно распространяемых библиотек») при компиляции проекта. Однако установки Visual Studio, а также установки Windows SDK не всегда включают распространяемые библиотеки (они являются необязательными и отключены по умолчанию). Мы рекомендуем обновить вашу установку, чтобы предоставить эти библиотеки, чтобы предотвратить проблемы во время выполнения на других компьютерах.

В случае, если установщик вашей игры установит соответствующие распространяемые файлы вместе с игрой, эти предупреждения можно смело игнорировать.
Примечание: Распространяемые файлы для сборок отладочной конфигурации не существуют, и такие сборки можно надежно запускать только на компьютерах с установленной версией MSVC.

Для пользователей Visual Studio 2015 обратите внимание, что текущий дистрибутив MSVC, похоже, не включает версию MBCS библиотек MFC, независимо от того, какая конфигурация выбрана во время установки. Видимо это недоработка установщика.

В качестве обходного пути можно скопировать mfc140.dll и mfcm140.dll в папку VC\redist\x64\Microsoft.VC140.MFC (из Windows\System32), которая должна быть доступна в вашей системе, если вы выбрали дополнительный пакет MFC во время установки Visual Studio.

Это требуется только при создании проекта редактора.

    Примечание: Это означает, что SDK необходимо установить с помощью установщика, предоставленного Microsoft.
  2. Выберите Windows SDK, используя версию, поддерживаемую по умолчанию, как указано в таблице выше в разделе «Рекомендуемые Windows SDK».
  3. Поведение на шаге 2 можно изменить через «force_winsdk» (выберите именно эту версию)
    Примечание: для Windows 10 и более поздних версий необходимо указать полный номер версии (т. е. «10.0.10240.0»).

Устранение неполадок: использование --auto-detect-verbose для поиска проблем с выбором WAF

Может быть сложно выяснить, почему WAF не работает должным образом, учитывая конфигурацию хоста с установленными различными версиями MSVC и Windows SDK.
Чтобы упростить поиск причины возникновения проблемы, была добавлена ​​опция, объясняющая логику выбора, используемую WAF.

Чтобы просмотреть расширенный вывод, откройте командную строку, указав в качестве текущего каталога корневую папку CRYENGINE, а затем запустите:
cry_waf.exe configure --auto-detect-verbose True --generate-vs-projects-automatically False
WAF должен предоставить выходные данные с подробным описанием решений, принятых во время настройки MSVC и Windows SDK, как описано выше.

Если проблема остается, откройте заявку в службу поддержки, приложив как минимум выходные данные указанной выше команды и ожидаемое поведение.
Примечание. Только комбинации, перечисленные в таблице выше под заголовком «Поддерживаемые версии Windows SDK», напрямую поддерживаются Crytek.

Устранение неполадок: компиляция завершается с ошибкой WAF после неудачного выбора конфигурации.

После изменения конфигурации MSVC или Windows SDK возможно, что существующие временные файлы вызывают проблемы.
Рассмотрите возможность использования «Чистого решения» от Visual Studio перед первой сборкой после переключения версий MSVC.

Устранение неполадок: WAF выдает предупреждения о невозможности найти определенные файлы.

Поскольку WAF поддерживает различные версии MSVC, зависимости скомпилированных проектов могут различаться в зависимости от того, какая версия MSVC используется во время компиляции. WAF автоматически попытается скопировать соответствующие зависимости (как указано в разделе «Примечание относительно распространяемых библиотек») при компиляции проекта. Однако установки Visual Studio, а также установки Windows SDK не всегда включают распространяемые библиотеки (они являются необязательными и отключены по умолчанию). Мы рекомендуем обновить вашу установку, чтобы предоставить эти библиотеки, чтобы предотвратить проблемы во время выполнения на других компьютерах.

В случае, если установщик вашей игры установит соответствующие распространяемые файлы вместе с игрой, эти предупреждения можно смело игнорировать.
Примечание: Распространяемые файлы для сборок отладочной конфигурации не существуют, и такие сборки можно надежно запускать только на компьютерах с установленной версией MSVC.

Для пользователей Visual Studio 2015 обратите внимание, что текущий дистрибутив MSVC, похоже, не включает версию MBCS библиотек MFC, независимо от того, какая конфигурация выбрана во время установки. Видимо это недоработка установщика.

В качестве обходного пути можно скопировать mfc140.dll и mfcm140.dll в папку VC\redist\x64\Microsoft.VC140.MFC (из Windows\System32), которая должна быть доступна в вашей системе, если вы выбрали дополнительный пакет MFC во время установки Visual Studio.

Это требуется только при создании проекта редактора.
