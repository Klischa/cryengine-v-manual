Описание

А FragmentID Файл определения содержит определение FragmentID, которое по сути представляет собой набор имен для FragmentIDs. Они используются для определения того, какой FragmentIDs может использовать персонаж-манекен.

Файлы определений FragmentID ссылаются на Файл определения контроллера и любой Файл базы данных анимации. Или они могут быть включены иерархически в другие файлы определений FragmentID. Смотрите обзорное изображение на странице о Mannequin Файлы.

Файлы определений FragmentID могут ссылаться на Файлы определения тегов определить Теги, специфичные для FragmentID (фрагтеги).

Создание файла определения FragmentID

FragmentID Файлы определений необходимо создавать вручную. См. тот FileFormat раздел.

FragmentID Файлы определений хранятся в папке Анимации/Mannequin/ADB/ папка. Однако это не является абсолютным требованием к двигателю.

Имя файла обычно заканчивается на Actions.xml, по крайней мере, в приведенных примерах. Но это вовсе не является обязательным требованием. Чтобы избежать путаницы, лучше использовать в названии что-то вроде «FragmentID».

Редактирование файла определения FragmentID

Файлы определений FragmentID редактируются косвенно путем добавления/удаления/переименования FragmentIDs с помощью Mannequin Браузер фрагментов и редактирование их настроек с помощью Mannequin FragmentID Редактор.

Формат файла

Это пример текущего формата (версия 2).

<TagDefinition version="2">
 <Imports>
  <Import filename="Animations/Mannequin/ADB/itemActions.xml"/>
 </Imports>
 <Tags>
  <Tag name="MotionIdle"/>
  <Tag name="MotionMovement"/>
  <Tag name="LedgeGrab" subTagDef="Animations/Mannequin/ADB/LedgeGrabTags.xml"/>
  <Tag name="Interact" subTagDef="Animations/Mannequin/ADB/InteractiveActionTags.xml"/>
 </Tags>
</TagDefinition>

Корневой элемент TagDefinition (NOT FragmentIDDefinition, как и следовало ожидать) и должен содержать правильный номер версии. Текущая версия — 2.

Импорт Элемент содержит список других включенных файлов определений fragmentID. Они объединяются во время загрузки. (аналогично оператору #include в коде C) В этом примере мы ссылаемся на общее определение itemActions.xml fragmentID, которое может содержать fragmentIDs, связанное с обработкой элементов, которые являются общими для нескольких типов символов.

Теги элемент содержит список отдельных FragmentIDs в Тег элементы. Каждому отдельному FragmentID может быть назначено определение тега, содержащее Теги, специфичные для FragmentID (фрагтеги). Это делается путем указания Файл определения тега (xxxTags.xml) в subTagDef атрибут.

Файл определения FragmentID использует тот же формат, что и файл определения. Файл определения тега (xxxTags.xml), поскольку он использует тот же базовый код, Mannequin CTagDefinition.
