Обзор

SubContexts — это удобство, предлагаемое программистам при работе с FragmentIDs чей Маска области видимости в конечном итоге может охватывать несколько контекстов области действия, каждый из которых относится к другому роль. Например, транспортное средство может иметь несколько сидений, каждое из которых имеет свою область применения и уникальный связанный тег. Другим простым примером может быть два персонажа, воспроизводящие синхронизированную анимацию, например, синхронное выполнение движения. SubContexts предоставляет программистам возможность явно ссылаться на одну из различных логических ролей, которые он может иметь (например, имя места или инициатор/цель исполнительного действия) при запросе действия.

SubContexts полностью прозрачен для аниматоров и дизайнеров. Они не влияют на способ настройки фрагментов в редакторе. Их цель — предоставить программистам игрового процесса безопасный и удобный способ предоставления некоторой дополнительной контекстной информации при работе с действиями, которые могут включать в себя несколько независимых контекстов области.

Использование

SubContexts определены в Файл определения контроллера. Каждый SubContext уникально идентифицируется именем и предоставляет Маска области видимости и Глобальный TagState. Продолжая пример с транспортным средством, этот фрагмент показывает, как файл определения контроллера транспортного средства может определять разные SubContexts для разных сидений, причем каждое сиденье имеет свой собственный набор областей действия.

<SubContexts>
 <Driver scopeMasks="Driver+DoorDriver" tags="Driver"/>
 <Passenger scopeMasks="Passenger+DoorPassenger" tags="Passenger"/>
</SubContexts>

При входе в транспортное средство персонаж обычно становится порабощенным либо Водителем, либо Пассажиром. Контекст области действия. При запросе FragmentID, который мы хотим разместить на одном из этих мест (например, при входе в транспортное средство или выходе из него), код игры должен будет указать, к какому SubContexts он относится. Это делается путем запроса SubContext в действии манекена:

// Driver just entered the vehicle, already enslaved to it
IActionController* pVehicleActionController;
IAction* pEnterVehicleAction;
 
// ...
 
// Queue the "EnterVehicle" FragmentID with the suitable SubContext
pEnterVehicleAction->SetFragment(EnterVehicle);
pEnterVehicleAction->SetTagContext(isDriver ? Driver : Passenger); // Change SubContext based on which role the enslaved character is supposed to have
pVehicleActionController->Queue(pEnterVehicleDriverAction);

Внутренне это приведет к тому, что соответствующие scopeMask и глобальные теги будут автоматически добавлены в состояние по умолчанию во время Процесс выбора фрагмента для этого действия. В этом примере, при правильной настройке, система будет знать, какого персонажа и какую дверь анимировать при обработке этого действия. Таким образом, мы можем просто запросить один и тот же FragmentID и разрешить его в разные scopeMasks и, в конечном итоге, фрагменты на основе заданного SubContext.
