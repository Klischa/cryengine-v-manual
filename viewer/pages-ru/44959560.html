CRYENGINE использует множество различных типов ресурсов, чтобы максимально реалистично моделировать реальный мир. Некоторые из наиболее распространенных типов ресурсов, используемых в CRYENGINE, — это текстуры .cgf (формат геометрии Crytek), .mtl (материал) и .dds (поверхность Directdraw), однако большинство пользователей в основном будут взаимодействовать со стандартным форматом геометрии .cgf, и им придется назначать материалы.

Как только вы начнете продвигаться вперед и начнете заниматься анимацией, вам придется работать с большим количеством типов ресурсов — ниже перечислены 4 основные категории:

  • Геометрия
  • Текстуры и материалы
  • Аудио
  • Анимация
  • UI

Если вы не видите свой актив в браузере активов, вы можете создать файл .cryasset для всех файлов, перейдя в браузер активов и щелкнув RMB в области папки, чтобы создать конкретные метаданные для активов в этой папке.

Геометрия

Текстуры

Ниже приведены некоторые из наиболее распространенных типов файлов ресурсов, с которыми вы можете столкнуться в движке:

Геометрия

  1. .cgf (формат геометрии Crytek): Файлы .cgf создаются в 3D-приложении и содержат геометрические данные (сгруппированные треугольники, атрибуты вершин, такие как касательное пространство или цвет вершин, дополнительные физические данные и дополнительные данные сферических гармоник).
  2. .chr (Персонаж) — Файлы .chr создаются в 3D-приложении и содержат данные скелета и физические прокси, которые используются для обнаружения попаданий и моделирования тряпичной куклы с помощью анимации.
  3. .skin (Скиновая сетка рендеринга) — Файлы .skin создаются в 3D-приложении и содержат данные персонажей со скинами. Это могут быть любые активы, анимированные с помощью вершин, взвешенных по костям, например, люди, инопланетяне, веревки, лампы, головы и парашюты. Файл .skin включает в себя сетку, вес вершин, цвета вершин и цели морфинга.

Текстуры и материалы

  1. .tif (формат файла изображения с тегами) — Файлы .tif следует создавать из Photoshop с помощью CryTif плагин. (Узнайте, как установить плагин здесь.) Файл TIFF в формате файла изображения с тегами) представляет собой высококачественное двухмерное растровое изображение плюс дополнительные метаданные, используемые компилятором ресурсов (RC). RC преобразует формат .tif в целевой формат файла используемой платформы. Хотя изображения TIFF могут использовать сжатие изображений LZW, оно осуществляется без потерь (в отличие от сжатия с потерями JPEG).
  2. .dds (поверхность DirectDraw) – Файлы .dds — это файлы текстур, созданные RC из исходных файлов .tif. Они могут содержать сжатые и несжатые данные и специально оптимизированы для каждой целевой платформы. Это оптимальный формат для видеокарт PC.
  3. .mtl (Материал) – Файлы .mtl создаются внутри Material Editor в Sandbox и описании материала (внутренне файл .xml). Они содержат настройки шейдеров, типов поверхностей и ссылки на текстуры. Файл .mtl — это текстовый файл, содержащий всю информацию внутриигровой библиотеки материалов. Библиотека материалов представляет собой набор дополнительных материалов, которые можно назначить каждой грани/многоугольнику геометрии. Например, вы можете использовать разные поверхности, такие как металл, пластик, человеческая кожа, в пределах разных идентификаторов актива. Каждый из этих субматериалов может использовать разные шейдеры и текстуры.

Аудио

  1. .wav (Волна) – Волновые файлы содержат несжатые звуковые данные. Обычно процесс сборки отфильтровывает файлы .wav, поскольку их не следует использовать во время выполнения, а только как высококачественные источники.
  2. .ogg (OGG-VORBIS) - Файлы OGG содержат сжатые звуковые данные, закодированные в OGG-Vorbis. В настоящее время они используются только на PC для музыки и со временем будут заменены конкретными файлами FSB.
  3. .fdp (Проект FMOD) Файл .fdp представляет собой файл проекта на основе XML для инструмента дизайнера FMOD. Он поставляется опционально, но необходим для SoundBrowser в Sandbox.
  4. .fev (Проект выполнения FMOD) Файл .fev — это двоичный файл, который необходим для загрузки данных события FMOD во время выполнения. Он содержит все необходимые метаданные для звуковых событий.
  5. .fsb (FMOD SoundBank) Файлы SoundBank содержат звуковые данные в определенном формате. Для Xbox360 они обычно кодируются в формате XMA. На PS3 используется формат .mpeg. Файлы FSB используются для звуковых событий, а также для музыки на консолях и в будущем будут использоваться и для голосовых файлов.

Анимация

.cga (Анимация геометрии Crytek)
Файл .cga содержит анимированные данные геометрии твердого тела на основе поворотов. Это означает, что мы не используем геометрию со скинами для этого типа ресурсов и по-прежнему используем анимированные жесткие части объекта в движке. Это тип ресурса, который следует использовать для транспортных средств, поскольку он позволяет использовать анимацию, например открытие двери, или любую анимацию, в которой не используются изгибы частей, например геометрия со скинами для персонажей. Файл .cga создается в 3D-приложении. Части будут связаны друг с другом в иерархии и будут иметь главную корневую базу. Он поддерживает только напрямую связанные объекты и не поддерживает анимацию на основе скелета (анимацию костей) с взвешенными вершинами. Работает вместе с файлами .anm.

.anm (Анимация)
Файл .anm создается в 3D-приложении и содержит данные анимации для объектов .cga. Каждый файл CGA, содержащий более одной анимации, использует файлы .anm для перемещения отдельных частей объекта CGA. Если для объекта существует только одна анимация, она будет сохранена в файле CGA как анимация по умолчанию в редакторе символов. Файлы .anm используются для группировки различных анимаций твердого тела. Например, можно сгруппировать опускание шасси отдельно от люка к проему кабины.

.cdf (Файл определения персонажа)
Файл определения персонажа создается в редакторе символов в Sandbox. Он содержит ссылку на файл .chr и его вложения (может быть .chr или .cgf).

.chrparams (Файл параметров персонажа)
Для (скелетного) персонажа в игре существуют определенные определения, которые должны быть сделаны в единой файловой структуре XML, называемой файлом .chrparams. Файл .chrparams имеет то же имя, что и символьный файл, на который он ссылается. Пожалуйста, посмотрите AnimEvents и файлы базы данных треков документ для получения дополнительной информации.

.i_caf (Файл анимации промежуточного персонажа)
Промежуточный файл анимации персонажа содержит данные анимированной кости для конкретного персонажа. Файлами .i_caf можно обмениваться между персонажами со схожей структурой костей. Промежуточный файл анимации персонажей хранит анимацию в несжатом формате и используется в производстве. Такие файлы создаются с помощью плагинов DCC, см. Экспорт анимации для получения подробной информации.

.animsettings (Настройки анимации)
Файл настроек анимации содержит настройки сжатия для каждой анимации. Это дополнительный файл, который хранится рядом с файлом .i_caf и описывает, как его следует скомпилировать компилятором ресурсов. Настройки анимации создаются с помощью инструмента импорта анимации в Sandbox, см. Экспорт анимации.

.caf (Файл анимации персонажа)
Сжатое представление формата i_caf. В этом формате используется сжатие с потерями, и такие файлы создаются либо Sandbox, либо во время сборки ресурса. Такие файлы загружаются движком во время выполнения.

.bspace (Смешивание-пространство)
Пространство смешивания определяет, как несколько анимационных ресурсов смешиваются вместе. Пространства смешивания параметризуются во время выполнения с помощью параметров передвижения, таких как скорость движения, направление движения, угол поворота или наклон. См. Смешать пространства.

.расческа (Комбинация Blend-Space)
Это позволяет объединить несколько более простых пространств смешивания в одно, обычно более высокого порядка.

.анимевенты (База данных анимационных событий)
В этом файле хранится список ресурсов с разметкой синхронизированных событий. Обычно используется для звуков шагов. Базу данных событий можно создать и изменить в редакторе символов, и она отображается в файле .chrparams.

SkeletonList.xml (Таблица псевдонимов скелета)
Таблица, которая сопоставляет псевдонимы скелетов (используемые в .animsettings) с именами файлов скелетов. Информация о структуре скелета необходима во время сжатия анимации.

Начиная с версии движка 5.6, список скелетов больше не используется.

DbaTable.xml (Таблица DBA)
Содержит список файлов .dba (базы данных анимации). Для каждой базы данных анимации существует список файлов .caf, которые включаются.

.dba (база данных анимации)
Такие файлы создаются компилятором ресурсов согласно DbaTable.xml. Они хранят несколько файлов анимации и устраняют избыточность, обеспечивая дополнительное сжатие без потерь. Отдельные файлы .caf больше не нужны, если они не являются ресурсами по требованию. Файл базы данных должен быть установлен в файле .chrparams.

UI

  1. .fla (авторский файл Flash-фильма) — Это редактируемые фильмы или анимации, созданные с помощью Adobe Flash; они обычно экспортируются в формате .swf для использования в Интернете. Файл FLA — это редактируемый файл проекта, сохраненный программой разработки Flash.
  2. .swf (файл формата Flash) – Анимация создана Adobe Flash. Файлы .SWF представляют собой сжатый формат, экспортированный из исходного файла .FLA и доступный для просмотра в большинстве веб-браузеров с помощью плагина Flash. Файл .swf может содержать текст, а также векторную и растровую графику. Будет воспроизводиться в веб-браузерах, в которых установлен плагин Flash. Большинство веб-браузеров оснащены последней версией плагина Flash.
  3. .gfx (сжатый Flash-файл, преобразованный в масштабную форму) — Scaleform GFx — это легкий, быстрый механизм рендеринга изображений и векторной графики, который разработан с учетом всех преимуществ современного оборудования для 3D-графики, но при этом совместим с широким спектром систем. В дополнение к основному механизму рендеринга Scaleform GFx содержит реализацию Flash-плеера «чистой комнаты», позволяющую разработчикам игр создавать пользовательские интерфейсы с помощью отмеченной наградами Adobe Flash Studio.
