Обзор

В этом разделе объясняется формат файлов реакций XML, свойства, которые он может использовать, как их использовать и т. д. Рассматривайте его как справочное руководство при редактировании системных файлов HitDeathReactions XML.

Как читать этот документ

В этом документе часто будут объясняться свойства XML. Формат, используемый для этих свойств, следующий:

  • <property_name><property_type> (<property_format>) <описание>
    • <property_name> -> Название свойства
    • <property_type> -> Тип свойства:
      • Элемент. Элементы XML, разделенные тегами XML. например, <HitReactionParam></HitReactionParam> или <HitReactionParam/>
      • Атрибут. Атрибуты XML, определенные внутри тегов XML. например, <Любой атрибут="значение"/>
    • <property_format> -> формат, используемый для значения этого свойства
    • <description> -> описание его функциональности

Если цвет объекта красный, это означает, что собственность имеет расширенное или предельное использование. Я не ожидаю, что они будут использоваться часто, и обычно только программистами или техническим персоналом в целях тестирования.

XML Расположение файлов

Вы можете найти файлы реакций XML в этом месте: GameData/Libs/HitDeathReactionsData/*.xml

Объект будет использовать данный XML-файл, если этот файл указан в его fileHitDeathReactionsParamsDataFile свойство (по умолчанию это будет Libs/HitDeathReactionsData/HitDeathReactions_Default.xml)

Разделы файла реакции

Каждый файл реакции состоит из пяти основных разделов:

  • Определение типа документа (или DTD)
  • Корневой элемент. Это основная часть файла XML (разделенная тегами <DeathHitReactionsParams> и </DeathHitReactionsParams>), он содержит остальные четыре важных раздела:
    • Нажмите «Конфигурация реакций смерти»
    • Реакция на попадание
    • Реакции смерти
    • Столкновения с реакциями окружающей среды

Все разделы не являются обязательными (но, конечно, наличие пустого файла мало что даст, не так ли?). Ниже вы найдете дополнительную информацию о них.

Определение типа документа

Этот раздел обычно находится в начале файла, за пределами корневого элемента (который <DeathHitReactionsParams>) и начинается с тега <!DOCTYPE. Этот раздел не относится к системе HitDeathReactions, а является частью стандарта XML, который может находиться в любом файле XML.

Он используется в файлах HitDeathReactions XML для определения XML Сущности, которые в основном макросы это облегчает редактирование. например:

<?xml version="1.0"?>

<!-- DTD (Document Type Definition) for defining XML Internal General Entities. Think of them as macros -->
<!DOCTYPE HitDeathReactions_Example [
  <!ENTITY Legs '
    <Part value="L Leg"/>
    <Part value="R Leg"/>
  '>

  <!-- Lower body part names -->
  <!ENTITY LowerBody '
    <Part value="Pelvis"/>
    &Legs;
  '>
]>

<DeathHitReactionsParams>
    <!-- HITS -->
    <HitReactionParams>

      <HitReactionParam animName="LowerBodyImpact">
        <AllowedParts>
          <!-- To use XML Entities put the name between the characters & and ; like &this;, it will be the same
          as if you had typed the same text you wrote on the Entity definition -->
          &LowerBody;
        </AllowedParts>
      </HitReactionParam>

    </HitReactionParams>

    <!-- DEATHS -->
    <DeathReactionParams>

      <DeathReactionParam animName="LowerBodyDeath">
        <AllowedParts>
          <!-- If we change the contents of the LowerBody entity, the changes will apply on every use of that
          entity, which is very useful while editing these files -->
          &LowerBody;
        </AllowedParts>
      </DeathReactionParam>

    </DeathReactionsParams>

</DeathHitReactionsParams>

Нажмите «Конфигурация реакций смерти»

Этот раздел позволяет настроить некоторые аспекты системы для персонажа, использующего файл, путем присвоения некоторых значений некоторым атрибутам элемента <HitDeathReactionsConfig>.

Вот атрибуты, которые вы можете использовать:

  • maximumReactionTime - Максимальное время (в секундах), в течение которого может длиться реакция. Система реакций на смерть при попадании автоматически останавливает (и печатает предупреждение об этом) любую реакцию, которая занимает больше времени, чем это значение, как отказоустойчивое поведение. Если правильная анимация реакции занимает больше времени, чем это значение, просто увеличьте его. Значение по умолчанию: «4,0».
  • collisionBone - Имя кости, в которой сфера обнаружения столкновений будет центрирована в горизонтальной (x-y) плоскости (см. Столкновения с реакциями окружающей среды). Значение по умолчанию: «Bip01 Spine1».
  • collisionRadius - Радиус (в метрах) сферы обнаружения столкновений (см. Столкновения с реакциями окружающей среды). Значение по умолчанию: «0,6».
  • collisionVerticalOffset - Высота (в метрах), на которой будет находиться сфера обнаружения столкновений (см. Столкновения с реакциями окружающей среды) от местоположения персонажа. Значение по умолчанию: «0,5».
  • collMaxHorzAngle - Синус максимального угла, разрешенного для нормали столкновения относительно горизонтальной плоскости (x-y) (см. Столкновения с реакциями окружающей среды). Значение по умолчанию: «0,342» -> грех 20°.
  • collMaxMovAngle - Косинус максимального угла столкновения нормали относительно направления движения (см. Столкновения с реакциями окружающей среды). Значение по умолчанию: «0,7071» -> cos 45°.
  • collReactionStartDist - Расстояние (в метрах) от точки столкновения (параллельно нормали), где начинается реакция столкновения (см. Столкновения с реакциями окружающей среды). Значение по умолчанию: «0,4».

Все свойства являются необязательными, если они не указаны, они примут значение по умолчанию.

Пример
<?xml version="1.0"?>

<!-- Omitted DTD -->

<DeathHitReactionsParams>

  <HitDeathReactionsConfig collisionBone="Spine02" collisionRadius="1"
    collisionVerticalOffset="0.8"
    maximumReactionTime="4.5"/>

  <!-- Omitted Hit/Death/Collision reactions sections -->
</DeathHitReactionsParams>

Реакция на попадание

Этот раздел ограничен тегами <HitReactionParams> и </HitReactionParams>. Он может содержать любое количество реакций, которые разделяются тегами <HitReactionParam> и </HitReactionParam>.

При обнаружении попадания система начинает оценивать реакцию за реакцией в том порядке, в котором они определены в файле XML. Если одна реакция подтверждена, она выполняется и процесс завершается.

Подробнее об их атрибутах и ​​параметризации см. Раздел свойств реакций

Реакции смерти

Этот раздел ограничен тегами <DeathReactionParams> и </DeathReactionParams>. Он может содержать любое количество реакций, которые разделяются тегами <DeathReactionParam> и </DeathReactionParam>.

При обнаружении убийства система начинает оценивать реакцию за реакцией в том порядке, в котором они определены в файле XML. Если одна реакция подтверждена, она выполняется и процесс завершается.

Основное различие между реакциями смерти и реакциями на попадание заключается в том, что выполнение реакции смерти всегда заканчивается включением тряпичной куклы в персонажа.

Подробнее об их атрибутах и параметризации см. Раздел свойств реакций

Столкновения с реакциями окружающей среды

Этот раздел ограничен тегами <CollisionReactionParams> и </CollisionReactionParams>. Он может содержать любое количество реакций, которые разделяются тегами <CollisionReaction> и </CollisionReaction>.

Некоторые реакции «Попадание» и «Смерть» обнаруживают столкновения с окружающей средой во время выполнения (особенно те, у которых есть ragdollOnCollision или reactionOnCollision набор свойств, см. раздел Свойства реакций).

Если столкновение обнаружено, оно может вызвать одну из этих «реакций на столкновение». Эти реакции не валидированы, вместо этого они выбираются на основе reactionOnCollision значение свойства или параметр некоторого AnimationEvents (ReactionOnCollision), запущенный во время реакции.

Если реакция столкновения срабатывает из-за реакции смерти, она всегда приводит к включению тряпичной куклы в персонажа.

Подробнее об их атрибутах и параметризации см. Раздел свойств реакций.

Реакционные элементы

Реакции делают две важные вещи:

Валидация

Реакция может быть выполнена только в том случае, если она действительна. То есть, если какой-либо из его блоков проверки действителен, это означает, что требования/ограничения этого блока проверки соответствуют контексту попадания.

Поэтому реакция может иметь несколько блоков проверки или только один. Вы можете указать несколько блоков проверки, включив их в <ValidationSection> элемент.

Я проиллюстрирую это примерами, чтобы было легче понять:

  <HitReactionParam animName="smallCaliberReaction">
    <AllowedProjectiles>
      <Projectile value="SMGBullet"/>
      <Projectile value="PistolBullet"/>
    </AllowedProjectiles>
  </HitReactionParam>

... эквивалентно этой версии:

  <HitReactionParam animName="smallCaliberReaction">
    <ValidationSection>
      <Variation>
        <AllowedProjectiles>
          <Projectile value="SMGBullet"/>
          <Projectile value="PistolBullet"/>
        </AllowedProjectiles>
      </Variation>
    </ValidationSection>
  </HitReactionParam>

В обоих предыдущих примерах <AllowedProjectiles> element — единственное ограничение единственной проверки, которую использует реакция.

Теперь представьте, что вы хотите, чтобы анимация «smallCaliberReaction» запускалась также тогда, когда тип удара — «столкновение», а урон меньше 100. Вы можете сделать что-то вроде этого:

  <HitReactionParam animName="smallCaliberReaction">
    <ValidationSection>
      <Variation>
        <AllowedProjectiles>
          <Projectile value="SMGBullet"/>
          <Projectile value="PistolBullet"/>
        </AllowedProjectiles>
      </Variation>
    </ValidationSection>
  </HitReactionParam>

  <HitReactionParam animName="smallCaliberReaction" maximumDamage="100">
    <AllowedHitTypes>
      <HitType value="collision"/>
    </AllowedHitTypes>
  </HitReactionParam>

Но в целом лучше, если вы максимально ограничите количество блоков реакции. Вместо этого вы можете использовать эквивалентную (и лучшую) следующую версию:

  <HitReactionParam animName="smallCaliberReaction">
    <ValidationSection>
      <Variation>
        <AllowedProjectiles>
          <Projectile value="SMGBullet"/>
          <Projectile value="PistolBullet"/>
        </AllowedProjectiles>
      </Variation>

      <Variation maximumDamage="100">
        <AllowedHitTypes>
          <HitType value="collision"/>
        </AllowedHitTypes>
      </Variation>
    </ValidationSection>
  </HitReactionParam>

Каждый процесс проверки можно настроить (с помощью validationFunc свойство, см. ниже) или просто используйте код проверки C++ по умолчанию (если validationFunc свойство не указано), это наиболее используемый подход.

Исполнение

После того как реакция проверена, следующим шагом будет ее выполнение. Процесс выполнения можно настроить (с помощью reactionFunc свойство, см. ниже) или просто используйте код выполнения C++ по умолчанию (если reactionFunc свойство не указано), что обычно приводит к воспроизведению анимации.

Свойства реакции

Свойства, связанные с проверкой

  • validationFunc - [Атрибут] Указывает имя функции LUA или C++ (зарегистрированной в классе CCustomReactionFunctions), которая будет выполнять проверку. Значение по умолчанию: будет использоваться код проверки C++ по умолчанию.

Код проверки C++ по умолчанию использует некоторые свойства, которые определяют, является ли реакция допустимой, в зависимости от контекста попадания или уничтожения. Вы можете рассматривать их как ограничения для выбранной реакции.

Если ограничение отсутствует, это означает, что оно не будет иметь никакого эффекта (например, реакция без какого-либо свойства/ограничения проверки всегда будет допустимой). Вот свойства, которые в настоящее время используются для кода проверки по умолчанию:

  • minimumSpeed - [Атрибут] Эта реакция не будет действительна, если персонаж не движется с этой скоростью или выше.
  • maximumSpeed - [Атрибут] Эта реакция не будет действительна, если персонаж не движется с этой скоростью или ниже.

Вы можете легко увидеть скорость персонажа, набрав g_hitDeathReactions_debug 1 на консоли и посмотрев на speedFlat ценность. Вы можете найти значения скорости, которые использует AI, если заглянете в его файл сценария AI. Найдите таблицу AIMovementSpeeds.

  • minimumDamage - [Атрибут] Эта реакция не будет действительна, если урон от удара не будет равен или больше этого значения. Для большинства ударов урон — это не фактически вызванное изменение здоровья, а чистый урон, нанесенный этим типом удара. Однако при убийствах это обработанный урон.
  • maximumDamage - [Атрибут] Эта реакция не будет действительна, если урон от удара не будет равен или меньше этого значения. Для большинства ударов урон — это не фактически вызванное изменение здоровья, а чистый урон, нанесенный этим типом удара. Однако при убийствах это обработанный урон.
  • OnlyWhenPassingHealthThresholds. [Элемент] Эта реакция HIT не будет действительна, если удар не приведет к тому, что здоровье персонажа превысит один из указанных в ней порогов. Для указания порогов здоровья вы можете использовать абсолютные значения здоровья или десятичный процент (плавающие значения в диапазоне [0, 1]) от максимального здоровья персонажа. например,
<!-- This reaction will be executed when the hit causes the health of the character to go past 75% of health, 50% of health, 1500 health points and 25% of health. The order in which you define them is not relevant -->
  <HitReactionParam animName="alienHeavyReaction">
    <OnlyWhenPassingHealthThresholds>
      <HealthThreshold value="0.75"/>
      <HealthThreshold value="0.5"/>
      <HealthThreshold value="1500"/>
      <HealthThreshold value="0.25"/>
    </OnlyWhenPassingHealthThresholds>
  </HitReactionParam>
  • minimumDistanceToShooter - [Атрибут] (метры) Эта реакция не будет действительна, если расстояние между стрелком и жертвой не будет равно или больше этого значения.
  • maximumDistanceToShooter - [Атрибут] (метры) Эта реакция не будет действительна, если расстояние между стрелком и жертвой не будет равно или меньше этого значения.
  • movementDirection - [Атрибут] (направление) Эта реакция не будет действительна, если персонаж не будет двигаться в указанном диапазоне направлений.
  • shotOrigin - [Атрибут] (направление) Эта реакция не будет действительна, если попадание не произойдет из указанного диапазона направлений.
  • вперед. Диапазон 90 градусов перед персонажем
  • назад. Диапазон 90 градусов позади персонажа
  • ушел. Диапазон 90 градусов слева от персонажа.
  • правильно. Диапазон 90 градусов справа от персонажа.
    —
  • впереди. Диапазон 180 градусов перед персонажем
  • позади. Диапазон 180 градусов позади персонажа
  • leftSide. Диапазон 180 градусов слева от персонажа.
  • rightSide. Диапазон 180 градусов справа от персонажа.
  • probabilityPercent. [Атрибут] (десятичный процент [0,0-1,0]) Эта реакция будет действительным только в процентах времени (например, приведенное ниже значение будет действительным только в 50% случаев)
<HitReactionParam animName="halfOfTheTime" probabilityPercent="0.5"/>
  • onlyIfUsingMountedItem - [Атрибут] (1/0) Эта реакция будет действительна только в том случае, если персонаж использует установленный предмет (например, установленный пулемет).
  • destructibleEvent - [Атрибут] Эта реакция будет действительна только в том случае, если попадание также вызвало событие разрушения тела с этим именем (события разрушения тела управляются системой BodyDestruction, вы можете найти их в файлах Libs/BodyDamage/BodyDestructibility_*.xml)
  • AllowedStances - [Элемент] Эта реакция будет действительна только в том случае, если персонаж находится в одной из позиций, указанных в этом свойстве. например,
<?xml version="1.0"?>

<!-- DTD (Document Type Definition) for defining XML Internal General Entities. Think of them as macros -->
<!DOCTYPE HitDeathReactions_Example [
  <!ENTITY StandingStances '
    <Stance value="STANCE_STAND"/>
    <Stance value="STANCE_RELAXED"/>
    <Stance value="STANCE_STEALTH"/>
    <Stance value="STANCE_ALERTED"/>
  '>
]>

<DeathHitReactionsParams>
  <!-- Omitted HitDeathReactions config section -->

  <HitReactionParams>

    <HitReactionParam animName="standingHitReaction">
      <AllowedStances>
        &StandingStances;
      </AllowedStances>
    </HitReactionParam>

    <HitReactionParam animName="crouchHitReaction">
      <AllowedStances>
        <Stance value="STANCE_CROUCH"/>
      </AllowedStances>
    </HitReactionParam>

  </HitReactionParams>

  <!-- Omitted Death/Collision reactions sections -->
</DeathHitReactionsParams>
Идентификаторы позиций

STANCE_PRONE, STANCE_CROUCH, STANCE_STAND, STANCE_RELAXED, STANCE_ALERTED, STANCE_STEALTH, STANCE_LOW_COVER, STANCE_HIGH_COVER, STANCE_SWIM, STANCE_LASTSTAND

  • AllowedHitTypes - [Элемент] Эта реакция будет допустима только в том случае, если тип попадания является частью типов попадания, указанных в этом свойстве. например,
<HitReactionParam animName="explosionReaction">
    <AllowedHitTypes>
      <HitType value="frag"/>
      <HitType value="explosion"/>
    </AllowedHitTypes>
  </HitReactionParam>
Типы попаданий

ближний бой, столкновение, осколок, нормальный, ремонт, пуля, gaussbullet, огонь, stealthKill, silentMelee, такт, падение, событие, наказание, punishFall, avmine, moacbullet, scout_moac, aacannon, emp, pingerPing, квольт, impulse_hit, heavyBullet, HMG, штамп, mike_burn, alienDropPodBounce, взрыв, disableCollisions

  • AllowedProjectiles - [Элемент] Эта реакция будет действительна только в том случае, если класс снаряда, вызвавшего попадание/убийство, является одним из указанных в этом свойстве. Чтобы узнать класс снаряда боеприпаса, отредактируйте файлы Ammo .xml и найдите значение имени свойства (например, <ammo name="GaussBullet" class="Bullet"> соответствует снаряду класса "GaussBullet"). Имена классов чувствительны к регистру, пишите их точно так, как указано в определении боеприпасов. например,
  <HitReactionParam animName="smallCaliberReaction">
    <AllowedProjectiles>
      <Projectile value="SMGBullet"/>
      <Projectile value="PistolBullet"/>
    </AllowedProjectiles>
  </HitReactionParam>
  • AllowedWeapons - [Элемент] Эта реакция будет действительна только в том случае, если класс оружия, вызвавший попадание/убийство, является одним из указанных в этом свойстве. Чтобы узнать класс оружия, отредактируйте файлы Weapon .xml и найдите значение имени свойства (например, <item name="Gauss" class="Weapon" ...> соответствует оружию класса "Gauss"). Имена классов чувствительны к регистру, пишите их точно так, как указано в определении оружия. например,
  <HitReactionParam animName="gaussHitReaction">
    <AllowedWeapons>
      <Weapon value="Gauss"/>
    </AllowedWeapons>
  </HitReactionParam>
  • AllowedParts - [Элемент] Эта реакция будет действительна только в том случае, если часть (или вложение), на которую повлияло последнее попадание, является одной из указанных в этом свойстве. например,
  <DeathReactionParam animName="legsDeathReaction">
    <AllowedParts>
      <Part value="L Leg"/>
      <Part value="R Leg"/>
    </AllowedParts>
  </DeathReactionParam>

Самый простой способ получить название интересующих вас костей или вложений (по крайней мере, проще, чем обращаться к техническому художнику) — это набрать i_giveItem debugGun на консоли, а затем нацелиться на персонажа. Часть или вложение, на которое вы нацелены, будет отображаться в виде текста: «partId: 77 (Bip01 Head)». Bip01 Head — это то, что вы ищете.

Свойства, связанные с выполнением

  • reactionFunc - [Атрибут] Указывает имя функции LUA или C++ (зарегистрированной в классе CCustomReactionFunctions), которая будет отвечать за выполнение. Значение по умолчанию: будет использоваться код выполнения C++ по умолчанию.
    Некоторые существующие пользовательские функции выполнения:
    • ReactionDoNothing - Ничего не делает (капитан очевидно), но реакция считается успешной, поэтому код игры не будет пытаться запустить резервное поведение.
    • MeleeDeath_Reaction - Особый случай для смертей в ближнем бою. Если значение CVar pl_melee.impulses_enable равно 3 или 1, он оставит код ближнего боя для обработки импульса к тряпичной кукле, иначе попытается воспроизвести анимацию, указанную в реакции, если она присутствует. Если анимация не указана, она превратит персонажа в рэгдолл и запустит код ApplyDeathImpulse из ActorImpulseHandler.
    • FallAndPlay_Reaction - Это вызовет падение и игру персонажа и запустит код ApplyDeathImpulse ActorImpulseHandler.
    • BackHitInCover_Reaction - Он запустит код выполнения по умолчанию и заставит AI покинуть укрытие.
    • DeathImpulse_Reaction - Он превратит персонажа в тряпку и запустит код ApplyDeathImpulse из ActorImpulseHandler.

Код выполнения C++ по умолчанию может вызывать разнообразные эффекты, параметризованные в его свойствах. Если свойство отсутствует, это означает, что оно не вызовет никакого эффекта.

Реакция без какого-либо свойства выполнения ничего не сделает и будет считаться неудачной, поэтому код игры запустит запасной код (физический импульс при ударах, тряпичная кукла + импульсы при смерти). Это может быть полезно в некоторых ситуациях (уже есть несколько реакций).

Это свойства, используемые в настоящее время для кода выполнения по умолчанию:

  • ReactionAnim - [Элемент] Указывает анимацию (или набор анимаций для случайного выбора), которая будет воспроизводиться вместо AnimationGraph, со временем перехода 0.1 секунды. Он использует некоторые свойства, влияющие на воспроизведение анимации:
    • добавка - [Атрибут] (1/0), если включено, анимация будет воспроизводиться как добавка. Значение по умолчанию: «0»
    • слой - [Атрибут] ([0-15]) это слой анимации, на котором будет воспроизводиться анимация. График анимации будет приостановлен, только если для анимации используется слой 0 (полный). Значение по умолчанию: «0»
    • overrideTransTimeToAG - [Атрибут] если это значение равно 0 или больше, оно будет указывать время перехода, которое будет использовать текущее состояние графа анимации, когда граф анимации возобновляется в конце реакции. Значение по умолчанию: «-1,0».
    • AnimNames - [Элемент] Содержит список анимаций. Система перемешивает список случайным образом и воспроизводит одну из содержащихся анимаций последовательно каждый раз, когда выполняется реакция. При выполнении полного списка он будет перетасовываться снова. Это делается для того, чтобы система обеспечивала случайность без повторений. например,
<!-- This reaction will play an additive animation in the layer 5 (I recommend using that layer or higher for partial/additive anims). In an hypothetical case, the system will behave like this:
(list is shuffled)
1st hit: Plays "stand_tac_hitShoulder_rifle_add_3p_01"
2nd hit: Plays "stand_tac_hitShoulderHMG_rifle_add_3p_02"
3rd hit: Plays "stand_tac_hitBelly_rifle_add_3p_01"
4th hit: Plays "stand_tac_hitShoulderHMG_rifle_add_3p_03"
5th hit: Plays "stand_tac_hitShoulderHMG_rifle_add_3p_01"
(list is shuffled)
6th hit: Plays "stand_tac_hitBelly_rifle_add_3p_01"
...
It won't matter which character has received the hit, the list is global to all the characters using the same reactions (so if you shot character A and then shot character B and both trigger the same reaction you can be sure they won't play the same animation in a row) -->
<HitReactionParam>
  <ReactionAnim additive="1" layer="5">
    <AnimNames>
      <AnimName name="stand_tac_hitBelly_rifle_add_3p_01"/>
      <AnimName name="stand_tac_hitShoulder_rifle_add_3p_01"/>
      <AnimName name="stand_tac_hitShoulderHMG_rifle_add_3p_0" variants="3"/>
      <!-- variants="3" above is equivalent to:
      <AnimName name="stand_tac_hitShoulderHMG_rifle_add_3p_01"/>
      <AnimName name="stand_tac_hitShoulderHMG_rifle_add_3p_02"/>
      <AnimName name="stand_tac_hitShoulderHMG_rifle_add_3p_03"/>
      -->
    </AnimNames>
  </ReactionAnim>
</HitReactionParam>
  • animName - [Атрибут] Упрощенная версия элемента ReactionAnim выше. Итак:
<DeathReactionParam animName="death_reaction_anim" />

... эквивалентно:

<DeathReactionParam>
  <ReactionAnim>
    <AnimNames>
      <AnimName name="death_reaction_anim"/>
    </AnimNames>
  </ReactionAnim>
</DeathReactionParam>

Если используются и animName, и ReactionAnim, animName будет игнорироваться.

  • AnimGraphReaction - [Элемент] Заставляет граф анимации воспроизводить анимацию, указав значение для сигнал входные данные и, при необходимости, некоторые значения для входных данных вариантов. Если этот элемент используется вместе с ReactionAnim или animName, он будет override. например,
<!-- if shot from the left while running the reaction will set the "signal" input to "hitRunForward" and will set the variation input "stance" to "stand", the variation input "hitName" to "lft_torso_3p" and the variation input "variant" to "01" -->
<HitReactionParam shotOrigin="left" minimumSpeed="&RunningSpeed;">
  <AnimGraphReaction inputValue="hitRunForward">
    <Variations>
      <Variation name="stance" value="stand" />
      <Variation name="hitName" value="lft_torso_3p" />
      <Variation name="variant" value="01" />
    </Variations>
  </AnimGraphReaction>
</HitReactionParam>
  • pauseAI - [Атрибут] (1/0) Указывает, следует ли приостановить AI во время выполнения реакции. Значение по умолчанию: «1»
  • АИСигнал - [Атрибут] Если используется, AI будет отправлен указанный сигнал в начале реакции. Если используются и этот атрибут, и pauseAI="1", второй атрибут будет проигнорирован.
  • reactionOnCollision - [Атрибут] Если используется и значение больше 0, это заставит систему обнаруживать столкновения с окружающей средой во время выполнения реакции. Проверка коллизий работает с использованием сферы, сосредоточенной на персонаже, с некоторыми параметризованными атрибутами (см. Раздел конфигурации для более подробной информации). Если столкновение обнаружено, система прервет текущую реакцию и воспроизведет collisionReaction какая позиция соответствует номеру, использованному здесь (однако при реакции на смерть «1» приведет к включению тряпичной куклы). Значение по умолчанию: «0». например,
<HitDeathReactionParams>
  <!-- HIT REACTIONS -->
  <HitReactionParams>
    <!-- If the collision sphere detects a collision with the environment, the system will trigger the collision reaction number 2 (front collision, see below) -->
    <HitReactionParam minimumSpeed="&RunningSpeed;" movementDirection="forward" reactionOnCollision="2">
      <AnimGraphReaction inputValue="hitRunForward">
        <Variations>
          <Variation name="stance" value="stand" />
          <Variation name="hitName" value="torsoStumble" />
          <Variation name="variant" value="02" />
        </Variations>
      </AnimGraphReaction>
    </HitReactionParam>

    <!-- If the collision sphere detects a collision with the environment, the system will trigger the collision reaction number 3 (right side collision, see below) -->
    <HitReactionParam minimumSpeed="&RunningSpeed;" movementDirection="right" reactionOnCollision="3">
      <AnimGraphReaction inputValue="hitStrafe">
        <Variations>
          <Variation name="hitName" value="Rgt_all_torso" />
        </Variations>
      </AnimGraphReaction>
    </HitReactionParam>
  <HitReactionParams>

  <!-- COLLISION REACTIONS -->
  <CollisionReactionParams>
    <!-- THE FIRST REACTION COLLISION SHOULD ALWAYS BE A FALL AND PLAY ONE, OTHERWISE ragdollOnCollision
    PROPERTY WON'T TRIGGER ANY RAGDOLL IN HIT REACTIONS -->
    <!-- Fall and Play collision -->
    <CollisionReaction reactionFunc="FallAndPlay_Reaction" />

    <!-- front collision -->
    <CollisionReaction animName="stand_tac_hitColl_front_torso_3p_01" snapOrientationAngle="0">
    </CollisionReaction>

    <!-- right side collision -->
    <CollisionReaction animName="stand_tac_hitColl_rgt_torso_3p_01" snapOrientationAngle="90">
    </CollisionReaction>

    <!-- ... -->
  </CollisionReactionParams>

</HitDeathReactionParams>
ReactionOnCollision анимационные мероприятия

Если анимация, воспроизводимая во время выполнения реакции, использует события анимации ReactionOnCollision, она сможет включать/отключать/изменять столкновения с окружающей средой. Пользовательский параметр события анимации изменит значение свойства reactionOnCollision реакции. Таким образом, запуск события анимации ReactionOnCollision с «0» в качестве пользовательского параметра отключит столкновения с окружающей средой, с «2» включит его и заставит запустить вторую определенную реакцию на столкновение и т. д.

Некоторые реакции даже не используют свойство reactionOnCollision, а полагаются на анимацию, чтобы установить столкновение с самой средой.

В Crysis 2 типичные показатели реакций столкновения следующие:

  1. Фронтальные столкновения
  2. Правосторонние столкновения
  3. Левосторонние столкновения
  4. Столкновения сзади
  5. Приседание при боковом столкновении справа
  6. Приседание при левом боковом столкновении
  7. Столкновения приседая назад
  • ragdollOnCollision - [Атрибут] (1/0) Более простая и удобочитаемая версия свойства reactionOnCollision. Итак:
<HitReactionParam animName="StumbleForward" ragdollOnCollision="1"/>

... эквивалентно:

<HitReactionParam animName="StumbleForward" reactionOnCollision="1"/>
  • collisionCheckIntersectionWithGround - [Атрибут] (1/0) Если включено, при реакциях, проверяющих столкновения с окружающей средой, сфера будет находиться на высоте ног персонажа. Используется при падающих смертях. Значение по умолчанию: «0»
  • noRagdollOnEnd - [Атрибут] (1/0) Если включено, рэгдолл не будет включен после завершения DeathReactions. Используется только для смертей от камеры от первого лица, поэтому заставляет персонажа оставаться на последнем кадре анимации. Значение по умолчанию: «0»
  • noAnimCamera - [Атрибут] (1/0) Указывает, будет ли камера следовать за анимацией или нет при реакции от первого лица. «1»: нет камеры с управлением анимацией, «0»: камера с управлением анимацией. Значение по умолчанию: «0»
  • endVelocity - [Атрибут] (Вектор) Он придает персонажу эту скорость, когда реакция заканчивается. Используется для улучшения перехода от реакций спотыкания к регулярным группам беговых движений. Если не указано, скорость не задается.
  • reactionFinishesAiming - [Атрибут] (1/0) Определяет, вызывает ли реакция (кроме DeathReaction) включение aimIk на персонаже после завершения. Это существует потому, что многие анимации реакции принимают следующую позу после того, как анимация реакции будет содержать прицеливание персонажа. Значение по умолчанию: «1»
  • snapOrientationAngle - [Атрибут] (Градусы) Если указано, ориентация персонажа будет привязана к началу выстрела, а затем повернута (против часовой стрелки) на количество градусов, указанное в свойстве right, когда начнется реакция. Это очень полезно для улучшения внешнего вида анимации реакции, которая показывает сильный импульс персонажа, поэтому импульс соответствует направлению выстрела, где бы он ни находился. например,
<DeathReactionParam animName="stand_deathHeavy_front_torso_01" snapOrientationAngle="0" shotOrigin="ahead" ragdollOnCollision="1">
  <AllowedHitTypes>
    &HeavyHitTypes;
  </AllowedHitTypes>
</DeathReactionParam>

<DeathReactionParam animName="stand_deathHeavy_back_torso_01" snapOrientationAngle="180" shotOrigin="behind" ragdollOnCollision="1">
  <AllowedHitTypes>
    &HeavyHitTypes;
  </AllowedHitTypes>
</DeathReactionParam>
  • snapToMovementDir - [Атрибут] (Градусы) Аналогично snapOrientationAngle, но вместо того, чтобы ориентировать персонажа по направлению к источнику кадра, он делает это по направлению его движения. Используется в некоторых реакциях бега (анимация реакции предполагает, что персонаж движется вперед, поэтому инерция движения анимируется вперед. Однако персонаж может бежать в любом направлении, но если привязать его к направлению движения, он будет выглядеть приемлемо, независимо от того, в каком направлении движется).

Советы по использованию системы

  • Система использует логику потоковой передачи вариаций анимации реакций, которая очень зависит от реакций и не является избыточной. Всегда старайтесь свести к минимуму количество реакций. используя <validationsection> как можно больше.
  • Работая с файлом данных, начните с определения наиболее конкретных реакций и закончите наиболее общими.
  • При добавлении новой реакции протестируйте ее, поместив ее определение в начало файла данных и удалив все условия для проверки. Таким образом, эта реакция будет выбрана в 100% случаев, и вам будет проще протестировать ее выполнение. После проверки выполнения вы можете начать добавлять ограничения проверки, пока не будете уверены, что оно выбрано в ожидаемом контексте. Затем переместите его на то место в списке реакций, которое имеет смысл. Использование g_hitDeathReactions_reload команду при каждом изменении, и все будет готово через несколько минут.
  • Настраиваемые функции LUA предназначены только для очень изолированных и специфических случаев или для быстрого тестирования. Если вы часто используете настроенную функцию, то лучше перенести этот код в код C++.
  • Не используйте Блокнот для редактирования файла данных HitDeathReaction.(если только вы не увлекаетесь мазохистскими практиками). Это лучший способ допустить синтаксические ошибки при редактировании файла. Я рекомендую использовать Ultra-Edit 32. (устанавливается по умолчанию на большинстве машин), Visual Studio, редактор XML или текстовый редактор с подсветкой синтаксиса для формата XML.
  • Используйте сущности XML, чтобы избежать дублирования в файлах XML. Если это поддерживается, используйте внешние объекты (описанные в Раздел «Определение типа документа») настолько, насколько это имеет смысл.
