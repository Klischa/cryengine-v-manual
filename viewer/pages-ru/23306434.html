Обзор


Создание треда на разных платформах со всеми нужными флагами может оказаться утомительной задачей. ThreadManager предлагает простой интерфейс для создания потоков и управления ими. Внутри он использует ThreadConfigurationManager, чтобы предложить решение на основе данных для управления различными характеристиками ваших потоков. Это также позволяет настраивать ваши потоки без необходимости повторной компиляции.

Загрузка файла .thread_config во время выполнения

Как только вы создадите свой thread_config вам нужно будет загрузить его во время выполнения. 

#include "ThreadConfigManager.h"

void Foo()
{
  ...
  // Load thread config
  gEnv->pThreadManager->GetThreadConfigManager()->LoadConfig("config/my_game.thread_config");
  ...
}

Перезапись конфигураций потоков

ThreadConfigurationManager позволяет загружать несколько thread_config файлы. Важно учитывать тот факт, что позже загружается thread_config файлы будут override характеристики потока, если они уже были определены ранее загруженным файлом. thread_config файл. Движок будет загружать файлы thread_config, специфичные для движка, перед кодом игры.

Порядок загрузки:

  1. engine_core.thread_config
  2. engine_sandbox.thread_config
  3. <ваша игра>.thread_config (управляется вами через вызов LoadConfig())

1. и 2. будут загружены в CSystem::Init() сразу после инициализации папок Engine.

Рекомендуется загрузить файл <вашей игры>.thread_config в CGameStartup::Init, чтобы избежать случая, когда вы пытаетесь инициализировать поток, еще не загрузив его конфигурацию.

Создание файла .thread_config

thread_config должен быть создан в пределах видимого пути среды движка/игры. например в твоем Активы папка/пак-файл. 

<ThreadConfig>
  <Platform name="TargetPlatform">
    <ThreadDefault Affinity="-1" Priority="Normal" StackSizeKB="32"/>
 
    <Thread name ="Bar" Affinity="-1" Priority="Normal" StackSizeKB="128"/>
    <Thread name ="Foo" Affinity="4,5" Priority="Normal"/>  
    ...
  </Platform> 
 
  <Platform name="OtherTargetPlatform">
    ...
   </Platform> 

</ThreadConfig>

Можно использовать следующие узлы XML:

<название платформы"">

Платформы с неизвестным количеством логических ядер:

Иногда вы сталкиваетесь с ситуацией, когда вам нужно изменить характеристики группы потоков, такие как их сходство, в зависимости от количества доступных ядер.

ThreadConfigurationManager позволяет вам добавлять исправления к каждому названию платформы с помощью "_Common", а также "_<AvailableCoreCount>".


"_Common":
 например <Имя платформы="PC_Common">

Определяет характеристики резьбы общий всеми AvailableCoreCount группы. Каждый AvailableCoreCount может override отображать характеристики каждой темы в своем разделе. Это сводит к минимуму необходимость переписывать одни и те же характеристики резьбы для каждой группы.


"_<AvailableCoreCount>
 например <Имя платформы="PC_8">

Определяет Группа AvailableCoreCount. Если число логических ядер равно, например, 8, ThreadConfigurationManager сначала выполнит поиск Настройте "PC_8" и загрузите конфигурации его потоков. Если он не может найти такую настройку, он будет искать следующую логическую базовую группу более низкого уровня.


<ThreadConfig>
  <!-- ============ -->
  <!-- === PC_Common === -->
  <!-- ============ -->
  <Platform name="PC_Common">
    <ThreadDefault Affinity="-1" Priority="Normal" StackSizeKB="32"/>    
    <Thread name ="Foo" Priority="Normal"/>
  </Platform>
  
  <!-- ============ -->
  <!-- === PC_4 === -->
  <!-- ============ -->
  <Platform name="PC_4">
    <!-- Extend for 4 core specific machines. May override Common settings -->
    <Thread name ="Foo_1" Affinity="0" Priority="Normal"/>
    <Thread name ="Foo_2" Affinity="0" Priority="Normal"/>
    <Thread name ="Foo_3" Affinity="1" Priority="Normal"/>
    <Thread name ="Foo_4" Affinity="1" Priority="Normal"/>
  </Platform>

  <!-- ============ -->
  <!-- === PC_8 === -->
  <!-- ============ -->
  <Platform name="PC_8">
    <!-- Extend for 8 core specific machines. May override Common settings -->
    <Thread name ="Foo_1" Affinity="0" Priority="Normal"/>
    <Thread name ="Foo_2" Affinity="0" Priority="Normal"/>
    <Thread name ="Foo_3" Affinity="1" Priority="Normal"/>
    <Thread name ="Foo_4" Affinity="1" Priority="Normal"/>
    <Thread name ="Foo_5" Affinity="2" Priority="Normal"/>
    <Thread name ="Foo_6" Affinity="2" Priority="Normal"/>
    <Thread name ="Foo_7" Affinity="3" Priority="Normal"/>
    <Thread name ="Foo_8" Affinity="3" Priority="Normal"/>
  </Platform>
</ThreadConfig>

Подстановочный знак "*":

Узел «Имя потока» XML позволяет использовать подстановочные знаки. Это полезно, если вы хотите создать любое количество потоков с одинаковыми настройками.

Мы могли бы переписать приведенный выше пример; «Пример: PC с определенным количеством логических ядер 4 и 8» который требует ручной настройки каждого потока для доступного количества ядер более общим способом, когда потоки группируются в группы сходства.

Код времени выполнения:

// Create arbitrary number of threads and distribute them on cores evently
int nMaxCoreCount = GetCoreCount();
for (int i = 0; i < nNumThreadsToSpawn; ++i)
{
    int nAffinityGroup= i % nMaxCoreCount; // stay within the bounds of available cores
 
  SFooThread* pFooThread = new SFooThread();
  if (!gEnv->pThreadManager->SpawnThread(pFooThread , "Foo_A%i_%i", nAffinityGroup, i))
  {
      // Handle error
  }
 
  // Store thread for later access
}


.thread_config

<ThreadConfig>
  <!-- ============ -->
  <!-- === PC_Common === -->
  <!-- ============ -->
  <Platform name="PC_Common">
    <ThreadDefault Affinity="-1" Priority="Normal" StackSizeKB="32"/>    
    <Thread name ="Foo_A0_*" Affinity="0" Priority="Normal"/>
    <Thread name ="Foo_A1_*" Affinity="1" Priority="Normal"/>
    <Thread name ="Foo_A2_*" Affinity="2" Priority="Normal"/>
    <Thread name ="Foo_A3_*" Affinity="3" Priority="Normal"/>
  </Platform>
  
  <!-- ============ -->
  <!-- === PC_4 === -->
  <!-- ============ -->
  <Platform name="PC_4">
    <!-- Now empty as all cases are handled by PC_Common section -->
  </Platform>

  <!-- ============ -->
  <!-- === PC_8 === -->
  <!-- ============ -->
  <Platform name="PC_8">
    <!-- Now empty as all cases are handled by PC_Common section -->
  </Platform>
</ThreadConfig>

Ключи узла:


<ThreadDefault name="">

Имеет те же характеристики, что и узел <Thread> XML, за исключением того, что он используется для всех потоков, в которых имя потока не определено узлом <Thread> XML.
