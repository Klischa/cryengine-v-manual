Нижеследующее не является полным списком изменений CRYENGINE 5.6 C++ API, а скорее указывает на наиболее важные изменения, о которых программистам необходимо знать.

Оглавление

Компоненты

  • RigidBodyComponent
    • RigidBodyComponent недвижимость для Плотность и Сопротивление теперь имеют более высокое значение по умолчанию 1000.
  • PointConstraintComponent
    • PointContraintComponent сейчас активный по умолчанию.
  • AudioSwitchComponent
    • Этот компонент был перенесен в SwitchStateComponent.

Основная система

  • CRY_ASSERT_MESSAGE устарел. CRY_ASSERT теперь имеет функцию предоставления сообщения в случае необходимости и его следует использовать вместо этого. В пользовательском коде достаточно простого поиска и замены.

Система сущностей

  • IEntityComponent::GetEventMaskподпись пользователя изменилась с uint64 GetEventMask() const чтобы Cry::Entity::EventFlags GetEventMask() const. Пользовательский код необходимо обновить, чтобы изменить возвращаемое значение, код внутри должен продолжать создаваться и функционировать, как раньше.
  • ENTITY_EVENT_BIT и БИТ64 макросы больше не нужно использовать для IEntityComponent::GetEventMask. Вместо этого событие можно применить напрямую. Например: Cry::Entity::EventFlags GetEventMask() const { return EEntityEvent::Обновить | EEntityEvent::NameChanged; }.
    • Переход от ENTITY_EVENT_BIT можно автоматизировать с помощью инструмента поиска и замены Visual Studio. Найти: "ENTITY_EVENT_BIT\((?<событие>.+?)\)", и замените на "${событие}", без кавычек. Обязательно включите «Использовать регулярные выражения».
  • Таймеры сущностей были перенесены с уровня сущностей (IEntity) на уровень компонента (IEntityComponent). Это изменение было сделано для того, чтобы исключить необходимость поиска уникального идентификатора на уровне экземпляра объекта во избежание конфликта с другими компонентами, что может оказаться очень дорогостоящим.
    • Большинство вариантов использования компонента могут измениться. m_pEntity->SetTimer чтобы это->SetTimer и сохранить поведение, как прежде. То же самое относится и к KillTimer.
