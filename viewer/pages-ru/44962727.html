Нижеследующее не является полным списком изменений CRYENGINE 5.4 C++ API, а скорее указывает на наиболее важные изменения, о которых программистам необходимо знать.

Оглавление

Visual Studio Поддержка

В CRYENGINE 5.4.0 представлена поддержка Visual Studio 2017. Кроме того, пользователям Visual Studio 2015 необходимо установить обновление 3, чтобы успешно скомпилировать версию исходного кода Engine 5.4.0.

Уведомления об устаревании

Этот выпуск официально устарел:

  • Игровые объекты (IGameObject, IGameObjectExtension — заменены новыми компонентами сущностей (IEntityComponent). Примечание: (IGameObject, IGameObjectExtension будут удалены в будущей версии движка.
  • Правила игры (IGameRulesSystem, IGameRules) — заменены на INetworkedClientListener (дополнительную информацию см. ниже).
  • Актеры (IActorSystem, IActor) — заменены новыми Entity Components, которые будут использоваться вместе с INetworkedClientListener.
  • Стандартные объекты 5.3.0 (дополнительную информацию см. ниже) — заменены новыми стандартными компонентами.
  • Папки устаревших игр (sys_game_folder, sys_dll_game) — заменены системой проектов. Примечание. Будет выполнена автоматическая миграция (после первого запуска 5.4.0). Поддержка старых папок с игрой будет удалена в будущем обновлении движка.
  • CryPlugin.csv — заменен системой проектов. Автоматическая миграция будет выполнена при первой загрузке, при этом все плагины будут перемещены в файл .cryproject.

Имейте в виду, что устаревший проект GameSDK использует множество устаревших систем и в будущем он будет удален. Однако мы еще не пометили его как устаревший, поскольку сначала ждем, пока шаблоны будут точно соответствовать функциональности GameSDK.

Система сущностей и схема

Схема

Новая система Entity Component (которая была представлена в CRYENGINE 5.3.0) была скорректирована для унификации с настройкой Schematyc. Это означает, что любой компонент, представленный в новом формате 5.4.0 (пример ниже), автоматически станет доступен в Инспекторе и Schematyc, так что дизайнеры смогут создавать более сложные логические объекты.

Существующий метод создания компонентов версии 5.3.0 по-прежнему доступен, однако мы будем постепенно отказываться от него по мере развития новой унифицированной установки. Частью развития новой настройки будет сокращение количества кода, необходимого для предоставления компонента, поэтому имейте в виду, что приведенный ниже пример в будущем не будет таким грубым:

#include <CrySchematyc/CoreAPI.h>
class CMyComponent final : public IEntityComponent
{
public:
  static CryGUID& IID()
  {
    static CryGUID id = "{AD383B41-C144-4F99-9A2B-0FA2D9D86245}"_cry_guid;
    return id;
  }
  
  void MyFunction() 
  {
    // Print to the console
    CryLogAlways("Hello world!"); 
    
    // Signals can only be sent when the component was attached through Schematyc
    if(Schematyc::IObject* pObject = m_pEntity->GetSchematycObject())
    {
      // Send the signal back to Schematyc, along with our instance GUID
      pObject->ProcessSignal(SMySignal { m_bSignalResult }, GetGUID());
    }
  }
  struct SMySignal { bool m_bReturnValue; };
  bool m_bSignalResult = false;
};
void ReflectType(Schematyc::CTypeDesc<CMyComponent>& desc)
{
  desc.SetGUID(CMyComponent::IID());
  desc.SetEditorCategory("MyCategory");
  desc.SetLabel("MyComponent");
  desc.SetDescription("Does awesome things!");
  desc.SetComponentFlags({ IEntityComponent::EFlags::Socket, IEntityComponent::EFlags::Attach });
  desc.AddMember(&CMyComponent::m_myMember, 'memb', "MyMember", "My Member", "A property that can be changed", 10);
}
static void ReflectType(Schematyc::CTypeDesc<CMyComponent::SMySignal>& desc)
{
  desc.SetGUID("{DBBDB49C-6C48-446E-9451-DAA32E6FA240}"_cry_guid);
  desc.SetLabel("My Signal");
  desc.AddMember(&CMyComponent::SMySignal::m_bReturnValue, 'ret', "ReturnVal", "Return Value", "Description", false);
}
static void RegisterMyComponent(Schematyc::IEnvRegistrar& registrar)
{
  Schematyc::CEnvRegistrationScope scope = registrar.Scope(IEntity::GetEntityScopeGUID());
  {
    Schematyc::CEnvRegistrationScope componentScope = scope.Register(SCHEMATYC_MAKE_ENV_COMPONENT(CMyComponent));
    // Functions
    {
      auto pFunction = SCHEMATYC_MAKE_ENV_FUNCTION(&CMyComponent::MyFunction, "{FE5B34ED-A5DD-4C3B-A81C-38B5D980A770}"_cry_guid, "MyFunction");
      pFunction->SetDescription("Triggers our test function");
      componentScope.Register(pFunction);
    }
    // Signals
    componentScope.Register(SCHEMATYC_MAKE_ENV_SIGNAL(CMyComponent::SMySignal));
  }
}
CRY_STATIC_AUTO_REGISTER_FUNCTION(&RegisterMyComponent);

Стандартные компоненты

Объекты по умолчанию, представленные в CRYENGINE 5.3.0, по-прежнему являются частью Engine, но теперь считаются устаревшими и будут удалены в будущем выпуске Engine. Эти объекты больше не доступны для создания в редакторе Sandbox, но существующие экземпляры продолжат работать.

Новые стандартные компоненты могут использоваться как дизайнерами, так и программистами, использующими C++. Например, обновленные шаблоны 5.4 активно используют новые стандартные компоненты, чтобы сократить объем кода, необходимого для начала работы. Новые компоненты можно включить по пути <DefaultComponents/...`>.

Все компоненты находятся в Cry::DefaultComponents namespace.

Разное

  • EntityGUID теперь является полноценным 128-битным GUID. Анализ устаревших 64-битных идентификаторов GUID по-прежнему будет работать, но преобразуется при экспорте.
  • IEntity::Activate удален. Отдельные компоненты теперь могут возвращать BIT64(ENTITY_EVENT_UPDATE) в GetEventMask и вызывать UpdateComponentEventMask для запуска повторной активации.
    • Для устаревшего кода используйте IGameObject::ForceUpdate(true), чтобы имитировать то же поведение, что и раньше.
  • IEntity::IsActive переименован в IsActivatedForUpdates.
  • Функции IEntityComponent PreInit, Initialize, OnShutDown, OnTransformChanged, ProcessEvent и Run теперь называются protected и поэтому не могут быть вызваны извне самого компонента.
    • Если вам нужно отправить событие определенному компоненту, используйте IEntityComponent::SendEvent.

Шаблоны

Шаблоны были подвергнуты рефакторингу, чтобы для достижения того же конечного результата требовалось гораздо меньше кода. Также были представлены новые системы, которые позволили нам удалить зависимости от устаревших систем:

  • Заменено использование IGameObject и IGameObjectExtension — теперь напрямую используется новая система IEntityComponent.
  • Удалены большие блоки дублированного кода в шаблонах. Теперь используются новые стандартные компоненты, чтобы упростить создание базового игрового процесса.
  • Заменены IGameRules и IActor — теперь используются INetworkedClientListener (дополнительную информацию см. ниже) и IEntityComponent напрямую. Играм больше не нужно использовать устаревшую систему актеров для поддержки игроков.

Сеть

Рефакторинг нашей сети продолжается и начнется с public API. Цель состоит в том, чтобы удалить сетевые зависимости (в устаревшем модуле CryAction), чтобы упростить использование сетей в коде играми. Это также подготовка к будущему рефакторингу внутренних компонентов нашей сети.

Получение обратных вызовов клиентского подключения

INetworkedClientListener и INetwork::AddNetworkedClientListener были добавлены в качестве альтернативы устаревшей системе правил игры. Этот интерфейс можно использовать для получения обратных вызовов при подключении клиентов по сети, что позволяет пропустить использование игровых правил в проектах. Шаблоны были обновлены, чтобы использовать это.

Поддержка удаленного вызова метода (RMI) для новых компонентов сущностей

В первоначальной версии движка 5.3.0 новая система Entity Component не поддерживала RMI, теперь это исправлено и позволяет объединять в сеть новый код сущности. См. пример ниже.

#include <CryNetwork/Rmi.h>
class CNetworkedComponent final : public IEntityComponent
{
  virtual void Initialize() final
  {
    SRmi<RMI_WRAP(&CNetworkedComponent::RemoteEntityMethod)>::Register(this, eRAT_NoAttach, false, eNRT_ReliableOrdered);
    m_pEntity->GetNetEntity()->BindToNetwork();
  }
  // Parameters to serialize an entity id across the network
  struct SEntityParams
  {
    EntityId entityId;
    void SerializeWith(TSerialize ser)
    {
      // Called to serialize and deserialize the entity id, note the 'eid' policy
      // This policy is used to convert entity identifiers between machines as id's are not unique over the network.
      ser.Value("entityId", entityId, 'eid');
    };
  };
  bool RemoteEntityMethod(SEntityParams&& params, INetChannel* pNetChannel)
  {
    if (IEntity* pEntity = gEnv->pEntitySystem->GetEntity(params.entityId))
    {
      // Success!
    }
    // Return true to indicate that RMI was valid, a value of false indicates that something went wrong - for example validation of input indicates cheating.
    return true;
  }
  void InvokeRemoteEntityMethod(EntityId id)
  {
    SRmi<RMI_WRAP(&CNetworkedComponent::RemoteEntityMethod)>::InvokeOnRemoteClients(this, SEntityParams{ id }, id);
  }
};

Сериализация сетевых аспектов для новых компонентов сущности

В дополнение к RMI, в версии 5.4 также представлена поддержка сериализации фрагментов данных как аспектов по сети. Это может быть полезно, например, для синхронизации ввода данных игрока. Мы прикрепили пример ниже:

class CNetworkedAspectComponent final : public IEntityComponent
{
  virtual void Initialize() final
  {
    m_pEntity->GetNetEntity()->BindToNetwork();
  }
  virtual NetworkAspectType GetNetSerializeAspectMask() const final { return 1 << GetNetSerializationAspect(); }
  // Called when serializing and deserializing
  virtual bool NetSerialize(TSerialize ser, EEntityAspects aspect, uint8 profile, int flags) final
  {
    if (aspect == GetNetSerializationAspect())
    {
      // Serialize or deserialize our flags, note that the optional third parameter specifies the selected compression policy
      ser.Value("m_flags", m_flags);
    }
  }
  const EEntityAspects GetNetSerializationAspect() const { return eEA_GameClientD; }
  // Call when m_flags changes and we want to serialize the data to the other machines.
  void RequestNetSyncToOthers() { m_pEntity->GetNetEntity()->MarkAspectsDirty(GetNetSerializationAspect()); }
  uint32 m_flags;
};

Анимация

  • Представлен IAnimEventPlayerGame — заменяет жестко запрограммированный поиск строк.
    • Character Tool ранее нашел пользовательскую реализацию игры IAnimEventPlayer, выполнив поиск класса с именем CVar 'sys_game_name'. Сейчас это удалено. Вместо этого система теперь ищет первую найденную реализацию IAnimEventPlayerGame и предоставляет ее Character Tool.
  • IAnimationPoseAligner::Update — теперь принимает экземпляр персонажа.
  • IActionController::FindOrCreateProceduralContext – больше не может принимать строку, вместо этого передается идентификатор класса, например CProceduralContextRagdoll::GetCID()

Аудио

  • Все аудиоинтерфейсы были переработаны для использования нового CryAudio namespace.
    • Например, AudioControlId теперь называется CryAudio::ControlId.

Обозреватель ресурсов и пути

  • Ресурсы движка больше нельзя загружать по пути «Engine/EngineAssets». Теперь его необходимо изменить на «%ENGINE%/EngineAssets». Ресурсы Engine автоматически появятся в браузере активов и будут автоматически использовать новый путь.

Разное

  • CryCreateClassInstance(const char*, std::shared_ptr<T>&) – удалено, используйте CryCreateClassInstance(const CryClassID& cid, std::shared_ptr<T>& p) или CryCreateClassInstanceForInterface(const CryInterfaceID& iid, std::shared_ptr<T>& p).
    • Например, CryCreateClassInstance("AnimationPoseModifier_OperatorQueue", m_poseModifier); становится CryCreateClassInstanceForInterface(cryiidof<IAnimationOperatorQueue>(), m_poseModifier);
  • Для загрузки ресурсов Engine в коде теперь требуется префикс «%ENGINE%», например «%ENGINE%/EngineAssets/Textures/White.dds».
  • Регистрация узла потока больше не требует реализации обширной дополнительной логики для каждой игры. Вместо этого вызовите CryRegisterFlowNodes во время инициализации и CryUnregisterFlowNodes во время завершения работы.
  • CryMath/Random.h — больше не включается по умолчанию в некоторые файлы заголовков. Это может привести к тому, что в проекты придется включать файлы вручную (#include <CryMath/Random.h>).
  • Функции IConsole, которые использовались для регистрации консольных команд и переменных CVar, больше не являются общедоступными. Возможно, вам придется обновить свой код, чтобы использовать уже существующие макросы или новый класс ConsoleRegistrationHelper (все они расположены в <CrySystem/ISystem.h>.
