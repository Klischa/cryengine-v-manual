CryPak Файловые архивы

CryPak — модуль, позволяющий хранить файлы игрового контента в сжатом или несжатом архиве.

Особенности

  • Совместим со стандартным форматом zip (реализация основана на библиотеке zlib).
  • Поддерживает хранение файлов в архиве или вне стандартной файловой системы.
  • Данные могут считываться синхронно (приостанавливается до тех пор, пока данные не будут загружены) и асинхронно (потоковая передача) через IStreamCallback (макс. смещение 4 ГБ, файлы 4 ГБ).
  • Файлы могут храниться в сжатом или несжатом виде.
  • При необходимости несжатые файлы можно прочитать частично.
  • Сравнение имен файлов не чувствительно к регистру (внутри все преобразуется в нижний регистр).
  • Поддерживает загрузку файлов zip/pak размером до 4 ГБ (доказано, что работает с файлами размером более 2,1 ГБ).

Юникод и обработка абсолютного пути

Внутри весь код обработки пути ASCII-на основе, поэтому есть нет Юникод (16-битные символы для разных языков), которые можно использовать. Это для экономии памяти и для простоты. В Unicode нет реальной необходимости, поскольку игру можно и нужно разрабатывать с именами путей ASCII. Производство без этого требования будет иметь проблемы с интеграцией представителей других национальностей. Поскольку пользователь может устанавливать игры в папку с символами Юникода, абсолютные пути явно избегаются во всем движке.

Многослойность

Обычно данные игрового контента организованы в несколько pak-файлов, которые расположены в каталоге игры. Если для операции открытия запрашивается файл, система CryPak просматривает все зарегистрированные файлы pak, чтобы найти файл. Файлы Pak просматриваются в порядке создания. Таким образом, предпочтительными являются файлы patch pak, которые были добавлены в сборку позже. Также возможно смешивать файлы pak со свободными файлами, которые хранятся непосредственно в файловой системе (а не в пакете). Если файл существует как в виде отдельного файла, так и в виде pak-архива, свободный файл предпочтительнее, когда игра находится в стадии разработки. режим разработки. Однако, чтобы избежать мошенничества в поставляемой игре, файл, хранящийся в пакете, предпочтительнее свободного файла, когда игра не запускается в режиме разработки.

Слэши

Обычно косая черта (/) используется для внутренней обработки, но пользователи могут вводить пути, содержащие обратную косую черту.

Специальная обработка папок

Псевдоним пути %USER% может использоваться для указания пути относительно пользовательской папки. Это может потребоваться для хранения пользовательских данных. Windows может иметь ограничения на то, где пользователь может хранить файлы. Например, папка программы может быть вообще недоступна для записи. По этой причине скриншоты, данные сохранений и другие файлы должны храниться в папке пользователя. Ниже приведены примеры допустимых имен файлов с указанием пути:

%USER%/ProfilesSingle/Lisa.dat
game/Fred.dat

Внутренности

  • Существует известная ошибка реализации, которая вызывает проблемы при использовании более 1000 файлов в каталоге.
  • Свойства формата:
    • Формат файла zip хранит каждый файл с небольшим заголовком, включающим его путь и имя файла в несжатой текстовой форме. Для более быстрого доступа к файлу в конце файла есть каталог. В каталоге также хранятся путь и имя файла в несжатой текстовой форме (избыточно).

Создание пак-файла с помощью 7za

Вы можете легко создать pak-файл, используя команду 7-Zip инструмент с помощью команды:

7za a -tzip -r -mx0 <PakFileName> [file1 file2 file3 ...] [dir1 dir2 ...]

Работа с большими Pak-файлами

zip RFC определяет два типа zip-файлов, обозначаемых форматом zip версии 45. Старые zip-архивы имеют возможность смещения на 4 ГБ, но в случае использования устаревших функций ввода-вывода можно искать только +- 2 ГБ. Поэтому практический предел составляет 2 ГБ. Смещения 4 ГБ не имеют ничего общего с собственными типами компьютеров (и, конечно, не меняют размер в зависимости от платформы, компилятора или конфигурации), смещения для zip-архивов более старых версий находятся в независимом от машины uint32, смещения для zip-архивов новой версии находятся в uint64, добавляемом к структурам старой версии. Версия, которую использует zip-файл, указана в заголовке, и приложения могут не поддерживать более новую версию: http://www.pkware.com/documents/casestudies/APPNOTE.TXT

Вам не нужно думать об обработке разделения вручную, RC поддерживает автоматическое разделение:

  • «zip_sizesplit» — «Автоматически разбивать zip-файлы при достижении максимального размера сжатого файла (настроенного или поддерживаемого)» (ограничение неявно составляет 2 ГБ, если оно не указано явно).
  • «zip_maxsize» — «Максимальный сжатый размер zip-архива в КБ» (это явное ограничение).

Разделение работает во всех случаях, поддерживает многопоточность и инкрементные обновления. Он автоматически расширяет и сжимает цепочку необходимых застежек-молний. Сортировка соблюдается в максимально возможной степени, даже несмотря на дополнительные модификации, но отдельные файлы могут быть помещены в конец частей, чтобы заполнить оставшееся пространство, вместо того, чтобы следовать строгой сортировке.
