Обзор

Можно отслеживать недействительные чтения файлов (происходящие в игре) во время выполнения. Сообщение об ошибке «Неверный доступ к файлу» означает чтение или попытку открытия файлов из потока, который не является потоком потоковой передачи. Эти операции доступа к файлам могут привести к серьезным зависаниям.

В настоящее время отслеживание доступа к файлам регистрирует доступ только из основного потока и потока рендеринга.

CVars

Следующие CVar активируют другую опцию для отслеживания доступа к файлу.

sys_PakLogInvalidFileAccess 1 (Настройка по умолчанию)

  • Доступ регистрируется в game.log
  • Генерирует предупреждение perfHUD
  • Написано на экране красным в верхнем левом углу экрана.
  • Остановка на 3 секунды в нерелизных сборках

sys_PakLogInvalidFileAccess 2

  • Доступ к файлу вместе со стеком вызовов регистрируется и сохраняется в файле на консоли в подкаталоге FileAccess (в настоящее время только для Xbox 360).
  • Также все функции 1 выше

sys_PakMessageInvalidFileAccess:

  • Создает всплывающее диалоговое окно (для PC и Xbox 360, отладка на PS3) при доступе к файлу. Вы можете войти в отладчик или продолжить.

Где определяется неверный доступ?

Точки, которые определяют, когда доступ к файлу недействителен, устанавливаются с помощью ICryPak::DisableRuntimeFileAccess с значением true или false. Эти точки, возможно, потребуется настроить для одиночной и многопользовательской игры.

Исключения

В отслеживание доступа к файлам можно добавить некоторые исключения, чтобы вы могли игнорировать определенные файлы (например, game.log).

Просто создайте экземпляр CDebugAllowFileAccess в области доступа к файлу.

Разрешение стеков вызовов доступа к файлам

Файлы, собранные с помощью pak_LogInvalidFileAccess 2 потребуется разрешение их стеков вызовов, для этого нам понадобится .pdb файлы из сборки, XenonStackParse инструмент и вспомогательный скрипт ProcessFileAccess.py.

Инструменты можно найти в XenonStackParse папка каталога Tools.

Структура каталогов для запуска ProcessFileAccess.py должна быть следующей.

<Корень>
--> XenonStackParse
--> FileAccessLogs (этот каталог должен содержать файлы .pdb)
------> Обработано (выходные данные от XenonStackParse)

Беги ProcessFileAccess.py из FileAccessLogs dir (XenonStackParse использует рабочий каталог для поиска файлов .pdb). Это создаст каталог с именемprocessed, в котором будет файл, содержащий разрешенный стек вызовов для каждого из зарегистрированных файлов.
