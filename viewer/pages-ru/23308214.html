Разделы

При пакетном преобразовании ресурсов с помощью RC (см. вышестоящую статью) вы можете выполнить преобразование XML в двоичный формат.

Двоичное преобразование XML принимает входной файл XML, анализирует его, фильтрует элементы и атрибуты XML и сохраняет дерево узлов в двоичном формате.

Преимущества

  • Меньший размер файла.
  • Быстрее читать во время выполнения.
  • Может быть отфильтрован, чтобы содержать только определенные данные.

Недостатки

  • Не читабельно для человека.
  • Недоступно для редактирования человеком.

Конверсия

В файле Job XML (см. вышестоящую статью) добавьте <Вакансия> Блок XML в группе <ConvertJob> выглядит следующим образом:

<Properties source_folder="..."/>
<Properties target_folder="..."/>
<Properties xml_types="..."/>
<!-- For SDK conversion, we use xml_types="*.animevents;*.animsettings;*.adb;*.bspace;*.cdf;*.chrparams;*.comb;*.dlg;*.ent;*.fsq;*.fxl;*.ik;*.json;*.lmg;*.mtl;*.setup;*.xml;*.node;*.veg" -->
 
<ConvertJob>
  <!-- Add a job similar to this -->
  <Job sourceroot="${source_folder}" input="${xml_types}" targetroot="${target_folder}" overwriteextension="xml" xmlfilter="xmlfilter.txt" />
</ConvertJob>

В этом примере ссылка на файл «xmlfilter.txt», этот файл находится в Bin64\RC\xmlfilter.txt. Этот файл определяет, какие файлы конвертируются и как.

Свойство overwriteextension используется для принудительной оценки файлов, соответствующих входному набору, как если бы они были файлами XML (см. родительский документ, посвященный overwriteextension).

Поскольку выходной файл можно фильтровать, преобразование потенциально может быть с потерями. Как и при большинстве преобразований ресурсов, вам всегда следует хранить исходный файл в другом месте в качестве преобразованного файла, чтобы предотвратить потерю данных.

Фильтровать файл

Файл, указанный через свойство xmlfilter, форматируется как простой текст, при этом каждая инструкция фильтра находится в отдельной строке файла.

При анализе этого файла пустые строки игнорируются, все остальные строки должны быть отформатированы следующим образом:

a <modifier> <attribute name>
e <modifier> <element name>
f table <file mask>
  • Строка, начинающаяся с «a», объявляет фильтр для атрибута XML. Используйте подстановочный знак «*», чтобы сопоставить несколько имен атрибутов.
  • Строка, начинающаяся с «e», объявляет фильтр для элемента XML. Используйте подстановочный знак «*», чтобы сопоставить несколько имен элементов.
  • Модификатором для «a» или «e» может быть либо «+» (чтобы включить соответствующие данные XML в двоичные данные), либо «-» (чтобы исключить соответствующие данные XML).
  • Строка, начинающаяся с «f table», объявляет фильтр для файлов XML, которые будут подвергаться преобразованию таблиц из экспортированного формата XML-таблицы Microsoft Excel. Укажите маску файла, чтобы применить фильтр к файлам, соответствующим маске. Используйте подстановочный знак «*», чтобы сопоставить несколько файлов.

Фильтры элементов и атрибутов файла фильтра оцениваются сверху вниз. Первое правило соответствия для каждого элемента XML выбирается, чтобы определить, будет ли он отфильтрован или нет. Если элемент фильтра атрибутов не соответствует элементу XML, он не будет отфильтрован.
