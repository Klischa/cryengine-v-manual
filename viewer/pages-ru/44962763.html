Примечания по переходу с CRYENGINE 5.4 на CRYENGINE 5.5


ВС2017 15.8

При обновлении до VS2017 15.8 проектам CRYENGINE потребуется перестройка. При обновлении у некоторых пользователей могут возникнуть такие проблемы, как ошибки компиляции. В таких случаях попробуйте следующее;

  1. При использовании шаблонного базового класса необходимо добавлять «this->» везде, где код ссылается на член базового класса.
  2. При ссылке на typedef, определенный в классе template, перед именем необходимо добавить ключевое слово typename.
  3. Если символ не может быть найден, даже если включен заголовок, содержащий объявление, попробуйте использовать упреждающие объявления и разбить заголовки, чтобы избежать циклических включений.
  4. Если компилятор жалуется на обнаружение члена класса template, попробуйте удалить пустое тело класса из базы класса template.

Более подробную информацию можно найти в записи блога VS. https://blogs.msdn.microsoft.com/visualstudio/2018/08/14/visual-studio-2017-version-15-8/

Создание резервной копии вашего проекта

При обновлении проекта с CRYENGINE 5.4 до 5.5 рекомендуется сделать резервную копию проекта.

Если вы используете программу запуска для доступа к своему проекту, вам будет предложено сделать это автоматически.

Если резервное копирование не выполняется через Панель запуска, выполните следующие действия:

  1. Щелкните правой кнопкой мыши файл .cryproject.
  2. Выберите Резервное копирование проекта
  3. Выберите место резервной копии (если вы хотите, чтобы оно отличалось от места по умолчанию)
  4. Нажмите Подтвердить

Обновление проекта шаблона (только ресурсы)

  1. Создайте новый проект, используя тот же template, который вы использовали ранее.
  2. Удалить новые проекты template' Активы каталог.
  3. Скопируйте свой Активы каталог и ваш Game.cryproject файл в новую папку проекта template.
  4. Щелкните правой кнопкой мыши на своем Game.cryproject файл и выберите Изменить версию двигателя и выбери CRYENGINE 5.5.
  5. Запустите редактор Sandbox с новым проектом template и следуйте инструкциям, чтобы обновить файлы уровней до нового формата.

Обновление проекта шаблона (активы и игровой код)

Обновление кода игры необходимо только в том случае, если вы внесли изменения в исходный код своей игры. В этом случае вам следует направить назначенного вам программиста в Важная информация CRYENGINE 5.5. Изменения данных и кода.

  1. Щелкните правой кнопкой мыши Game.cryproject файл и выберите Переключить версию двигателя и выбери CRYENGINE 5.5.
  2. Затем восстановите файлы решения исходного кода, щелкнув правой кнопкой мыши Game.cryproject и выбирая Создать решение.

Теперь вы сможете следовать указанному выше руководству по изменению интерфейса, чтобы внести изменения в исходный код и перестроить файл проекта.

Обновление проекта GameSDK (только ресурсы)

  1. Щелкните правой кнопкой мыши GameSDK.cryproject файл и выберите Переключить версию двигателя и выбери CRYENGINE 5.5.
  2. Обновите/подтвердите свой GameSDK Пример проекта актив через лаунчер.
  3. Скопируйте бин/win_x64/GameSDK.dll файл из проекта Launcher в свой проект в соответствующий каталог.
  4. Запустите редактор Sandbox с новым проектом template и следуйте инструкциям, чтобы обновить файлы уровней до нового формата.

Обновление проекта GameSDK (активы и игровой код)

Обновление кода игры необходимо только в том случае, если вы внесли изменения в исходный код своей игры. В этом случае вам следует направить назначенного вам программиста в Важная информация CRYENGINE 5.5. Изменения данных и кода. Поскольку код GameSDK содержится только в исходном коде Engine, создание Engine выходит за рамки данного руководства, но подробности можно найти на наших страницах документации. здесь.

  1. Щелкните правой кнопкой мыши GameSDK.cryproject файл и выберите Переключить версию двигателя и выбери CRYENGINE 5.5.
  2. Пересоберите проект GameSDK, внеся изменения в соответствии с приведенной выше документацией, и скопируйте новый GameSDK.dll в ваш проект.
  3. Запустите редактор Sandbox с новым проектом template и следуйте инструкциям, чтобы обновить файлы уровней до нового формата.

Перенос файлов редактора управления звуком (ACE)

Начиная с версии 5.5, файлы ACE будут сохраняться в папке, специфичной для промежуточного программного обеспечения, поэтому каждая реализация промежуточного программного обеспечения полностью отделена друг от друга.

  1. Создайте папку под названием «assets» внутри текущего audio/<middleware> папка.
  2. Переместите все звуковые банки и аудиофайлы из папки промежуточного программного обеспечения в новую подпапку «assets». Например:

    • audio/wwise чтобы audio/wwise/assets

    • audio/fmod чтобы audio/fmod/assets

    • audio/sdlmixer чтобы audio/sdlmixer/assets

  3. Сделайте резервную копию всех файлов *.xml в audio/ace папка.
  4. Снимите защиту от записи для всех файлов .xml внутри файла. audio/ace папка.
  5. Удалите все файлы .xml из файлов .pak (обычно внутри audio.pak).
  6. Запустите редактор Sandbox и откройте Редактор управления звуком из Инструменты меню.
  7. Все аудиобиблиотеки теперь должны быть помечены как измененные. Нажмите кнопку Сохранить все кнопка внутри Редактор управления звуком.
  8. Если проект содержит запросы на предзагрузку, появится диалоговое окно с запросом на перезагрузку аудиосистемы. Нажмите Да.
