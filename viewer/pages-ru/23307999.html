Обзор

Для (скелетного) персонажа в игре существуют определенные определения, которые должны быть сделаны в единой файловой структуре XML, называемой файлом .chrparams.

Эти определения сгруппированы в 3 группы: LOD Определения, IK Определенияи Список анимаций.

Ранее эта информация была помещена в 3 файла: *.setup, *.ik и *.cal. В CRYENGINE 3.3 файлы .cal, .ik и .setup были объединены в один более удобный файл.

Все определение подкреплено <Параметры> </Параметры> тег. Внутри этого тега есть три тега, охватывающие три раздела, названные выше.

CHRPARAMS Определения

LOD Определения

Для каждого LOD предоставляется JointList, который определяет количество имен соединений, доступных в этом LOD:

<JointList level="number">
  <Joint name="Name Of Joint 1"/>
  <Joint name="Name Of Joint 2"/>
  ...
</JointList>

Таким образом, весь раздел будет выглядеть так:

<Lod>
  <JointList level="0"> ... </JointList>
  <JointList level="1"> ... </JointList>
</Lod>

В файле chrparams может быть не более одного блока <Lod>.

IK Определения

В этом разделе определяются имена соединений, которые используются для различных механизмов IK (AimIK, LookIK, LimbIK и управляемых анимацией IK целей).

Вам необходимо включить каждое определение IK в тег <IK_Definition>.

<IK_Definition>
  <AimIK_Definition>
    <RotationList>
      <Rotation Additive="1" JointName="Bip01 Pelvis" Primary="1"/>
      <Rotation Additive="1" JointName="Bip01 Spine" Primary="1"/>
      <Rotation Additive="1" JointName="Bip01 Spine1" Primary="1"/>
    </RotationList>
    <PositionList>
      <Position JointName="Bip01 Camera"/>
    </PositionList>
    <RWeaponJoint JointName="weapon_bone"/>
    <LWeaponJoint JointName="Lweapon_bone"/>
    <DirectionalBlends>
      <Joint AnimToken="AimPosesL" ParameterJoint="Lweapon_bone" StartJoint="Bip01 L UpperArm"/>
    </DirectionalBlends>
  </AimIK_Definition>
  <LookIK_Definition/>
  <LimbIK_Definition>
    <IK EndEffector="Bip01 R Hand" Handle="RgtArm01" Root="Bip01 R UpperArm" Solver="2BIK"/>*
    <IK Handle="RGAlign1" J0="Bip01 R Thigh" J1="Bip01 R Calf" J2="Bip01 R Foot" J3="Bip01 R Heel" J4="Bip01 R Toe0" Solver="CCD5"/>
  </LimbIK_Definition>
  <Animation_Driven_IK_Targets>
    <ADIKTarget Handle="LftArm01" Target="Bip01 LHand2Weapon_IKTarget" Weight="Bip01 LHand2Weapon_IKBlend"/>
  </Animation_Driven_IK_Targets>
</IK_Definition>

В файле chrparams может быть не более одного блока <IK_Definition>.

Цель IK Определение

Вы можете определить имена соединений, необходимые для Aim IK. Вы можете обратиться к научиться создавать прицельные позы.

Первичный необходим только для того, чтобы быстрее всего пройти через иерархию до конечной кости (weapon_bone).

Аддитив предназначен для указания, будет ли движение осуществляться снизу или нет.

Если вы используете другое имя для кости оружия, обязательно замените здесь все экземпляры weapon_bone своим собственным именем!

    <Rotation JointName="Bip01 Neck"                   Primary="1" Additive="0" />
    <Rotation JointName="Bip01 Head"                   Primary="0" Additive="0" />

    <Rotation JointName="Bip01 R Clavicle"             Primary="1" Additive="0" />
    <Rotation JointName="Bip01 R UpperArm"             Primary="1" Additive="0" />

    <Rotation JointName="Bip01 R Hand"                 Primary="1" Additive="0" />
    <Rotation JointName="weapon_bone"                  Primary="1" Additive="0" />

Внутри <IK_Definition> может быть не более одного блока <AimIK_Definition>. Внутри <AimIK_Definition> может быть не более одного из следующих блоков: DirectionBlends, PositionList, RotationList, ProcAdjustments.

Конечность IK Определение

Для конечности IK вы можете указать здесь имена суставов. Пожалуйста, проверьте для получения дополнительной информации о конечности IK.

     <LimbIK_Definition>
      <IK EndEffector="Bip01 R Hand" Handle="RgtArm01" Root="Bip01 R UpperArm" Solver="2BIK"/>
      <IK EndEffector="Bip01 L Hand" Handle="LftArm01" Root="Bip01 L UpperArm" Solver="2BIK"/>
      <IK EndEffector="Bip01 R Foot" Handle="RgtLeg01" Root="Bip01 R Thigh" Solver="2BIK"/>
      <IK EndEffector="Bip01 L Foot" Handle="LftLeg01" Root="Bip01 L Thigh" Solver="2BIK"/>
     </LimbIK_Definition>

Вы можете выбрать тип решателя — если это двухкостная цепочка IK (2BIK), укажите корневую кость и концевой эффектор. Кроме того, вы можете определить дескриптор вашего IK.

Это имя дескриптора используется позже при доступе к IK через блок-схему или код.

Внутри <IK_Definition> может быть не более одного блока <LimbIK_Definition>.

Определение отдачи оружия

Здесь вы можете указать используемые рукоятки IK, шарнир оружия, на который влияет, а также ударные шарниры с задержкой и весом в определении отдачи.

<Recoil_Definition>
  <RIKHandle Handle="RgtArm01"/>
  <LIKHandle Handle="LftArm01"/>

  <ImpactJoints>
    <ImpactJoint Arm="3" Delay="0.3" Weight="0.2" JointName="Bip01 Pelvis" />
    <ImpactJoint Arm="3" Delay="0.2" Weight="0.3" JointName="Bip01 Spine"  />
    <ImpactJoint Arm="3" Delay="0.1" Weight="0.5" JointName="Bip01 Spine1" />
    <ImpactJoint Arm="3" Delay="0.0" Weight="1.0" JointName="Bip01 Spine2" />
    <ImpactJoint Arm="3" Delay="0.0" Weight="1.0" JointName="Bip01 Spine3" />
    <ImpactJoint Arm="3" Delay="0.0" Weight="1.0" JointName="Bip01 Neck" />

    <ImpactJoint Arm="3" Delay="0.10" Weight="0.10" JointName="Bip01 R Thigh" />
    <ImpactJoint Arm="3" Delay="0.05" Weight="0.05" JointName="Bip01 R Calf" />
    <ImpactJoint Arm="3" Delay="0.10" Weight="0.10" JointName="Bip01 L Thigh" />
    <ImpactJoint Arm="3" Delay="0.05" Weight="0.05" JointName="Bip01 L Calf" />

    <ImpactJoint Arm="2" Delay="0.0" Weight="1.0" JointName="Bip01 R Clavicle" />

Цели, управляемые анимацией IK

Цели IK, управляемые анимацией, определяются внутри тега <Animation_Driven_IK_Targets> </Animation_Driven_IK_Targets>.

Вы можете указать используемый дескриптор IK, определенный в определении конечности IK, целевых костях IK и костях смешивания.

<Animation_Driven_IK_Targets>
  <ADIKTarget Handle="LftArm01" Target="Bip01 Chin_IKTarget" Weight="Bip01 Chin_IKBlend"/>
</Animation_Driven_IK_Targets>

Целевые кости — это цель, которую система IK в движке использует для достижения конечности.

Кости Blend используются для определения степени достижения цели. В качестве веса система принимает локальное (родительское пространство) расстояние по оси X от родителя.

  • Расстояние 0 см = 0% веса
  • Расстояние 100 см = 100% веса.

Длина всегда фиксируется на уровне 0–100 см, поэтому, если вы превысите 100 см, она останется на уровне 100%.

Если вы работаете с добавками, IK уже активирован на 100% на нижнем уровне и хотите удалить его с помощью IK (может потребоваться для анимации перезагрузки), вам необходимо сгенерировать отрицательный вес: 1. кадр = расстояние 0 см; 2. Рамка = расстояние -100 см. Это создаст отрицательный вес и деактивирует IK.

Рекомендуется всегда включать IK, и в тот момент, когда вы хотите сделать с рукой что-то еще, кроме захвата оружия, вместо этого вы анимируете IKTarget. Это предотвращает проблемы с интерполяцией при смешивании IK.

В движке нет ничего жестко запрограммированного, что могло бы препятствовать изменению имен костей, поэтому всякий раз, когда вы настраиваете персонажа, вы можете называть кости как хотите, например long, обновляя файл .chrparams разными именами.

Подробную информацию о ретаргетинге конечностей IK см. на странице .

Внутри <IK_Definition> может быть не более одного блока <Animation_Driven_IK_Targets>.

BBoxIncludeList

<BBoxIncludeList>
  <Joint name="Bip01 L Hand"/>
  <Joint name="Bip01 R Hand"/>
  <Joint name="Bip01 L Foot"/>
  <Joint name="Bip01 R Foot"/>
  <Joint name="Bip01 L Forearm"/>
  <Joint name="Bip01 R Forearm"/>
  <Joint name="Bip01 Head"/>
  <Joint name="Bip01 Pelvis"/>
</BBoxIncludeList>

По умолчанию ограничивающая рамка персонажа основана на всех суставах персонажа. Однако вы можете включить необязательный раздел <BBoxIncludeList> и указать, какие именно соединения вы хотите использовать в ограничивающей рамке.

Примечание:

  • минимальный размер ограничивающей рамки — 5 см х 5 см х 5 см.
  • вложения включаются в ограничивающую рамку (если код не помечает их FLAGS_ATTACH_NO_BBOX_INFLUENCE)

BBoxExtension

<BBoxExtension>
  <Axis  negX="0.3" negY="0.2" negZ="0.3" posX="0.4" posY="0.1" posZ="0.7" />
</BBoxExtension>

Чтобы расширить ограничивающую рамку, вы можете использовать дополнительный раздел <BBoxExtension>.

В приведенном выше примере ограничивающая рамка расширяется на 30 см в отрицательном направлении по оси X, на 20 см в отрицательном направлении по оси Y и т. д.

Дополнительная информация

  • Вам не обязательно придерживаться соглашения об именах Biped, но есть некоторые жестко запрограммированные вещи, которые не будут работать, если вы измените свое собственное соглашение об именах. В настоящее время для выравнивания по земле вам необходимо соглашение об именах Biped для ног и ступней. А для зеркальной анимации вам понадобится соглашение об именах Biped.
  • Движок включает реализации CCD IK для большего количества костей. Если вы измените код выравнивания земли для поддержки большего количества костей и вызовете один из этих решателей CCD вместо обычного решателя, вы сможете заставить выравнивание земли работать для ваших персонажей, у которых количество костей превышает количество костей по умолчанию. Это потребует некоторых изменений кода. Кроме того, суставы могут сгибаться в неправильном направлении, как это может случиться с CCD IK.

Списки анимации персонажей

Списки анимации персонажей теперь также включены в структуру файла *.chrparams, в тег <AnimationList>. Для получения подробной информации, пожалуйста, обратитесь к документ.

В файле CAL перечислены все имена файлов анимационных ресурсов, которые движок должен загрузить для этого персонажа, и каждому активу присваивается новое игровое имя, которое будет использоваться повсюду в движке.

Раздел <AnimationList> охватывает все функциональные возможности файла CAL, но теперь все инкапсулировано в синтаксис XML.

Псевдоним анимации назначается файлу анимации с помощью

<Animation name="name" path="path\to\anim_file.caf"/>

Базы данных анимационных событий определяются:

<Animation name="$AnimEventDatabase" path="path\to\database.animevents"/>

Другие файлы .chrparams с разделом <AnimationList> включаются с помощью тега:

<Animation name="$Include" path="path\to\other_file.chrparams"/>

Будет прочитан только раздел анимлиста включенных chrparams. Остальные разделы будут игнорироваться. Включенные анимлисты могут включать в себя сами chrparams.

Отслеживаемых администраторов баз данных можно определить, как и раньше, с помощью директивы $TracksDatabase:

<Animation name="$TracksDatabase" path="animations\human\male\hits.dba"/>

Новой особенностью здесь является то, что к определениям $TracksDatabase можно применять флаги. Единственный доступный флаг на данный момент — «постоянный», что означает, что база данных должна оставаться в памяти после загрузки.

<Animation name="$TracksDatabase" path="animations\human\male\locomotion.dba" flags="persistent"/>

#Filepath используется для перемещения следующих ссылок анимации локально по пути:

<Animation name="#Filepath" path="animations\human\male"/>

Как и раньше, подстановочные знаки также поддерживаются с добавлением подпапок:

<Animation name="_*" path="lmg\*.bspace"/>
<Animation name="_*" path="lmg\*.comb"/>
<Animation name="poses_*" path="locomotion\poses\*\*.caf"/> <!-- includes subfolders -->
<Animation name="*" path="*\*.caf"/> <!-- includes subfolders -->

Пример:

<AnimationList>
  <Animation name="$AnimEventDatabase" path="animations\human\male\events.animevents"/>
  <Animation name="$Include" path="animations\human\male\male.chrparams"/>
  <Animation name="$TracksDatabase" path="animations\human\male\hits.dba"/>
  <Animation name="$TracksDatabase" path="animations\human\male\locomotion.dba" flags="persistent"/>

  <Animation name="#Filepath" path="animations\human\male"/>
  <Animation name="*" path="*\*.caf"/> <!-- includes all cafs in #Filepath and subfolders -->
  <Animation name="_*" path="*\*.bspace"/> <!-- includes all bspace in #Filepath and subfolders and prepend with _ -->
  <Animation name="_*" path="*\*.comb"/> <!-- includes all comb in #Filepath and subfolders and prepend with _ -->
</AnimationList>

В файле chrparams может быть только один блок <AnimationList>.

Создание файла .chrparams с использованием скрипта Python

При переходе со старой сборки CRYENGINE на последнюю версию CRYENGINE 3.3 или выше вам необходимо настроить файл .chrparams для всех ваших персонажей. В противном случае ваша анимация и IK не будут работать в последней сборке.

Вы можете использовать наш скрипт Python для создания файла .chrparams из существующих файлов .setup, .ik и .cal. convert_to_chrparams.py файл доступен в папке «Инструменты» вашей последней сборки.

  • Установите последнюю версию Python и поместите convert_to_chrparams.py файл в папке с игрой.
  • Дважды щелкните файл .py, чтобы выполнить сценарий Python, который пройдет через все папки внутри папки игры, найдет файлы .setup, .ik и .cal и создаст объединенный файл .chrparams.
