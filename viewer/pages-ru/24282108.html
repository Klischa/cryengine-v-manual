Большая часть взаимодействий с физическими объектами будет осуществляться через функции AddGeometry, SetParams, GetParams, GetStatus и Action. Объекты могут иметь несколько геометрий («физизированные геометрии»), которые можно добавить с помощью вызова AddGeometry (есть соответствующее RemoveGeometry функция тоже). SetParams устанавливает различные параметры. Их всегда можно запросить позже с помощью GetParams. GetStatus запрашивает состояние параметров моделирования. Отличие от GetParams это что GetStatus запрашивает значения, которые объект должен изменить во время моделирования, то есть выходные данные моделирования, в то время как GetParams параметры запросов (хотя между ними есть некоторое совпадение). Action заставляет сущность выполнить какое-то действие, например добавить импульс. Все эти функции принимают указатели на структуры в качестве параметров. Если вы хотите выполнить определенную команду, объявите где-нибудь соответствующую структуру (например, как локальную переменную) и заполните только те поля, которые вам нужны (большинство структур имеют больше полей, чем вам обычно нужно использовать за один вызов). Конструктор каждой структуры заполняет все поля специальным значением, которое сообщает физическому движку, что это поле не использовалось (для этого можно использовать макрос MARK_UNUSED и is_unused чтобы проверить, не используется ли поле).

AddGeometry добавляет к объекту физикализованную геометрию. Каждая геометрия имеет следующие свойства:

  • идентификатор: уникальный идентификатор детали в пределах объекта, которому принадлежит геометрия. Может быть задано явно или сгенерировано автоматически (AddGeometry возвращает это значение). id никогда не меняется при изменении массива частей (например, если некоторые части из середины удаляются), но внутренний индекс частей может.
  • позиция, ориентация и равномерное масштабирование относительно сущности. Неравномерное масштабирование можно указать в дополнительном параметре матрицы, но учтите, что динамическое неравномерное масштабирование не поддерживается, поэтому внутри физика просто клонирует геометрию и «запекает» в нее неравномерный масштаб.
  • масса: имеет смысл только для объектов, отличных от static; Объекты static принимают бесконечную массу во всех взаимодействиях). Можно указать массу или плотность, при этом дополнительное значение будет рассчитываться автоматически (по формуле масса = плотность*объем; объем хранится в структуре физической геометрии и масштабируется, если геометрия масштабируется).
  • surface_idx: используется, если ни IGeometry, ни физическая геометрия не имеют идентификаторов поверхности (материала).
  • флаги и flagsCollider: всякий раз, когда объект проверяет столкновения с другими объектами, он проверяет только те части, которые имеют маску флага, пересекающую flagsCollider его текущей части (т. е. [CRYENGINE:current entity part].flagsCollider & [CRYENGINE:potential collider part].flags != 0). Можно использовать 16 битов типа (называемых geom_colltype) для представления некоторых групп сущностей. Хотя это не является обязательным, хорошей практикой является сохранение этих отношений симметричными, например:
    (entityA part_i).flags & (entityB part_j).flagsCollider -> (entityB part_j].flags & (entityA part_i).flagsCollider
    В ситуациях, когда известно, что проверки на конфликты являются односторонними (т. е. объект A может проверять конфликты с объектом B, но никогда наоборот), можно не поддерживать это правило. Некоторые флаги зарезервированы для специальных групп столкновений, например, geom_colltype1 равен geom_colltype_players и geom_colltype2 равен geom_colltype_explosion (т. е. при расчете давления взрыва учитываются только детали с этим флагом). Существуют также специальные флаги для трассировки лучей и расчета плавучести, geom_colltype_ray и geom_floats соответственно (однако можно указать разные флаги, которые будут использоваться для трассировки лучей). Классы столкновений являются дополнительным способом фильтрации взаимодействий между сущностями.
  • minContactDist: Минимальное расстояние между контактами, которые эта часть объекта может иметь с другой частью другого объекта (обратите внимание, что контакты, принадлежащие разным частям, для этого не проверяются). Можно оставить неиспользованным, чтобы он был инициализирован значением по умолчанию, основанным на размере геометрии.
    Каждая деталь может иметь как геометрию, так и прокси-геометрию. Геометрия используется исключительно для трассировки лучей и прокси-геометрии во всех остальных случаях. Если прокси-геометрия не указана, обе геометрии устанавливаются равными. Идея состоит в том, чтобы позволить трассировке лучей тестироваться на высокополигональных сетках без необходимости внесения изменений в макет массива деталей.

Общие структуры аргументов

pe_params_pos
Устанавливает положение и ориентацию объекта. Можно использовать либо значения смещения/кватерниона/масштабирования напрямую, либо позволить физике извлечь их из матрицы 3x3 (ориентация+масштабирование) или 4x4 (orientation_scaling+смещение). В физике используется соглашение о порядке преобразования справа налево, где векторы являются столбцами, т. е. vector_in_world = Matrix_Entity * Matrix_Entity_Parts * vector_in_geometry. Все структуры интерфейса, поддерживающие матрицы, могут использовать в памяти расположение матриц либо по строкам, либо по столбцам (последнее считается транспонированным, поэтому соответствующий член имеет T в конце своего имени). Обратите внимание, что масштабирование по каждому объекту отсутствует. Масштабирование присутствует только для частей, поэтому всякий раз, когда новое масштабирование устанавливается через pe_params_pos, оно копируется в каждую часть и override копирует любые предыдущие отдельные масштабы, которые могли иметь эти части. Эта структура также позволяет вручную установить тип моделирования. Обычно после внесения изменений границы объекта пересчитываются, и объект перерегистрируется в хеш-сетке столкновений, хотя это можно отложить, если bRecalcBounds установлено на 0.

pe_params_bbox
Позволяет принудительно установить ограничивающую рамку объекта на определенное значение или запросить его (при использовании с GetParams). Обычно ограничивающая рамка пересчитывается автоматически на основе геометрии объекта, но установка ее вручную может быть полезна для объектов без геометрии (например, триггеров) или заполнителей. Обратите внимание: если объект имеет некоторую геометрию, он может позже пересчитать свою ограничивающую рамку, переопределив эти значения. Ограничительные рамки выровнены по осям и находятся в мировой системе координат.

pe_params_outer_entity
Позволяет указать внешнюю сущность для сущности. Всякий раз, когда интересующий блок (а именно, его центр) находится внутри объекта с внешним объектом, этот внешний объект исключается из набора потенциальных коллайдеров. Таким образом, можно быстро удалить внешний вид здания, когда интересующая область находится внутри здания. Внешние объекты могут быть вложенными, а также поддерживается дополнительная геометрия для проверки на включение.

pe_params_part
Устанавливает или запрашивает свойства части сущности. Деталь можно указать либо с помощью внутреннего индекса детали, либо по ее идентификатору.

pe_simulation_params
Устанавливает параметры моделирования для объектов, которые могут принимать эти параметры (в настоящее время это все чисто физические объекты, веревки и мягкие объекты). minEnergy равен квадрату скорости сна. Обратите внимание, что демпфирование и гравитация могут быть заданы независимо для состояний столкновения и падения (т. е. при отсутствии контактов). Важный член, если параметры моделирования maxAllowedStep, который устанавливает максимальный шаг, который может сделать физическое лицо. Если текущий мировой шаг больше этого, для этой сущности он будет разделен на несколько шагов максимально допустимой продолжительности и остаток. Для групп объектов («островов моделирования») будет использоваться минимальный предел шага.

pe_params_buoyancy
Чаще всего используется для установки параметров физических зон воды/воздуха. Для других объектов его можно использовать для масштабирования средней плотности или сопротивления воды. Например, если обнаружено, что объект находится в акватории с плотностью воды 1000 кг/м.3 и имеет шкалу плотности 0,01, эффекты упругости будут рассчитываться так, как если бы плотность воды составляла 1000*0,01 = 10 кг/м.3. Масштабы можно задавать непосредственно с помощью элементов с префиксом «k» или как псевдоабсолютные значения, и в этом случае они будут храниться как масштабы относительно значений по умолчанию, хранящихся в глобальной водной области. Это масштабирование можно использовать для моделирования негерметичной геометрии, например металлической клетки, которая в физике представлена ​​простым прямоугольником.

pe_action_impulse
Позволяет добавить сущности разовый импульс. импульс — свойство импульса (в Н*с; импульс P изменит скорость объекта на P/массу). точка это точка в мировом пространстве, где прикладывается импульс. Он используется для расчета вращательного воздействия импульса. Вместо этого точки, импульс можно использовать для явного указания вращательного импульса. Если не указаны ни точка, ни импульс, предполагается, что импульс приложен к центру масс объекта. iApplyTime определяет время подачи импульса. По умолчанию оно равно 2 («после следующего шага»), потому что, если объект на чем-то лежит, лучше сначала дать решателю возможность отразить импульс (он может даже полностью поглотить его), а не пытаться сначала сделать шаг с потенциально очень высокой скоростью.

pe_action_add_constraint
Добавляет ограничение между двумя объектами (в настоящее время это действие поддерживают только чисто физические объекты). Точки определяют позиции ограничений в мировом пространстве (если вторая точка не используется и отличается от первой, решатель попытается объединить их). Относительные положения могут быть либо фиксированными, либо лежать на одной линии, в одной плоскости, либо быть полностью независимыми, а относительные вращения могут быть ограничены в направлениях скручивания и изгиба. Эти направления соответствуют вращению вокруг оси x и оставшемуся вращению вокруг линии на плоскости yz (оно описывает наклон оси x) относительного преобразования между двумя системами координат ограничений, прикрепленными к затронутым телам. Исходное положение рамок ограничений указывается с помощью qframe параметры и могут быть указаны либо в мировом пространстве координат, либо в пространстве координат объекта (как указано соответствующим флагом в флаги). Если один или оба qframe не используются, они считаются преобразованием идентичности либо в мире, либо в кадре сущности. Пределы вращения указаны с помощью ограничения и yzlimits параметры, при этом элемент 0 является минимальным, а элемент 1 — максимальным (если минимум больше или равен максимуму, соответствующее относительное вращение полностью запрещено).

Для позиционных ограничений линии направление x в дочернем кадре определяет направление линии, а для ограничений плоскости направление x определяет нормаль к плоскости. Ограничительный кадр всегда принадлежит более тяжелому объекту из двух ограниченных (при этом статика считается безусловно более тяжелой, чем твердое тело) и движется вместе с ним.

pConstraintEntity указывает сущность, которая представляет ограничение. Это может быть объект веревки для ограничений, автоматически создаваемых натянутыми веревками (в неразделенном режиме), или это может быть физическая область (созданная с помощью AddArea). В последнем случае области с IГеометрии действовать как ограничения на основе поверхности и ожидать, что остальная часть ограничения будет установлена как ограничение плоскости (точка присоединения которого будет постоянно проецироваться на поверхность, а нормаль будет совмещена с нормалью поверхности), а области 3D-сплайна действуют как ограничения на основе линий и ожидать, что остальная часть ограничения будет установлена как ограничение линии (точка присоединения которого будет проецироваться на сплайн, а направление x будет совмещено с направлением сплайна). Обратите внимание, что ограничения на основе площади все еще требуют некоторых pBuddy ограничиться чем-л. Если pBuddy динамичен, площадь (от pConstraintEntity) можно прикрепить к нему вручную через другое ограничение, но это не обязательно (и это не предполагается автоматически).

Когда прошел pe_action_add_constraint указатель, Action возвращает идентификатор ограничения (который позже можно использовать для удаления ограничения). Оно никогда не будет равно 0, поэтому 0 указывает на сбой.

pe_action_set_velocity
Непосредственно устанавливает скорость объекта. Это очень полезное действие для твердых тел с бесконечной массой (представленной как масса). Он сообщает физической системе о скорости, с которой движется это тело, что поможет решателю обеспечить нулевую относительную скорость с объектами, с которыми оно контактирует (если скорость не задана и изменяется только положение, движок будет полагаться исключительно на проникновения для обеспечения контактов). Обратите внимание, что скорость не будет рассчитываться автоматически, если положение задается вручную в каждом кадре. Тело будет продолжать двигаться с указанной скоростью, как только она будет установлена.

pe_status_pos
Запрашивает текущую трансформацию (положение, ориентацию и масштаб) объекта или его части. Альтернативный способ — использовать pe_params_pos с GetParams. Если установлены какие-то указатели матрицы, движок заполнит их данными в соответствующем формате. Обратите внимание, что БиБокс член в этой структуре относится к позиции объекта, в отличие от pe_params_bbox.

pe_status_dymamics
Служит распространенным способом получения параметров движения объекта. Ускорение и угловое ускорение рассчитываются на основе силы тяжести и взаимодействия с другими объектами. Обратите внимание, что любые внешние импульсы, которые могли быть добавлены к объекту, не учитываются, поскольку они считаются мгновенными. submergedFraction — это часть объема объекта, находившаяся под водой во время последнего кадра (естественно, учитываются только части с флагом geom_float). waterResistance содержит максимальное сопротивление воды, с которым объект столкнулся в течение одного кадра с момента последнего запроса этого статуса (это означает, что накопленное значение очищается при возврате статуса). Это значение может быть полезно для создания эффектов всплеска.

Структуры аргументов, специфичные для живых существ

Живые существа используют цилиндры или капсулы в качестве ограничивающей геометрии. Обычно цилиндры парят над землей, и сущность стреляет вниз одним лучом, чтобы определить, стоит ли она на чем-то. Эта геометрия цилиндра всегда занимает первый паз детали (он создается автоматически). При необходимости можно добавить дополнительные геометрии вручную. Однако другие объекты будут обрабатывать их при тестировании коллизий с этим объектом. Живые существа сами никогда не меняют своей ориентации – они всегда заданы извне. Обычно ожидается, что живые существа будут вращаться только вокруг оси Z, но поддерживаются и другие ориентации, за исключением того, что столкновения с живыми существами всегда предполагают вертикально ориентированные цилиндры.

pe_player_dimensions (GetParams/SetParams)
Устанавливает размеры ограничивающей геометрии живого существа. heightPivot указывает координату Z точки в кадре объекта, которая считается на уровне ног (обычно 0). heightEye — координата Z камеры, прикрепленной к объекту. Эта камера не влияет на движение объекта, ее единственная цель — сгладить изменения высоты, которым подвергается объект (во время ходьбы по сильно ухабистой поверхности, такой как лестница, после изменения размеров и во время приземления после периода полета). Положение камеры можно запросить через pe_status_living структура. sizeCollider определяет размер цилиндра (x — радиус, z — половина высоты, y — не используется). heightColliders - координата z центра цилиндра. Голова — это вспомогательная сфера, которая проверяется на предмет столкновений с объектами над цилиндром. Столкновения голов не влияют на движение, но приводят к опусканию камеры. headRadius - радиус этой сферы и headHeight — это координата z его центра в самом верхнем состоянии (т. е. когда он ничего не касается).

pe_player_dynamics (GetParams/SetParams)
Устанавливает параметры движения живого существа. Живые существа имеют «желаемую» (также называемую «запрошенной») скорость движения (устанавливается с помощью pe_action_move) и они пытаются достичь его. Насколько быстро это произойдет, зависит от kInertia настройка. Чем больше это значение, тем быстрее достигается эта скорость. Значение по умолчанию — 8, а 0 — это особый случай, который означает, что желаемая скорость будет достигнута мгновенно. kAirControl (0..1) определяет, насколько сильно запрошенная скорость влияет на движение, когда объект летит (1 означает, что всякий раз, когда устанавливается новая запрошенная скорость, она копируется в фактическую скорость движения). kAirResistance описывает, насколько высокая скорость гасится во время полета. nodSpeed (по умолчанию 60) задает силу реакции камеры на приземление. bSwimming — это флаг, который сообщает, что объекту разрешено пытаться двигаться во всех направлениях (хотя гравитация все равно может тянуть его вниз). Если не установлено, запрошенная скорость всегда будет проецироваться на землю, если объект не летает. У живых существ есть несколько пороговых углов, которые определяют максимальные или минимальные уклоны земли для определенных видов деятельности (minSlideAngle, maxClimbAngle, maxJumpAngle и minFallAngle). Обратите внимание: если ограничивающий цилиндр объекта сталкивается с наклонной поверхностью, поведение определяется не только этими уклонами. Настройка bNetwork заставляет объект выделять гораздо более длинный массив истории перемещений, который может потребоваться для синхронизации (если не установлен, этот массив будет выделен при первом запросе действий, связанных с сетью, таких как выполнение шага назад). Настройка bActive Значение 0 переводит живое существо в специальное «неактивное» состояние, в котором оно не проверяет столкновения с окружающей средой и движется только с запрошенной скоростью (однако другие объекты все еще могут сталкиваться с ним; обратите внимание, что это применимо только к объектам того же или более высокого класса моделирования).

pe_action_move
Требует движения от живого существа. реж. — это запрошенная скорость, которую объект попытается достичь. Если iJump не равно 0, эта скорость не будет проецироваться на землю, и привязка к земле будет отключена на период short. Если iJump равно 1, скорость движения полагается равной реж. мгновенно. В случае 2, реж. к нему добавляется). дт зарезервирован для внутреннего использования.

pe_status_living
Возвращает статус живого существа. вел — это скорость, усредненная по изменению положения объекта за несколько кадров. velUnconstrained — текущая скорость движения. Оно может отличаться от вел потому что во многих случаях, когда объект натыкается на препятствие, он ограничивает фактическое движение, но сохраняет скорость движения той же, так что, если в следующем кадре препятствие закончится, скорость не будет потеряна. Если существо стоит на чем-то, groundHeight и groundSlope будет содержать координату z точки и нормаль, в противном случае bFlying будет 1. Обратите внимание, что pGroundCollider устанавливается только в том случае, если объект стоит на объекте, отличном от static. camOffset содержит текущее смещение камеры в виде трехмерного вектора в кадре объекта (хотя фактически в нем изменяются только координаты z). bOnStairs — это эвристический флаг, указывающий, что объект предполагает, что он в данный момент идет по лестнице из-за частых и резких изменений высоты.

Прогулка по жестким структурам аргументов, специфичным для сущностей

Walking Rigidentity — это реализация Living Entity, использующая Rigid Entity в качестве основы. Он может использовать проверки сдвига и скольжения, как живые существа, но также может поддерживать сложные и постоянные контакты с другими физическими объектами, такими как твердые тела. Он поддерживает некоторые живые структуры интерфейса для (ограниченной) обратной совместимости, такие как pe_player_dimensions (который автоматически создаст геометрию коллайдера и наземный луч), и pe_status_living. Как твердое тело, оно имеет бесконечную инерцию вращения, то есть физика не сможет его вращать (только перемещать/перемещать). Как и живым существам, ему нужны «земные лучи», чтобы войти в режим «стоя», но в отличие от живых существ у него может быть несколько таких лучей (однако только ближайший из них будет рассматриваться как контакт в каждом кадре). Контакт ног — это особый тип контакта с настраиваемой мягкостью и трением. Все остальные функции изменения скорости (например, все, что связано с «инерцией») были удалены из физики, и ожидается, что вызывающий код игры реализует их любым необходимым способом. Компонент SampleRigidbodyActor содержит реализацию, которая воспроизводит поведение живого существа.

pe_params_sensors (GetParams/SetParams)
Устанавливает наземные лучи. pOrigins устанавливает начало координат (в пространстве сущностей) и pDirections - направления с длиной. Важно настроить лучи так, чтобы они могли касаться земли во время обычной ходьбы (т. е. заканчиваться ниже, чем любая геометрия коллайдера), и в идеале начинать внутри некоторой геометрии, чтобы эта геометрия могла защитить их от ухода под землю (если весь луч находится под землей/внутри какой-либо геометрии, он не сможет обнаружить попадание).

pe_params_walking_rigid (GetParams/SetParams)
Устанавливает трение и мягкость (вдоль направления ноги) контактов земного луча («ног»). Кроме того, можно указать фильтрацию на основе типа столкновения и порога массы для столкновений земных лучей (minLegTestMass и legsColltype). velLegStick устанавливает, насколько быстро земля должна удаляться от нижней части луча, чтобы объект потерял контакт с землей и перешел в режим падения (обычно вам нужно некоторое умеренное значение для ходьбы по неровной местности, особенно вниз, и 0 для отрыва во время прыжка).

Структуры, специфичные для частиц

pe_params_particle
Устанавливает параметры объекта частицы. Во время движения частицы прослеживают лучи по своим траекториям длиной размер*0,5 (поскольку размер означает «диаметр», а не «радиус»), чтобы проверить, не задели ли они что-нибудь. Когда они уже лежат или скользят, они располагаются на расстоянии толщина*0,5 с поверхности (таким образом можно моделировать тонкие предметы, такие как осколки стекла). Частицам можно задать дополнительное ускорение за счет тяги подъемной силы (при условии, что у них есть крылья) с параметрами accThrust и accLift но их никогда не следует использовать без указания kAirResistance, иначе частицы приобретут бесконечную скорость. Частицы могут опционально вращаться в воздухе (переключается флагом particle_no_spin). Вращение не зависит от линейного движения частиц и меняется только после ударов или падения с поверхностей. Частицы также могут выравниваться по направлению движения (переключается кнопкой particle_no_path_alignment flag), что очень полезно для таких объектов, как ракеты. Таким образом, ось Y объекта выравнивается по курсу, а ось Z устанавливается ортогональной к Y и направленной вверх (направление «вверх» считается противоположным гравитации частицы). Двигаясь по поверхности, частицы могут как скользить, так и катиться. Прокрутку можно отключить с помощью флажка particle_no_roll (автоматически отключается на крутых склонах). Обратите внимание, что при прокатке в качестве демпфирования используется трение материала частиц, тогда как при прокатке трение обрабатывается обычным способом. Прикасаясь к земле, частицы выравниваются так, что их нормаль (определенная в рамке объекта) параллельна нормали к поверхности. Частицы также всегда могут сохранять первоначальную ориентацию (particle_constant_orientation) и полностью остановиться после первого контакта (particle_single_contact). minBounceVel определяет нижний порог скорости, после которого частица не будет отскакивать, даже если упругость контакта больше 0.

Сочлененные структуры, специфичные для сущностей

Сочлененные объекты состоят из связанных твердых тел. Петли при связывании не допускаются, а структура соединения должна представлять собой дерево с одним корнем. Структурной единицей сочлененного объекта является твердое тело, имеющее сустав, соединяющий его с родительским элементом (такой сустав может быть только один). Когда шарнирный объект используется для имитации некоторых эффектов тела без взаимодействия с окружающей средой, он использует метод Физерстоуна, который настроен так, чтобы выдерживать сильные удары и жесткие пружины в сложных структурах тела. В интерактивном режиме используется общий решатель.

pe_params_joint
Создает соединение между двумя телами в шарнирном объекте или изменяет (или запрашивает при использовании с GetParams) параметры существующего. Соединение создается между двумя телами, указанными в оп параметр в точке поворота (в рамке объекта). Всякий раз, когда геометрия добавляется к шарнирному объекту, она должна использовать pe_articgeomparams чтобы указать, какому телу принадлежит эта геометрия (в идбоди). идбоди может быть любым уникальным числом, и каждое тело может иметь несколько геометрий. Ограничений на порядок создания соединений нет, но необходимо, чтобы все тела в объекте были соединены до начала моделирования. В соединениях используются углы Эйлера для определения пределов вращения. Флаги, которые начинаются с угол0_ можно указать для каждого угла индивидуально, сдвинув их влево на индекс угла, отсчитываемый от 0 (например, чтобы заблокировать ось z, необходимо OR установить флаги с angle0_locked<<2). Система координат дочернего тела наследуется от первой назначенной ему части объекта (геометрии). Угловые пределы сустава определяются в относительной системе координат между телами, которые соединяет сустав. Рамку дочернего тела можно дополнительно сместить, указав ориентацию дочернего элемента, соответствующую углам поворота (0,0,0) (с помощью q0, pMtx0 или pMtx0T). Это может помочь получить пределы, которые можно надежно представить с помощью углов Эйлера. Общее правило относительно пределов состоит в том, чтобы устанавливать верхнюю и нижнюю границы на расстоянии не менее 15-20 градусов (хотя это зависит от настроек моделирования и от того, насколько высокой может быть скорость этого соединения) и сохранять предел по оси Y в диапазоне -90..90 градусов (желательно в пределах некоторого безопасного запаса от его концов). Обратите внимание, что в структуре параметров все углы определены в радианах. pe_params_joint использует трехмерные векторы для представления групп из трех значений, которые определяют некоторые свойства для каждого угла. В дополнение к ограничениям каждый угол может иметь пружину, которая будет приводить угол к 0, и приборную панель, которая будет демпфировать движение, когда угол приближается к своему пределу. Для удобства пружины задаются в терминах ускорения, т. е. жесткость и демпфирование могут оставаться одинаковыми для соединений, соединяющих тела с разными массами (кроме того, демпфирование можно рассчитать автоматически, чтобы получить критически демпфированную пружину, указав auto_kd для соответствующего угла). joint_no_gravity делает сустав не подверженным влиянию силы тяжести (это может быть полезно, если мы предположим, что сил, удерживающих сустав в исходном положении, достаточно, чтобы противостоять силе тяжести) и joint_isolated_accelerations заставляет сустав использовать специальный режим, в котором он рассматривает пружины не как физические пружины, а скорее как некоторые рекомендации о том, каким должно быть ускорение (этот режим рекомендуется для моделирования воздействия на скелет). Эти два флага, а также пружины и приборные панели в настоящее время поддерживаются только в режиме Featherstone. Эффективные углы соединения всегда представляют собой сумму д и qext. Если пружины активированы, они пытаются двигаться д (но не qext) до 0. Идея заключается в том, чтобы позволить установить некоторую позу из анимации, а затем применить к ней физические эффекты. В сочлененных объектах столкновения между частями проверяются только для пар, явно указанных в pSelfCollidingParts (таким образом, эта настройка относится к телу или суставу, а не к части).

pe_params_articulated_body
Позволяет устанавливать и запрашивать параметры режима моделирования шарнирного объекта. Сочлененные объекты могут быть либо прикреплены к чему-либо, либо быть свободными, как это установлено bGrounded флаг (последний не поддерживается в режиме Featherstone). При заземлении объект может либо получать динамические параметры от объекта, к которому он прикреплен (если bInreritVel установлен; сущность указана в pHost) или установите их а, ва, ш и в параметры. bCollisionResp эффективно переключается между режимом Featherstone (0) и режимом ограничения (1). bCheckCollisions включает и выключает обнаружение столкновений. В настоящее время он поддерживается только для режима ограничений. iSimType указывает тип моделирования, определяющий способ развития тел, составляющих объект. 0 означает, что повороты суставов всегда выполняются точно путем проецирования движения дочерних тел в набор ограниченных направлений, а 1 означает, что тела развиваются независимо и полагаются на решатель для обеспечения соблюдения суставов. Второй режим не поддерживается в режиме Featherstone, а в режиме ограничений он включается автоматически, если некоторые тела движутся достаточно быстро (поэтому имеет смысл оставить это значение равным 1, поскольку это делает замедленное движение более плавным). Сочлененные объекты поддерживают так называемый «режим лежания», который включается, когда количество контактов становится больше заданного порога (nCollLyingMode). Режим лежа имеет отдельный набор параметров моделирования, таких как гравитация и демпфирование. Эта функция была разработана для рэгдоллов, чтобы помочь им выглядеть менее неряшливыми при ударе о землю и простым способом имитировать высокое демпфирование человеческого тела (это достигается путем установки более низкого значения силы тяжести и более высокого, чем обычно, демпфирования). Обратите внимание, что стандартные параметры моделирования могут отличаться от параметров свободного падения. При использовании режима ограничений сочлененные объекты могут попытаться представить шарнирные соединения (т. е. вращательные соединения с включенной только осью) как две зависимости «точка-точка», что в некоторых случаях может дать лучшие результаты. Для того чтобы это произошло, организация должна иметь bExpandHinges набор параметров (он внутренне передает это значение joint_expand_hinge флажки для всех суставов, поэтому не пытайтесь установить их для суставов вручную).

Структуры, специфичные для веревочных объектов

Веревки моделируются как цепочки соединенных палочек одинаковой длины («сегментов») с точечными массами. Каждый сегмент может индивидуально сталкиваться с окружающей средой. Веревки могут связать два объекта вместе, и в этом случае они добавят ограничение к тем, когда они полностью натянуты, и не будут влиять на их движение, если нет. Для того, чтобы сталкиваться с другими объектами (при необходимости толкать их) в натянутом состоянии, веревка должна использовать режим динамического деления (задается параметром rope_subdivide_segs флаг). pe_params_rope определяет все параметры, необходимые веревке для начала работы (веревочным объектам не нужна никакая геометрия). Если начальные положения точек не указаны, предполагается, что веревка свисает со своего исходного положения, а если это так, то сегменты должны иметь одинаковую длину с некоторым допуском погрешности. Обратите внимание, что в веревках для определения трения используются не материалы, а явное значение трения. Если pe_params_rope передается GetParams, pPoints будет указателем на первую вершину во внутренней структуре вершин веревки и iStride будет содержать его размер.

Мягкие структуры, специфичные для сущностей

Существует два типа мягких объектов — на основе сетки (они используют решатель, подобный мягким ограничениям; обычно объекты ткани) и на основе тетраэдральной решетки (они используют пружинный решатель; обычно желеобразные объекты). Самые длинные ребра всех треугольников при желании можно отбросить с помощью sef_skip_longest_edges флаг. В настоящее время столкновения обрабатываются только на уровне вершин (хотя вершины имеют настраиваемую толщину) и лучше всего работают с примитивной геометрией, а не с сетками.

pe_params_softbody
Это основная структура для настройки рабочей программной сущности (еще одна — pe_simulation_params). Здесь толщина — это размер столкновения вершин (поэтому они рассматриваются как сферы). Если какое-то ребро отличается от первоначальной длины более чем maxSafeStep, вступает в силу принудительное соблюдение позиционной длины. Демпфирование пружины определяется с помощью kdRatio как отношение к критическому значению демпфирования (общее демпфирование от pe_simulation_params также поддерживается). Мягкие объекты будут реагировать на ветер, если airResistance не 0 (если ветер равен 0, имея ненулевое значение airResistance будет означать, что объект будет выглядеть так, как будто он дополнительно демпфирован - сопротивление воздуха будет пытаться сравнять скорость поверхности со скоростью воздуха). То же самое будет происходить и под водой, только параметры, указанные в pe_params_buoyancy вместо этого будет использоваться. Обратите внимание, что архимедова сила, действующая на вершины, погруженные в воду, будет зависеть от плотности объекта, которая должна быть явно определена в pe_simulation_params (зависимость будет такая же, как для твердых тел – сила будет равна 0, если waterDensity равно плотность). collTypes позволяет конфликтовать с объектами определенного типа моделирования, используя ент_ маски.

pe_action_attach_points
Может использоваться для присоединения некоторых вершин мягкого объекта к другому физическому объекту. piVtx задает индексы вершин и очки указать позиции привязки в мировом пространстве (если не используется, точки присоединения станут текущими позициями вершин). Он также поддерживается для веревок.
