Реализация нового расширения игрового объекта на C++

Использование вспомогательного шаблона

CGameObjectExtensionHelper template можно использовать для упрощения реализации GameObjectExtension. Этот помощник template будет обрабатывать функциональность RMI интерфейса расширения.

Этот template включен в заголовочный файл IGameObject.h. Чтобы использовать вспомогательный класс, объявление должно соответствовать следующему примеру:

class CNewGameObjectExt
 : public CGameObjectExtensionHelper <CNewGameObjectExt, IGameObjectExtension>
{
  //...
}

Доступен третий параметр CGameObjectExtensionHelper, который обозначает максимальное количество ИРМ поддерживается этим игровым объектом.

Важными функциями для реализации самого базового расширения игровых объектов являются следующие:

Регистрация нового расширения

Новый GameObjectExtension должен зарегистрироваться в IGameFramework, прежде чем станет возможным создавать новые экземпляры его класса.

Макрос REGISTER_FACTORY, определенный внутри IGameFramework.h, используется для упрощения регистрации.

IGameFramework *pFramework = gEnv->pGame->GetIGameFramework();
REGISTER_FACTORY(pFramework, "NewGameObject", CNewGameObjectExt, false);

Инициализация GameDLL — идеальное место для регистрации GameObjectExtension.

GameObject Обновить правила

CGameObject — класс, ответственный за включение или отключение объекта, выполняющего игровой код. Поскольку существует множество разрозненных систем, которые могут нуждаться в обновлении в разное время, класс использует механизм голосования для принятия решений между вещами. По сути, если что-то говорит, что оно нуждается в обновлении, объект активируется, и те части системы, которые в нем нуждаются, получают галочку.

Для игрового кода имеется четыре слота обновления для каждого расширения игрового объекта, и каждый из них может управляться встроенным правилом. Это правило позволяет игровому объекту самому определять состояние активации без необходимости вызова внешнего кода (чтобы избежать перегрузки памяти). Правила подробно описаны в EUpdateEnableCondition. Частью этих правил является то, зависит ли условие обновления от состояния AI или нет — обычно это так, но для некоторых слотов обновлений мы хотим, чтобы оно обновлялось отдельно (например, GameRules).

Чтобы включить или отключить AI, у нас есть отдельное правило, которое настраивается на CGameObject. EGameObjectAIActivationMode доступен и устанавливается через AIProxy. Он имеет три значения (Никогда, Всегда и VisibleOrInRange — значение по умолчанию). Игровой объект использует это значение, чтобы решить, следует ли активировать AI или нет. Важно отметить, что всякий раз, когда объект активируется, AI получает информацию, чтобы он мог поддерживать синхронизацию состояния с объектом.

Наконец, есть третье настраиваемое правило, определяющее, когда событие предварительного обновления физики должно быть отправлено объекту EPrePhysicsUpdate. Мы используем этот предварительный физический вызов для выполнения некоторой работы в AnimatedCharacter.

Чтобы увидеть, как работает эта система, вы всегда можете использовать g_showUpdateState 2. Он показывает все подробности о том, почему конкретный объект был включен.
Чтобы выполнить проверки видимости и диапазона для оценки правил обновления, делается следующее:

  • Для видимости: когда объект невидим, он регистрируется на событие от средства рендеринга, что он снова стал видимым, после чего он «становится видимым», и правила обновления переоцениваются. Когда объект видим, чтобы избежать слишком большого количества спама о событиях системы сущностей, объект регистрируется на это событие только периодически, поэтому объекту может потребоваться 5 или 10 секунд, чтобы стать невидимым, как только вы отведете взгляд.
  • Для проверки расстояния: вокруг игрока расположен довольно большой триггер приближения. Этот триггер привязан к координатам двухметровой сетки, и мы стараемся перемещать его лишь изредка (в настоящее время раз в секунду), чтобы предотвратить слишком сильное колебание системы бесконтактного триггера. По мере того, как объекты перемещаются в этот регион и покидают его, они обновляются как «далекие» или «близкие». Триггер близости нужен для того, чтобы активировать объекты сразу же, как только они войдут в зону действия.

Этот процесс управляется небольшим конечным автоматом, управляемым таблицей. CGameObject::UpdateTransitions.
