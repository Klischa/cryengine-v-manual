Обзор

Схематическая (экспериментальная) реализация плагина GamePlatform имеет три основных аспекта:

  • Типы данных, которые передаются другим узлам/функциям и хранятся в переменных.
  • Функции, которые работают с типами данных и выполняют функциональные возможности сервисов платформы.
  • События, которые прослушиваются через компонент «Приемник сигналов платформы».

На следующей странице подробно описаны типы данных и события платформы.

Функции GamePlatform работают/обслуживаются как любая другая Schematyc (экспериментальная) система.
  • Узлы Schematyc (Экспериментальные) можно использовать только при активном уровне, поскольку система Schematyc (Экспериментальная) основана на компонентах сущностей и графах сущностей.
  • В системе GamePlatform поддерживается определенная последовательность использования схематических (экспериментальных) типов данных. Однако из-за того, что система Schematyc является частично завершенной, конкретные варианты использования зависят от способа взаимодействия с системой GamePlatform (например, при обработке массивов различных типов данных).

GamePlatform Типы данных

Общая функциональность

Типы данных, перечисленные в категории GamePlatform, имеют общие функции, такие как IsEqual, NotEqualи функции преобразования строк. Это позволяет легко выводить строковое представление типа данных (обычно это уникальный идентификатор, связанный с типом данных).

Это полезно, например, при взаимодействии с системой Flash UI, которая изначально не может принимать тип данных AccountIdentifier в качестве входных данных. С помощью функций преобразования строк, когда пользователь нажимает на другое имя пользователя в UI, Flash может вернуть AccountIdentifier, связанный с выбранным пользователем.

Убедитесь, что любой ToString функция, используемая для типа данных конкретной платформы, сопоставляется с FromString на том же типе данных для той же платформы.

Смешивание значений типов данных иногда может привести к ошибке, если вам повезет; однако сами платформы смешивания (например, Steam и Discord AccountIdentifiers) не будут отображать никаких ошибок, за исключением случаев, когда вы пытаетесь получить доступ к несуществующей учетной записи на платформе.

Типы массивов

Функциональность массивов в Schematyc ограничена.

Чтобы использовать массивы определенных элементов, вам нужно будет создать переменную (типа элемента, для которого вы хотите создать массив) в вашем Script Entity. Затем вы можете использовать эту переменную с различными узлами, которые работают с массивами в качестве выходных данных.

Компонент приемника сигналов платформы и события

Компонент «Приемник сигналов платформы» предоставляет доступ к нескольким узлам сигналов, которые затем можно использовать для обработки событий платформы.

Вы можете иметь несколько компонентов приемника сигналов платформы в одном объекте Schematyc, а также можете выбирать, какие события (и с какой платформы) будут получены компонентом.

Это означает, что вы можете называть свои компоненты соответствующим образом, если хотите, например, прослушивать несколько платформ на одном объекте схемы.

Типовые события экземпляра

Некоторые типы данных в Сервисах платформы имеют свои собственные события.

Например, каждое лобби может запускать события, когда игроки входят или выходят; специальные функции добавления и удаления прослушивателя доступны из компонента приемника сигналов платформы для этих типов данных.
